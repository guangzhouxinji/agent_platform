# 三类知识产权智能助手角色权限与职责矩阵

版本：V0.2（待确认建议稿）  
日期：2026-09-14

## 1. 适用说明

本文件只汇总权限风险和供评审使用的角色候选，不替代中心现行组织制度，也不能作为代码、菜单或数据库权限表的输入。下表全部角色名称、人员范围、DataScope、是否允许兼任、多级审核和签发权限均未被确认。

“机构范围 + 业务域 + 资源范围 + 操作 + 当前状态”只是技术设计候选。当前只确认安全护栏：客户端显示不能替代服务端授权，AI 和服务身份不能冒充人工审核或正式决定。

## 2. 建议角色

| 角色标识 | 建议名称 | 核心职责 | 明确限制 | 状态 |
|---|---|---|---|---|
| PLATFORM_ADMIN | 平台管理员 | 平台级配置、业务域开关、角色映射 | 不默认查看案件、证据和咨询正文；不能代替业务审核 | 待确认 |
| INTEGRATION_SERVICE | 接口服务身份 | 在授权范围内同步或查询中心数据 | 不能执行人工审核、签发或冒用人员身份 | 待确认 |
| CONFIG_MANAGER | 配置管理员 | 维护提示词、Workflow、规则和模板草稿 | 发布权限可与编辑权限分离；不能确认正式法律结论 | 待确认 |
| CONFIG_PUBLISHER | 配置发布人 | 校验依赖并发布、回滚、紧急撤销配置 | 不直接修改已发布版本 | 待确认 |

| ENF_HANDLER | 执法承办人 | 核实线索、登记证据、发起分析、修订工作草稿 | 不能将辅助结果直接确认为正式处罚或签发文书 | 待确认 |
| ENF_REVIEWER | 执法复核人 | 复核线索解析、证据、侵权分析和建议 | 最终复核默认与提交人分离 | 待确认 |
| ADJ_HANDLER | 裁决承办人 | 管理授权案件、确认材料、发起分析和修订报告 | 不能用模型结果直接推进正式案件状态 | 待确认 |

| OFFICIAL_CONFIRMER | 正式状态确认人 | 根据真实签发动作或中心回执登记正式状态 | 与普通复核分离；没有事实或回执不得确认 | 待确认 |
| AUDITOR | 审计人员 | 查询授权范围内的操作、访问和运行追踪 | 默认只读；敏感正文需额外资源权限 | 待确认 |
| OPS_OPERATOR | 运维人员 | 部署、监控、备份恢复和故障处理 | 数据库运维权限不自动获得业务数据查看权 | 待确认 |

## 4. 职责分离建议（待 P0-04/P0-09 确认）

- 是否要求最终报告或文书的提交人与最终复核人分离，由中心制度确认；在确认前不得自行放宽或强制。
- 配置编辑与生产发布是否强制分离，由中心按风险等级确认；紧急撤销必须单独授权并留痕。
- 模型、服务账号和接口服务身份永远不能成为人工审核人、复核人或正式状态确认人。
- 数据库管理账号、部署账号和业务账号分离，运维权限不推导业务查看权限。
- Evidence 的上传人、收集人、核验人、采信人按真实职责分别记录。
- 代理审核、多级审核和临时代办必须有有效期、授权来源和操作审计。

## 5. 当前授权与历史记录的技术建议

- 运行时使用当前可信身份和授权结果；历史运行证据仅用于追溯，不能作为永久访问凭证。具体字段和对象在目标 MVP 设计时确定。
- 用户查看历史会话、报告、引用和文件时必须重新检查当前权限。
- 权限收紧或资源撤回后，禁止通过缓存、旧下载链接、索引片段和历史报告泄露正文。
- 审计记录可保留“谁在何时访问了什么”的最小信息，不等于审计人员自动获得全部业务正文。

## 6. 评审待确认

1. 中心已有角色名称、组织层级及 SSO/网关提供的身份字段。
2. 咨询数据是仅本人可见、机构共享还是按项目授权。
3. 执法和裁决是否允许一人兼任承办与中间审核，最终复核如何分离。
4. 规则、模板、Prompt 和 Workflow 的编辑与发布是否强制双人控制。
5. 正式状态由哪个系统和角色确认，线下签发需要什么证明。
6. 审计、运维和技术支持可见的数据范围及脱敏方式。
