# 执法 MVP 逻辑持久化设计

版本：V0.1  
日期：2026-09-15  
关联任务：`ARC-10-ENF-LOGICAL`  
设计输入：`docs/21-执法MVP最小领域模型.md`、`docs/22-执法MVP领域行为与不变量.md`、`docs/23-执法MVP用例与服务设计.md`、`docs/24-执法MVP最小API设计.md`。  
设计性质：存储无关的逻辑记录设计；不定义 DM8 表名、列类型、主外键语法、索引、SQL、迁移、连接、事务实现或代码。

## 1. 持久化边界

V0 只保存合成执法工作结果和使其可追溯的最小来源引用。真实中心线索、案件、证据原件、权利、法规/规则、权限和正式业务状态仍由权威系统拥有；没有 P0-03/07 的真实授权时不得因本设计复制、索引或长期保留真实正文/文件。

必须满足：

1. 每个版本化结果追加保存，机器原始结果、人工修订和审核历史不能覆盖。
2. 每个关系和分析能够定位实际输入对象与确切版本，不使用“最新”替代历史证据。
3. 当前授权在读取时由外部端口判断；历史授权判定只保留最小审计引用，不能作为永久放行凭证。
4. 来源失效、证据排除或输入更新通过追加影响记录和新结果版本表达，不删除/改写旧历史。
5. 任务、审核、证据可用性和正式业务状态不共用一个状态字段；正式状态不在 V0 本地模型中。

## 2. 逻辑记录总览

```text
WorkItem
  ├─ SourceLocator (clue/case/right/rule/evidence source identity)
  ├─ ClueAnalysisVersion
  │    ├─ ClueFieldCandidate
  │    └─ ClueIssue (missing/conflict)
  ├─ EvidenceReferenceVersion
  ├─ EvidenceRelationSetVersion
  │    ├─ EvidenceRelation
  │    └─ TimelineEntry / Gap / UnprocessedItem
  ├─ AuxiliaryAnalysisVersion
  │    └─ AnalysisItem
  ├─ HumanReviewRecord
  ├─ ReviewImpact
  └─ IdempotencyBinding
```

## 3. 核心逻辑记录

### 3.1 WorkItemRecord

唯一归属：`EnforcementWorkItem`。

最小内容：本地 `workItemId`、固定 `clueSourceLocatorId`、可选案件/权利来源定位引用、`organizationRef`、V0 范围标识、创建时间和技术版本。它不保存中心正文、中心案件状态或“是否违法”。

### 3.2 SourceLocatorRecord

唯一归属：权威来源引用的技术承载，由使用它的执法对象引用。

最小内容：本地 `sourceLocatorId`、来源类型、来源系统标识、源对象稳定标识、源版本；无源版本时保存获取时间与内容摘要；可选页码、字段路径、片段定位或音视频时间点；创建时间。受控资源引用另存，不能把磁盘路径当来源定位。

同一权威来源可以有多个版本记录；历史结果引用确切 `sourceLocatorId`。新源版本不覆盖旧记录。

### 3.3 ClueAnalysisVersionRecord

唯一归属：`ClueAnalysisVersion` 版本头。

最小内容：`analysisId`、版本号、本地工作项、输入线索定位、前一版本引用、版本产生类型（机器/人工修订）、机器/测试替身引用、可信操作主体引用、理由、创建时间、合成范围标识。

#### ClueFieldCandidateRecord

记录一个解析字段候选：所属解析版本、字段种类（主体/疑似事实/时间/地点/证据提及）、序号、结构化候选值、原始表达、可选标准化值、角色标签和 `sourceLocatorId`。信用代码没有有权来源时保持空，不创建占位假值。

#### ClueIssueRecord

记录所属解析版本、问题类型（缺失/冲突）、字段路径、说明及涉及的来源定位集合。冲突的各候选值仍保存在字段候选记录中，不在问题记录中选出“正确值”。

### 3.4 EvidenceReferenceVersionRecord

唯一归属：`EvidenceReference` 的一个不可变来源版本/可用性快照。

最小内容：本地 `evidenceRefId` 与版本、工作项、权威来源定位、至少一个关联线索/案件引用、受控资源标识、收集人/时间或缺失原因、完整性算法和值、原件引用/派生类型、当前可用性类别、不可用原因、记录时间、前一版本引用。

逻辑上必须分开：

- 来源可用性：可用、无权限、来源失效、不可解析、上游故障。
- 证据业务状态：待核验/已核验/已排除/已归档的完整规则尚未冻结，V0 不以可用性替代。
- 人工采信：不在本记录中自动产生。

相同摘要不形成唯一合并约束；不同来源或收集过程继续拥有不同记录。

### 3.5 EvidenceRelationSetVersionRecord

唯一归属：`EvidenceRelationSetVersion` 版本头。

最小内容：`relationSetId`、版本、工作项、输入解析版本、规则来源定位、前一版本、完整性分类、机器/测试替身引用、创建时间。

输入证据使用关联记录固定每个 `evidenceRefId + version`，不得只保存可变化的证据主标识。

#### EvidenceRelationRecord

最小内容：所属关系集版本、待证明事项本地标识/合成检查项、具体证据版本、关系类型（支持/反对/冲突/缺失）、理由、具体 `sourceLocatorId`、待人工核实标识。不保存“已采信”或“事实已证明”自动值。

#### TimelineEntryRecord

最小内容：所属关系集版本、时间语义（事实发生/证据收集/上传）、原始表达、可选标准化值、来源定位。未知时间不创建猜测值。

#### RelationIssueRecord

统一承载关系集内的缺口、冲突和未处理材料，但必须保留类别、受影响事项/证据版本、来源定位和原因，不得用一个空文本掩盖差异。

### 3.6 AuxiliaryAnalysisVersionRecord

唯一归属：`AuxiliaryAnalysisVersion` 版本头。

最小内容：`analysisResultId`、版本、工作项、固定解析版本、固定关系集版本、规则/权利来源定位、前一版本、受限辅助结果分类、逐项原因、非正式决定标识、机器/测试替身引用、创建时间。

输入证据和其他输入使用清单记录固定每个对象类型、对象标识、确切版本与来源定位；历史权利状态缺失也作为输入缺口，不以当前状态补齐。

#### AnalysisItemRecord

最小内容：所属分析版本、检查项本地标识、内容类别（已确认事实/当事人陈述/机器推断）、文本或结构化结果、支持/排除关系引用、来源定位、缺口、不确定性。机器推断必须有具体依据和不确定性；不得提升为已确认事实。

#### AnalysisIssueRecord

记录资料不足、规则不适用、历史状态缺失、来源故障、模型故障和未处理项，类别不可互换。严重程度、程序或处罚字段在 V0 不存在。

### 3.7 HumanReviewRecord

唯一归属：可信人工动作的追加审计记录。

最小内容：本地审核记录标识、工作项、对象类型、对象标识和确切版本、动作、前后版本引用、理由、服务端可信 `actorRef`、操作时间、范围标识、`notOfficialDecision=true`。

V0 测试身份记录只能说明测试动作发生。记录不得包含由请求体伪造的审核人，不产生证据采信、正式认定、处罚或中心状态。

### 3.8 ReviewImpactRecord

唯一归属：来源/输入变化对历史结果的影响关系。

最小内容：影响记录标识、变化类型、变化来源引用、新旧版本、受影响对象类型/标识/版本、需复核原因、发现时间。它不修改受影响历史对象，也不读取/复制已失权正文。

### 3.9 IdempotencyBindingRecord

唯一归属：应用写用例的技术幂等绑定。

最小内容：可信主体引用、用例/操作、作用域对象引用、幂等键摘要、规范化输入摘要、结果对象类型/标识/版本、创建时间。不得保存凭据或未经授权正文。相同绑定和相同输入返回原结果；输入摘要不同产生冲突。

## 4. 逻辑关系与基数

| 关系 | 基数 | 不变量 |
|---|---|---|
| WorkItem → ClueAnalysisVersion | 1:N | 每个版本固定一个线索来源版本；版本不可覆盖 |
| WorkItem → EvidenceReference | 1:N | 每个证据至少关联线索或案件之一；来源/版本不可由模型生成 |
| WorkItem → RelationSetVersion | 1:N | 每个关系集固定一个解析版本、规则版本和证据版本集合 |
| RelationSetVersion → EvidenceRelation | 1:N | 每条关系定位具体事项、证据版本、关系类型、理由和来源 |
| RelationSetVersion → Timeline/Issue | 1:N | 时间语义分离；缺口/冲突/未处理类别分离 |
| WorkItem → AuxiliaryAnalysisVersion | 1:N | 每个分析固定解析、关系集、证据、规则和可选权利版本 |
| AuxiliaryAnalysisVersion → AnalysisItem/Issue | 1:N | 事实/陈述/推断分离；异常类别不可互换 |
| WorkItem → HumanReviewRecord | 1:N | 每条审核绑定确切对象版本，追加不覆盖 |
| Source/Input change → ReviewImpact | 1:N | 一个变化可影响多个历史对象；只标记影响不改写历史 |
| Write use case → IdempotencyBinding | 1:1 per key/input | 绑定与业务结果原子保存 |

## 5. 写入原子性与历史规则

逻辑上要求下列内容同时成功或同时失败，具体事务由后续物理设计决定：

1. 新工作项与其幂等绑定。
2. 新解析版本、字段候选、缺失/冲突和幂等绑定。
3. 新证据引用版本及其关联/完整性信息和幂等绑定。
4. 新关系集版本、固定输入清单、关系、时间线、问题记录和幂等绑定。
5. 新辅助分析版本、固定输入清单、逐项内容、问题记录和幂等绑定。
6. 新人工修订版本或审核记录与幂等绑定。
7. 来源变化产生的影响记录；旧业务记录保持原样。

外部 API、文件读取、规则和模型调用不能依赖长时间持有数据库事务。保存前必须重新校验预期本地版本；当前授权复核点由用例/实现设计明确。

## 6. 读取与授权

- 工作项和本地版本读取先按当前主体、机构和资源执行授权。
- 打开线索、证据、权利、规则或文件内容时，对确切来源再次授权；本地引用存在不表示当前可读。
- 失权时可按批准策略保留最小审计标识，但不能返回正文、片段、派生内容或永久下载链接。
- 来源失效时返回可用性和需复核影响；不能改写为“无证据”“不构成”或删除历史。
- 具体权限缓存、撤权传播和保留期限由 P0-03/04/07、ARC-06/11 决定，本逻辑模型不推定。

## 7. 必须保存、条件保存与禁止保存

| 分类 | 内容 |
|---|---|
| 必须保存 | 本地对象稳定标识；权威来源标识和确切版本；对象版本关系；每项来源定位；缺失/冲突/异常；固定输入清单；机器/测试替身版本引用；可信人工动作；需复核影响；幂等结果绑定；最小时间和请求追踪引用 |
| 条件保存 | 经明确授权的来源快照/片段；文件完整性摘要；收集信息；权利历史状态；模型/规则版本；具体内容只在 P0-03/07/10 允许且为目标用例必需时保存 |
| 仅临时处理 | 获授权读取的源正文、文件字节、解析中间结构、模型请求上下文；用例完成后按批准策略清理 |
| 禁止保存 | 中心凭据、真实磁盘路径、未经授权正文/文件/索引、模型隐含推理、客户端伪造身份/授权、自动证据采信、正式违法/侵权/处罚/程序/状态、用于永久放行的历史权限快照 |

V0 合成环境允许保存合成正文和片段作为测试数据，但必须带 `SYNTHETIC_V0` 范围标识并与未来真实环境隔离。

## 8. 三类样例的逻辑记录验证

| 样例 | 关键记录 | 验证结论 |
|---|---|---|
| 正常 | 1 个工作项、线索来源与解析版本、2 个证据引用、1 个关系集及关系/时间线、1 个辅助分析及逐项内容、1 个审核记录、各写操作幂等绑定 | 全部来源和版本可回查；审核指向确切分析版本；没有正式状态记录。 |
| 资料不足/冲突 | 解析候选及冲突、3 个证据引用（含未知收集原因/不可处理材料）、关系问题、部分分析问题、退回记录 | 冲突值分别保留；缺失/不可解析/历史状态缺失分类独立；无需补造数据。 |
| 无权限/来源失效 | 授权拒绝仅保留最小技术追踪；证据引用新可用性、ReviewImpact、旧关系/分析/审核历史 | 失权正文不落库/返回；旧历史不删除；新结果不继续使用失效证据。 |
| 幂等/并发 | 幂等绑定、版本前后关系和冲突结果 | 同键同输入不重复；同键异输入冲突；并发修订不覆盖。 |

## 9. 物理设计前仍需决定

- DM8 主键、字符串/长文本/时间/摘要类型、命名、主外键、唯一约束和索引。
- 版本号生成、并发控制、事务隔离、幂等锁和批量写入策略。
- 合成测试数据的初始化/回滚、真实数据分区/保留和敏感字段处理。
- SourceLocator 是否按复用收益拆表；嵌入式结构和 JSON 使用必须经 DM8 Spike 验证。
- 外部调用与本地事务间的检查后变化处理、失败补偿和可观测字段。
- 文件元数据与文件本体的存储边界；V0 不把文件本体放进关系数据库。

这些决定必须在 `MVP-ENF-V0-01` D 门后建立独立物理设计任务或纳入仓储实现任务设计，不能从咨询表结构直接复制。

## 10. 需求一致性复核

| 检查项 | 结果 |
|---|---|
| 涉及需求 | ENF-04、ENF-05、ENF-07、ENF-11 |
| 对象覆盖 | 六个领域对象、来源定位、影响和幂等关系均有唯一逻辑归属 |
| 三样例覆盖 | 正常、资料不足/冲突、无权限/来源失效及幂等/并发均能形成可追溯记录 |
| 无来源业务字段 | 0；技术标识、时间、摘要、幂等和影响关系明确为技术数据 |
| MUST_NOT 违规 | 0；禁止保存客户端伪造身份、自动采信、正式决定、失权正文和模型隐含推理 |
| 未进入范围 | DM8 表/类型/SQL/迁移、真实数据授权、文件本体、模型、正式权限和代码 |
| 验证范围 | 存储无关逻辑设计和合成样例映射；未执行物理数据库或业务验收 |

结论：V0 必需记录、版本关系、追加历史、影响传播、幂等绑定和禁止落库内容均有明确归属，三类样例可以完整追溯。该结论只完成 `ARC-10-ENF-LOGICAL`；下一步必须先建立 `MVP-ENF-V0-01` 具体实现任务和 D 门证据，不得直接写 DM8 SQL、API 或业务代码。
