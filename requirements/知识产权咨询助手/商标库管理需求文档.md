# 商标库管理需求文档

对应需求：一.1.1.1.1.1.1 商标库管理  
文档状态：需求初稿；中心 API 的具体能力尚未核验。  
交付原则：后端服务为对外交付内容；前端页面用于内部开发、联调和验收验证，不属于对外交付内容。


## 国产化与达梦 DM8 适配要求

- 本模块面向国产化环境交付，业务关系型数据库固定使用达梦 DM8；开发联调及数据库兼容验收均须覆盖真实 DM8，不能以 MySQL、H2 等环境通过替代。
- 本模块需要持久化的业务内容包括：授权保存的商标映射、来源时间、缓存元数据和更新记录；是否保存源数据仍受中心授权约束。数据库采用 DM8；文件二进制可使用项目已批准的文件存储，DM8 保存受控引用及元数据，不要求把所有图片和附件存入数据库。
- 驱动、连接池、ORM/持久层、分页、建表及升级脚本按实际 DM8 小版本和实例参数适配；不得直接依赖其他数据库专有语法、JSON 类型或函数。长文本、结构化内容、编号、时间及分数应选用经目标实例验证的数据类型和访问方式。
- 本模块 DM8 专项验收覆盖：注册号字符串及前导零、多类别关联、中文名称/注册人组合查询、日期边界和分页。验证事务失败回滚、连接故障恢复和权限控制；接口故障不伪装成空结果。需要恢复的任务应识别中断状态，按幂等规则恢复或显式失败，不盲目重放。
- 全文、向量和图像检索能力不得因采用 DM8 就视为已经具备；优先调用中心 API，自建时按总目录的国产化与检索约束选型并验证。
- 交付本模块适用的 DM8 初始化/升级脚本、数据库配置说明和真实 DM8 验证记录；确无本地业务表时注明原因，仍须验证与共用 DM8 服务的集成。其他国产操作系统、CPU、JDK、模型及中间件的具体型号以中心环境清单为准，不预设已完成适配。

详细共用要求见[需求总目录](知识产权咨询助手需求文档总目录.md)“3.7 国产化部署与达梦 DM8 数据库”。

## 1. 功能概述

通过裁决中心提供的 API 接入商标注册信息、异议信息、无效信息及变更记录，提供统一字段转换、分类查询、详情查看及数据更新能力，为商标检索比对和咨询服务提供基础数据。

本模块包含后端服务和内部验证页面。页面必须调用本项目后端服务，由后端访问中心 API，验证实际交付能力。中心接口凭据不得下发浏览器。

本模块不包含商标相似度检索、近似判断、注册可行性分析；以上分别在对应小模块中编写需求。首版不提供手工新增、编辑、删除中心商标源数据的能力。

## 2. 数据来源与接入规则

### 2.1 数据来源

- 商标基本信息、核定商品/服务、商标状态、异议、无效和变更记录均以中心 API 返回信息为依据。
- 基本信息与历史记录可能来自不同接口，后端应通过稳定标识建立关联。
- 接口接入方式、认证信息由后端配置；复用项目已有的数据源管理能力，不在本模块重复建设通用接口管理平台。
- 首版按需调用中心 API 查询；是否持久化、缓存或批量同步，须依据中心授权及接口能力确定，不默认承诺全量建库。
- 开发阶段允许使用明确标识的模拟数据；真实数据联调和最终业务验收不得仅使用模拟数据。

### 2.2 数据标识与转换

- 以数据源标识与源记录唯一标识共同定位记录；不得以商标名称作为唯一标识。
- 商标注册号按字符串处理，保留前导零、字母及源数据格式。无源记录 ID 时，应核实注册号与类别的唯一性后确定映射规则。
- 商标名称、注册人等文本按源数据展示；不得由模型补写缺失的事实字段。
- 商品/服务类别保留标准类别编码及名称；一个记录关联多个类别或多个商品/服务项目时不得丢失明细。
- 商标状态保留源状态值，并可映射为统一展示值。未识别状态显示“未映射”并保留原值，不能默认判为有效。
- 日期以源数据精度展示，日期字段不得因时区转换偏移一天。
- 字段为空显示“未提供”；字段无法解析时记录数据异常，不得静默生成替代值。

### 2.3 更新维护

- 查询和详情服务应返回本次获取时间；源数据提供更新时间时同时返回，两者不得混用。
- 内部页面提供“重新获取”操作，重新调用服务获取当前条件或当前记录的数据。
- 若启用缓存，“重新获取”应绕过缓存；普通查询须返回是否命中缓存及缓存对应获取时间。
- 获取失败不得用空结果覆盖已展示或已保存的数据。页面保留旧数据时，应明确标识“更新失败，当前为此前获取的数据”。
- 源记录暂时无法获取或返回不存在，不得直接推断为商标注销、失效，也不得删除相关历史记录。

## 3. 商标信息字段

下表定义服务和页面应支持承载的字段，不代表中心 API 已提供全部字段。联调时逐项记录实际映射及缺口。

| 字段名称 | 用途及规则 |
|---|---|
| 数据源标识、源记录标识 | 关联详情、历史记录及其他模块的稳定引用 |
| 商标注册号 | 展示及精确查询，按字符串保存与传递 |
| 商标名称 | 展示及名称查询；图形商标无名称时显示“未提供” |
| 商标图样 | 提供时展示及预览；缺失或加载失败不影响其他信息查询 |
| 注册人 | 展示主体名称；多个主体保留完整列表 |
| 注册地址 | 详情展示 |
| 核定使用商品/服务类别 | 类别编码及名称，支持多值 |
| 核定使用商品/服务明细 | 与类别关联的项目明细 |
| 类似群 | 源接口提供时展示，供后续模块使用 |
| 注册日期 | 日期查询及展示 |
| 有效期至 | 日期查询及展示，不单独据此推导法律状态 |
| 商标状态 | 源状态及统一展示状态 |
| 来源更新时间 | 中心提供的记录更新时间；缺失时显示“未提供” |
| 本次获取时间 | 本服务实际获取数据的时间 |
| 来源引用 | 源记录标识；中心提供原文链接时附带链接 |

## 4. 查询服务与列表

### 4.1 查询条件

| 条件 | 业务规则 |
|---|---|
| 商标注册号 | 精确匹配，去除输入首尾空格，不改变内部字符 |
| 商标名称 | 按包含关系查询，不在此处进行语义或相似度扩展 |
| 注册人 | 按名称包含关系查询 |
| 商品/服务类别 | 支持多选，多选类别之间为“或” |
| 商标状态 | 支持多选，多选状态之间为“或” |
| 注册日期范围 | 包含起止日期，可仅填写一端 |
| 有效期至范围 | 包含起止日期，可仅填写一端 |

不同条件之间为“且”。起始日期晚于结束日期时，前后端均应拒绝并返回明确提示。

以上为目标查询能力。如中心接口无法满足，须通过获授权的数据索引补齐或书面调整范围；不得只过滤当前页后声称已完成全库筛选。名称匹配语义与源接口不一致时，也应在联调清单中记录并解决。

### 4.2 分页与排序

- 内部页面默认每页 20 条，支持每页 10、20、50 条；后端限制单次最大 50 条。
- 使用稳定排序，默认注册日期倒序，同日期按稳定记录标识排序；缺失注册日期的记录排在后面。
- 源接口无法提供上述全局排序时，须在联调时确定可实现的排序规则并更新接口约定，不得仅对当前页排序冒充全局排序。
- 源接口提供可靠总数时展示总条数及分页；仅提供游标或是否有下一页时，页面使用上一页/下一页，不伪造总数。
- 支持无条件浏览为目标能力；源接口禁止无条件查询时，页面明确提示所需条件，该差异纳入范围确认。
- 修改查询条件后回到第一页。重复点击查询应避免重复提交；较早请求的迟到结果不得覆盖较新查询结果。

### 4.3 列表展示

列表展示：商标注册号、商标名称、商标图样缩略图、注册人、商品/服务类别、注册日期、有效期至、商标状态、来源更新时间和操作项。

操作项包括“查看详情”“变更记录”“异议信息”“无效信息”。历史子项是否有数据未知时不能显示为零条。

## 5. 详情与历史信息

### 5.1 商标详情

点击“查看详情”，以抽屉或详情页展示第 3 节的全部字段。商品/服务明细按类别分组，长文本可完整查看，商标图样支持放大预览。

基本信息加载成功后，允许独立加载变更、异议和无效信息。某个子项失败不影响已成功展示的内容。

### 5.2 变更记录

通过详情页标签或列表操作打开变更记录，支持分页，按变更日期倒序展示：

| 字段 | 说明 |
|---|---|
| 源记录标识 | 定位本次变更记录 |
| 变更日期 | 源数据提供的业务日期 |
| 变更事项 | 例如注册人、地址等变更事项，按源数据展示 |
| 变更前内容 | 未提供时明确显示缺失 |
| 变更后内容 | 未提供时明确显示缺失 |
| 依据或来源 | 原文编号、链接或来源标识，提供时展示 |

不得根据当前信息反推历史变更前内容，不提供源记录新增、编辑或删除按钮。

### 5.3 异议信息与无效信息

分别展示异议信息列表、无效信息列表及单条详情。字段包括源记录标识、关联商标标识、案件/决定编号、事项名称、申请或受理日期、决定日期、处理机构、进展状态、结果以及原文引用；均按接口实际提供情况展示。

不得把“存在异议申请”展示成“异议成立”，或把“存在无效申请”展示成“已宣告无效”。基本状态与历史事项存在冲突时保留原始信息并提示需核实，不自动改写法律状态。

### 5.4 子项数据状态

各子项须区分：加载中、查询成功有记录、查询成功无记录、数据源未提供该能力、访问受限、查询失败。未提供能力、访问受限或查询失败不能显示为“无异议”或“无无效记录”。

## 6. 内部验证页面

### 6.1 页面组成

| 区域 | 内容及操作 |
|---|---|
| 查询区 | 第 4 节查询条件、查询按钮、重置按钮 |
| 列表区 | 查询结果、分页、详情与历史记录入口 |
| 详情区 | 基本信息、商品/服务明细、图样预览、历史标签 |
| 数据来源区 | 来源更新时间、本次获取时间、缓存标识、重新获取按钮 |
| 内部联调信息区 | 当前数据模式（真实/模拟）、请求追踪号、错误摘要；不展示凭据 |

### 6.2 页面行为

- 点击“查询”提交条件；点击“重置”清空条件并回到第一页，按确认后的无条件浏览规则处理。
- 请求期间显示加载状态；成功但无结果显示“在当前数据范围和查询条件下未检索到商标”。
- 请求失败显示失败原因和重试入口，保留用户填写的条件。
- 页面展示的信息、筛选和分页均来自后端服务，不由前端直接调用中心 API 或硬编码正式数据。
- 页面复用项目现有登录及样式。具备模块查询权限的内部账号可访问；无权限账号由后端拒绝访问，即使绕过页面直接请求也不能查询。
- 验证页面不包含对外门户、公众注册、品牌化装修等交付要求。

## 7. 服务输入输出与异常要求

具体 URL 和代码字段名由技术设计确定，复用项目现有接口规范。以下业务契约必须覆盖，并提供可独立于页面执行的调用示例。

| 服务 | 输入 | 输出 |
|---|---|---|
| 商标列表查询 | 查询条件、分页参数 | 商标列表、实际分页信息、数据来源及获取时间 |
| 商标详情查询 | 数据源及稳定记录标识 | 商标详细信息、各历史子项的能力状态 |
| 变更记录查询 | 商标稳定标识、分页参数 | 变更记录列表、分页信息 |
| 异议信息查询 | 商标稳定标识、分页参数；查看单条时传子记录标识 | 异议列表或详情、分页信息 |
| 无效信息查询 | 商标稳定标识、分页参数；查看单条时传子记录标识 | 无效列表或详情、分页信息 |

错误须至少区分：参数错误、未登录、无权限、记录不存在、数据源未提供能力、中心认证失败、限流、超时、中心服务异常和数据解析异常。对外返回可理解的错误码、说明及请求追踪号，不返回接口密钥、内部堆栈或完整敏感请求内容。

中心 API 的连接与响应超时须有有限配置；重试仅用于可重试的只读请求，次数有上限，不得无限等待或重试。具体超时、限流及性能目标根据中心接口约束和试测结果确定，记录在联调接口约定中。

调用日志记录调用时间、操作类型、调用结果、耗时及追踪号，便于排查；不得记录认证凭据。

## 8. 验收要求

中心提供或双方选定已知期望结果的测试记录，至少覆盖普通商标、多类别或多项目商标、图形商标、字段缺失、变更记录、异议和无效事项。不存在相应真实样本的能力须单独说明，模拟测试不能替代真实联调验收。

| 编号 | 验收场景 | 预期结果 |
|---|---|---|
| TM-01 | 使用已知注册号查询 | 返回对应记录，注册号及关键字段与源数据一致 |
| TM-02 | 名称、注册人、类别与状态组合查询 | 满足约定匹配规则及“且/或”规则，无当前页过滤冒充全库筛选 |
| TM-03 | 日期范围边界与错误范围 | 边界日期被包含；非法范围前后端均拒绝 |
| TM-04 | 多页查询及修改条件 | 分页符合约定，切换条件回到首页，不伪造总数 |
| TM-05 | 查看详情、多个商品/服务项目及缺失字段 | 明细完整关联，缺失内容不被编造，图样可预览或明确提示不可用 |
| TM-06 | 查看变更、异议、无效信息 | 关联到正确商标，历史记录可追溯，不混淆申请与处理结果 |
| TM-07 | 子项未提供、无记录或失败 | 三类状态明确区分，局部失败不影响基本信息 |
| TM-08 | 中心更新数据后重新获取 | 展示新数据及新获取时间；源更新时间按源值展示 |
| TM-09 | 中心超时、限流、认证失效及解析失败 | 返回明确错误和追踪号，不伪装成空结果，不无限重试 |
| TM-10 | 使用无权限账号访问页面和直接调用服务 | 两种入口均不能获取数据 |
| TM-11 | 快速发起不同条件查询 | 页面最终展示最后一次查询结果 |
| TM-12 | 不启动验证前端，直接调用交付接口 | 完成查询、详情和历史记录验证，服务不依赖页面运行 |

## 9. 交付内容

对外交付：商标库管理服务、接口说明、字段及状态映射说明、部署配置说明、错误码说明、调用示例和验收记录。代码、镜像等载体按项目整体交付约定执行。

内部产物：商标列表与详情验证页面、历史信息查看界面、真实及模拟数据模式说明、联调用例。前端页面不纳入对外交付清单。

## 10. API 联调确认清单

以下信息当前尚未提供，技术评审时须逐项核验；本初稿不把它们视为已具备能力。

1. 基本查询、详情、变更、异议、无效分别对应哪些接口，是否有稳定关联标识。
2. 名称匹配、多条件组合、类别多选、日期范围、全局排序及分页是否满足第 4 节规则。
3. 字段覆盖程度，商标状态字典、图样访问方式及历史原文的获取方式。
4. 数据地域及时间覆盖、源更新时间含义、更新频率，以及权限对结果范围的影响。
5. 是否允许缓存、持久化及建立索引；如允许，约定保留时间、刷新和清理规则。
6. 认证方式、测试环境、限流、超时、服务可用性及双方故障排查职责。

核验后形成“满足、需补齐、调整范围”的逐项结论，并更新本需求中的对应规则。只有受影响的功能需要等待相关结论，其余页面与服务可以按模拟契约开展开发，但不得标记为真实 API 已验证。
