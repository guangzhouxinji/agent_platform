## 3. 状态修正核对

修订后的主任务聚合具有以下不变量：

1. 一个任务版本只能保存一个九状态主状态。
2. 用户取消优先阻断新动作；历史完成产物不消失。
3. 全部主要目标完成才可已完成；只要存在已完成和未完成主要子目标即为部分完成。
4. 没有完成项时，人工、等待确认、等待补充、进行中、技术失败、证据不足按明确顺序聚合。
5. 无结果、无权限、来源失效、证据不足和技术失败分别保留原因；原因不是产品状态扩展。
6. 技术失败恢复引用失败前任务版本/活动点，只重做未提交或已失效动作。
7. 取消与工具完成以成功提交的任务版本排序，迟到结果不推进已取消任务。

未增加第十个产品状态。

## 4. 逻辑记录修正核对

修订后的逻辑记录能够形成以下证据链：

```text
任务/分支/任务版本
  -> 交互焦点版本
  -> 原表达与指代绑定版本
  -> 结果集 ID / 结果集版本 / 该快照序位
  -> 候选稳定身份 / 专利文献与来源版本
  -> 候选选择版本
  -> 对照输入依赖与对照版本
  -> 回答版本 / 实质陈述版本
  -> 证据集合版本 / 充分性评估版本
```

结果集谱系另保存父版本、产生原因、检索策略变化和差异。序位只属于某个结果集快照，绝不是候选身份。所有记录均为逻辑语义，不对应本轮数据库表或字段决定。

纠正传播链为：

```text
纠正事实版本
  -> 直接依赖
  -> 传递依赖
  -> 失效产物
  -> 仍有效产物
  -> 重算命令
  -> 新产物版本
```

影响分析和执行结果自身都保存任务/依赖版本，因而可以审计和重放。

## 5. 证据充分性修正核对

评估结果 `足够 / 不足 / 冲突 / 不可评估 / 尚待补证` 不映射为新的产品状态。任务状态仍由九状态聚合：例如评估“尚待补证”且有合法补证动作时任务可进行中；合理动作耗尽且最低证据不满足时可证据不足；已有其他完成子目标时主任务可部分完成。

AI 只提供建议，确定性规则校验权限/版本/证据类型/白名单/已批准矩阵，正式专业判断仍由授权人员完成。`OQ-EVD-01` 没有关闭时，不得提交依赖未知专业阈值的“足够”。

## 6. 来源/权限变化修正核对

六类事件均使用反向依赖关系局部传播，不物理删除历史。失效来源支持的当前陈述、对照项和充分性评估被降级/失效；不相关分支继续有效。资料或权限恢复只允许重新核验，不自动复活旧证据、旧评估或旧回答。重复事件按权威事件身份和变化版本幂等，异内容冲突不会静默覆盖。

核心原则：**历史可审计不等于当前可继续使用。**

## 7. 统一变更命令修正核对

继续、补充、确认、纠正、选择、检索、对照、人工交接/回流、取消和恢复均使用统一逻辑命令：

- 同命令同载荷返回原结果。
- 同命令/幂等键不同载荷返回冲突。
- 旧任务、对象或依赖版本不写入，并返回当前版本和冲突。
- 同版本并发先提交者成功，后提交者冲突，禁止最后写覆盖。
- 重试沿用原范围和权限；变更范围/权限/业务含义必须新命令并确认/授权。
- 每次执行重验当前权限；授权快照只作审计。
- 技术锁、超时、重试次数和容量继续由 OQ-NFR-01 决定。

## 8. 纯设计反演

### 8.1 重启后恢复任务

1. 任务 T 在版本 T7 因检索工具故障进入技术失败；恢复点记录子任务 S、J09、目标/事实/范围版本、父结果集 R2、已提交产物和未完成命令 C。
2. 系统重启后读取 T7 当前快照和恢复点，重新验证身份、DataScope、来源及 C 的依赖版本。
3. 已提交的 R2 和无关完成子任务不重跑；仅对未提交或已失效的 C 继续。
4. C 成功后生成新执行、结果集 R3 和任务 T8，再按子任务状态聚合主状态。

反演结论：可恢复到明确活动点，不需要全任务重跑；真实保留期限和技术重试参数仍由 OQ-RET/NFR 阻塞。

### 8.2 来源撤回后

1. 权威来源事件 E 撤回来源版本 SV，该事件进入任务并按事件身份/版本去重。
2. 反向依赖定位证据 EV、陈述 CL、对照项 CP、充分性评估 AS 和相关任务。
3. 当前受控内容立即不可用；SV、历史引用和旧回答身份保留。
4. CL 当前有效性降级，CP/AS 局部失效并触发重评；不相关证据和对照继续有效。
5. 活动任务提示用户并在有替代合法路径时继续，否则按九状态聚合；已完成任务下次合法读取时提示。

反演结论：历史与当前使用明确分离；不会继续把撤回资料作为当前有效证据。真实事件来源和通知通道仍由 OQ-DATA/AUTH 阻塞。

### 8.3 两个并发用户纠正同一事实

1. 命令 C1、C2 均引用任务 T7 和事实 F3，但载荷不同。
2. 两者分别通过初始读取；C1 先提交，形成事实 F4、影响集合和任务 T8。
3. C2 提交时发现 expected version T7 与当前 T8 冲突，拒绝写入并返回 T8/F4 及需重新选择的冲突。
4. C2 不覆盖 F4；用户基于 T8 重新确认后才能产生新命令。

反演结论：不存在最后写覆盖；冲突行为不依赖技术锁实现或超时数值。

### 8.4 “第二个结果”跨轮引用

1. 在任务 T5、焦点 FP2、结果集 RS1-V2 中，“第二个”绑定候选 P-B；保存原表达、序位 2、RS1-V2 和 P-B 稳定身份。
2. 后续检索形成 RS1-V3 并重排 P-B，但旧绑定仍引用 RS1-V2/P-B。
3. 用户下一轮说“用第二个比较”时，若当前明确焦点仍是 FP2，则解析到旧绑定；若焦点已明确切换至 RS1-V3，则形成新绑定；多个同等焦点时澄清。
4. 重启后读取焦点和绑定版本即可重放，不按当前页面序位猜测。

反演结论：序位不作为候选身份，跨轮和重排不会静默漂移。

### 8.5 候选版本变化导致充分性失效

1. 评估 AS1 引用候选 P-B 的文献版本 PV1、特征 FV2、证据集合 ES3 和矩阵 EM1，结果为足够。
2. 候选当前文献版本变为 PV2，依赖检查确认 AS1 使用 PV1。
3. AS1 保留历史但失去当前完成依据；依赖 PV1 的陈述/对照项局部失效。
4. 系统对 PV2 重新取证形成 ES4，并按仍适用的矩阵版本重新评估为 AS2；若矩阵/证据不可用则只能记录不可评估或尚待补证，不能沿用“足够”。

反演结论：充分性可以按版本失效和重评；专业阈值没有被本设计填充。
