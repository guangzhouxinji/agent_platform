# V1-V2 需求价值对比与 V2 准入评估

评估日期：2026-09-25。结论是**尚不能证明 V2 比现有 V1 更有业务价值，也不宜以此为理由启动三域完整正式开发**。V2 对 V1 的一些真实缺口提出了可检验的行为合同，但多数仍是设计或开发期窄切片；应先验证一个内部专利技术参考 Golden Job，再决定扩大投入。此结论不否定已过 R/D 门的限定开发工作，也不撤销原始 41 项义务。

## 评估口径和事实边界

- 比较对象是同一用户目标下的**现行可用 V1 路径**和 **V2 最小任务路径**，不是代码行数、Agent 数量或页面观感。主要看首次可核查成果时间、含查证与复核的总工时、关键错误和漏项、证据核查操作、人工修订量，以及为这些收益付出的开发和运行复杂度。
- 原需求要求的不只是专利聊天：咨询涉及专利、商标、案例、独立资料库与检索；执法涉及线索、证据、规则和文书；裁决涉及历史法规、双方材料、报告与人工复核。参见[咨询专利库需求](../requirements/知识产权咨询助手/专利库管理需求文档.md)、[商标检索需求](../requirements/知识产权咨询助手/商标相似度检索需求文档.md)、[执法文书需求](../requirements/知识产权执法助手/14-执法文书自动生成需求文档.md)、[裁决总览](../requirements/知识产权裁决助手/00-需求总览与通用约定.md)。
- V1 是**已有路径和有限实现**，不是经过真实专业验收的成熟产品。当前路由仍提供专利/商标/案例检索与库、专利/商标对照、执法各工作页和裁决页，见[AppRoutes.tsx](../frontend/src/app/AppRoutes.tsx)；路由存在不证明底层数据或专业质量。V2 当前计划记载 41 项 R ready、完整范围 D 0/13，咨询开发期合成切片及部分隔离 DM8 验证已完成，但完整首任务、真实数据、专业与生产验收未完成，见[总计划第0节](../docs/08-总开发实现计划.md)。
- V2 文档自己将“减少总工时、查证成本、漏项”写为**价值假说**，将真实对照列为 E2/E3 证据要求，见[产品需求](../docs/v2/01-product-requirements-v2.md)、[评测规范](../docs/v2/13-evaluation-v2.md)。本次没有取得同题 V1/V2 真实用户试验数据；下文的“可能改善”不是“已解决”。

## 1. V2 针对 V1 的明确问题，究竟解决到哪一步

| V1 可观察问题 | V2 对应改变 | 业务价值判断和现状 |
|---|---|---|
| 当前本地公开专利检索按包含命中给标题 30 / 正文 15 分、排序及候选上限；其返回不能证明专业召回，见[PublicLocalPatentCatalogAdapter.java](../backend/adapters/public-source/src/main/java/cn/xinji/agentplatform/consultation/patentsearch/adapter/out/publiclocal/PublicLocalPatentCatalogAdapter.java#L43)。 | 披露实际范围、截断、源版本，允许获准范围内继续检索，按专家样本测召回，见[V2 工作流](../docs/v2/04-domain-workflows-v2.md)、[评测规范](../docs/v2/13-evaluation-v2.md)。 | 能降低“前几条就是全部”的误导；**尚无检索覆盖或查找时间改进证据**。增加自动扩检还可能使完成变慢。 |
| 当前专利特征建议取自 `featureTags`，对应关系使用 `claimsText().contains(feature.text())`，见[PatentComparisonService.java](../backend/patent/src/main/java/cn/xinji/agentplatform/consultation/patentcomparison/application/PatentComparisonService.java#L22)。 | V2 要权利要求原文定位、逐项对应/部分/未找到/无法判断，摘要不足时停止深层判断，见[V2 工作流](../docs/v2/04-domain-workflows-v2.md)。 | 针对显著的错判风险；**设计上更可核查，尚未证明专业准确率、修订工时改善**。保留 V1 的保守限制比假称完整专业判断更重要。 |
| 日常咨询前端把 `turns` 保存在组件状态并把历史问题文本传给下一次提交；Fixture session 使用内存 map，人工状态可为 `UNAVAILABLE`，见[DailyConsultationChat.tsx](../frontend/src/features/consultation/DailyConsultationChat.tsx#L40)、[PatentConsultationFixtureFlow.java](../backend/consultation/src/main/java/cn/xinji/agentplatform/consultation/patenttask/application/PatentConsultationFixtureFlow.java#L14)。 | V2 绑定目标、结果集、所选对象及修订版本；纠正后同任务继续，真实受理回执才称转人工，见[产品需求](../docs/v2/01-product-requirements-v2.md)、[工作流](../docs/v2/04-domain-workflows-v2.md)。 | 更可能减少重复输入、错用“第二条”和假转人工；**局部开发切片不等于完整路径已可用**，人工新增确认步骤也可能抵消节省时间。 |
| 裁决 V0 适配器返回写明“合成本地草稿”的固定两段文字，见[Dm8AdjudicationSourceAdapter.java](../backend/adapters/persistence-dm8/src/main/java/cn/xinji/agentplatform/adjudication/adapter/out/dm8/Dm8AdjudicationSourceAdapter.java#L51)。 | V2 计划按争点、双方材料、时点法规生成可修订、可复核报告，见[V2 工作流](../docs/v2/04-domain-workflows-v2.md)。 | V1 明显不是正式裁决成果；V2 是针对性目标，**不能从目标描述推断生成质量或人工节省**。 |

所以，V2 **识别并设计了**这些缺口，不等于已经在真实业务中“解决”。尤其 V1 也有版本、权限、来源及人工复核相关要求和局部实现，不能把所有正确约束记成 V2 独有创新。

## 2-3. 只有设计变化或复杂度增加、价值尚未证明的部分

| V2 提案 | 相对业务价值的证据缺口 | 复杂度与判断 |
|---|---|---|
| 三独立 Agent + 按域业务数据服务、端口和适配器 | 尚无证据表明比现有模块化服务让用户更快找到材料或少改报告；部署边界可能改善隔离、恢复，但须做故障/权限验证。 | 接口、版本、事务、运维成本增加。作为技术选择按任务验证，**不得当作产品优越性**；见[总体方案](../docs/01-总体需求与架构方案.md)、[总计划](../docs/08-总开发实现计划.md)。 |
| 通用 Goal/Task、DAG、Run/Artifact/Human/Official 多维状态、检查点、CAS、撤回传播和多维预算 | 稳定指代、纠错、防迟到覆盖与故障诚实呈现有用户价值；但是否需要全套模型、每步计划和预算维度尚无实测。 | 首任务只需相关版本、引用、授权、必要恢复点；通用 Runtime 前置会扩大设计/回归面。[Runtime 规格](../docs/v2/03-agent-runtime-spec-v2.md)已明确 P0 不预建通用引擎，应执行此限制。 |
| 四动作 ASK/CONFIRM/REVIEW/TAKE_OVER 与每处关键确认 | 真受理与有权决定是可靠性底线；频繁确认是否降低错误超过它增加的操作与等待，未知。 | 简单号码查询不应强制特征表或审核；触发依目标风险分级，只问影响结果的缺口，见[产品需求](../docs/v2/01-product-requirements-v2.md)。 |
| Agent Studio、Skill/Tool 发布图、灰度/回滚及统一任务箱 | 管理发布与追溯可能有治理收益；普通用户是否需要新工作面、管理员是否需要全域 Studio，未观察验证。 | 额外配置、审批、迁移和培训成本。首期仅记录实际用到的依赖版本与停用能力；不建画布/市场/通用灰度。[工作面提案](../docs/v2/09-workbench-ux-v2.md)本身未将对外页面视为已批准交付。 |
| 全域统一 Claim/Evidence/Source/Citation 或统一状态枚举 | 证据定位有价值，但执法采信、裁决事实认定、咨询技术参考的充分性不同。 | 若强制一套模型，可能损害领域准确性并增加映射维护；仅为首任务保留最小关系，领域语义各自负责，见[总体方案](../docs/01-总体需求与架构方案.md)。 |

安全、权限与正式决定隔离即使没有“提速”证据也不能以低价值删除；它们是原需求和业务边界。真正要证伪的是**增加的任务交互和通用机制**能否换来足够的质量、查证和修改成本收益。

## 4-5. 原目标改变与 V1 能力遗漏风险

V2 文本层面仍保留“咨询、执法、裁决的全流程辅助、服务接口与内部验证”，没有明示删除原 41 项；首条内部专利任务被称为验证方式而非最终范围，见[V2 路线图](../docs/v2/14-roadmap-v2.md)。但**实施重心**从独立资料/检索/规则/文书服务转为“同一任务的连续辅助成果”，且先做内部专利技术参考。若把首任务验收当三域交付，或用新工作台取代原服务 API，就实质改变了原目标。原总览明确执法、裁决自研前端用于内部验证、对外交付服务接口，见[执法总览](../requirements/知识产权执法助手/00-需求总览与通用约定.md)、[裁决总览](../requirements/知识产权裁决助手/00-需求总览与通用约定.md)；公众/企业咨询入口仍待范围确认，不能擅自删或承诺。

当前 V2 文档**没有明文遗漏**商标、案例、图形、执法文书、规则管理和裁决法规/报告；[产品需求](../docs/v2/01-product-requirements-v2.md)和[路线图](../docs/v2/14-roadmap-v2.md)将它们放在后续。但相对 V1 已有路由与局部服务，它们在首任务阶段没有替代验收，存在交付期被“延后即遗忘”的风险：

- 独立专利/商标/案例查询、资料库浏览及原有接口消费者；不能强制所有用户先开 Agent 任务。商标文字/读音/含义/图形和商品服务关系、案例的程序/历史法差异须分别保留，不可用专利首任务覆盖。
- 执法来源/线索/证据管理、规则配置、程序辅助及可编辑文书与导出；[执法文书需求](../requirements/知识产权执法助手/14-执法文书自动生成需求文档.md)明确重生成不覆盖人工修订。裁决法规导入/维护、双方材料、报告模板/版本、人工复核亦不能被通用证据包代替。
- 对现有入口逐项判断“可继续用/须改/待替代/无消费者”，在真实替代验收之前不删除有用功能；现有页面也不能据此直接认定已满足原需求。

## 6-9. V2 需求取舍建议

| 处理 | 具体内容 | 理由与边界 |
|---|---|---|
| **保留** | 目标/范围清楚且少问；真实来源版本和原文定位；缺全文/失败/无权限分开；稳定所选对象；纠错留历史并继续；当前授权；人工受理与正式决定隔离；真实任务对照评价。 | 分别针对误判、不可核查、重复劳动和假完成；前述 V1 代码与原需求给出了问题或安全依据。保留的是可观察行为，不预先承诺实现形态。 |
| **简化** | 首任务仅记录目标、确认特征、结果集/选择、逐项证据与一个纠正版本；必要时人工接手。完成展示只区分“辅助成果/缺口或失败/待真实人工”，正式状态仍由权威系统掌握。 | 保住核查和纠错价值，同时避免为普通查询加载全域多状态、全部四动作及普遍专业审核。具体字段与触发仍需目标任务 D 门。 |
| **暂缓** | 全域 Studio/Skill 市场、拖拽编排、通用 DAG/事件溯源、复杂灰度、统一任务箱、三域全量改造、自动扩检策略和数值预算优化。 | 等 Golden Job 或相应领域真实样本显示瓶颈/收益，再做分域决策；既有 V2 文档已将部分平台化明确延后。原需求的商标、执法、裁决能力只是**排期后置，不是删除**。 |
| **删除 V2 额外要求** | 删除任何“首版必须先建通用 Runtime/通用证据图/全域统一状态机/Studio 才能交付首任务”的**强制前置条件**，以及“每个简单查询都必须走多轮 Agent 和人工审核”的强制口径。 | 这些不是已证实的业务必要条件，且部分已被现行 V2 自己排除；仅删除不当的 V2 新增约束，不删除原 41 项、权限边界或必要追溯。正式范围变更仍须在唯一总计划/确认记录中完成。 |

上述是本报告的产品建议，不是 R/D 状态、范围批准或代码删除指令；已有的四项共同产品约束确认见[待确认事项第23节](../docs/02-待确认事项清单.md)，不能由本报告擅自撤销。

## 10. 唯一最小验证任务与准入决定

**建议任务 GJ-CON-PATENT-01（未启动、非总计划 READY 项）**：让获准的内部咨询人员用**同一个真实专利技术参考目标**，分别走现行可用 V1 路径和 V2 最小任务路径，使用同一许可数据包和来源版本，完成“找候选、明确选一篇、按权利要求核对关键特征、纠正其中一项特征、交出可核查的技术参考或明确证据不足”。任务内设置一个缺全文/来源不可用情况，以检查诚实降级；不是另开第二个验证任务。交叉安排路径先后以减小学习效应，保留原始输出和人工修订版本；专家预先写明可接受的对照与严重错误，并盲评结果。不要用 Fixture 命中或 V2 页面演示代替 V1/V2 同题比较。

- **依赖/准入输入**：真实目标与人员、逐用途获准来源和模型/人工访问、V1 可用路径、V2 最小路径、专家及预注册判据；V2 代码只在其当前 Task 的 R/D 门和数据许可满足后实施。缺真实数据时只能做交互/契约演练，不能据此判产品胜出。
- **记录**：从任务开始到可核查成果的时间、含核查/复核/纠正的总工时、逐项专业错误和漏项（严重错误单独阻断）、证据打开及定位正确率与操作次数、人工新增/删除/改写量、重复追问、失败或部分完成；同时记录构建和运行该最小路径的新增机制及维护成本。保持同一输入/许可范围与专家标准；不能只比较模型生成耗时。
- **退出判据**：事前由业务/专业责任人登记严重错误禁项和可接受的时间/修订/核查差异。V2 必须不增加严重错误，且在总工时、可靠性、核查或修订成本至少一项达到预注册的实质收益，同时其他关键指标不越过容忍线；若只换了架构或多出步骤而无净收益，停止扩大 V2，保留/改进 V1 路径并复盘具体瓶颈。一个 Golden Job 只能决定**是否继续该咨询切片**，不外推商标、执法、裁决的专业验收。
- **状态和下一步**：仅为待采纳建议；若启动，先按[开发治理规范](../docs/09-开发治理与需求追踪规范.md)把 ID、依赖、退出条件、状态写入[唯一总计划](../docs/08-总开发实现计划.md)，不得在本报告维护并行 Gate/Trace 台账。当前主任务及既有门禁不因本报告自动改变。

**最终准入判断**：当前可以继续已获准的限定开发/安全验证，但 V2 **尚不具备以“业务价值优于 V1”为依据进入三域完整正式开发或业务验收的条件**。先完成上述一个 Golden Job 的真实配对验证；如果只拿到合成数据，结论应严格写为“技术路径可行、业务增益未证”。
