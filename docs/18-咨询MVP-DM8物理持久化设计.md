# 咨询 MVP DM8 物理持久化设计

版本：V0.2  
日期：2026-09-15  
关联任务：ARC-10-CON-PHYSICAL  
前置：[逻辑持久化设计](16-咨询MVP逻辑持久化设计.md)、SPK-01-CON-JDBC。

本设计仅将咨询 V0 的逻辑记录映射到本机 Docker DM8 的可回滚初始化 SQL。它不表示中心 DM8 环境、真实来源内容、数据保留授权或专业验收已经通过。

## 1. 物理对象与唯一事实

| DM8 表 | 对应逻辑记录 | 关键约束 | 明确不保存 |
|---|---|---|---|
| `con_consultation` | 咨询会话 | 请求者引用、V0 范围和创建时间 | 角色、DataScope、正式状态 |
| `con_user_input`、`con_information_issue` | 用户输入、未决项 | 输入顺序唯一；均归属会话并引用来源定位 | 模型抽取或推理过程 |
| `con_source_locator` | 来源定位 | 只保存来源身份、版本、位置和获取时间；由其他表引用 | 专利全文、附件正文、权限策略 |
| `con_retrieval_request` | 检索请求、授权结果、执行结果 | 会话外键；授权和执行结果仅允许最小 V0 分类 | 角色规则、中心授权内容 |
| `con_retrieval_candidate` | 检索候选 | 归属检索请求并引用文献来源；可用性是本次检查结果 | 中心专利主数据与全文 |
| `con_assisted_answer`、`con_answer_candidate`、`con_answer_source_link` | 回答版本及其候选/来源关联 | 每会话版本唯一；回答、候选和来源显式关联 | 正式意见、复核决定、模型中间数据 |
| `con_idempotency_record` | 最小幂等记录 | `(requester_ref, idempotency_key)` 唯一，并精确回指本次会话和回答版本 | 请求原文、权限快照 |

`con_source_locator` 是唯一的来源身份记录。用户输入正文、候选可展示摘要和回答正文分别在其拥有的表中保存；它们只通过来源 ID 表达出处，避免重复保存版本和位置。

## 2. 约束范围

- 主键、会话归属、来源/检索/回答关联、输入顺序、回答版本和幂等键由 DM8 外键、唯一约束或检查约束保证；幂等重放返回其首次写入的确切 `answer_id`，不随会话最新回答变化。
- `access_outcome`、`execution_outcome`、`source_use_outcome` 和复核提示只限制当前 V0 的存储值，不构成完整业务状态机或权限规则。
- “候选必须来自获准检索”“失效候选不得用于新回答”“读取时重新授权”等跨表或实时不变量由领域服务执行，不能误称为 SQL 已证明。
- 所有 ID 由应用生成；未采用序列、触发器、ORM 或数据库特有主键策略，保留后续替换空间。

## 3. 初始化、回滚与验证

- 初始化脚本：[V001__consultation_mvp_v0.sql](../db/dm8/V001__consultation_mvp_v0.sql)。仅在空的本地开发账号中执行。
- 回滚脚本：[U001__consultation_mvp_v0.sql](../db/dm8/U001__consultation_mvp_v0.sql)。按外键依赖逆序删除，不删除中心数据或 DM8 账号。
- 自动测试执行 `初始化 → 三类样例最小记录 → 外键/幂等约束检查 → 回滚 → 再初始化 → 再回滚`。它只连接由环境变量提供的本地 DM8。
- 脚本不含密码、中心 URL、真实数据或业务规则；生产迁移、升级、备份恢复、并发和保留清理仍待后续任务和确认。

## 4. 三类样例落库

| 样例 | 需要的记录 | 关键结果 |
|---|---|---|
| 正常 | 会话、问题来源/输入、允许授权来源/检索、候选文献来源、候选、带来源回答、幂等记录 | 回答只关联可用候选与对应来源 |
| 资料不足/冲突 | 会话、两项冲突输入来源/输入、未决项、补问回答 | 不创建检索请求或候选 |
| 无权限 | 会话、输入、授权判定来源、拒绝检索请求、拒绝回答 | 不创建候选、回答关联或受限内容 |
| 来源失效 | 已有检索请求、来源不可用候选、来源失效回答 | 候选可保留作历史追溯，但不关联为新回答依据 |
