# V2 咨询全能力详细设计

版本D1，2026-09-24；文档交付任务ARC-V2-ALL-DESIGN-01。覆盖CON-01～12当前R及ARC-CON-TASK/SEARCH/COMPARE/CORRECT/HUMAN/OUTCOME六个切片。共用协议、身份、事务及恢复采用[docs/55](55-V2业务数据服务与运行恢复详细设计.md)，不复制为Agent数据库。D状态仅见docs/08。

## 1. 一条用户任务与六个设计切片

用户说“找与这项技术相关的专利，比较第二篇；刚才材料写错了，改后继续”。入口创建目标及消息→解析用途和必要缺口→获准检索→结果快照→明确选择→确认特征→逐项对照→纠正影响→新成果/人工→继续或完成。用户无需选择内部模块。所有动作绑定同一taskId及可追溯分支，不把新执行任务当新业务目标。

| 设计切片 | 命令及逻辑数据 | 最小独立设计验例 |
|---|---|---|
| ARC-CON-TASK-01 | CreateTask、AttachSession、SubmitMessage、ContinueTask、CancelTask；Goal/Fact/Session/Message/Attempt/Checkpoint | D-CON-TASK：重启续同目标、双会话竞争、重连不重计轮次 |
| ARC-CON-SEARCH-02 | ResolvePatent、ReadDocument、StartSearch、SelectResult、ContinueSearch；SourceVersion/ResultSet/Focus | D-CON-SEARCH：S2排序不改S1第二项，限源失败与无结果分开 |
| ARC-CON-COMPARE-03 | PrepareComparison、ConfirmFeatures、StartComparison、ReadComparison；Feature/PairResult | D-CON-COMPARE：缺权项不深入、单候选失败、从属展开 |
| ARC-CON-CORRECT-04 | ProposeCorrection、ApplyCorrection、CreateBranch；Change/Dependency/ArtifactRevision | D-CON-CORRECT：改事实只失效依赖项，保留人工修订 |
| ARC-CON-HUMAN-05 | RequestHuman、WithdrawRequest、AcceptHuman、RecordHumanResult；Package/Receipt/Decision | D-CON-HUMAN：无接收显示未受理，旧版决定不可套新版 |
| ARC-CON-OUTCOME-06 | AssessCompletion、PublishAnswer、ExportOutcome及配置命令；Claim/Citation/Completion | D-CON-OUTCOME：部分成果不变全完成、受限历史不泄露 |

设计依赖为TASK→SEARCH→COMPARE→CORRECT→HUMAN→OUTCOME，引用前段逻辑协议即可书面设计，不要求先写代码。实现仍按总计划逐段交付并回归，不能由这张设计表产生编码准入。

## 2. 任务状态、目标和确认

首条专利任务的开发期公共入口、可信身份、逐用途来源与持久恢复，以及PB-01～10验收输入见[咨询公共边界设计](61-咨询首任务开发期公共边界与独立验收设计.md)；其文稿完成不表示本篇六个切片D通过。

会话状态为进行中/结束/过期；消息为已接收/处理中/完成/失败/取消；检索执行为排队/处理中/成功/部分成功/失败/取消。用户任务九状态与docs/02第20节一致，不合并这些字段。

子目标存`goalId,revision,purpose,objectRefs,scope,requiredInputs,confirmedFacts,completionEvidence`。任务聚合按docs/38第4.1节的顺序：已接受主取消优先；非空主要目标全部满足才完成；一项完成其他未完成为部分完成；否则依次看必须人工、等待确认、关键补充、可继续活动、技术阻断、证据不足。无明确目标时保持理解/澄清，不能用空集合全满足判完成。低风险冲突并列披露，专业/权限/结论相关冲突先确认。

`POST /v2/consultation/tasks`输入原问题、允许附件引用、调用方幂等键；输出taskRef、messageRef、待补字段与允许动作。自然语言不被“必须已有专利号/已确认全部特征”挡在入口。主要目标须来自用户表达或确认，模型不得为早结束降级用户目标。

`POST tasks/{id}/messages`、`.../continue`携带消息或继续理由、预期版本及明确继承引用；非关键缺失允许先执行并披露，关键缺口返回合并追问。目标解析可给多个候选及有依赖顺序；只有服务校验后的动作可执行。

`GET tasks/{id}?revision=...`返回目标、事实、已做事项、成果、缺口、允许动作和当前权限下历史。`POST .../cancel`和`.../corrections`走控制通道，按docs/55串行版本规则中止旧尝试；普通并发消息仍409忙碌。完成后明确继续同一目标可新建关联执行，完全不同目标创建新task并保存关联与继承许可清单；开发期取消后的旧任务不可恢复，也不可借普通continue绕过，新建关联任务须重新核权与核来源；生产策略仍待证据。

## 3. 焦点、选择、纠正与人工

焦点记录`branchRef,setRef,ordinal,objectRef,selectionEvent,focusRevision,availability`。`SelectResult`必须带结果集版本与成员id或其中序位；服务解析后存对象版本。“第二个”只按已明确焦点解析；无焦点或多合理对象先澄清。“最新结果的第二个”可绑定当前分支最近已送达的唯一集合，仍须保存解析依据。新结果生成/展示/查看不改已有焦点。来源失效使原焦点不可用，不自动跳到另一篇。

`ProposeCorrection(taskRef, factRefs, replacement, sourceMessageRef)`返回影响预览、待确认项；`ApplyCorrection`仅接受用户已明确纠正/确认的值及expectedVersion。影响图规则：核心技术、目标对象、检索范围→依赖检索及后续对照/回答失效；排序→新集合排序版本，旧集合引用不变；对照特征→受影响PairResult及回答陈述；只改显示别名→展示版本，不无故重检。混合内容按字段依赖；影响无法确定的产物标待核对并禁止当前采用，不假定无影响。事实新版本、失效集合与重规划检查点同事务提交，人工原稿不覆写。

`RequestHuman`包必须包含目标、确认事实版本、实际范围、结果/选择、证据、冲突、失败步骤、未决项、可访问引用与具体请求；服务端确认接收范围，不转发全历史。请求、实际受理、决定为不同记录。`AcceptHuman`仅可信人员领取或验证的外部回执；无接收渠道返回未受理及已有获准指引。`RecordHumanResult`绑定包/产物版本、具名主体、决定依据和意见。包更新生成新修订，旧受理事件留存且显示接收的是哪一版；重要变更需再接收/复核，不暗换包。

开发期按docs/02第28节先由咨询内部工作台提供待领取列表、领取、退回、意见提交和原任务回流。领取须用服务端可信具名测试主体和expectedVersion原子占用确切包版本；请求保存或页面通知不改变为已受理。意见保存后原任务重新核对当前包、来源和权限，旧包迟到意见留在历史并提示新版需复核；断线重进可恢复待办，不能重复领取或覆盖人工原稿。真实外部人工系统后接入时仍须其可信回执，不把内部测试事件冒充甲方受理。

撤回未受理请求可本地终止；已外部受理须请求撤回并等待实际回执，超时为待核实。旧版人工结果只写回其原版并标当前需复核；新材料不自动解除人工要求。咨询普通技术参考不一律强制人工审核；正式法律/高风险/重要冲突/关键缺证及用户要求按已确认规则触发。

## 4. 逐能力详细设计

下列每节完整适用对应`governance/contracts/{ID}.json`所有条款，原文数据字段为只读输入/输出义务。表内是责任模型与操作细化，不把中心未返回字段强制伪造。每节所列D-*是设计预期，实际C/I/B证据须后续执行。

<a id="CON-01"></a>
### CON-01 商标资料

对象`TrademarkObservation`保留源id/记录id/版本、字符串注册号、名称、图样Ref、注册人数组、地址、类别及项目明细、类似群、注册/到期日期、源状态/映射、来源更新与获取时间。`TrademarkEvent`按变更/异议/无效类型及稳定子id保存日期、事项、前后值、决定机构/编号/结果/原文；能力未提供不同于零记录。

查询`GET /v2/consultation/trademarks`输入原文条件、页码/游标；不同字段AND，同字段多值OR，名称/注册人包含、注册号trim后精确，日期含端点。默认20、可选10/20/50、上限50，注册日期降序、稳定id次序、无日期最后。上游不支持全局条件/排序时返回能力缺口及实际执行范围，不对单页处理冒全库；无条件浏览不支持须显式说明。

详情、`/changes`、`/oppositions`、`/invalidations`独立查询；`refresh`绕过获准缓存，失败保留旧观察且显示失败。域模块调用公共资源，按用途决定是否保存快照，无权保存则仅受控源引用。相同名称不合并，同注册号不同类别关系需源证明。页面为查询、列表、详情、历史、图样及来源区，无中心源编辑按钮。

D-CON-01：`00012A`原样往返；多类别不丢项目；异议接口503不变“无异议”；请求q1晚于q2返回不能覆盖q2。真实I验证字段映射/图片授权，B验证与中心样例一致。

<a id="CON-02"></a>
### CON-02 专利资料

对象`PatentRecord`（源记录、号码typed列表、标题、类型、多申请人/发明人、分类体系、各日期、优先权、状态观察）、`PatentDocumentVersion`（摘要/权利要求/说明书/附图及位置、质量）、`PatentEvent`（业务日期、事件类型、结果和来源）。申请号/公开号/授权公告号字符串分开；一申请多文献版本，外观不造权利要求。

`POST /patents/resolve`输入号码和可选类型或自然语言查询上下文，返回唯一文献或候选，歧义不默认选首篇。`GET /patents`按原文号码/名称/主体/分类/状态/类型/申请与授权日期查询，分类子级显式参数，分页20/10/20/50，申请日期降序稳定id；全文与`/events`独立读取。`GET /patent-documents/{id}/versions/{v}/content?kind=`返回原文Ref、解析质量、定位及获取时间；全文/下载另验用途。

查询结果事务保存授权观察与来源版本，解析新任务追加派生文本，不覆盖文献；下载失败不影响元数据。资料任务完成须回答用户需要的字段及披露缺口；权利失效仅源事实支持，不能由缺记录推断。D-CON-02：号码歧义返回候选；同申请不同公开版本并存；OCR失败不显示完整全文；缴费接口缺失不改法律状态。I检查真实文献和DM8长文本，B检查目标信息可核验。

<a id="CON-03"></a>
### CON-03 案例及派生标注

`CaseDocumentVersion`保存案例编号/案号/标题、案件与IP类型、机构、程序/审级、审理/决定日期、结果摘录、附件、源版本；`CaseAnnotationRevision`保存事实、争点、要点、法条Ref、位置、关联文书及状态。不同程序文书不能以同案号自动合并；源原文只读。

`GET /cases`按原文编号、案号、名称、类型、机构、程序、日期、标注状态筛选，默认20/10/20/50、决定日期倒序再id。`POST /cases/{id}/extractions`固定原文和配置异步提取；`POST /case-annotations`保存草稿；`.../submit`、`.../review`、`.../publish`、`.../withdraw`分别动作，受控人工身份，不将普通保存变发布。仅已发布且源未变更标注进入已校核检索。

同原文与配置重复提取可返回已有任务；失败重试另尝试不覆盖人工版本。源更新旧标注转待复核，停止当前知识输出，保留历史。审核可同人两步仅在中心制度允许范围，不能移用裁决最终审核的职责设置。页面原文/标注并列，版本差异、退回理由、独立任务/审核入口齐备。D-CON-03：不能定位的提取待核实；重新提取不覆盖人工；待审核不得供已校核要点；源更新停止旧标注当前检索。I核原文/机构程序映射，B逐字段标注。

<a id="CON-04"></a>
### CON-04 专利检索及继续

本节的最终V1检索方法、字段准入、评分/融合/分页、Benchmark、性能和法律边界以`docs/70-专利相似度检索最终实现标准.md`为实现合同；本节任务/继续/停止语义继续适用。docs/70中的工程参数是项目技术基线，不自动扩大任何来源字段权利。

`SearchInputRevision`保存原方案/特征/号码、purpose、用户范围、日期依据、确认值；`SearchAttempt`保存query改写、method/version、实际覆盖、授权来源、开始结束/失败；`ResultSet`保存成员固定文献、匹配定位、稳定rank、可空分值及标尺、返回数/候选数/可靠总数/截断，不能混计。

`POST /patent-searches/prepare`提取候选特征，号码歧义先选文献；`POST /patent-searches`创建当前目标的执行，`GET /patent-searches/{id}/results`查固定集合；`POST .../continue`给未补缺口、动作差异及范围版本；取消按docs/55。技术参考可自然语言启动，进入正式对照才需关键特征确认。新颖性辅助须相关日期依据，不默认今天或只查有效权利。

候选召回前授权；默认相关度降序同分id，建议上限100/页20随配置披露，同族只在可靠关系时聚合可展开。不具语义召回时明确字面检索，未标定时无数值，有限重排披露候选范围。结果新建、执行完成与检查点原子提交，不把目标置完成。

Agent每轮建议`gap,proposedAction,expectedNewInformation,scopeRef`；服务比对操作指纹、权限及确认范围。原范围内改写、获准方法切换可连续执行；时间/地域/源/权限/明确范围扩大先确认并再授权。无新信息、需补件/人工、故障或目标满足有各自停止理由；资源预算耗尽是技术暂停，不是专业检索穷尽。预算无批准值不默认无限执行。

D-CON-04：S1第2篇已选，S2重排不得重绑；源A成功B超时列部分失败；只有摘要不能深入权项关系；无新信息停止保留缺口而非“无相关技术”。I验证检索覆盖/重启/撤权，B预注册Recall@K、排序、证据及任务完成，K/阈值待专家证据。

<a id="CON-05"></a>
### CON-05 商标检索

`TrademarkSearchInput`保留原文字、标准化值、原图Ref、OCR建议/人工确认、读音/含义候选、确认类别/项目、类似群/分类版本、维度、范围及用户明确状态过滤。名称/图样可以启动目标，执行前类别项目确认，不能模型补类或默默跨类。

`POST /trademark-images`检查实际类型、解码、EXIF、原文JPG/PNG及10MB可配置初值，返回受控Ref；`.../trademark-searches/prepare`给建议，`POST /trademark-searches`、查询/取消覆盖全任务。图像权限和入模分开，原图不被归一化覆盖。`DimensionResult`逐文字/读音/含义/图形给执行状态、依据、可空分值/标尺；组合权重缺批准不生成综合分，未分析不是0。

默认最多100/页20，相关度再稳定id；图像接口缺失返回该维不可用，允许明确请求剩余能力并披露，不能OCR冒图像。传CON-07时包含确认输入、源快照、维度及评分版本，不只传名称。D-CON-05：假PNG拒绝；缺图像能力无视觉分；状态未选不排除失效记录；跨类范围未确认不扩检。I图像许可/真实能力，B按维度评测。

<a id="CON-06"></a>
### CON-06 专利技术对照

`ComparisonInput`固定task/branch、目标方案或专利、候选文献版本、purpose、已确认FeatureRevision、权项、必要时点地域；`Feature`有原文、上下文、独立/从属边和定位；`PairResult`按候选逐特征保存对应/部分对应/未找到/无法判断、支持位置、差异、原因、实际范围、机器与人工版。

`POST /patent-comparisons/prepare`验证材料及权项依赖，输出特征建议/待补；`.../features/confirm`保存用户确认版本；`POST /patent-comparisons`锁定输入，逐候选尝试；报告读取、失败候选重试、人工复核和取消独立。直接指定对象及明确特征可进入，不强制先检索。

所选从属项递归展开有向引用链，循环/前项缺失拒绝该项深入分析，说明书支持不能添加为权项限定。每个特征必须有结果行，未分析行不能省略。权项文本缺失只给线索/缺证或人工；摘要不能替代。新颖性辅助按单篇覆盖，禁止多篇拼成单篇。外观单独视图/整体和局部差异分支，无独立图像能力/规则保持未执行。

批次结果允许部分成功，整体对照只有所需候选/必要特征齐备才辅助完成。未标定不出百分数，检索分与对照分不可共用。报告初始未复核，普通技术参考与正式采用分开。D-CON-06：从属链遗漏前项拒完整报告；候选B模型失败不抹A；纠正特征F2仅重算相关行；人工修改不被重生成覆盖。I权项/模型/DM8，B专家核特征、证据、意见。

<a id="CON-07"></a>
### CON-07 商标辅助比对

`TrademarkComparisonInput`固定目标/候选快照、原图、商品服务/类似群/分类版本、目的、地域、时间、选定维度和依据；`DimensionComparison`含事实、来源、意见、已分析/不适用/材料不足和理由。综合意见只采用需重点复核因素、已分析差异明显、材料不足等辅助表述，不用多数投票判法律近似。

`POST /trademark-comparisons/prepare`重新取得候选原图及实际商品服务；确认OCR/读音歧义后创建异步任务，报告/复核/取消按独立候选。文字、读音、含义、图形、整体视觉与商品服务各自证据；缺图不能从名称推视觉，同类不等同类似，未执行不计零。准备阶段缺用途/地域/时间按契约追问，不套专利条件必填规则。

报告事务绑定输入及逐维成果，重跑追加版本。D-CON-07：无候选图返回视觉材料不足；相同类别不同项目仍需关系依据；直接指定候选可比对不强制检索；历史图样撤权不从报告泄露。I标准/原图/权限，B逐维专业审阅，不评价注册成功概率。

<a id="CON-08"></a>
### CON-08 案例参考检索

`CaseSearchInput`原问题、用户事实、确认争议/IP类型、关键词与法律问题、机构/程序/时间范围；`CaseReferenceResult`文书Ref、事实/程序/法律问题对应、参考点、关键差异、历史法条Ref、排序依据/范围。初步主题可提建议，执行前按原文确认检索要素；宽泛问题不补造事实。

准备/创建/查询/取消逻辑端点`/case-searches`，默认最多50/页10、相关度再稳定id。源原文可单独检索，派生标注仅已发布版本；临时解释标本次生成且有定位。可靠关联才能聚合同纠纷，仍分别展示不同程序结果。不生成最终咨询答复，成果交CON-12重验引用后组织。

D-CON-08：同事实不同审级不合并结果；旧法案例不自动用现行法解释；源失败不返回无案例；无标尺不出精确分。I真实原文/程序字典，B专家核参考点及差异。

<a id="CON-09"></a>
### CON-09 咨询配置与运行治理

`AgentConfigRevision`稳定agentId、场景/适用用户、模型Ref、工具allowlist、知识范围、回复规则、prompt/intent/flow版本、变更说明、操作者；`ServiceAvailability`独立未启用/运行/暂停/故障降级及来源；配置草稿/校验通过/发布/归档不可混用。

`POST /agent-configs`存草稿、`/{id}/validate`核引用发布状态、工具/权限和回退，`/publish`在同事务追加不可变版并切current指针，失败旧版不变。`/rollback`重验历史依赖，紧急撤销版本不可恢复；`/pause`立即阻后续工具，新会话拒绝，历史按权限读。普通发布只影响新会话；新工具能力不能凭配置授权给用户。

`/trial-runs`固定草稿与测试标识；统计独立事件：首个有效问题正式会话数、用户消息、工具调用、成功/失败、首响应/最终耗时，Asia/Shanghai日界。测试排除；准确率有标注数/有效分母、日期和版本，无评测显示未评测。任务完成用目标定义，部分完成单列，点赞非准确率。

D-CON-09：发布事务失败旧版仍运行；固定旧会话遇紧急撤销也停止；试运行不进正式量；回滚失权依赖拒绝。I真实配置角色/模型通道，B完整目标与证据质量。

<a id="CON-10"></a>
### CON-10 提示词

`PromptRevision`稳定id、名称、GUIDE/SYSTEM类型、正文、场景/意图、用户范围、语言、变量schema（类型/必填/来源/允许默认）、版本状态、生成来源/编辑发布/测试审计。变量类型校验先于渲染；用户和文献内容转义/分隔，不提供任意模板脚本。

管理查询编号精确/正文名称包含/类型场景状态，更新时间倒序默认20；保存/预览/测试/发布/停用/紧急撤销/复制/归档独立动作。管理端`/prompts`，普通引导查询`/guides`不返回系统模板。发布校验变量定义、关联场景和完整性；调用缺必填无允许默认直接拒绝，不残留占位符。新发布不自动换agent绑定。

普通停用拒新绑定/引导展示但既有固定执行引用可继续，紧急撤销所有调用拒绝；历史引用只归档。展示、点击、成功渲染/调用、失败事件按eventId去重、测试隔离。D-CON-10：未定义变量拒发布；无权查系统正文拒绝；缺变量不执行模型；引导点击仅普通问题。I许可变量/发布人/模型，B引导有效性与注入反例。

<a id="CON-11"></a>
### CON-11 意图和目标理解

`IntentRevision`含稳定id/标签/类别/描述、正反例、关键词、槽位（类型/校验/敏感级别/关键性/追问Ref）、routeRef、资源范围及版本；`Interpretation`固定消息、获准结构上下文、意图序列、候选、提取值、来源轮次、确认性质、缺口和变化影响。置信指标可空且非准确率。

`/intents`保存/测试/发布，校验标签唯一、路由登记存在、类型匹配、回退；固定发布版不可改，普通停用/紧急撤销区别沿原文。`POST /interpretations`输入问题、上下文Ref和配置版本，输出有依赖多意图/未知/澄清，不直接执行工具。解析服务校验上下文权限，执行服务再次授权。

首批路由覆盖商标查询/检索/比对、专利查询/检索/比对、案例、法规办理、未知，能力未接通诚实返回路由不可用。批量评测固定集与模型配置，输出逐类精确/召回、槽位、多意图、未知及分母，调参集不作独立验收。D-CON-11：模型猜值不成确认事实；相关日期按目的条件必填；“刚才那个”歧义不强选；纠正影响清单不直接抹旧事实。

<a id="CON-12"></a>
### CON-12 持续对话与成果

输入输出端点采用本篇第2节和docs/55有序事件接口；`Session`固定配置、结束/到期依据，`Message`存角色、序号、原文、输入与执行引用；`ContextSnapshot`由目标、事实、选择、证据、未决和依赖版本构成，不能只拼历史问句。摘要存来源消息清单和关键字段保全结果，保全失败重取或追问，不把摘要当新的事实来源。

`FlowRevision`保存首场景、补问、工具、回复、异常出口及控制参数引用；发布校验入口唯一、可达、回退、循环技术预算和依赖有效。技术预算是获准防失控策略，不是固定业务轮数。运行根据中间结果继续，不创建通用拖拽平台。

`AnswerRevision`包含逐陈述claimId、目标Ref、证据Ref、原文定位、事实/辅助意见类型、不确定性、实际范围、限制、未完成项；`AssessCompletion`核主要目标/最低证据/限制披露，`PublishAnswer`在版本、权限、epoch及检查通过后一次发布。证据最低结构：资料回答需真实字段来源；检索线索可摘要；权项级对照需权项全文/确认特征/逐项定位；法律依据需真实条文版本，缺项降级或人工。专业充分性不能由sourceId存在推导。

用户结束/会话到期关闭输入，不等取消目标或删除历史；新会话显式连接可恢复目标并选获准继承内容。内部工作面显示目标/事实/范围、检索集合与明确选择、对照与引用、缺口、继续/纠正/取消/人工、版本变化和成果层次；管理配置页与业务工作面分权。模型隐含推理和密钥不显示。

D-CON-12：工具全成功但缺主要目标不完成；A完成B失败为部分完成；流式中断不出现完成记录；历史会话过期不能继续发消息但可在新会话重授权恢复目标；人工回执回原任务；权限变化阻历史导出。15类完整任务预期见docs/59。

## 5. 迁移、交付及未决边界

历史Fixture、内存Task和固定工具序列不直接复用为新主线；优先验证源适配器、文件/DM8组件、渲染器及稳定ID处理。旧API不支持任务/版本/当前授权的调用返回明确旧范围，不能暗造新task假兼容。新旧入口在验收后受控切换，旧报告保持原版本及历史性质，具体清单见docs/59。

全部12项交付仍是可独立调用服务、接口样例/错误说明、字段与来源映射、DM8初始化升级与实际验证、部署配置和验收记录，页面内部使用。商标/案例/外观、新颖性辅助等未被首条专利路线删除；扩展实现需本身D与外部依据。真实岗位、领域标准、预算/恢复保留及源能力缺口见docs/02第25节，不在本设计填默认业务事实。
