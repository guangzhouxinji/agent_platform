本文只记录结果集焦点转换设计修正，不是 D 门复评结论，不批准实现，不改变任何 `CON-*` 或 OPEN QUESTION 状态。

## 1. 原缺口

`docs/41` 的反向重放发现：设计能够保存结果集版本、候选稳定身份和指代绑定，但没有唯一规定 V2 的产生、送达、展示或查看是否替换 V1 当前明确焦点。因此，同一条“刚才第二个”可能被实现为绑定 V1 或 V2，开发人员仍需临场决定业务行为。

缺口不在候选身份，也不在结果集谱系，而在“系统产生新结果”和“用户明确改变交互对象”之间缺少转换守卫。

## 2. 修正后的唯一规则

1. 结果集产生、送达、展示和用户查看都不建立或切换当前明确焦点，只形成或更新当前任务/分支内的焦点候选。
2. 只有用户明确选择某个结果集版本，或用户表达包含能够唯一解析的结果集限定并成功形成指代绑定，才创建当前明确焦点新版本。
3. 省略结果集限定的“第一个”“第二个”“刚才第二个”只使用当前任务、当前分支中已经保存的当前明确焦点；无焦点或歧义时必须澄清。
4. 结果集重排或再检索形成新版本时，旧焦点及旧指代不漂移。序位只属于特定结果集快照，永远不是候选身份。
5. 来源失效、版本失效、权限收紧或 DataScope 缩小保留焦点的历史身份并将其标为当前不可用，绝不自动切换到另一个结果集。
6. 系统重启或任务恢复从持久化逻辑记录恢复任务、分支、焦点及绑定，不依据页面位置、最新生成时间、展示顺序或模型置信重新计算。

这组规则使“新结果出现”和“用户改变对象”成为不同事件。它没有增加产品任务状态；焦点仅是交互语义和逻辑记录状态。

## 3. 焦点状态语义

| 交互语义 | 定义 | 允许的后续行为 |
|---|---|---|
| 当前明确焦点 | 当前任务、当前分支中，最近一次由用户明确选择或无歧义显式限定形成的结果集版本 | 可解析省略结果集限定的序位指代；每次消费仍重验当前权限与可用性 |
| 焦点候选 | 已产生、送达、展示或查看，但尚未被用户明确选择/限定的结果集版本 | 可供用户选择；不能承接“刚才第二个”等省略限定表达 |
| 无焦点 | 当前分支从未形成明确焦点，或新分支尚未由用户明确选择结果集 | 省略限定的序位指代必须澄清 |
| 歧义焦点 | 当前表达可对应多个同等合理的任务、分支或结果集版本，无法唯一绑定 | 保存歧义候选并等待澄清；不得创建明确焦点或调用依赖该绑定的下游动作 |

上述四项不是“进行中”等九种产品任务状态，也不形成第十种产品状态。当前明确焦点还具有独立可用性；“不可用”是可用性，不是新焦点种类或产品状态。

## 4. 焦点转换表

| 当前状态 | 事件 | 唯一结果 | 是否产生新焦点版本 | 是否需要用户明确动作 |
|---|---|---|---|---|
| 任意 | 新结果集产生 | 保存结果集、版本和谱系，加入当前任务/分支的焦点候选；原明确焦点不变 | 否 | 否 |
| 任意 | 新结果集送达 | 记录送达及其分支内顺序；原明确焦点不变 | 否 | 否 |
| 任意 | 新结果集展示 | 记录展示；页面位置不改变焦点 | 否 | 否 |
| 任意 | 用户查看/打开 | 记录查看，结果集仍只是焦点候选 | 否 | 否 |
| 无焦点或有旧焦点 | 用户明确选择 V2 | 唯一解析 V2，创建绑定 V2 的焦点新版本，保留前一焦点 | 是 | 是 |
| 无焦点或有旧焦点 | 用户明确限定“V1 里的第二个” | 唯一绑定 V1 快照第二候选并创建 V1 焦点新版本 | 是 | 是 |
| 有明确焦点 V1 | 用户说“刚才第二个” | 绑定 V1 快照第二候选；焦点不变 | 否 | 是，当前表达即明确动作 |
| 有明确焦点 V1 | 普通事实、特征或范围纠正 | 焦点对象不变；依赖分析决定结果集是否失效或重算 | 否 | 是，但不是焦点动作 |
| 任意 | 用户纠正焦点/指代为 V2 | 创建 V2 焦点新版本和纠正后绑定；保留旧版本 | 是 | 是 |
| 有明确焦点 V1 | V2 是重排/再检索新版本 | V2 成为候选；V1 继续是明确焦点 | 否 | 否 |
| 有明确焦点 V1 | 来源撤回或来源版本失效 | 保留 V1 焦点身份，记录可用性变更并阻止继续消费；不自动选 V2 | 是，仅焦点记录的可用性版本变化，对象不切换 | 否；切换须用户明确动作 |
| 有明确焦点 V1 | 权限收紧或 DataScope 缩小 | 保留审计绑定，停止当前展示/消费；不自动选 V2 | 是，仅焦点记录的可用性版本变化，对象不切换 | 否；切换须用户明确动作 |
| 不可用明确焦点 V1 | 资料重新可用或权限恢复 | 重验后更新 V1 可用性；不自动恢复旧证据结论，也不切换对象 | 是，仅焦点记录的可用性版本变化，对象不切换 | 否 |
| 当前分支 | 用户明确切换任务/分支 | 恢复目标分支最后一个明确焦点；没有则为无焦点 | 是，记录上下文切换，不改写分支历史 | 是 |
| 当前分支 | 系统自动创建分支 | 新分支为无焦点；相关结果集只能成为候选 | 否 | 否 |
| 已保存任务 | 任务恢复/系统重启 | 恢复当前任务、分支、最后明确焦点及其绑定，再重验可用性 | 否 | 否 |
| 任意 | 表达可对应多个结果集/分支 | 进入歧义焦点并要求澄清，不创建明确焦点 | 否 | 需要后续澄清 |

## 5. 三次反向重放

### 5.1 V1、重启、V2 与“刚才第二个”

```text
V1 产生
-> 用户绑定 V1 第二个，形成 V1 当前明确焦点和指代绑定
-> 系统重启，恢复同一任务/分支、V1 焦点和绑定
-> V2 产生、送达、展示，仅形成焦点候选
-> 用户说“刚才第二个”
-> 使用当前明确焦点 V1
-> 唯一绑定 V1 快照中的第二个候选稳定身份
```

结论：最终绑定 V1 的第二个候选。V2 不改变 V1 的焦点和序位绑定。

### 5.2 显式回到 V1

```text
V1 产生 -> V2 产生/送达 -> 用户说“V1 里的第二个”
-> 显式版本限定唯一解析 V1
-> 创建/确认 V1 焦点新版本
-> 绑定 V1 快照中的第二个候选稳定身份
```

结论：无论 V2 是否更新，唯一回到 V1。

### 5.3 显式使用最新结果

```text
V1 产生/送达 -> V2 产生/送达 -> 用户说“用最新结果里的第二个”
-> 在当前任务/分支中查找最近已送达且唯一的结果集版本
-> 唯一解析 V2
-> 创建 V2 焦点新版本
-> 绑定 V2 快照中的第二个候选稳定身份
```

结论：唯一绑定 V2 的第二个候选。未送达的后台结果不参与“最新结果”解析；存在多个同等合理对象时进入歧义并澄清。

## 6. 逻辑记录变化

`docs/38` 的逻辑记录现在明确承载：焦点对象、焦点记录版本、焦点形成事件、焦点形成原因、前一焦点版本、新焦点版本、用户明确动作、当前任务、当前分支、指代绑定、结果集稳定身份与结果集版本、当前可用性，以及产生/送达/展示/查看形成的焦点候选事件。

这些是为了跨请求、重启和审计保存的业务逻辑记录，不等同于数据库表、字段、DTO、Controller、Runtime 或 Workflow 设计。

## 7. Component/Contract 测试设计变化

`docs/38` 14.3 新增以下契约级场景，不实现测试：

| 场景 | 核心断言 |
|---|---|
| V1 后产生 V2 | V1 保持明确焦点，V2 只成为候选 |
| V2 展示/查看 | 展示和查看均不自动切换 |
| 用户明确选择 V2 | 创建 V2 焦点新版本并保留前一焦点 |
| 用户明确引用 V1 | 唯一绑定 V1，不受 V2 送达影响 |
| “刚才第二个” | V2 仅候选时仍绑定 V1 第二候选 |
| 多分支焦点 | 先绑定当前任务/分支，再恢复该分支焦点；歧义必须澄清 |
| 重启后焦点恢复 | 由逻辑记录恢复，不按 UI 或最近结果重算 |
| V2 重排 | V1/V2 序位分别属于各自快照，旧绑定不漂移 |
| V1 失效 | 保留历史身份并标不可用，不自动切换 V2 |
| 权限收紧 | 保留审计绑定、停止消费，不自动选择其他结果集 |
| 歧义焦点 | 不建立明确焦点，不执行依赖该绑定的动作 |

这些场景只能证明 Component/Contract 行为，不能替代真实权限、来源、模型链路或 Business Acceptance。
