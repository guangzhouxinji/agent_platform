## 2. 跨契约共同语义

### 2.1 产品任务与工具执行分离

所有被咨询任务调用的契约共同遵守：

- 产品任务状态：`进行中 / 等待用户补充 / 等待确认 / 部分完成 / 已完成 / 证据不足 / 需要人工复核 / 技术失败 / 用户取消`。
- 工具执行状态只描述一次执行，例如待执行、执行中、成功、部分成功、失败、取消；不得直接把工具成功映射为产品任务完成。
- “已完成”要求主要用户目标达成、最低证据要求满足、剩余限制已披露。
- “部分完成”只用于复合目标中至少一个子任务形成可用结果且另有子任务未完成，不得掩盖核心目标失败。
- “证据不足”与真实无结果、无权限、来源失效、模型失败、工具失败和系统故障分别表达。

来源：正式总目录第 8 节；`docs/35` TASK-11、END-01～END-08、P-06～P-08；`docs/36` 第 2、4、9 节。

### 2.2 共同权限与责任边界

- 当前身份、组织和 DataScope 由权威身份/权限系统决定；不得信任前端自报身份。
- 授权范围内、只读、低风险、可恢复且不改变正式业务状态的动作可以连续执行。
- 扩大权限、实质业务范围、高风险决定、不可逆动作或正式提交必须暂停并取得对应确认。
- AI 可以理解、抽取、检索、归纳、辅助分析和草拟；不得授予权限、改写源事实或作正式法律/业务决定。
- 开发、合成或公开试点数据只能作为技术证据，不能作为正式业务验收数据。

来源：正式总目录第 8 节；`docs/35` AUTO-01～AUTO-09、DATA-01～DATA-10、P-02、P-04、P-09、P-10。

### 2.3 共同来源、版本与失败语义

- 用户输入、确认事实、工具结果、候选、证据、来源、模型输入输出和人工交接必须能区分来源与版本。
- 用户纠正不得覆盖历史；只使依赖被纠正事实的下游结果失效。
- 来源撤回、权限收紧或版本失效后，历史审计引用保留，但当前展示和继续使用服从当前权限及有效性。
- 失败至少区分无结果、证据不足、无权限、来源失效、模型失败、工具失败和系统故障，并保留可恢复进度。

来源：`docs/35` EVD-07～EVD-10、CHG-01～CHG-08、END-02～END-03、P-05、P-08。
