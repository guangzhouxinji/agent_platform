# 专利裁决报告生成需求文档

模块标识：ADJ-11；对应原需求：一.1.1.1.1.3.2。  
版本：V0.1 技术评审稿；日期：2026-09-12。  
建设条件：中心主要通过 API 提供数据；国产化部署，业务关系型数据库固定为达梦 DM8。  
交付边界：对外交付服务及接口、部署和验收资料；自研前端仅供内部验证，不交付对外页面。

本文与[需求总览与通用约定](00-需求总览与通用约定.md)共同构成开发要求。字段中文名为业务契约，接口路径和英文名由详细设计统一。涉及事实的字段缺失时返回缺口，不以模型推测满足必填。当前未完成中心 API、模型或 DM8 实测。

## 1. 功能概述

根据案件信息、确认的法律引用、专利解析、有效性与证据分析，使用指定模板生成专利裁决报告初稿，并提供修订、版本及导出服务。生成结果默认草稿，不因模型任务成功而成为正式裁决文件。

模板中无需某分析项时按配置标为不适用；需要但缺失时保留缺项，不伪造内容补齐报告。

## 2. 字段与输入快照

| 字段 | 说明 |
|---|---|
| 案件编号、案件资料版本 | 报告所属案件和冻结输入 |
| 报告编号、版本、用途 | 系统内部编号不冒充正式文号 |
| 模板编号/版本 | 固定发布版本 |
| 法律匹配/引用、解析、有效性、证据分析版本 | 列明实际采用项及其确认状态 |
| 报告结构及章节内容 | 对应稳定章节/段落 ID |
| 内容来源映射 | 每个关键事实/结论对应材料或人工意见 |
| 生成任务、生成时间、模型/规则版本 | 运行追踪 |
| 撰写人、生成执行主体 | 人工责任人和模型主体分开 |
| 完整性状态、审核状态 | 缺项与审核流程分开 |
| 修订记录、审核意见、输出文件 | 可追溯版本及受控访问 |

## 3. 生成及修订流程

1. 选择案件、用途及已发布模板，取得各资料版本及权限。
2. 执行生成前检查，列明缺必填字段、待复核分析、引用冲突和模板不适用项。
3. 允许生成“不完整草稿”用于补充，但不得提交正式复核；已满足条件时进入正常草稿生成。
4. 以冻结输入组装报告：案件事实、数字、主体、原文引用采用确定性数据；解释性段落可辅助生成并关联依据。
5. 保存结构化草稿及引用锚点，检查报告中的事实、法条和分析意见能回到实际来源。失败批次不产生已采用孤立引用。
6. 人工编辑产生新修订版本，保留原生成内容及差异；整篇或单章节重新生成须预览差异并确认采用，不覆盖人工修改。
7. 内容和来源校验通过后提交 12 人工复核。
8. 经复核通过的版本锁定为待签发/办结确认材料；正式状态须有授权签发动作或中心系统真实回执。

模型不得生成未提供的调查过程、质证记录、办理日期、事实认定、裁决结果、签章及正式文号。证据分析仍为未复核时，报告保留辅助意见身份，不把它叙述成机关已认定事实。

## 4. 版本变更与文件生成

案件、证据、引用或模板变更后，新报告使用新输入；历史报告保留原快照。已提交或通过复核的报告涉及实质内容修改时必须生成新版本并重新审核。

首版提供结构化报告、DOCX 和 PDF 输出。输出引用同一锁定内容版本，记录内容摘要值和渲染配置；DOCX/PDF 不因重复导出混入其他版本。转换失败只标记输出失败，不能丢失已保存草稿。

草稿文件清楚标注草稿；仅复核通过未签发的文件标注相应状态，不能标为已正式签发。终版输出使用中心认可模板及签发状态，不由系统自行移除审批要求。

## 5. 内部验证页面

案件和模板选择、资料版本/缺项确认、开始生成、任务进度、章节编辑、来源侧栏、引用定位、新旧差异、保存修订、重新生成、提交复核及文件预览/下载。

列表按案件、报告、模板、完整性、审核状态和时间筛选。无权限材料、缺数据、部分失败、渲染失败与任务失败分别显示。用户离开页面后可恢复查看服务端进度。

## 6. 服务契约

| 服务 | 输入 | 输出 |
|---|---|---|
| 生成准备 | 案件版本、模板、输入选择 | 完整性清单和依赖版本 |
| 创建生成 | 确认快照、用途、幂等键 | 任务 ID |
| 查询/保存修订 | 报告版本或编辑内容、并发版本 | 结构化报告或冲突 |
| 重新生成/采用 | 范围、原版本、确认动作 | 候选修订及新版本 |
| 导出 | 报告版本、格式 | 渲染任务及受控文件 |
| 提交审核 | 报告版本、补充说明 | 复核任务或阻断清单 |

报告与引用采用数据库事务或可追踪补偿保持一致。导出、下载与历史查看均执行当前权限，不能用旧文件链接绕过。任务重复提交、取消和重试遵循总览约定。

## 7. 国产化与 DM8 要求

DM8 保存报告正文、输入清单、引用位置、编辑历史、状态和文件元数据。验证大报告读写、并发编辑冲突、生成失败补偿、内容锁定及重启恢复。渲染、字体和模型在国产环境单独验证。

## 8. 验收要求

| 编号 | 场景与预期 |
|---|---|
| RPT-01 | 固定案件/模板/分析版本，缺项清单完整 |
| RPT-02 | 不完整草稿可保存但不能提交正式复核 |
| RPT-03 | 关键事实、法条和结论有来源，不编造流程或签章 |
| RPT-04 | 人工编辑及重生成差异可控，不覆盖已有修订 |
| RPT-05 | 实质修改重新审核，复核通过不自动已签发 |
| RPT-06 | DOCX/PDF 对应同一内容版本，草稿状态可见 |
| RPT-07 | 渲染失败不丢失正文，生成失败无孤立已采用引用 |
| RPT-08 | 独立 API、DM8 与国产渲染环境验证生成、编辑、导出和并发 |

## 9. 依赖与交付

依赖 04—10、12 复核及文件/模型/渲染能力。交付生成、版本和导出服务、字段来源契约及验收记录。确认模板强制项、允许生成内容、格式样例、签发衔接方式及性能规模。
