# 三类知识产权智能助手 MVP 范围与业务闭环

版本：V0.4（ARC-04 候选范围确认版，尚未正式冻结）  
日期：2026-09-14  
关联任务：ARC-04

2026-09-22 负责人基线：咨询域的完整产品目标和首段任务型闭环以 `docs/02` P0-20、`docs/35` 及已更新咨询正式需求为准。本文原有 V0/候选范围继续作为历史技术验证材料，不得用于把最终产品收缩为单一检索或单轮回答。

咨询域首段实现路线聚焦“专利资料查询 + 专利检索 + 必要时迭代检索/深化证据 + 专利技术对照 + 多轮辅助回答”，并覆盖一个由这些能力组成的复合咨询场景。商标、案例、法规和更广泛复合咨询继续保留为完整产品目标。

## 1. 评审定位

本文件依据 `requirements/`、`docs/02-待确认事项清单.md` 和 ARC-03 结论，记录三个 MVP 当前能够由原需求支持的候选范围及正式冻结缺口。三个候选业务闭环和职责范围已经基本明确，可以用于收集样例和准备业务确认；它不是新增业务规则，也不代表三个 MVP 已正式冻结或取得详细设计、开发准入。

ARC-04 只处理业务目标、使用者类别、输入、最小闭环、AI/系统/人工职责、输出、业务终点、排除项、异常场景和验收条件。本阶段不冻结具体角色名称、DataScope、状态枚举、字段、API、数据库、Runtime、模型供应商、技术栈或文件存储方案。

“授权使用者”“授权业务人员”“专业复核人员”是职责类别，不是已确认角色。具体人员、权限和职责分离由 `P0-04/P0-09` 确认。

## 2. 咨询助手 MVP 候选范围

| 项目 | 当前可由原需求支持的范围 |
|---|---|
| 目标 | 对获授权用户的知识产权问题进行必要补问和授权检索，返回能够定位来源的辅助回答；不形成正式专业意见 |
| 用户 | 提出知识产权问题并获授权访问相关资料的使用者；需要正式采用时由待确认的专业人员复核 |
| 输入 | 用户原始问题、后续补充或确认、受控附件引用，以及获授权的商标、专利、案例、法规等查询结果 |
| 流程 | 用户问题 → 问题理解/必要补问 → 授权检索 → 结果与来源核验 → 辅助分析 → 带来源辅助回答 → 满足待确认条件时进入人工复核 |
| AI 职责 | 识别问题意图、提取已有信息、提出必要补问、比较获授权检索结果、生成带缺口说明的回答草稿；不得补造来源或把相关度写成法律结论 |
| 系统职责 | 校验当前访问授权；调用已授权知识服务；区分无结果、资料不足、无权限和来源故障；保留问题、检索结果及回答所用来源版本；展示可核验引用 |
| 人工职责 | 用户补充并确认关键输入；需要正式采用的判断由获授权专业人员复核。具体触发条件、复核责任和转人工方式待确认 |
| 输出 | 检索候选、未完成或冲突项、带来源定位的辅助回答，以及适用时的待复核提示或复核结果引用 |
| 业务终点 | 普通场景止于向用户返回明确标识为辅助信息的回答；需要正式采用的场景止于提交或完成经确认的专业复核，不自动形成正式意见 |
| 中心权威数据 | 商标、专利、案例、法规等源记录及其可用版本；具体权威系统、覆盖范围和引用方式待确认 |
| 本地工作副本/引用 | 会话、用户补充、检索请求、候选结果引用、回答版本和复核衔接记录；不得覆盖中心源记录 |
| 必须人工确认 | 关键缺失信息或分析对象；正式采用的专业判断。哪些问题必须复核由 `P0-09` 确认 |
| 明确不做 | 不默认覆盖全部咨询意图、图形商标检索、完整相似性法律判断、正式法律意见、真实人工转接、外部通知或公众聊天门户 |

范围依据主要来自咨询总目录第 2、3.1、3.2、3.5、6 节及咨询对话流第 1、3、5、8 节。首批是否采用“专利问题及检索”作为场景仍属 `P0-08`，不能由本文件决定。

## 3. 执法助手 MVP 候选范围

| 项目 | 当前可由原需求支持的范围 |
|---|---|
| 目标 | 从一条已存在且获授权的线索出发，形成可追溯的线索解析、证据链和辅助侵权分析版本，交由人工审核 |
| 用户 | 处理获授权线索、证据和辅助分析的执法业务人员；具体核实人、审核人及职责分离待确认 |
| 输入 | 已有线索及版本、关联案件或权利信息、获授权证据、证据链规则、分析规则和法律依据；规则必须已经业务确认 |
| 流程 | 已有线索 → 线索解析 → 人工核实关键解析结果 → 证据整理/证据链 → 辅助分析 → 人工审核 |
| AI 职责 | 从线索中抽取疑似主体、事实和关联信息；辅助识别证据关系、缺口和冲突；生成逐要件候选分析。不得认定违法、采信证据或计算未经确认的严重程度 |
| 系统职责 | 校验线索、案件、证据和规则版本及访问授权；保留原始输入、机器结果和人工修订关系；执行已确认的确定性规则；区分缺失、冲突、无权限和来源故障 |
| 人工职责 | 核实线索解析结果；修订证据关系；判断证据是否采用；审核、退回或确认辅助分析版本。正式决定由谁作出及如何进入后续流程待确认 |
| 输出 | 线索解析版本、证据与待证明事实的关系、时间线、缺口/冲突清单、逐要件辅助分析和人工审核记录 |
| 业务终点 | 止于“经人工审核确认或退回的辅助分析版本”；不等于立案、违法认定、处罚决定或其他正式处理结果 |
| 中心权威数据 | 原始线索、案件、权利、证据、法规及正式业务状态；具体权威系统和回写责任待确认 |
| 本地工作副本/引用 | 线索解析和修订版本、证据关系、证据链、辅助分析及审核记录；不得覆盖中心源记录或伪造正式状态 |
| 必须人工确认 | 关键解析字段、证据关系及采信、辅助分析结果；正式立案、认定和处罚始终不由 AI 完成 |
| 明确不做 | 不包含全量自动线索发现、完整执法流程合规校验、自动违法认定、自动处罚、正式文书签发、送达或执行 |

范围依据主要来自执法总览第 2、4、5、7、8 节以及 `ENF-04/05/07/11`。从“已有线索”开始是当前最小候选，不代表业务方已经排除首批自动发现；最终入口和人工审核后的业务衔接仍由 `P0-08/P0-09` 确认。

## 4. 裁决助手 MVP 候选范围

| 项目 | 当前可由原需求支持的范围 |
|---|---|
| 目标 | 对一件获授权案件及明确材料版本进行模板所需的知识和证据辅助分析，形成可追溯的报告草稿并交由人工复核 |
| 用户 | 处理案件材料、分析结果和报告的授权裁决业务人员及专业复核人员；具体承办、复核和签发责任待确认 |
| 输入 | 中心案件及材料版本、已确认事实或待核实事项、法规、专利知识、证据、人工确认的引用和中心认可的首批报告模板 |
| 流程 | 案件 → 材料/事实版本整理 → 模板所需的法规、专利等知识分析 → 来源与完整性检查 → 报告草稿 → 人工修订/复核 |
| AI 职责 | 辅助提取法律问题、召回和解释候选法规、整理专利或证据分析、生成解释性段落草稿；不得补造案件事实、调查过程、裁决结果、文号或签章 |
| 系统职责 | 校验案件、材料、知识、证据、模板及分析版本和访问授权；列出缺项、冲突和待复核项；按指定模板组装草稿；保留来源、修订和复核所针对的确切版本 |
| 人工职责 | 确认案件事实与争议焦点；调整和确认法律引用及所需分析；修改草稿；复核确切报告版本。正式签发、送达、办结和归档责任待确认 |
| 输出 | 模板所需的分析结果和来源定位、不完整或完整报告草稿、人工修订版本及复核记录 |
| 业务终点 | 止于“针对确切版本完成人工复核的报告材料”；复核通过仅表示可进入正式办理流程，不等同正式裁决、签发、送达、办结或归档 |
| 中心权威数据 | 案件、材料、法规、专利、证据、报告模板及正式业务状态；具体权威系统和回执责任待确认 |
| 本地工作副本/引用 | 案件工作记录、材料使用版本、候选分析、引用、报告草稿、修订和复核记录；不得冒充中心正式案件或正式裁决文件 |
| 必须人工确认 | 案件关键事实、争议焦点、法律依据采用、模板所需分析、报告修订及最终复核；AI 不得代替签发 |
| 明确不做 | 不预设 `ADJ-07/08/09` 全部进入首批 MVP；不包含正式裁决生成、电子签章、送达、办结、归档或中心正式状态自动更新 |

范围依据主要来自裁决总览第 2、4、5、8、9 节及 `ADJ-04/05/06/10/11/12`。原需求说明报告可依赖专利解析、有效性和证据分析，但模板未要求的分析可标记不适用；因此 `ADJ-07/08/09` 的实际纳入范围只能由真实模板和样例决定。

## 5. MVP 验收场景矩阵

下表固定必须覆盖的场景类型和最低预期，不代替真实样例。实际输入、专业预期、允许差异和验收人目前均未提供。

| MVP | 场景 | 最低预期 | 当前证据状态 |
|---|---|---|---|
| 咨询 | 正常 | 完成必要补问和授权检索；回答中的关键事实或依据可定位来源；清楚标识辅助性质 | 待 `P0-08` 提供真实问题、预期回答与验收人 |
| 咨询 | 资料不足或冲突 | 明确指出缺失、冲突或待核实内容；可返回有依据的部分回答，但不补造结论 | 待 `P0-08` 提供真实边界样例和允许差异 |
| 咨询 | 无权限或来源失效 | 拒绝访问或明确报告来源失效/故障；不得把源故障解释为“没有相关权利、案例或法规” | 待 `P0-03/P0-08` 提供授权与样例 |
| 执法 | 正常 | 保留线索来源；解析字段可定位原文；证据链和逐要件分析可回溯；人工审核对象版本明确 | 待 `P0-08/P0-09` 提供真实线索、专业预期和审核人 |
| 执法 | 资料不足或冲突 | 输出具体证据缺口、冲突和无法判断事项；不得生成确定违法认定或处罚结论 | 待 `P0-08/P0-09` 提供专业边界样例和允许差异 |
| 执法 | 无权限或来源失效 | 拒绝未授权线索、案件或证据；区分不可访问、源故障和真实空数据；不形成伪完整分析 | 待 `P0-03/P0-08` 提供授权与样例 |
| 裁决 | 正常 | 使用指定案件、材料和模板版本；关键事实、法条和分析能够回到来源；草稿经人工复核 | 待 `P0-08/P0-09` 提供真实案件、模板、预期和复核人 |
| 裁决 | 资料不足或冲突 | 列出缺项、冲突和待复核项；允许保存不完整草稿但不得提交正式复核或补造事实 | 待 `P0-08/P0-09` 提供模板必填规则和边界样例 |
| 裁决 | 无权限或来源失效 | 阻止使用无权限或失效材料；标记受影响分析/报告；不得沿用旧来源形成看似完整报告 | 待 `P0-02/P0-03/P0-08` 提供来源、授权与样例 |

## 8. ARC-04 结论

| MVP | 候选范围结论 | 正式冻结结论 | 尚缺内容 |
|---|---|---|---|
| 咨询 | **通过**：闭环和辅助回答边界基本明确 | **未完成** | `P0-08` 真实样例、预期、允许差异、验收人；`P0-09` 正式复核触发条件 |
| 执法 | **通过**：闭环和“止于辅助分析版本”的边界基本明确 | **未完成** | `P0-08` 真实线索样例及验收依据；`P0-09` 人工审核后的业务衔接 |
| 裁决 | **通过**：闭环和报告草稿/复核边界基本明确 | **未完成** | `P0-08` 真实案件、模板及验收依据；`P0-09` 模板实际需要的 `ADJ-07/08/09` 范围和复核后责任 |

ARC-04 应继续处于“候选范围确认 / 业务样例收集”阶段。`P0-03/P0-04` 不再作为业务闭环冻结条件；三个 MVP 仍因 `P0-08/P0-09` 未满足而不能宣称正式冻结。正式冻结前不得进入依赖真实样例、专业规则或正式流程的设计与实现；已有 V0 样例和明确排除条款的合成/可逆领域、接口和本地技术工作按对应窄范围 D 门推进。
