# 咨询 MVP Use Case / Service 设计

版本：V0.1  
日期：2026-09-15  
关联任务：ARC-05-CON-UC  
前置：[咨询 MVP 最小领域模型](12-咨询MVP最小领域模型.md)、[领域行为与不变量](13-咨询MVP领域行为与不变量.md)、[V0 产品样例](11-咨询MVP-V0产品样例基线.md)。

本文件只定义第一条咨询闭环的应用用例和服务边界，不定义 HTTP、消息协议、数据库、任务平台或模型实现。

## 1. 用例清单

| 用例 | 输入 | 输出 | 领域对象变化 | 主要责任 |
|---|---|---|---|---|
| UC-01 提交咨询问题 | 请求者引用、原始问题、受控附件引用 | 需要补充、超出 V0 范围或可继续处理的会话结果 | 新建咨询会话或追加 `userInputs`、`informationIssues` | 应用服务接收；AI 只给出意图/特征候选；用户确认事实 |
| UC-02 补充或更正检索条件 | 会话引用、请求者引用、补充内容 | 更新后的缺失/冲突清单，或可形成的检索请求 | 追加输入；解决或新增问题；创建新的检索请求快照 | 应用服务验证归属；AI 不确认用户未确认值 |
| UC-03 执行获授权专利检索 | 会话引用、检索请求引用、请求者引用 | 无权限、真实无结果、部分结果、来源/工具失败或候选结果 | 写入授权结果、实际范围、执行结果和检索候选 | 授权系统判定；专利检索端口返回事实；应用服务分类 |
| UC-04 形成或读取辅助回答 | 会话引用、检索请求/候选引用、请求者引用 | 带来源回答、来源失效降级、无权限说明或复核提示 | 生成新的辅助回答版本；仅关联可使用候选 | 回答生成能力组织受检验事实；来源端口复查；人工只在正式采用时复核 |

四项用例不包含“自动相似度判断”“生成正式意见”“转人工受理”“配置发布”“会话并发/取消/重试”等原始需求范围。

## 2. 应用服务及端口

```text
ConsultationApplicationService
  ├── ConsultationRepository              （保存/读取五个领域对象）
  ├── InputUnderstandingPort              （候选意图、特征、缺失/冲突提示）
  ├── AuthorizationPort                   （当前访问判定）
  ├── PatentSearchPort                    （获授权的候选与实际范围）
  ├── PatentSourcePort                    （来源定位解析与可用性复查）
  └── AuxiliaryAnswerComposer             （基于已验证事实生成辅助回答）
```

端口只是依赖方向，不承诺实现技术：

| 端口 | 最小请求 | 最小返回 | 禁止承担 |
|---|---|---|---|
| `InputUnderstandingPort` | 用户输入和允许的会话上下文 | 意图/特征候选、缺失/冲突建议及来源位置 | 确认用户事实、授予工具或数据权限 |
| `AuthorizationPort` | 请求者引用、拟访问资源范围 | 允许、拒绝或不可判定及权威判定引用 | 让模型或会话自行修改权限 |
| `PatentSearchPort` | 已确认的检索输入、范围和授权后的访问上下文 | 候选、文献版本、匹配依据、实际范围、结果类别 | 自建未获授权索引、推断法律结论 |
| `PatentSourcePort` | 来源定位和当前访问上下文 | 当前可用性、可展示定位或来源不可用类别 | 返回失权/撤回缓存正文 |
| `AuxiliaryAnswerComposer` | 已验证候选、来源定位、限制和回答边界 | 辅助回答草稿与关键内容-来源对应 | 编造来源、提升为法律结论、作出正式决定 |
| `ConsultationRepository` | 领域对象及其关系 | 同一会话下的持久化/读取语义 | 决定权限、修改中心专利源记录 |

`ConsultationApplicationService` 负责顺序、对象一致性和异常分类；它不拥有授权策略、专利权威数据、模型推理或人工决定。

## 3. 用例流程与结果边界

### UC-01 / UC-02：接收问题、补充与澄清

1. 校验请求者与会话归属；首次输入建立会话，后续输入追加为不可覆盖的用户输入。
2. 请求理解端口返回候选意图和特征；应用服务只把有来源的候选写入会话。
3. 若不属于 V0 技术参考范围、缺少必要信息或存在冲突，生成“需要补充/范围说明”的辅助回答；不得调用授权、检索或来源读取。
4. 用户补充或更正后重新判定；已经产生的检索请求不被改写，新的确认条件形成新的请求。

结果类别：`需要补充`、`范围外`、`可检索`。这是用例结果分类，不是完整会话状态机。

### UC-03：执行获授权检索

1. 仅当会话没有未解决必要问题时，创建或读取对应检索请求。
2. 先调用 `AuthorizationPort`。拒绝或不可判定时记录授权结果，直接返回 `无权限`，不调用检索或读取正文。
3. 允许后调用 `PatentSearchPort`，保存实际范围、候选和可区分执行结果。
4. 对结果进行必要去重、稳定排序和来源绑定；有限范围、截断、部分成功、工具失败和真实无结果分别保留。

结果类别：`无权限`、`无结果`、`部分结果`、`来源不可用`、`工具失败`、`候选可用`。这些类别直接对应三个 V0 样例，不把失败伪装为空结果。

### UC-04：形成或读取辅助回答

1. 对每个拟采用候选经 `PatentSourcePort` 复查当前可用性和当前授权。
2. 失效或失权候选从回答依据排除；若没有剩余可用候选，产生来源失效或无权限说明，而非带事实的回答。
3. 仅将可使用候选、其匹配依据、来源定位、实际范围和限制交给回答生成能力。
4. 保存新的回答版本及关键内容的来源对应；若用户拟正式采用，只加专业复核提示，不创建复核、受理或正式决定。

结果类别：`带来源回答`、`降级回答`、`无权限说明`、`需要补充`、`需要专业复核提示`。

## 4. 三样例覆盖和责任边界

| 样例 | 用例路径 | AI 可做 | 权威系统/人工必须做 |
|---|---|---|---|
| 正常 | UC-01 → UC-03 → UC-04 | 提取特征、候选排序说明、回答草稿 | 授权系统允许访问；专利端口提供真实候选事实；正式采用由专业人员复核 |
| 资料不足/冲突 | UC-01 → UC-02 | 发现缺失/冲突并生成补问草稿 | 用户确认技术条件；专业人员确认未来专业必填规则 |
| 无权限 | UC-01 → UC-03 | 解释拒绝类别，不读取受限正文 | 授权系统作出允许/拒绝判定 |
| 来源失效 | UC-03 → UC-04 | 基于剩余有效事实生成降级说明 | 来源端口返回当前可用性；授权责任方处理恢复权限 |

## 5. 当前设计不解决的事项

- HTTP URL、认证报文、幂等键、事件流、分页、同步/异步协议和错误码。
- 数据库表、字段类型、事务、索引、缓存、DM8 适配和文件存储。
- 完整 Task、重试、取消、并发、断线恢复和会话生命周期。
- 真实授权策略、外部中心 API、真实数据保留与外部模型数据出域。
- 模型/提示词供应商和参数，以及自动相似度评分算法。
- 专业复核受理、人员身份、正式意见、法律结论和业务状态回写。
