# 三类知识产权智能助手待确认事项清单

版本：V0.14
日期：2026-09-25

## 1. 定位与使用规则

本文件是业务决定和待确认事项的唯一人工维护入口。`requirements/` 是最高业务事实来源；V0 临时产品决策只用于在缺少专职业务人员时形成保守、可回滚的开发基线，不能覆盖原需求，也不能冒充法律、专业、安全或中心系统确认。

每项信息分为四类：

| 类型 | 含义 |
|---|---|
| 原需求已明确 | 可以直接追溯到原始需求，后续设计必须遵守 |
| V0 临时产品决策 | 项目负责人当前采用的保守默认，可据此开展不越界的设计和开发 |
| 待专业人员确认 | 项目负责人无权代替专业责任方决定，相关结论只能在后续证据到位后升级 |
| 技术后置 | 不影响当前业务边界，可在对应设计、Spike、联调或部署阶段确定 |

V0 决策变更时必须保留旧结论并做影响分析。没有来源、责任方、日期、适用范围和明确结论的外部意见，不得标记为专业确认。

## 2. P0-01 中心 API 与外部系统接入

**原需求已明确**

- 中心主要通过 API 提供商标、专利、案例、法规、案件、线索和证据等数据。
- 本项目负责接口适配、异常处理、来源展示和服务运行；中心凭据不得进入浏览器。
- 中心源调用失败、无结果、无权限和资料不足必须区分，不能用模拟结果冒充真实结果。

**V0 临时产品决策**

- 所有中心数据接口默认按只读使用；没有明确写接口、授权动作和真实回执时，禁止回写中心源数据或推进中心正式状态。
- 本地只保存本项目工作结果和来源引用；开发阶段可使用明确标记的模拟适配器、公开数据或脱敏固定样例。
- 外部调用统一保留可替换边界，中心 API 缺失不阻塞领域逻辑和异常路径设计，但真实联调保持未验证。
- 项目负责人于 2026-09-18 决定：执法智能体开发期采用与咨询智能体一致的本地数据库主路径；经授权导入本地 DM8 的线索、证据及其来源快照是默认运行输入，中心数据通过独立只读适配器作为可选补充来源。该决定不把本地记录冒充中心权威记录，也不代表中心接口、真实数据授权或正式联调已经完成。
- 项目负责人于 2026-09-19 决定：咨询、执法和裁决三域后续均以本地 DM8 为常规数据主路径，不再规划真实中心 API、同步、合并、故障回退或中心优先规则。既有中心或模拟中心适配器只保留为开发测试和历史兼容材料，不得装配为常规运行数据来源。本决定不授权导入任何真实数据，也不改变来源、版本、撤回、权限、专业规则、人工决定或业务验收的证据要求。

**待专业人员确认**

- 待后续中心接口责任方确认 API 目录、读写范围、负责人、环境、认证、限流、错误语义、回执和服务等级。

**技术后置**

- 具体 URL、协议字段、客户端实现、重试、熔断、超时、对账和监控方案在接口详细设计与 Spike 中确定。

## 3. P0-02 权威标识、版本与增量语义

**原需求已明确**

- 源记录必须保留来源、稳定标识和版本；没有源版本时保存本次授权快照及内容摘要值。
- 名称、标题、条号和显示编号不能替代跨系统唯一标识；历史引用和人工结果不得被新数据静默覆盖。

**V0 临时产品决策**

- V0 统一按“来源系统 + 来源对象标识 + 来源版本；无版本时使用获取时间和内容摘要”记录来源身份。
- 本地工作对象使用独立本地标识并引用中心对象，不冒充中心编号；任何重新获取、重跑或人工修订均形成新版本关系。
- 在中心增量语义未知时不做自动增量合并，只允许全量读取单个对象或使用固定快照进行开发验证。

**待专业人员确认**

- 待后续中心数据责任方确认各类对象的稳定 ID、版本、删除/撤回、增量游标、历史查询和变更通知语义。

**技术后置**

- 标识字段映射、摘要算法、同步游标、冲突处理、缓存刷新和索引重建机制在数据与接口设计阶段确定。

## 4. P0-03 数据查询、存储、索引、模型使用与保留授权

**原需求已明确**

- 只能处理获授权数据；缓存、落库、索引、模型处理、出域和保留范围必须遵守中心授权。
- 权限撤回或源内容撤回后，不得继续通过缓存、报告、引用、附件或索引向失权用户泄露内容。
- DM8 的采用不自动授予复制中心源数据的权限。

**V0 临时产品决策**

- 采用默认拒绝原则：未经明确授权的真实业务数据不得落库、建立索引、发送给模型或带出受控环境。
- 当前设计只写“使用经过授权的数据”，不虚构数据范围。开发和自动测试优先使用公开、合成或已脱敏且获准的固定数据。
- 开发阶段允许使用拟真编造数据完成接口、异常、排序和回归测试；每条拟真数据及其预期标签必须显式标识为开发测试数据、可替换且非专业结论，禁止混入真实中心数据、专家标注、正式效果指标或业务验收。上线前的数据清洗、授权核验和真实数据接入另行实施。
- 中心源数据保持只读引用；本地只拥有会话、解析、候选分析、草稿、版本和审计等工作结果。真实数据授权缺失只阻塞相应数据通路，不阻塞纯领域逻辑、端口和异常处理开发。
- 项目负责人决定：真实中心检索来源能力边界及数据处理/访问授权证据不再阻塞 CON-04 的 V0 详细设计和仅处理 `PUBLIC_LOCAL` 开发数据的实现；它们仍是激活真实中心连接、处理真实中心数据、向外部模型发送该类数据及正式验收的必要证据。
- 项目负责人于 2026-09-18 决定：执法智能体的 V0 详细设计和实现不再以中心数据到位为前提，可处理公开、合成或已脱敏且获准导入本地 DM8 的执法试点数据；中心数据仅作为可选补充来源。数据授权仍按记录和来源分别校验，未经授权的真实执法数据不得导入、索引、发送给模型或用于正式验收。
- 项目负责人于 2026-09-19 决定：本地 DM8 主路径适用于三个业务域。真实本地数据仍须由数据所有者和安全责任方逐类确认来源、允许用途、保存/索引、模型使用、保留和撤回处理；没有该证据时只能使用公开、合成或已脱敏且获准的开发数据。
- 项目负责人于 2026-09-19 决定：三域均可参照咨询域，通过可追溯的公开网页/API 或已获明确授权的本地来源采集来补充开发期所需数据，并以本地 DM8 保存不可变来源快照。每次采集必须记录来源站点、稳定源 ID、源版本或获取时间、原始响应摘要、定位、采集时间、数据模式、用途限制、撤回处理和原始响应校验；公开可访问不等于生产索引、再分发、外部模型处理或正式证据授权。不得绕过访问控制、验证码、付费墙、robots/站点限制或采集非公开案件、当事人材料、证据、个人信息和未授权模板。咨询可继续使用已登记的公开专利/案例采集；执法仅可设计公开线索、公开权利状态和公开法规等开发数据采集；裁决仅可设计公开法规、公开裁判文书和已明确授权模板的开发数据采集。真实案件、证据、材料、采信、法律适用、正式裁决和业务验收仍须独立证据。
- 当前工作区用户以项目负责人兼数据/法律责任方身份于 2026-09-20 明确授权建设执法智能体的正式本地线索、证据和专业规则接入能力，并决定身份鉴权复用咨询对外 API Key 的可信主体、scope、限流和审计方式；本地 DM8 继续作为唯一常规数据主路径，不建设真实中心通路。该授权允许建立正式数据交付合同、校验器、隔离导入和受控读取，不等于任何未交付数据已经存在，也不免除每个数据包登记来源、数据集 ID、版本、记录范围、用途、保留期限、撤回方式、内容摘要和责任方。未携带上述信息的数据默认拒绝；专业规则还必须具有稳定规则 ID、版本、发布状态、批准责任方、适用范围和生效信息，未发布规则不得执行。外部模型处理真实数据仍保持关闭，证据采信、侵权认定、处罚和官方状态仍由授权人员或权威系统负责。
- 当前工作区用户以项目负责人兼数据/法律责任方身份于 2026-09-20 明确批准 `ADJ-SOURCE-REVIEW-SPC-IP-COURT-V1` 当前 100 条最高人民法院知识产权法庭文书定位记录，仅用于内部开发、本地 DM8 保存和索引，保存至开发试点结束；须保留来源名称、原始链接和“中华人民共和国最高人民法院 版权所有”标识。来源撤回或授权撤销后立即标记不可用、移除本地索引并停止查询/使用，仅保留不含文书内容的审计摘要至试点结束。禁止外部模型、生产、再分发、正式案件/材料、法律适用、正式草稿及裁决工作流输入。版本化决定与完整结论见 `data/adjudication/source-review/spc-ip-court-v1/approval.json`；该批准不覆盖公开法规或授权模板。
- 当前工作区用户以项目负责人身份于 2026-09-20 再次明确：真实案件包只阻塞执法专业效果和正式验收，不阻塞不依赖真实事实的功能建设；当前优先继续实现执法业务功能。首项为 `ENF-01` 本地数据源管理，复用既有 API Key 可信身份和机构范围，以本地 DM8 保存配置、同步任务、失败明细、源记录快照和审计。首期仅允许明确登记的本地/开发适配器和隔离测试数据，不接入真实中心，不自行抓取电商或社交平台，不调用外部模型，不把同步记录自动升级为违法线索。该决定允许完成开发期 D/V 门技术证据，但不替代真实联调、专业样例或业务验收。

**待专业人员确认**

- 待后续中心数据所有者和安全责任方逐类确认查询、缓存、落库、索引、模型使用、出域、共享、保留、删除及权限撤回后的处理要求。

**技术后置**

- 数据分级、加密、脱敏、清理任务、缓存生命周期、索引隔离和权限撤回传播方案在安全与数据设计阶段确定。

## 5. P0-04 身份、职责角色、组织范围与 DataScope

**原需求已明确**

- 身份必须来自可信认证上下文；模型、服务账号和调用方传入的人员名称不能冒充真实人员。
- 权限由服务端执行；案件、线索、证据、报告、文件和历史结果必须按当前授权范围访问。
- AI、Agent 和模型适配器不得写入权限、人工审核决定或正式状态。

**V0 临时产品决策**

- V0 只使用职责类别：`授权用户`、`业务审核人员`、`专业复核人员`、`系统集成身份`；它们不是具体系统角色或权限枚举。
- 采用默认拒绝、最小授权和职责分离原则。开发环境测试身份必须明确标记，不能作为生产身份或专业确认人。
- P0-04 不阻塞 MVP 业务职责和领域对象设计，但阻塞具体角色映射、组织范围、DataScope、生产鉴权和真实权限验收。

**待专业人员确认**

- 待后续中心身份责任方和业务负责人确认 SSO/身份来源、机构关系、角色映射、资源范围、服务身份、职责分离和授权变更规则。

**技术后置**

- 鉴权协议、策略模型、缓存、策略执行点、前后端会话和审计字段在权限详细设计阶段确定。

## 6. P0-05 DM8 环境与数据库适配

**原需求已明确**

- 业务关系型数据库确定使用达梦 DM8，不再重新选型。
- 真实数据库验收必须覆盖连接、事务、分页、中文和长文本、时间与精度、初始化/升级、故障恢复和备份恢复。
- 其他数据库或内存库测试不能代替真实 DM8 验收。

**V0 临时产品决策**

- 领域设计保持存储无关，领域模块只依赖持久化端口；不得为其他数据库特性反向修改业务模型。
- 项目负责人于 2026-09-15 决定 V0 开发使用 JDK 21；Maven 构建目标固定为 Java 21，中心最终 JDK 兼容性仍待运维确认。
- 项目负责人于 2026-09-15 决定使用本机 Docker 的独立 DM8 实例进行 V0 开发验证：容器 `agent-platform-dm8`，仅绑定 `127.0.0.1:5237`，独立命名卷 `agent-platform-dm8-data`；本地应用账户为 `admin`。密码不记录在本文件或代码库。
- 本地实例已完成账户登录及最小建表、写入、查询、清理验证；它可用于 SPK-01 的开发验证，但不能替代中心 DM8 环境、备份恢复或交付验收。
- 不引入第二种生产关系型数据库作为既定依赖。

**待专业人员确认**

- 待后续运维和数据库责任方确认 DM8 小版本、兼容模式、字符集、大小写、拓扑、账号权限、JDK/驱动、测试库及备份恢复责任。

**技术后置**

- ORM/SQL 方案、迁移工具、主键策略、数据类型、索引、连接池和部署参数由 DM8 Spike 后确定。

## 7. P0-06 国产化环境与部署约束

**原需求已明确**

- 项目必须适配中心国产化环境；数据库使用 DM8。
- 全文、向量、图像、OCR、文档转换、模型和中间件能力不能因架构设想视为已经具备。

**V0 临时产品决策**

- 代码和领域设计保持供应商中立，不把特定国外 SaaS、中间件、数据库扩展或操作系统能力设为不可替换前提。
- 当前可做平台无关的领域设计、契约和单元验证；未在目标国产环境运行的结果只能标记为开发验证。
- 不提前承诺部署拓扑、性能或国产化验收通过。

**待专业人员确认**

- 待后续运维、安全和采购责任方确认 OS、CPU、JDK、中间件、网络区划、密码规范、推理硬件、部署方式和可用产品清单。

**技术后置**

- 容器/进程方式、配置管理、监控、容量、主备、灾备和发布回滚方案在部署设计及目标环境 Spike 中确定。

## 8. P0-07 文件、原文、证据与报告载体

**原需求已明确**

- 中心原文和证据来源保持权威；本项目可在授权范围内读取、上传或保存受控引用和工作副本。
- 文件访问必须执行当前权限；不可读、损坏、缺失、无权限和来源故障必须分别表达。
- 文件转换失败不能丢失已保存业务内容，不能生成虚构签章、文号或正式文件状态。

**V0 临时产品决策**

- 中心来源的原文、证据、知识和正式文件一律按只读权威资源处理；本项目不得覆盖、替换或物理删除中心源文件。
- 本地上传、解析文本、预览件和报告文件只作为非权威工作副本，必须关联来源和版本；没有中心确认时不得称为正式证据或正式文书。
- 未取得真实文件授权前，只使用公开、合成或获准脱敏文件开发；不调用外部文档转换 SaaS，不生成永久公开下载链接。

**待专业人员确认**

- 待后续中心文件/证据所有者和安全责任方确认允许格式、大小、病毒检测、预览下载、存储位置、保留删除、证据原件责任和恢复要求。

**技术后置**

- 文件存储产品、对象键、分片上传、扫描工具、DOCX/PDF 转换、字体、受控 URL 和备份一致性方案在文件 Spike 后确定。

## 9. P0-08 MVP 样例、预期、允许差异与验收人

**原需求已明确**

- 专业效果验收必须使用来源明确、版本固定的样例，并记录输入、预期、实际、未处理项和分母。
- 技术模拟、模型自评分和只选成功样本不能替代真实业务验收。
- 三个 MVP 都必须覆盖正常、资料不足/冲突、无权限/来源失效场景。

**V0 临时产品决策**

- 在没有专职业务人员期间，使用从原需求 MUST/MUST_NOT 和验收场景构造的 `V0 产品样例` 支撑设计与自动测试；样例必须标记为合成、公开或脱敏来源，不能标记为真实专业样例。
- 项目负责人只验收范围、流程、来源可追溯、异常处理、人工门禁和禁止行为，不验收法律结论、专业准确率或处罚/裁决正确性。
- 生成性文字允许措辞不同，但来源事实、引用、缺口、辅助性质和禁止结论必须一致；专业阈值和允许误差不在 V0 中虚构。
- V0 样例允许对应 MVP 进入领域设计和非专业实现；真实业务验收仍保持待专业人员确认。

**待专业人员确认**

## 10. P0-09 AI、规则、人工复核与正式业务责任

**原需求已明确**

- AI 可以理解、抽取、分类、总结、检索候选、辅助分析和生成草稿；不得决定权限、证据采信、正式法律结论、处罚、裁决、签发、送达、办结或归档。
- 确定性条件只能由已确认并发布的规则或领域代码执行；模型不得创造法律规则、阈值、期限、金额或正式状态转换。
- 授权人员或权威系统负责人工确认和正式决定；AI 原始结果与人工修订必须分别保留。

**V0 临时产品决策**

- 咨询 MVP 止于带来源的辅助回答。普通辅助回答可直接展示；任何拟作为正式专业意见、执法依据或裁决依据的内容必须进入专业复核，在无人复核时保持“仅供辅助/待复核”。
- 执法 MVP 止于线索解析、证据链和辅助分析提交人工审核；所有证据采信和侵权分析必须人工审核。V0 可以验证审核动作和版本留痕，但不得把测试身份的操作称为专业认定，更不得进入处罚或正式执法。
- 裁决 MVP 止于报告草稿提交人工复核；法律依据采用、专利有效性/侵权证据意见和报告均需专业复核。V0 可以验证复核流程，但复核结果不等同正式裁决、签发、送达、办结或归档。
- 没有已确认专业规则时只实现“规则缺失/不适用/待确认”的安全路径，不编写虚构规则。所有正式中心状态保持外部只读引用。

**待专业人员确认**

- 待后续业务和法律责任方确认适用规则、人工控制点、证据采信标准、咨询复核触发范围、执法审核后正式衔接、裁决模板所需 `ADJ-07/08/09` 分析、正式状态及签发/送达/归档责任。

**技术后置**

- 规则表达方式、审核工作流配置、状态名称、任务分配、电子签章和中心状态回执适配在对应专业结论到位后设计。
