# 知识产权智能工作平台 V2：重构摘要

版本：V2 产品评审提案，2026-09-24。**不是**原需求变更、详细设计 D 门、法律意见或验收结论。事实来源为 [原始方案](../../知识产权智能体方案.docx) 与 [47 份需求](../../requirements/)；现有代码/API/数据库/UI/Prompt 不作为设计输入。历史实现仅用于辨识落地风险，不能证明本稿的产品价值。41 项正式状态仍以 [总计划](../08-总开发实现计划.md) 为准。

2026-09-25 的项目产品组织与实施原则见[已确认决定](../02-待确认事项清单.md#33-2026-09-25-v2-产品组织与旧实现取舍原则)：任务型三域闭环、逐MVP评估旧代码和每域及时真实验证已作为执行方向；本稿其余逐项取舍并未因此成为41项合同范围变更、完整D门或正式验收。

## 十个结论

1. **原产品为何容易效果不好**：原始方案按“库管理、检索/相似度、意图/提示词/对话、规则/文书”列功能，却没有统一描述用户完成一件工作的终点。接口成功、相似度分数、引用数量、流畅回答和正式业务成果之间有多次不被保证的跃迁。细化需求已补任务、版本、证据和异常，但分散在 41 项模块中，容易形成孤立功能；真实数据授权、专家样例和验收阈值尚缺，技术验证不能证明专业收益。此为产品诊断，不是对现有代码的断言。
2. **需要推翻什么**：把 Intent 当核心路由器、把 Prompt 管理当业务能力、把 Chat 当主工作面、把单次 RAG/相似度当分析、把“全流程辅助”解读为自动正式决定、把 41 功能等同 41 产品模块、把模型分数叫法律概率，都不作为 V2 前提。保留它们背后的目标：目标理解、引导、多轮、可发现资料、逐项比较、规则解释及人工控制。逐项取舍见 [追踪](15-requirement-traceability-v2.md)。
3. **新产品是什么**：面向知识产权咨询、执法和行政裁决的**任务型、证据约束的智能工作平台**。一个任务有明确目标、范围、完成定义、工作成果、限制和负责人；Agent 协调合法的工作步骤，领域服务掌握业务语义，权威系统及授权人员掌握正式决定。这是从原始方案三条“全流程辅助”与细化需求的检索、证据、报告、复核链路推导的产品提案，不声称原文已批准“平台”名称或新交付 UI。
4. **用户的核心流程**：提出目标或接收线索/案件 → 看到任务范围和关键缺口 → 系统在许可内检索、提取、对照及校验 → 检查证据与反证 → 修正事实、补材料或改变范围 → 形成可编辑、可核查产物 → 必要时人工复核/接管 → 明确完成、部分完成、证据不足或失败，并保留继续入口。聊天是该流程的一种输入和协作通道。
5. **Agent 负责什么**：围绕已授权 Goal 执行 Observe → Plan → Act → Observe → Evaluate → Re-plan；选择发布的 Skill、读中间结果、补问、有限检索、降级、停止、请求人工。它不授予权限、不采信证据、不创制法律规则、不写正式状态。
6. **Task Runtime 负责什么**：接收任务/子任务、持久化检查点、并发与幂等、预算与停止、重试/取消、版本依赖、失效传播和可恢复结果发布。Runtime 不决定证据是否法律充分，也不取代案件系统。首条闭环只做必需的运行语义，不预建通用引擎。
7. **Evidence / Rule / Human 分工**：证据保存来源、版本、位置、血缘、支持/反驳及可访问性；规则仅执行经有权发布、适用范围/时点明确的确定性条件；AI 形成候选与草稿；人确认事实、采信、复核和专业判断；权威系统形成正式回执。引用存在不等于证据充分，人工“已读”不等于通过。
8. **三域如何统一**：共享 Task、版本、来源、权限检查、运行记录、人工请求和产物基础协议；咨询按技术/商标/案例的专业对照决定“足够”；执法按待证明事项、程序与处罚权限决定；裁决按争点、条文时点和双方材料决定。共享对象不消灭领域事实、采信、程序和正式状态。
9. **第一条黄金业务闭环**：**内部专利技术参考任务**：用户给出技术方案/目标 → 最少必要补问并确认关键特征/范围 → 获准资料检索和候选比较 → 选定文献版本与权利要求逐项对照 → 每条关键陈述链接直接证据及缺口 → 用户纠正后局部失效重做 → 交付技术参考包或明确证据不足。优先理由：原需求 CON-02/04/06/12 和 2026-09-22 咨询产品行为基线提供连续链路，且不依赖处罚/裁决正式决定。**[待确认]** 真实任务、数据许可、专业基线、交付接口/UI 和阈值；这些缺失时只能用合成样例证明流程，不能声称黄金业务已验证。
10. **新旧需求变化**：保留三域目标与 41 项来源；合并重复法律资源、模板/规则发布和执行基础；重定义“相似度判断”为有证据的多维对照、“意图”为目标理解辅助、“提示词”为版本化执行配置、“对话”为任务协作；把自动侵权/有效性/处罚/裁决措辞约束为辅助意见及人工/权威控制；新增任务完成、证据支持、局部失效、人机协作、预算、恢复、安全与任务级评测契约。删除/合并是**提案**，未经责任方决定不取消原 41 项交付义务。

## 当前可做与不能做

- 可做：原文反查、目标和产物样例、合成异常/负向场景、评测方案、数据/权限/人工/规则接口清单、产品评审。
- 不可做：将 V2 作为已批准需求、越过咨询 stale R 门或三域 D 门、接入未经授权真实资料、虚构法条/期限/角色/效果阈值、以技术样例宣称业务验收。
- 决策者需要先确认 [待确认事项](14-roadmap-v2.md#待确认事项) 与 [变更清单](15-requirement-traceability-v2.md#取舍和冲突)，随后才在总计划和 `docs/02` 登记正式结论。设计细节从 [PRD](01-product-requirements-v2.md)、[蓝图和 ADR](02-product-blueprint-v2.md) 进入。
