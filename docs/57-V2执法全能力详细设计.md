# V2 执法全能力详细设计

版本D1，2026-09-24；交付任务ARC-V2-ALL-DESIGN-01。依据ENF-01～17当前契约及原文、docs/02第23节；技术协议采用[docs/55](55-V2业务数据服务与运行恢复详细设计.md)。API路径为本项目候选协议，不是中心现有协议。规则业务内容及真实岗位不能由设计补造。状态仅在docs/08。

## 1. 用户闭环和领域对象

执法人员从获准来源取得可核查线索→查看机器提取和原文→登记真实材料及收集过程→按已发布适用规则组织待证事项、支持/反证/缺口→必要的流程/行为辅助分析→形成带范围和未决项的辅助包→真实人工接收、修订与决定回流。通知成功不替代接收，辅助包完成不代表立案、违法认定或处罚完成。

三切片：ARC-ENF-MATERIAL-01覆盖ENF-01～05来源到材料；ARC-ENF-EVIDENCE-02覆盖ENF-06/07及所需已发布规则引用；ARC-ENF-HANDOFF-03覆盖版本化辅助包/人工回流。ENF-08～17的程序、行为、处罚和文书扩展在下文逐项设计，实施仍按真实验证后扩展路线，不把17项一次性上线。

域对象：`Clue(sourceObservationRef,discoveryRefs,disposition)`、`CaseWorkRef(authoritativeSource,id,version)`、`FactRevision(originKind,sourceLocator,humanConfirmation)`、`EvidenceVersion(originalFileRef,collectionRecord,caseOrClueRefs)`、`RuleRevision(type,applicability,basisRefs,publication)`、`AnalysisRevision(inputManifest,findings,gaps,review)`、`WorkPackage(manifest,request,receipt,decision)`。执法工作记录不能自己生成权威案件编号。

工作包记录稳定目标、事实/材料集合版本、人工请求和状态；跨轮指代绑定具体EvidenceSet或ReportRevision，不能套咨询ResultSet类。纠正事实或排除证据追加版本→依赖分析待复核→重算受影响事项→新辅助包；原始及人工结果均保留。同一案件的补料继续原工作链，全新案件另建且不默认继承证据授权。

## 2. 共用操作、权限及事务

逻辑前缀`/v2/enforcement`。下列每类资源均有列表、完整详情、版本历史；列表条件来自对应原文，统一页码/游标和稳定排序，默认更新时间倒序后id（原文另定者从原文），不伪造总数。编辑/状态命令均采用docs/55信封。内部工作面显示条件、来源/版本、逐项结果、缺口、状态、失败/无权限及request_id，实际业务规则在服务端。

规则管理明确六种资源：discovery-rules、evidence-rules、procedure-rules、conduct-rules、document-rules、penalty-rules，模板独立。可复用草稿/发布技术组件，不共用规则schema。草稿保存→依赖校验→固定样例试跑→授权人发布→新运行显式绑定；发布版不可改，停用不破坏历史。试跑无正式线索、通知或案件副作用。专业标准、法规有效性和样例欠缺时允许保存不完整草稿，拒发布。

授权动作分读、同步/采集、材料写、规则编辑/发布、辅助运行、人工核验/审核、文书导出；这些是技术能力名，不虚构真实岗位拥有者。每条命令校验域、机构、案件/线索、源及用途；跨机构仅在可信授权允许时操作。Agent只可提交候选或请求，核验/处置/审核须具名人员。未接可信身份时不得实际核验。

事务组：源观察+游标进度；线索+命中明细；证据元数据+受控文件关联；分析版本+逐项关系+依赖；人工决定+被审对象状态；文书+引用采用绑定；工作包+请求/outbox。外部源、模型、通知和渲染在事务外；所有异步任务保存固定输入manifest及检查点，失败单列，按docs/55租约和epoch控制，不因重启重放正式动作。

## 3. 逐能力详细设计

<a id="ENF-01"></a>
### ENF-01 来源与同步

`SourceConfigRevision`：编号/名称、受控数据类型、API受控地址、凭据Ref、字段映射、owner/机构、同步模式及带单位周期、enabled；`ConnectionHealth`独立；`SyncAttempt`：固定配置、起始/成功游标、逐记录结果、最近成功时间（可空）、任务状态。配置查询不返回密钥，模型不能选择任意地址。

`POST /sources`及版本编辑保存配置；`/{id}/connection-tests`核认证/结构/稳定键/分页/时间；`/{id}/syncs`手动或定时创建任务，源级活动槽防并发同步；启停与连接测试分开。读取页→逐条校验源id/version→幂等追加观察→同事务推进连续成功位置。乱序/部分失败不跨越缺口推进游标；上游无增量时须已确认窗口才能启动窗口重拉。

状态queued/running/succeeded/partial_failed/failed/cancelled。停用禁止新任务；在途继续或取消策略须配置且有依据，未决定时不能激活真实定时源，不能自行取消外部动作。撤回单独记录，不从404推断对象不存在。D-ENF-01：页中第3条失败不越过；重复页不重复记录；配置编辑不改变在途版本；超时不变空数据。I验证实际分页限流撤回，B核覆盖与漏项。

<a id="ENF-02"></a>
### ENF-02 发现规则

`DiscoveryRule`：稳定id、名称、疑似行为类型、说明、数据源Refs、已登记字段条件树、阈值/范围（评分型必需）、语义任务schema/模型版本、依据及试跑记录。解释器仅存在/包含/数值比较/AND/OR，不执行任意脚本SQL或URL。

`/discovery-rules/{id}/trial`固定规则/样例版本，逐条件输出命中/未命中/缺字段/失败；`/publish`校验字段依赖、类型、阈值和业务确认样例，事务绑定发布人/依据。假冒专利、专利侵权和宣传分类分别配置；未知类型拒适用，不用默认通用违法规则。D-ENF-02：非法操作符拒绝；阈值无依据拒发布；试跑命中不建线索；停用旧运行仍保留原引用。

<a id="ENF-03"></a>
### ENF-03 发现线索

`POST /discoveries`输入已提交同步批次/源观察集合及发布规则版本，输出attemptRef；`Clue`保存源Ref、疑似类型、原文引用/摘要、首次发现时间、多条命中、可空模型置信及版本、处置与通知状态。唯一约束为域归属内源记录+源版本，一条线索多个规则明细；发现重试按规则执行manifest去重，不重复首次发现或通知。

源新版本追加发现历史，不覆盖旧处置；跨源相似仅疑似重复关系，合并关联须人工。线索处置值待核实/核实中/已转处置/排除/关闭，`/disposition`具名人员、reason和expectedVersion；实际允许转移按确认流程策略，尚未确认不推导法定程序。`/notifications`使用已批准接收通道、eventId及有限重试，不默认短信。通知投递与工作包真实受理不同。

D-ENF-03：同源多规则只一线索；模型失败是未处理非未命中；通知成功不改已转处置；跨源相同文本不自动并案。I同步批次与规则及真实接收，B专家误漏报。

<a id="ENF-04"></a>
### ENF-04 线索解析

`POST /clues/{id}/parses`固定线索版本/解析配置，输出`ParseRevision`：主体候选数组及原文角色、信用代码ObservedField、事实定位、原始/标准化时间地点、真实材料Ref或待接入引用、优先级依据与缺项、模型/输入版本、待审核状态。结构字段与自由文本模型通道分别披露，旧STRUCTURED_LOCAL_V1不能冒语义解析。

`/revisions`具名修订追加版本，`/review`确认/退回并留理由；重解析另机器版，不覆盖人工确认。主体核验端口仅在获准时调用，有来源才填写信用代码；缺优先级规则返回待评估，不填“中”。D-ENF-04：两个主体分别保原角色；空信用代码不补造；标准化失败原文仍在；确认后重跑不覆盖。I原文/模型/核验，B字段与定位标注。

<a id="ENF-05"></a>
### ENF-05 材料登记与核验

`POST /evidence`输入案件或线索至少一项、名称/类型、来源渠道、受控文件/中心Ref、真实收集信息或未知原因；服务分配证据id、机构/审计、摘要算法/值、原件/派生关系、待核验状态。物证保存描述照片及真实保管信息，不宣称替代实物。

文件按docs/55暂存→验证→关联；预览/下载每次授权，元数据更正追加修订；OCR/转码另派生版本。`/verification`由有权人作核验/排除/归档动作并记录根据，具体状态转换按已批准策略；Agent无此端口。已被引用禁止物理删除，排除事件使依赖成果需复核。相同哈希不同收集过程仍两份证据。

D-ENF-05：上传者不自动成为收集人；无案件/线索拒绝；孤儿文件不成材料；排除证据新分析不能作有效支持；直链撤权拒绝。I文件/DM8恢复，B收集过程与核验职责。

<a id="ENF-06"></a>
### ENF-06 待证规则

`EvidenceRuleRevision`：适用案件类型、待证明事项id/必要性、允许证据与替代材料、关系类型、缺项判据、依据版本。关系按原文至少证明/补强/矛盾/无关，支持/反证是成果呈现，不替代原关系字典。

草稿、试跑、发布/停用端点`/evidence-rules`；发布检查必要事项、重复要素、空映射、字典/依据/范围、已确认专业内容；缺来源拒发布。不用材料数量/模型分判充分。D-ENF-06：同证据对两个事项分别说明作用；缺必需事项拒发布；未知案件类型不套规则；试跑不改变案件事实。

<a id="ENF-07"></a>
### ENF-07 证据整理

`POST /evidence-organizations`输入中心案件Ref/资料版本、EvidenceSet、已发布规则；输出`EvidenceAnalysisRevision`，逐事项保存支持/反对/冲突关系、位置及理由、未证实标记、未处理材料、三类时间线和缺口。音视频使用获准转写/实际时间点，不可解析保异常而非略掉。

固定关系记录`matterRef,evidenceRef,locator,relation,basis,originKind`；机器提出与人工确认分字段。`/revisions`人工修订、`/review`待审核→已确认/退回；重跑新机器版本。证据排除或规则变化沿依赖图使当前版需复核，旧确认记录不删除。完整性只表示存在缺口/冲突/待核验等真实情况，不能等于合法有效证据链。

D-ENF-07：预填输入关系不能冒新分析；相矛盾材料并列；排除证据后新结果缺口可见；人修关系不被重跑覆盖。I原件定位和回流，B待证事项及关系逐项专家核验。

<a id="ENF-08"></a>
### ENF-08 程序校验规则

`ProcedureRuleRevision`保存地区/机构/程序/环节、有效期间与依据、前置事件、必要字段材料、时限表达（数值/单位/起算事件/含起算日/截止调整）、日历版本、延期/中止/恢复及例外。日期计算为受控确定性表达，模型只解释已算轨迹。

`/procedure-rules/{id}/trial`输入固定事件/日历/例外，输出适用性、逐步日期轨迹和缺口；`/publish`核边界样例/冲突/完整公式/有效依据，任一缺失拒绝。历史适用需业务确认，不能按“最新发布”替代。D-ENF-08：缺日历不算工作日截止；起算语义不明拒发布；重叠范围未定优先关系拒发布；停用不改旧计算。

<a id="ENF-09"></a>
### ENF-09 程序辅助校验

`POST /procedure-checks`固定案件快照/真实事件/材料、适用规则，`CheckItem`含环节、要求、输入证据、通过/不通过/无法判断/不适用、疑似问题、整改建议、时间轨迹。适用范围不匹配才不适用；字段缺失无法判断；接口失败另为执行失败，不能落全部通过。

`/rectifications`登记具名说明和证据，`/rechecks`另尝试及报告版本，旧结果不被改通过。临期提醒仅已确认阈值/通道及真实计算，通知状态单独。D-ENF-09：缺事件非合规；整改说明不改旧报告；上游503为失败；历史规则不自动换现行。I真实事件及日历，B专业时间边界和例外。

<a id="ENF-10"></a>
### ENF-10 行为分析规则

`ConductRuleRevision`：行为类型、标准和依据、要件/事实/证据要求、排除抗辩及确认记录、地区职权程序、严重程度因素/取值/计算（可无能力）。允许为空的抗辩列表也需业务确认，不能默认不存在抗辩。

`/conduct-rules`草稿/试跑/发布；核每一要件和适用性，专利要逐权项输入、商标要实际标识与商品关系；假冒专利不共用侵权程序。程序映射缺依据拒发布相关分支。D-ENF-10：语义相似不能成为侵权确定条件；地区职权冲突拒发布；严重程度未定不出等级；无排除标准不假装完整。

<a id="ENF-11"></a>
### ENF-11 逐要件辅助分析

`POST /conduct-analyses`输入案件/线索解析/证据链/证据/规则版本及发生时点权利资料；`ElementFinding`区分确认事实、当事人陈述、机器推断，逐项支持/反证/排除、依据、缺口/不确定性。输出仅支持疑似成立/存在排除依据/材料不足无法判断及解释，程序仍候选。

先适用性，再事实/证据/规则核验，必要历史权利状态未知保持缺口。严重程度仅足够确认输入和已发布规则才算。修订/审核/重跑新版本，金额或正式侵权认定不能由本任务写。D-ENF-11：当前有效不证明行为时有效；缺材料不当不侵权；必须保反证；规则变更旧人工版需复核。I实际规则和证据，B逐要件专业审查。

<a id="ENF-12"></a>
### ENF-12 文书模板

`DocumentTemplateRevision`：模板id/名称、执法环节、地区/机构/程序、DOCX文件Ref、章节/重复区块、稳定占位符、类型/必填/格式、字体编号页眉页脚、来源批准及审计。模板与文书实例独立；正式文号/签章仅预留。

`POST /document-templates`受控上传、字段配置；`/previews`固定样例/模板/渲染器试填；`/publish`核模板批准、字段唯一/完整、依赖及版式样例，发布版不可覆盖，停用限制新文书。禁宏/脚本/外链，首版DOCX输出，PDF可选预览，不建通用排版器。D-ENF-12：未知占位符拒发布；长表格/重复段落需实际渲染；缺字体明确失败；旧实例不随模板变更。

<a id="ENF-13"></a>
### ENF-13 文书字段映射

`DocumentRuleRevision`绑定精确模板版本；`FieldMapping`为字段id、来源路径及schema版本、直接值/确定计算/辅助叙述方式、缺失策略。主体、金额、日期、原文法条不得模型填造。叙述保存来源片段、模型和模板版本。

`/document-rules/{id}/validate`解析所有路径/类型/权限；`/trial`返回逐字段来源及缺失；`/publish`要求真实映射确认。缺失策略仅阻断、留空提示、省略可选段落；必填缺失可有明确不完整草稿但不可提交审核。调查笔录无真实问答拒相关生成。模板变化旧映射待复核，不自动迁移。D-ENF-13：无问答不造提问回答；不存在路径拒发布；金额缺失不默认0；辅助段落不称原始记录。

<a id="ENF-14"></a>
### ENF-14 文书草稿

`POST /documents/prepare`核案件/模板/规则和实际所需输入；`POST /documents`固定manifest生成结构章节、字段来源和缺失项。`DocumentRevision`存系统草稿id、contentHash、撰写发起人/系统辅助、审核状态、原始与修订、模板规则、引用锚点，不生成正式文号。

`/revisions`保存人改、`/regenerations`产生候选版及差异、`/adoptions`具名采用，不能覆写当前人改。`/submit-review`阻必填/未确认处罚结论；`/review`决定绑定精确版。对外交付导出及其预览使用同一已审核内容版本，草稿工作区可显示结构化未审核内容且不能冒正式导出。渲染失败不丢结构稿。源改变只标需核对，不自动替换正文。

D-ENF-14：未知金额留缺项不能审核；旧审核不能导出新修订为已审核；重生成不抹手改；引用绑定失败整个文书提交回滚。I真实DOCX/国产字体/权限，B逐字段和版式专业验收。

<a id="ENF-15"></a>
### ENF-15 处罚规则

`PenaltyRuleRevision`保存行为、职权/程序/地区/有效期间、ENF-17依据版本、法定幅度、裁量基准、因素及证据、从轻/减轻/不罚条件、金额口径/币种/单位/精度/舍入/上下限、冲突优先关系。范围和基准分开，缺裁量基准不能套惯例。

`/penalty-rules`保存/试算/发布；数值表达为类型化确定性公式，不执行脚本。发布逐项校验依据、边界样例、输入口径及重叠优先关系；缺任何金额语义拒发布金额分支。D-ENF-15：冲突不能默认从轻/从重；缺舍入拒发布；不适用处罚不算罚款；来源变更不改历史建议。I实际标准/样例，B专业批准公式及例外。

<a id="ENF-16"></a>
### ENF-16 条件化处罚建议

**共享路由单一所有者的最小改造合同。** 在platform-api的现有最高优先级V2边界处保留唯一入口，按`domain + method + exact path pattern + enabled predicate + required kind`登记咨询/执法路由；启动校验由同一所有者按实际域开关生成期望集合，与Spring实际`/v2/`映射双向比较，而不能继续依赖咨询task-core开关。路由声明和Controller装配须同一开关生效，内部`/v2/internal/enforcement/dev-material/retention/reconcile`也必须列入。请求先拒编码路径、反斜杠及非规范路径，再匹配域与方法，最后用**该域**的服务端凭据认证；未经匹配不能落到V0或其他域的认证链。共享入口把不可由客户端构造的`domain,principal,org,kind,credentialVersion,expiresAt`交给领域端口；不代做job归属或逐字段用途判定。现有`DevelopmentSubjectPolicy`的哈希比对、状态及撤销版本机制可作算法参考，但其咨询属性前缀、至少两H一A一J的构造限制和主体集合不可直接复用；本候选仅需执法许可中的一个H及独立最小权限J，A无命令。四种域开关启动矩阵及咨询旧路由回归见6.4.1；共享边界负责人须先确定配置与路由声明的单一维护点，避免两个过滤器先后放行。

到期先在全部H路由按DB时间拒读/拒旧key；J仅选`expires_at<=now OR state=PURGING`，事务1锁job并标`PURGING`，事务2锁同job后按`projection -> event -> receipt -> job`删子表/父表并提交。事务2失败回滚保留PURGING，独立无正文失败计数/作业日志后续重试，不能把失败计数永久留在已清理的业务表；事务1失败则下次仍由到期谓词选中。撤回当下立即拒业务使用；manifest是文件，撤回与DB提交之间没有原子共同事务，仅“提交前重验”不能排除最后一瞬撤回后写入。要声称严格撤回生效，安全/数据服务负责人须确定带单调版本的权威许可读取与并发栅栏或等效失败关闭协议，并给出撤回竞态I反例；当前仅能保证后续读取拒绝，不把该竞态写成已解决。撤回后物理清理触发时点还须按项目自有数据的撤回/删除条件补证，不能从六个月保留期擅推即时删除。备份回灌、文件与索引均不在本纯文本物理候选，不能称完整清理通过。

### 6.4.4 共享入口、撤回与物理约束的候选ADR（待定案）

**现状反证。** `V2ConsultationBoundaryFilter`以最高优先级截获整个`/v2/`，其路由匹配、开关与主体策略均只认咨询；`V2ConsultationBoundaryConfiguration.v2TaskRouteRegistry`又仅在咨询task-core启用时存在，期望集合只含咨询映射。故“仅执法开”既没有覆盖全部V2路由的启动核对，也会被现过滤器404；“两域同时开”会因多出的执法Controller映射启动失败。旧`DevelopmentSubjectPolicy`还硬要求两H、一A、一J，`SyntheticUsePolicy`只认咨询schema/字段与固定数据集，不能用同一实例装配执法单H许可。这些是现代码的适用范围，不是ENF原文规定；不因咨询开发C/I通过而视为执法共享入口已可用。

| 技术路线 | 改造边界与取舍 | D前可审且D后须测的结果 |
