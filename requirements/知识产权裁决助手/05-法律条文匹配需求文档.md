# 法律条文匹配需求文档

模块标识：ADJ-05；对应原需求：一.1.1.1.1.2.2。  
版本：V0.1 技术评审稿；日期：2026-09-12。  
建设条件：中心主要通过 API 提供数据；国产化部署，业务关系型数据库固定为达梦 DM8。  
交付边界：对外交付服务及接口、部署和验收资料；自研前端仅供内部验证，不交付对外页面。

本文与[需求总览与通用约定](00-需求总览与通用约定.md)共同构成开发要求。字段中文名为业务契约，接口路径和英文名由详细设计统一。涉及事实的字段缺失时返回缺口，不以模型推测满足必填。当前未完成中心 API、模型或 DM8 实测。

## 1. 功能概述

根据案件核心事实、争议焦点、程序和相关时间，召回并解释可能适用的法律条文，供裁决人员调整确认。检索相关度不等同于条文已经适用；确认后的条文通过 06 法律条文引用进入报告。

不从当前案情之外补造事实，不因事实描述类似而忽略权限、地域、时效、程序及例外条件。

## 2. 输入输出字段

| 字段 | 说明 |
|---|---|
| 案件编号、资料版本 | 冻结本次案件输入 |
| 核心事实、争议焦点 | 保留事实状态、来源及用户确认值 |
| 程序、管辖/地域、相关日期 | 时点不明时返回补充要求 |
| 查询关键词、法律问题 | 模型提取，允许人工修正 |
| 匹配条文 ID、法规/条文版本、原文 | 稳定引用，不只保存条号文本 |
| 相关度、排序规则版本 | 检索指标及范围，不代表法律适用概率 |
| 匹配原因、要件对应、适用疑点 | 引用条文及案情来源 |
| 匹配时间、任务 ID、实际范围 | 标明资源覆盖和失败部分 |
| 人工调整记录 | 新增/移除/确认、理由、人员、时间、结果版本 |

## 3. 匹配流程与规则

1. 从案件获取授权事实快照，检查程序、地域和时间是否足以判断候选范围。
2. 提取法律问题和关键词，使用条文原文、已审核解析及可用要点辅助召回。
3. 在授权法规版本内召回候选并排序；历史时点案件保留当时版本及过渡规则核实项，不只查现行有效法。
4. 为候选逐项列出对应事实、构成要件、尚缺条件和不适用风险，分别说明实体依据、程序依据等用途。
5. 人工可确认、移除或新增条文，必须选择具体版本并填写调整理由；形成新的匹配结果版本。
6. 输出候选和人工确认记录供引用模块选择，系统候选不得自动成为已确认法律依据。

采用混合检索或中心接口的实际能力须可核验。只在有限候选中重排时说明范围。数值相似度须有确定算法/映射，未标定时使用排序及标签，数值能力记为待补齐。

重新匹配产生新任务，不覆盖人工调整。案件资料或法规版本变化后标记受影响结果待复核；人工已确认也不能自动继承到新案情。法规中有关处罚内容不自动纳入裁决理由。

## 4. 内部验证页面

案件选择和事实/争议预览、地域/时间补充、关键词确认、开始匹配、任务进度。结果展示法规、条号、版本、原文、相关度、事实对应、缺口及状态。

支持原文定位、解析/要点查看、人工新增/移除/确认、查看理由历史及“准备引用”。比较新旧匹配版本，资料不足、无结果、源故障、部分成功独立展示。

## 5. 服务契约

| 服务 | 输入 | 输出 |
|---|---|---|
| 匹配准备 | 案件版本、分析范围 | 要素建议及缺口 |
| 创建匹配 | 确认要素、版本、幂等键 | 任务 ID |
| 查询结果 | 任务 ID、分页 | 候选、证据、范围、版本及状态 |
| 人工调整 | 结果版本、条文版本、动作、理由 | 新结果版本或冲突 |
| 引用候选查询 | 案件及结果版本 | 人工确认项及待核实状态 |

后端校验案件和法规权限。异步状态遵循总览；原文不可读、时间缺失、依赖故障、权限及版本冲突分别返回，不伪装成无匹配。

## 6. 国产化与 DM8 要求

DM8 保存任务、案情输入快照、候选条文版本、评分和调整记录。验证长文本、分数精度、复合引用、幂等及人工调整事务；全文/向量能力须单独选型验证，不假定 DM8 原生具备所需能力。

## 7. 验收要求

| 编号 | 场景与预期 |
|---|---|
| MATCH-01 | 时间/程序缺失返回补问，不自动套用现行法 |
| MATCH-02 | 原文版本、案情来源及匹配解释对应可核验 |
| MATCH-03 | 处罚与裁决程序不混用，构成要件缺口可见 |
| MATCH-04 | 候选与人工确认分开，调整留理由及版本 |
| MATCH-05 | 重算不覆盖人工结果，资料变化触发待复核 |
| MATCH-06 | 专家样本评估 Recall@K、排序及适用解释支持度，阈值试测确认 |
| MATCH-07 | DM8 验证精度、关联、任务幂等，脱离页面完成匹配调整 |

## 8. 依赖与交付

依赖 01—04、中心检索或授权索引及专家样本。交付匹配/调整服务、评分说明和验收记录。确认历史版本、法域范围、检索覆盖、模型及性能目标。
