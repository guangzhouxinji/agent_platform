# ADR-DB-PAIR-PREPARE-01：双实例部署准备的限定技术设计

日期：2026-10-07（Asia/Shanghai）。来源：本会话用户选择一个业务实例和一个独立校验实例并要求开始；docs/54允许按域schema/账号隔离，docs/09及当前主计划优先级。本决定不修改业务规则、来源许可、身份、授权、恢复批准或专业验收。任务状态唯一见docs/08。

## 当前R/D及实施范围

R只覆盖部署精简这一基础设施请求；D只放行新空实例的可重复部署准备与独立schema/账号校验。原咨询主任务及发布合同不更改，不使用过期Task/来源/模型额度。既有ProductGrantWatermarkConfiguration已支持独立authority schema，V001的维护者singleton不能在三域共用schema；因此共享实例、不合并表。不存在本切片新增业务阻断决定；实际数据迁移/身份配置及切换另取当前D，不能以本准备放行。

## 两实例和六schema

新增明确拥有的business/authority两个DM8容器、各一个独立named volume，loopback不同端口。咨询/执法/裁决分别CON_BIZ/ENF_BIZ/ADJ_BIZ及CON_AUTH/ENF_AUTH/ADJ_AUTH。每schema有迁移owner和独立APP账号，运行账号不得获得RESOURCE/DBA/跨schema授权。不让三个Agent共享万能数据库账号；数据库连接由原领域服务管理。产品启动配置还需领域迁移及当前授权，不在本工具中启动Agent/API。

初始准备仅应用当前已有共享identity/OAuth/client/workload/checkpoint SQL；authority使用V001及该域已有来源水位SQL。不创建用户主体、Grant、maintainer、OAuth client、模型额度或案件；不运行ProductIdentityBootstrap。现有SQL自身的空来源generation初始化保留，不新增业务批准。

## 安全执行与失败

配置固定三域及迁移白名单、SHA、schema/账号唯一。名称不得重用旧容器或卷；排除现行端口、源库、未知镜像。Docker仅固定本地DM8镜像、两端口/两卷；缺Compose插件时直接使用现有Docker CLI，不安装依赖。准备前核端口/资源为空，保存原资源快照；创建后核label/pair、image ID、唯一卷使用者和挂载，再连接。验证模式只允许manifest同归属资源，拒绝改配置后重用；不自动DROP user/重置/重建/删除资源。DDL不是全局事务，半完成保留错误现场并拒绝盲目重跑；错误输出仅SQL code/state，不泄露凭据。

密钥随机生成，只在进程中使用、通过Windows用户加密凭据保存至工作区外；manifest不存口令，日志不输出docker环境或完整连接异常。Docker管理员依然可读取容器初始化环境，不宣称该机制防本机管理员；正式凭据托管另取部署合同。

## 验证出口

Node反例验证配置、同端口/保护端口、schema/账号冲突、恶意标识、SQL漂移及缺业务准入；真实两DM8验证所有基线表、APP可读所属表、临时自有probe读写、跨域SELECT/UPDATE拒绝、APP DDL拒绝、两实例独立及原资源不变。Probe真实SQL且清除，仅工程准备，不伪造业务链。工具成功须留manifest/SQL SHA/运行源码SHA和报告；全仓verify红灯仍保留。

## 后继迁移边界

业务库和校验库不共同回灌；保留授权generation/history_sha、来源epoch、Task/Run/文件/密钥及确切SHA。迁移必须静止点/并发围栏及当前身份许可，切换后新写入需对账才能回退。原容器/卷/冻结证据不删除，本切片不自动迁移数据或切换连接。后继仍在唯一主计划登记，不让双实例准备成为所有业务编码的新前置。


## 独立校验必要性复评（2026-10-07）

用户随后要求重新评估，以上限定准备设计保留为历史候选，不再作为继续实施准入。状态唯一见docs/08；本次不创建/删除资源、不迁移数据、不切换连接、不关闭身份或现时来源保护。

### 当前依据与技术判断

- docs/02第39节和docs/69要求生产备份外现时水位、恢复先对账再放流量；这是已确认的派生恢复合同，不能默默删掉。但它不等价于必须另建一个DM8实例，也不是权限表数量要求。
- ProductGrantWatermark当前以独立authority的generation/history_sha及READY/PENDING检测业务授权历史回退；业务提交后authority推进失败会保持PENDING并拒绝受保护请求。安全性需要承担双数据源可用性、跨库非原子提交与对账恢复成本。
- db/identity-authority/V001只有3张基础表；V002—V005和裁决来源authority还承载来源撤回、删除与恢复状态，不能只以清会话替代。
- 当前ProductGrantWatermarkConfiguration强制独立authority连接，因此直接删校验库不是可用方案；需要适配实现、恢复门禁和回归测试。
- 技术上，授权管理可与业务共享实例并用最小权限表组/schema隔离。真正不可缺的是：旧备份恢复后不得把历史授权/来源许可当作现时许可。独立库如果与业务一起回滚，也不能满足这个保证。

### 可选替代与适用边界

1. 保留独立校验实例：复用当前实现，维持自动识别旧授权/来源回灌；独立备份/恢复管理和PENDING修复须真实演练。不保证抵抗可同时改两实例的管理员。
2. 一个业务实例＋强制恢复隔离：恢复前从外部运维入口关闭全部业务流量、Worker、模型外发、下载和写入；不能依赖会一起被回滚的库内开关。旧会话/委托失效，依据备份外现时权威或逐项重新批准重建Grant、来源许可和删除状态；无法确认的内容继续关闭；核验完成再放行。若没有完整的现时记录，就无法恢复原授权并自动继续运行。这个方案可减少数据库实例，但改变现行恢复合同，当前尚未实施或验证。
3. 一个业务实例＋外部权威服务/独立可信持久状态：替代DM8 authority适配器，而非去掉现时保护；需要完整记录、不可共同回退、持久性、并发围栏、故障关闭和审计证明。新增Redis或普通本地文件并不自动满足，也未证明比复用当前DM8更简单。

建议不再把双DM8当必选架构：先以单业务实例＋强制恢复隔离作为简化候选，核定是否接受恢复后重新核验/批准而不是自动恢复原权限。若必须维持现有自动防回灌合同且没有可替代外部权威，现阶段保留独立校验更稳妥。三Agent逻辑边界和独立权限账号不受实例数量选择影响。测试环境不得以关闭保护冒充同等产品合同。

### 验证边界

本次是源码/既有合同复评，不是单库方案验收；未运行新单库业务链或恢复演练。前置verify-all退出1，测试证据stage已有红灯，不能宣称全仓通过。候选Java bootstrap尚未编译和真实运行，Node validator通过不能证明部署成功。后继替代实施必须覆盖旧Grant恢复、来源撤回/删除恢复、旧令牌/Worker委托、恢复期间拒绝访问、多进程竞争、异常重启及重新放行，并另核D门禁。


后续评估入口：用户同日指定按单业务库＋强制恢复核验评估，详见[单库恢复部署评估](single-database-recovery-assessment-20261007.md)。该评估不授权删除现有校验库或切换连接，也不自动替代原恢复保障合同；任务状态仍仅见主计划。
