# Task Workspace、Agent Studio 与 Release 体验

产品体验提案，不声称原交付范围已包含公众门户或对外页面。咨询总目录、执法/裁决总览均写“前端内部验证、服务接口交付”；2026-09-22 咨询补充内部工作台。因此工作面应先供获授权内部用户验证，实际对外交付 UI/嵌入方式 **[待确认]**。`ADR-V2-05/12`。

## 信息架构

```text
任务箱（我的/待我处理/待复核/异常）
  └─ 任务工作面：目标与范围 | 当前成果 | 关键缺口/下一步
       ├─ 来源与证据（版本、定位、支持/反驳）
       ├─ 候选/对照/规则结果（按领域逐项）
       ├─ 产物（事实集、证据包、报告草稿、差异）
       ├─ 协作（ASK/CONFIRM/REVIEW/TAKE_OVER）
       └─ 活动与历史版本（权限内查看）
管理入口：资源/规则/Skill/模型/Prompt → Studio 草稿/测试 → Release/监控
```

首屏不是聊天营销页：任务箱按领域、责任、阻断原因、更新时间过滤；新建任务只收用户目标/案件或线索引用，系统显示下一关键缺口。工作面主区域呈现真实成果和一项主要动作；消息输入保留作追问/纠正/指令，不能遮蔽来源和正式产物。手机窄屏按“目标→需处理→成果→证据”逐层展开，按钮稳定且不与长名称重叠。

## 关键交互

- 目标卡：原始请求、当前 Goal 版本、对象、时点/地域、数据范围和受限能力；变更时并列显示前后影响，关键确认才弹交互。非关键缺口可以先给线索级成果。
- 进度：真实 Run 与 Task outcome 分离；显示已取得、未分析/失败的步骤、预计下一个动作与停止原因，不用“正在思考”掩盖长期无进展。离开页面后任务继续，恢复后定位最近有效产物。
- 候选与证据：候选结果集有版本和实际范围，选中对象稳定；并列原文/对照、支持/反证和无法判断。引用可打开具体页段/条款，失权时显示受控不可用，不继续显示缓存内容。
- 编辑与回流：事实/特征/报告章节修正展示受影响产物，用户确认后产生新版本；Agent 重做只涉及影响范围，原人工段落保留。审阅者看到原文、模型草稿、修订差异、缺口和审批版本。
- 状态措辞：`当前范围未找到`、`来源失败未能判断`、`资料不足`、`未获权限`、`待专业复核` 分开；模拟/开发数据明显标记且不参与正式统计。已复核与已签发分开。

## Agent Studio

面向有权限的产品/业务/技术治理者，不向普通业务用户暴露系统 Prompt 或工具密钥。按“任务目标→可用 Skill→授权 Tool/数据→规则/模型/Prompt→人工门禁→产物/完成条件→评测”编排；展示引用版本、依赖图、用途和不可用项。首期使用结构化配置/样例测试，不必建设任意拖拽画布。Prompt 是执行模板，用户引导是独立可见内容；用户文本/文献不能改变工具白名单。

## Agent Release

`草稿 → 静态校验 → 获准样例试运行 → 负向与任务 Eval → 有权审批 → 发布快照 → 受控观察 → 回滚/紧急撤销`。发布前检查必填变量、循环与异常出口、越权工具、已撤销规则/来源、模型数据许可和评测退化。试运行不计正式咨询量、不得生成正式线索/案件/报告。新任务绑定发布组合；旧任务保留版本但权限和紧急撤销即时生效。灰度/回滚需有责任人与退出条件 **[待确认]**，不能以技术开关代替业务发布批准。

## 使用性验证

让真实目标用户不看说明完成：启动任务、找到下一缺口、选文献/证据、核对定位、纠正一项事实、识别“部分/证据不足/来源失败”、提交/退回复核、恢复任务。记录首次有用产物时间、总工时（含审核）、误操作、重复追问、纠错成本及理解状态的正确率。数值门槛待观察后预注册；仅截图好看或页面可点击不是成功。
