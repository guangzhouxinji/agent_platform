## 1. 设计定位与边界

本设计把负责人确认后的第一条专利咨询主线转换为可进入 D 门评审的业务详细设计。它定义产品旅程、业务语义、状态、逻辑接口、逻辑记录、测试与外部证据边界，不定义 Java 类、DTO、Controller、数据库表、字段、迁移、部署或通用运行时。

权威顺序为：相关正式咨询需求、`docs/35-咨询智能体产品行为待确认清单.md`、`docs/36-咨询智能体R门需求变化影响评审.md`、`docs/37-咨询智能体契约重基线.md`、本设计。`docs/11`～`docs/17` 及当前 V0 实现只可作为历史技术证据，不构成本设计的产品边界。

设计约束：

- 用户表达业务目标，不要求理解内部模块；复合目标形成可独立跟踪的子目标。
- 同一任务可跨轮继续，授权范围内的只读、低风险、可恢复工具可连续调用。
- 任务状态、工具执行状态、模型调用状态、HTTP 状态、人工受理状态彼此独立。
- 用户纠正只使依赖该事实的下游产物失效，并保留历史版本。
- 有候选、有引用、工具成功、模型成功或 HTTP 200 均不直接表示任务完成。
- AI 可理解、抽取、改写、归纳、辅助分析和草拟；不得授予权限、补造证据或作正式法律/业务决定。
- 不设置固定检索轮数作为业务停止条件，不建设通用 Agent Runtime、Workflow 或三域统一运行时。

来源追溯：本设计的规则均来自 `docs/35` 的 TASK、INFO、AUTO、RET-P、EVD、CHG、END、QLT、DATA、ACC、P 系列决定，以及 `docs/37` 中上述七个契约的 `RB-MUST` / `RB-MUST_NOT`。外部证据缺口沿用第 16 节 OPEN QUESTION，不作默认决定。

## 2. 端到端产品旅程

### 2.1 总体流向

```text
自然语言目标
  -> 目标/对象/约束理解 -> 最小必要追问 -> 关键事实确认
  -> 专利资料查询 -> 初次检索 -> 稳定结果集
  -> 充分性判断 -> 自动改写/深化/再检索，或确认后扩大范围，或停止
  -> 候选选择 -> 技术特征确认 -> 逐项技术对照
  -> 证据充分性判断 -> 带证据辅助回答
  -> 追问/纠正 -> 局部失效 -> 重检/重算 -> 同一任务继续
  -> 已完成 / 部分完成 / 证据不足 / 需要人工复核 / 技术失败 / 用户取消
```

### 2.2 步骤设计表

| 步骤 | 输入 | 输出 | 前置与决策点 | 自动/确认/工具 | 失败恢复、下一步与结束 |
|---|---|---|---|---|---|
| J01 接收目标 | 用户自然语言、请求人、当前 DataScope；可选既有任务引用 | 原始表达快照、任务候选或继续任务候选 | 服务端重验身份、任务归属和当前权限；判断创建、继续或歧义 | 接收自动；任务归属歧义须澄清；不调用业务工具 | 无权限单独返回；合法输入进入 J02；用户取消则结束 |
| J02 理解目标 | 原始表达、获准上下文 | 用户目标、子目标、对象、约束、模型候选事实、冲突、未决项、指代候选 | 区分资料查询/检索/技术对照及复合目标；模型候选不得成为确认事实 | CON-11 可自动解析；模型/规则状态另记；不授予工具权限 | 模型失败可用已获准规则或转人工/技术失败，不伪装成功；进入 J03/J04 |
| J03 最小必要追问 | 缺失、冲突、目标影响分析 | 合并后的必要问题、为什么需要、可先执行部分 | 仅追问会改变结果含义、专业判断或权限的关键项；非关键缺失可披露后先行 | 提问需要用户回答；等待期间不得执行依赖缺失事实的工具；无依赖子目标可继续 | 回答后回 J02；无法取得关键输入则等待补充、证据不足或取消 |
| J04 确认关键事实 | 用户明确事实、模型候选、冲突项 | 已确认事实版本、未确认候选、被替代事实 | 关键范围、目标对象、对照目的与关键特征在使用前确认；低风险冲突可并列披露 | 用户确认；规则校验版本/权限；确认本身不触发越权工具 | 版本冲突要求基于最新快照重试；满足对应前置后进入 J05/J06/J11 |
| J05 专利资料查询 | 号码或自然语言主题、所需资料、确认范围 | 专利事实、文献版本、来源定位、缺失/权限/失效状态 | 数据源与用途已获准；读取全文/权利要求需对应授权 | 同一授权范围内可自动调用 CON-02；可按任务需要深化 | 无记录、无权限、来源失效、资料不足、技术失败分别处理；可靠资料可进入 J06/J09/J12 |
| J06 初次检索 | 用户目标、确认技术事实、确认范围、获准源 | 检索执行记录、结果集 ID/版本、候选、实际范围、解释与限制 | 首次范围只能是用户确认范围；方法只能声明真实具备能力 | CON-04 自动执行获准只读检索；允许连续调用资料能力 | 故障可重试且不重复产生业务副作用；成功后进入 J07；无结果仍进入充分性判断 |
| J07 结果集形成 | 本次执行、候选与来源版本 | 不可变结果集快照、稳定候选身份、序位映射 | 去重不能抹除来源/版本差异；新检索产生新版本，不覆盖旧快照 | 系统自动；不需用户确认；不扩大范围 | 快照保存失败为技术失败；成功进入 J08 |
| J08 结果充分性判断 | 目标、范围、结果集、覆盖/证据/重复/质量信号 | 充分、可自动改善、需确认扩大、无合理新信息、需人工等判断及理由 | 专业阈值未获证据时不得填数值或把启发式当专业结论 | 结构化规则约束 + AI 辅助建议；可继续调用只读工具；范围扩大须确认 | 按第 5 节进入 J06/J09/J10/J15 或证据不足；不得以轮数停止 |
| J09 查询改写/再次检索 | 不足原因、既有执行历史、同一确认范围 | 新查询策略、新执行、结果集新版本、与旧版差异 | 判断是否仍可能获得新信息；防止完全相同输入无意义重放 | 同范围改写、同义扩展、方法切换、重排、再检索可自动 | 新信息回 J08；没有合理新信息则停止并说明；工具失败可恢复/重试 |
| J10 证据深化 | 候选、回答目标、缺失证据类型 | 摘要/全文/权利要求等获准证据及来源版本 | 读取深度必须为当前目标所需且处于授权范围；数据用途另行校验 | 同一授权范围内可自动；未授权全文/权利要求不能读取或送模 | 无权限/来源失效/资料缺失分别返回；补足后回 J08/J13，否则降级、人工或证据不足 |
| J11 候选选择 | 结果集 ID/版本、自然语言指代 | 已选候选稳定身份、选择版本、歧义项 | 指代必须绑定快照；结果集变化不自动迁移旧序位 | 无歧义可自动解析并请用户执行选择；歧义必须澄清 | 候选失效/不可访问时提示并允许从有效版本重选；进入 J12 |
| J12 技术特征确认 | 目标、候选、用途、模型预提取特征 | 确认特征版本、未确认/冲突特征 | 对照最低需要目标、候选、目的和必要特征；关键特征必须用户确认 | 预提取可自动；确认由用户作出；可调用资料工具支持确认 | 缺关键事实则等待确认；确认后进入 J13 |
| J13 逐项技术对照 | 原任务、目标/候选版本、确认特征版本、获准证据 | 逐项相同/差异/无法判断、原因、证据定位、对照版本 | 权利要求级对照须取得对应文本与版本；不得输出正式法律结论 | CON-06 自动辅助对照；可连续深化证据；高风险/冲突转人工 | 模型/工具故障不抹除已完成项；缺证据标无法判断；进入 J14 |
| J14 对照证据充分性 | 对照项、回答目标、证据、冲突 | 每项及整体充分性、限制、可继续动作 | 有引用不等于充分；最低证据按第 6 节 | 规则约束 + AI 辅助归纳；可继续 J10/J13 | 足够进入 J15；局部不足可部分完成；重要冲突/高风险进入 J17 |
| J15 带证据辅助回答 | 已完成子目标、充分证据、限制、失败项 | 陈述到证据的可追溯回答、来源/版本/定位、不确定性、子目标状态 | 提示词只能组织已获准事实，不改变权限、证据或状态 | CON-10 已发布版本可用于草拟；最终状态由任务规则判定 | 生成失败可重试/换获准模型/返回结构化结果；进入 J16 或结束状态 |
| J16 追问/纠正/变化 | 新表达、当前任务快照 | 继续问、纠正版本、局部失效集合、分支/新任务建议 | 区分追问、事实纠正、指代修正、对象变化和目标变化 | CON-11 辅助识别；关键变化由用户确认；必要时继续工具 | 按第 7 节重检/重算；未受影响产物继续有效；回相应步骤 |
| J17 人工交接/回流 | 触发原因、任务交接包、当前权限 | 权威受理回执或明确“人工服务暂不可用”；回流结果版本 | 只有真实人工接口/角色/权限证据才能声称受理；正式决定由授权人员作出 | 发起需满足授权；回执来自权威人工系统/人员；AI 不模拟 | 已受理进入需要人工复核；不可用保持明确状态；回流后回 J02/J08/J13/J15 |
| J18 结束/取消/恢复 | 目标达成、停止原因、用户命令、可恢复依据 | 九状态之一、剩余限制、下一步、合法历史 | 完成需目标+最低证据+限制披露；取消停止活动执行 | 状态转换由规则校验；工具不得自行决定 | 恢复须重验身份、权限、来源有效性和版本冲突；不合法或过期则拒绝并说明 |

## 3. 任务业务语义

| 概念 | 业务定义 | 必须保留的关系与不变量 |
|---|---|---|
| 用户目标 | 用户希望取得的业务结果及用途，不是内部模块名 | 有稳定身份和版本；可包含多个子目标；变化须追踪 |
| 子目标 | 可独立判定进度和证据的资料查询、检索、对照或其业务片段 | 各自有状态、依赖、产物；汇总后允许部分完成 |
| 已确认事实 | 用户明确陈述或确认、且在当前版本被任务采用的事实 | 记录来源、确认人/时间、适用范围、版本；不被模型静默覆盖 |
| 模型候选事实 | AI 从表达或材料中提取、尚未获用户确认的候选 | 显式标为候选；不能触发依赖关键事实的正式步骤 |
| 未决项 | 会阻塞某子目标或降低结论等级的缺失、冲突、歧义、确认或外部依赖 | 记录影响范围、责任方、可继续工作和解除条件 |
| 任务上下文 | 当前有效目标、事实、权限快照引用、子目标、结果集、证据、未决项和版本关系 | 不是历史问题文本拼接；每轮只读取获准且仍相关内容 |
| 结果集 | 某次或一组可追溯检索执行在确定范围下形成的候选快照 | 稳定 ID；不可变版本；保存实际范围、方法、来源、执行与限制 |
| 结果集版本 | 结果集因重检、改写、重排、纠正或来源变化形成的新快照 | 旧版保留；序位指代只对绑定版本有效；明确衍生原因 |
| 候选 | 结果集中指向专利对象及其具体文献/版本的稳定对象 | 稳定身份不等同展示序位；可跨版本关联但不得静默替换 |
| 工具执行 | 对获准资料、检索或对照能力的一次可审计调用 | 保存输入快照、权限/配置引用、输出、状态、错误、重试关系；不决定任务完成 |
| 证据 | 支持特定事实或分析陈述的来源版本、定位、片段及使用限制 | 与陈述/特征逐项关联；来源失效不删除历史身份，但停止未授权消费 |
| 证据充分性 | 针对明确回答目标，证据是否达到该类型最低要求的结构化判断 | 与“有引用”分离；记录不足原因、冲突和可补救动作；阈值保持 OPEN |
| 任务分支 | 对象或目标变化时，从父任务的确定版本派生、只继承仍有效上下文的工作线 | 有父版本、继承清单和隔离边界；不是复制全部历史 |
| 用户纠正版本 | 对既有事实、范围、对象、指代或目标的显式替代记录 | 指向被替代版本、影响分析、失效产物和重算产物；历史不可覆盖 |
| 人工交接 | 将任务上下文以受控交接包交给授权专业角色的请求 | 请求、受理、处理、回执分离；没有权威回执不得声称已受理 |
| 人工回流 | 权威人工结果及其依据进入原任务形成的新版本 | 保留责任人、范围、结论、证据和时间；不覆盖 AI/旧人工历史 |

### 3.1 关键判定术语

| 术语 | 判定输入 | 判定规则与责任 | 审计输出 / OPEN 边界 |
|---|---|---|---|
| 当前明确焦点 | 当前任务/分支版本、最近一次用户明确选择或可唯一解析的明确指代、对象当前可用性 | 只有用户明确选择或明确指代成功绑定结果集时才能建立/切换；结果集产生、送达、展示、查看均不能替换它；绑定失效时保留焦点身份并标当前不可用，不自动换到其他结果集 | 焦点版本、形成事件/原因、前后焦点、用户动作、绑定对象和当前可用性；保存规则不等于数据库表 |
| 焦点候选 | 当前任务/分支中新产生、已送达、已展示或用户已查看但尚未明确选择/指代的结果集版本 | 可以按权威发生顺序记录多个候选和事件，但候选不能承担“第一个/第二个”等省略指代的默认结果集；用户明确选择或明确指代后才可转为当前明确焦点 | 候选结果集/版本、产生/送达/展示/查看事件及时间顺序；不是产品任务状态 |
| 无焦点 | 当前任务分支从未建立明确焦点，或用户明确清除焦点且没有新绑定 | 省略结果集限定的序位指代必须澄清；“最新结果”可按当前分支最近已送达的唯一结果集解析，成功后才建立明确焦点 | 无焦点原因和候选清单；不是产品任务状态 |
| 歧义焦点 | 用户表达可合理地指向多个任务/分支/结果集，或显式描述不足以从候选中唯一选择 | 不选最近页面、不按模型置信度强选；生成澄清项。澄清完成前保留原明确焦点（如有），但本次歧义表达不绑定任何候选 | 歧义候选集合、解析依据、澄清问题和解决版本；不是产品任务状态 |
| 主要目标 | 用户表达并已确认的目标/子目标层级、用途和变更版本 | 只有用户明确目标或经用户确认的目标可标为主要目标；无法判断主次时并列为待确认，不由模型自行降级某目标 | 目标版本、确认来源、适用分支；不新增目标优先级默认值 |
| 合理新信息 | 当前未满足目标、已执行策略/证据历史、同一授权范围内尚未尝试的合法动作及其补缺假设 | 只有存在可说明“预计补哪个缺口”、不与既有动作实质重复、且不越范围/权限的动作，才视为仍可能获得合理新信息；AI 可建议，任务规则校验重复/权限，专业有效性依赖 OQ-RET-01/QLT-01 | 动作假设、目标缺口、与既有执行差异、授权范围和停止理由；不设置固定轮数、分数或候选数 |
| 同一授权范围 | 用户确认的业务范围与当前权威 DataScope、来源/用途授权的交集 | 改写、同义扩展、方法切换只有不改变该交集才可自动；任一边界扩大均进入确认/授权 | 范围版本及权威授权引用；具体授权等待 OQ-AUTH-01/DATA-01/02 |
| 当前有效产物 | 产物及其全部必要依赖版本仍有效、当前有权使用且未被纠正/撤回事件失效 | 由依赖和权限规则确定；历史存在不代表当前有效 | 有效性版本、失效原因和关联事件 |

## 4. 九种产品任务状态

工具执行状态至少表达“待执行、执行中、成功、无结果、无权限、来源失效、失败、取消”等执行事实，但其具体枚举待实现设计确认。无论采用何种枚举，都不得直接映射为产品任务完成。

| 产品状态 | 进入条件 | 退出条件 | 工具/用户/重检/人工规则 | 与工具执行状态关系 |
|---|---|---|---|---|
| 进行中 | 至少一个有效子目标正在理解、查询、检索、深化、对照或组织回答 | 需要输入/确认、满足终态或发生取消 | 允许获准工具、用户输入和重检；满足触发条件可交接 | 可同时存在多个成功/失败/运行中执行；均不替代本状态 |
| 等待用户补充 | 缺失信息会改变目标含义或阻塞依赖步骤，已向用户提出最小必要问题 | 用户补充、取消，或明确无法补充后转证据不足/人工 | 不执行依赖缺失项的工具；无依赖子目标可继续；允许用户输入和人工 | 工具可为空、成功或暂停，不得因工具成功退出等待 |
| 等待确认 | 已有候选事实、范围扩大、关键特征或高影响动作等待用户确认 | 确认、拒绝、纠正、取消 | 不执行依赖确认的动作；可做不改变范围的准备；允许人工交接 | 执行状态不能代替确认；旧成功结果继续按版本有效 |
| 部分完成 | 复合目标中至少一项满足完成条件，另有子目标未完成、证据不足、人工或技术失败 | 剩余子目标解决后转已完成，或状态重新汇总 | 允许继续工具、输入、重检与人工；必须逐项展示状态 | 某工具失败不抹除已完成子目标，工具全成功也不保证剩余目标完成 |
| 已完成 | 主要用户目标均达到、对应最低证据满足、限制已披露且无阻塞未决项 | 新追问可继续同任务；纠正/目标变化可重开相关子目标；取消无意义 | 默认不再自动执行；用户继续后重验权限和版本；可因新变化重检 | HTTP/工具/模型成功、有候选或有引用均非充分条件 |
| 证据不足 | 合理获准动作后仍缺最低证据，或无合理新信息且不能支持目标 | 新证据、范围确认、用户补充、人工结果后恢复；也可取消 | 仅在新输入/新授权/确认后继续；允许用户输入、重检和人工 | 可以发生在工具成功且有结果时；不得伪装成无结果或技术失败 |
| 需要人工复核 | 正式法律/业务决定、高风险结论、重要冲突、关键证据缺失、能力/权限边界或用户要求人工 | 权威人工回流、撤回请求、人工不可用后转相应状态 | 未授权自动工具停止；允许用户补充；必要且获准的资料准备可继续 | 人工请求/受理/处理状态独立；无回执不得称已受理 |
| 技术失败 | 模型、检索、资料、系统等技术故障阻断当前可恢复路径，且不等于业务无结果 | 成功重试、切换获准能力、恢复，或取消/人工 | 允许幂等重试和用户输入；是否自动重试与技术策略由后续设计确定；不得扩大权限 | 明确关联失败执行；局部失败不自动覆盖已完成子目标 |
| 用户取消 | 用户明确取消，活动执行已停止 | 仅在获批保留/恢复规则允许且重新校验后恢复 | 不启动新工具；允许查看合法历史；人工未受理请求按契约撤回 | 正在执行工具须请求停止并记录实际结果；取消不等于物理删除 |

状态汇总原则：复合任务按子目标状态汇总；只要部分子目标完成且其余未满足，使用“部分完成”而不是“已完成”。状态转换必须记录原因、前后版本、责任来源和相关执行/证据，不允许模型或提示词单独写入完成状态。

### 4.1 子任务状态到主任务状态的唯一聚合

主任务在一个任务版本上只能有一个九状态。子任务状态、业务原因、执行原因和当前允许动作分别保存；原因不得扩展成第十个产品状态。聚合按下列顺序命中第一条适用规则，且每次聚合保存命中的规则、子任务状态快照和理由：

| 顺序 | 子任务/任务条件 | 唯一主任务状态 | 原因与允许动作 |
|---:|---|---|---|
| 1 | 用户取消主任务已被当前版本接受 | 用户取消 | 停止新工具；已完成子任务作为历史成果保留，不把主状态改回部分完成 |
| 2 | 所有适用的主要子目标均满足目标、证据和限制披露条件 | 已完成 | 非主要探索分支不阻止完成，但必须披露其状态；新追问产生后按新版本重新聚合 |
| 3 | 至少一个主要子目标已完成，且至少一个主要子目标尚未完成 | 部分完成 | 同时展示未完成子目标的等待补充、等待确认、人工、技术失败或证据不足原因和下一动作 |
| 4 | 没有子目标完成，且至少一个子目标必须由授权专业人员处理或已有权威人工处理中 | 需要人工复核 | 其他等待项继续逐项展示；AI/工具不得替代人工决定 |
| 5 | 没有完成项/人工优先项，且至少一个子目标等待用户确认关键事实、范围或动作 | 等待确认 | 不执行依赖该确认的动作 |
| 6 | 没有完成项/更高顺序项，且至少一个子目标等待用户提供关键缺失信息 | 等待用户补充 | 无依赖子目标仍可工作；若其后完成则下一版本按顺序 3 聚合 |
| 7 | 没有完成项/更高顺序项，且至少一个子目标存在可合法继续的活动动作 | 进行中 | 包括理解、查询、检索、深化、对照、回答和获准恢复动作 |
| 8 | 没有可继续活动动作，且至少一个子目标被技术故障阻断 | 技术失败 | 保留未受影响产物；等待幂等恢复、获准替代能力或人工 |
| 9 | 没有完成项、活动动作或技术阻断，全部未完成主要子目标均因最低证据无法满足而终止 | 证据不足 | 展示无结果、无权限、来源失效、资料缺失等具体原因及已做事项 |

指定组合的聚合结果：

| 组合 | 主任务状态 | 补充语义 |
|---|---|---|
| 一个已完成 + 一个等待补充 | 部分完成 | 等待补充是未完成子任务原因/下一动作 |
| 一个已完成 + 一个等待确认 | 部分完成 | 等待确认仍阻断对应子任务 |
| 一个已完成 + 一个需要人工复核 | 部分完成 | 人工子任务单独保持需要人工复核，不伪装主任务已完成 |
| 一个已完成 + 一个技术失败 | 部分完成 | 技术失败作为未完成子任务状态和主任务原因保留 |
| 一个已完成 + 一个证据不足 | 部分完成 | 已完成产物仍有效，证据不足项明确披露 |
| 全部适用主要子目标已完成 | 已完成 | 仍须满足证据和限制披露 |
| 全部未完成主要子目标均证据不足 | 证据不足 | 每个子目标分别保留不足原因 |
| 部分完成后用户取消主任务 | 用户取消 | 完成产物作为历史保留；取消优先阻断新动作 |
| 部分完成后用户提出新追问 | 依据新追问形成的新任务版本重新聚合，通常为部分完成或进行中 | 旧完成子目标不自动失效，新子目标单独跟踪 |
| 人工复核中用户继续输入 | 若输入只补充人工子任务，主状态仍需要人工复核；若另有子目标完成则按顺序 3 为部分完成 | 新输入形成事实候选/版本，不解除人工要求 |
| 技术失败后成功恢复 | 回到失败记录指定的恢复点，并依据恢复后子任务快照重新聚合 | 不默认重新执行全部任务 |

### 4.2 原因层、恢复点与取消竞态

`无结果 / 无权限 / 来源失效 / 证据不足 / 技术失败` 必须分别记录。前四者可以是子任务未完成的业务/可用性原因，技术失败是执行阻断原因；它们不增加产品状态。无结果、无权限或来源失效导致没有最低证据且无其他可继续动作时，主任务按 4.1 聚合为证据不足，同时保留原始原因；若需要权威授权处理或正式专业处理，则进入需要人工复核；用户确认不能授予权限。技术故障才可聚合为技术失败，不得把无结果或无权限伪装成技术故障。

每个可恢复失败必须保存恢复点：失败前任务版本、子任务、旅程步骤、目标/事实/范围版本、已提交产物、未完成动作、失败工具执行、待重试命令及依赖版本。恢复先重验权限、来源和依赖版本，只重新执行未提交或已失效的动作；已完成且仍有效的产物不得无条件重算。若依赖已变化，先进入纠正/冲突处理并生成新版本，不在旧恢复点继续。

取消以被任务版本接受的取消命令为边界：接受后立即拒绝新业务变更和新工具调用；已运行工具收到停止请求。取消前已经权威提交的执行结果保留为历史，但不得在取消后自动推进任务或生成当前回答；取消后才到达的执行结果只记录为迟到执行结果。恢复时可在权限、来源和保留规则允许的前提下显式选择是否消费这些结果。取消与工具完成同时发生时，以先成功提交的任务版本确定先后，后到命令不得最后写覆盖。

## 5. 结果不足与迭代检索

### 5.1 可测试决策表

| 观察 | 是否结果不足 | 可自动动作 | 必须确认/人工 | 停止与状态 |
|---|---|---|---|---|
| 没有结果，查询或方法仍有同范围改写空间 | 是 | 改写、同义扩展、切换已获准检索方式、再次检索 | 若下一步要扩大时间/地域/数据源/权限/明确业务范围，先确认 | 有新信息回评估；否则继续判断是否尚有合理新信息 |
| 没有结果，已无合理同范围新信息 | 是 | 组织已执行范围和失败解释 | 可询问是否扩大范围；重大专业判断可人工 | 用户不扩大或无可用范围时，以“无结果”事实结束相应子目标，不伪装技术失败 |
| 有结果但核心技术特征覆盖不足 | 是 | 同范围改写、特征组合调整、方法切换、再次检索 | 改变用户确认特征或范围须确认；专业争议可人工 | 仍可能获新信息则继续；否则证据不足/部分完成 |
| 有结果但支持目标的证据不足 | 是 | 深化获准摘要、全文或权利要求；补查来源版本 | 未授权证据读取/模型用途须停止并确认或拒绝；关键缺失可人工 | 补足后继续；不能补足则降级、证据不足或人工 |
| 结果高度重复且未增加覆盖/证据 | 是 | 去重、改变同范围策略；记录重复关系 | 需扩大实质范围时确认 | 无合理新信息则停止，不能靠重复轮次宣称充分 |
| 结果质量低，但仍有未尝试的获准策略 | 是 | 调整关键词/语义组合、排序、查询结构并再检索 | 专业质量阈值仍由 OQ-RET-01/OQ-QLT-01 决定 | 新信息回评估；不得以固定分数直接完成 |
| 仍可能获得新信息且动作不改变范围/权限 | 未定，继续处理 | 可自动连续调用 | 无需逐步点击 | 每次形成执行记录和结果集新版本；无固定最多轮数 |
| 已经没有合理的新信息 | 是且停止迭代 | 汇总已做动作、覆盖、缺口、限制 | 需要正式/高风险判断时人工；可询问用户是否改变范围 | 证据不足、部分完成或无结果；不能继续无意义重放 |
| 需要扩大时间范围 | 是 | 只生成建议和影响说明 | 必须用户确认 | 未确认保持等待确认；拒绝则按原范围结束 |
| 需要扩大地域 | 是 | 同上 | 必须用户确认 | 同上 |
| 需要改变数据源 | 是 | 校验候选源和用途，不实际切换 | 必须用户确认且数据源已获授权；授权缺失不能执行 | 未授权返回无权限/不可用，不伪装无结果 |
| 需要扩大权限 | 是 | 不得自动扩大 | 必须走权威授权；用户确认本身不能授予权限 | 未授权停止该分支；可用已有证据降级 |
| 需要改变用户明确业务范围 | 是 | 生成变更建议 | 必须用户确认 | 确认后形成目标/范围新版本并局部失效 |
| 重要证据冲突无法消解或目标要求正式决定 | 不以继续搜索强行解决 | 可准备交接材料 | 必须人工复核 | 有权威回执才进入已受理路径；否则明确人工暂不可用 |

### 5.2 停止判据结构

停止依据只能是：目标及证据已满足；用户停止/取消；同一范围已没有合理新信息；继续动作需要未取得的确认/权限/外部证据；重要冲突或正式决定需人工；技术故障阻断。是否“仍可能获得新信息”的专业判定结构已定义，但判定样例、阈值和评测标准仍由 `OQ-RET-01`、`OQ-QLT-01` 提供。

## 6. 证据充分性模型

| 回答目标/分析类型 | 最低证据结构 | 摘要地位 | 不足/冲突处理 |
|---|---|---|---|
| 普通主题线索 | 可核验的来源、版本、定位，以及支持主题关联的资料 | 可作为初步线索 | 明示仅为线索、范围和不确定性；不升级为技术结论 |
| 技术相关性参考 | 与相关技术特征直接对应的可定位资料，覆盖用户关心的关键点 | 可用于初筛，但是否足够取决于回答陈述 | 未覆盖关键点则继续深化/检索，或标证据不足 |
| 技术特征逐项对照 | 每个确认特征对应候选中的直接证据、版本、定位；能区分相同/差异/无法判断 | 原则上不能单独支撑深入逐项判断 | 缺项标无法判断；局部完成；关键缺失可人工 |
| 权利要求级对照 | 对应专利文献版本的权利要求文本及逐项定位，并保留目标/候选/特征版本 | 不足 | 未取得权利要求则降级为线索/初步参考，不输出范围或法律结论 |
| 证据冲突 | 各冲突来源、版本、权威层级/效力信息及无法消解原因 | 仅描述冲突，不消解冲突 | 按权威层级和版本处理；无法消解则并列披露、继续检索或人工 |
| 来源失效 | 历史来源身份、曾用版本、失效/撤回状态及当前可核验替代来源（如有） | 不适用 | 停止未授权展示/消费；历史回答保留原引用身份并标失效 |
| 资料缺失 | 已查范围、所缺资料类型、缺失对目标的影响、已尝试动作 | 不得补造 | 允许返回“未找到足够依据”、已有线索和下一步；与技术失败区分 |

充分性判断对象是“具体陈述或分析目标”，而不是文档是否挂有 `sourceId`。结构必须能表达：目标类型、所需证据类别、实际证据、覆盖关系、冲突、缺失、权限限制、判断状态和理由。专业等级、数量、阈值及权威来源矩阵等待 `OQ-EVD-01`，不得用实现便利值替代。

### 6.1 独立的证据充分性评估

证据充分性评估是版本化逻辑产物，不是产品任务状态、引用计数、模型自由文本或数据库表。每次评估至少保存以下业务语义：

| 语义 | 定义 |
|---|---|
| 评估对象 | 被评估的回答、实质陈述、检索目标、对照整体或具体对照项的稳定身份与版本 |
| 对应任务/子任务 | 评估所属任务、分支、子任务及其版本 |
| 回答/分析目标 | 普通主题线索、技术相关性、逐项技术对照、权利要求级对照或其他经契约批准的目标 |
| 目标版本 | 评估采用的用户目标、确认事实、范围、特征和候选版本集合 |
| 证据集合版本 | 本次评估实际使用的证据身份、来源版本、定位、可用性和集合版本 |
| 证据规则/矩阵版本 | 适用的已批准最低证据结构、专业等级和冲突规则版本；专业内容等待 OQ-EVD-01 |
| 评估结果 | `足够 / 不足 / 冲突 / 不可评估 / 尚待补证`，仅是评估结果，不增加产品状态 |
| 结果理由 | 哪些要求已满足或未满足，以及该结果如何由输入和规则得到 |
| 缺失/冲突证据 | 缺失类型、影响和可补救动作；冲突各方、版本及不能消解原因 |
| 限制 | 权限、来源、资料深度、适用范围和不得形成的正式结论 |
| 责任来源 | AI 建议、确定性规则检查、用户确认、权威来源或授权专业人员各自贡献；最终提交者可追溯 |
| 产生时间 | 评估产生的业务时间和所依据任务版本，不作为专业时效默认值 |
| 失效条件 | 目标、确认事实、范围、特征、候选、证据集合、来源版本、权限或规则矩阵发生相关变化 |
| 重评触发 | 新证据、纠正、候选/来源版本变化、来源/权限事件、人工回流或规则矩阵更新 |

结果语义：`足够` 表示当前目标在适用矩阵下满足最低结构；`不足` 表示合理获准动作后仍未满足；`冲突` 表示关键证据不能按当前规则消解；`不可评估` 表示缺少适用矩阵、授权、可用来源或必要输入，不能作出充分性判断；`尚待补证` 表示已明确缺口且仍有获准、合理的补证动作。`不足`、`不可评估` 和`尚待补证`必须分别表达，但都不得被直接当作新的产品状态。

AI 只能生成评估建议和理由候选；确定性规则负责权限、版本、证据类型、引用白名单和已批准矩阵约束；用户确认事实不等于确认专业充分性；正式专业判断由授权人员完成。只有任务行为规则基于可用的已批准矩阵、有效输入版本和可追溯责任来源，才能提交当前评估版本。专业阈值、证据等级和权威矩阵仍由 `OQ-EVD-01` 提供；缺失时不得提交依赖该未知规则的“足够”，只能按实际情况记录不可评估或尚待补证。

目标、关键事实、范围、特征、候选或证据集合变化时，只使依赖这些变化的评估失效；来源版本/权限变化按第 11.2 节传播。失效评估保留历史但不得作为当前完成依据。新评估必须引用新输入和证据集合版本，不得原地覆盖旧评估。

## 7. 用户纠正与局部失效

| 变化类型 | 必须失效 | 可继续有效 | 重检/重算 | 历史、分支与继承 |
|---|---|---|---|---|
| 技术特征纠正 | 依赖旧特征的查询、结果充分性、选择理由、对照项和回答陈述 | 无关事实、无依赖资料、其他子目标结果 | 核心特征变化须重检；仅对受影响特征重算对照 | 生成纠正版本；旧结果标被替代但保留；同一目标通常留在原分支 |
| 检索范围纠正 | 旧范围下的充分性和依赖该范围的结果集当前有效性 | 与范围无关的确认事实、合法历史证据 | 形成范围新版本并重检；对照仅在候选/证据变化时重算 | 保留旧范围及结果集；若是替代范围可同分支，探索性范围可建子分支 |
| 候选对象纠正 | 依赖旧候选的选择、对照和回答 | 目标、确认特征、其他候选/资料 | 不一定重检；必须针对新候选重做受影响对照和证据判断 | 选择版本更新；旧候选对照保留历史 |
| 结果集引用纠正 | 错绑候选的选择及其下游对照/回答 | 原结果集快照、其他正确引用和无依赖产物 | 通常不重检；按正确快照/候选重算下游 | 保存错误绑定与纠正原因；不改写旧快照序位 |
| 目标变化 | 不再服务新目标的充分性、回答和相关子目标状态 | 仍相关且权限有效的确认事实、来源资料 | 是否重检取决于新目标对范围/证据的影响 | 相关变化可建任务分支；完全不同目标新建任务；只继承列明内容 |
| 对象变化 | 依赖原主对象的查询、检索关系、候选选择、对照和回答 | 通用约束及经重新验证仍适用的事实 | 核心对象变化通常重检并重做对照 | 同一目标下建新子任务/分支；完全不同对象和目标可新任务 |

失效是业务可用性标记，不物理删除历史。每次影响分析记录“纠正事实 -> 直接依赖 -> 传递依赖 -> 失效产物 -> 可复用产物 -> 重算动作”，禁止一次纠正无条件清空任务。

## 8. 自然语言结果集指代

### 8.1 绑定规则

指代解析的输入是当前表达、当前任务主对象、最近有效交互焦点、用户可访问的结果集快照和候选稳定身份。输出必须是明确的 `结果集稳定身份 + 结果集版本 + 候选稳定身份` 或“存在歧义”。序位只是某一快照内的展示映射，不是候选身份。

| 表达 | 绑定规则 | 歧义/版本变化处理 |
|---|---|---|
| “第一个” | 绑定当前明确焦点结果集版本中的第 1 个候选 | 有多个同等焦点结果集时澄清；新版重排后仍绑定原快照，除非用户明确改用新版 |
| “第二个” | 同上，绑定第 2 个候选 | 原版本不存在第 2 个时不能猜测 |
| “刚才那个” | 优先绑定当前任务最近一次明确选中或明确提及的主对象 | 多个合理对象时澄清，不按模型置信强行选定 |
| “和第一个比较” | 当前主目标/对象与绑定快照中的第 1 候选形成对照对象对 | 主目标或结果集不明确时分别澄清 |
| “把第二个换成第三个” | 在同一明确结果集版本中，以第 3 候选替代现有第 2候选选择并触发局部失效 | 跨版本或序位缺失时澄清；旧对照保留历史 |
| “只看刚才提到的两篇” | 绑定最近一次明确共同提及的两个候选稳定身份 | 不能唯一确定“两篇”时列出歧义选项并等待确认 |

结果集产生新版本后，旧指代绑定不自动漂移到新序位。来源撤回、权限收紧或候选失效时，绑定历史仍保留，但当前使用状态变为不可用；系统应要求重选或基于有权访问的版本继续。

### 8.2 结果集与焦点的唯一转换规则

焦点语义只存在于当前任务的当前分支内。结果集产生、送达、展示和用户查看只形成焦点候选，**均不自动建立或切换当前明确焦点**。只有用户明确选择某个结果集，或用户表达中包含可唯一解析的结果集限定并成功形成指代绑定，才创建新的当前明确焦点版本。该原则来自 `docs/35` CHG-04～05“指代绑定具体结果集快照、歧义必须澄清”和 P-01“用户表达业务目标”，避免页面位置或系统最近输出静默改变用户已建立的对象。

交互焦点的记录状态为“当前明确焦点 / 焦点候选 / 无焦点 / 歧义焦点”，它们不是产品任务状态。焦点还带独立的当前可用性；来源失效或权限收紧可使当前明确焦点变为不可用，但不把它替换成另一个结果集。

| 当前交互语义 | 事件 | 唯一结果 | 是否产生新焦点版本 | 是否需要用户明确动作 |
|---|---|---|---|---|
| 任意 | 新结果集产生 | 保存结果集及谱系并加入当前任务/分支的焦点候选；现有明确焦点保持不变 | 否 | 否 |
| 任意 | 新结果集送达用户 | 记录授权送达事件并更新该候选的送达顺序；现有明确焦点保持不变 | 否 | 否 |
| 任意 | 新结果集展示 | 记录可选展示事件；展示位置、滚动或排序不改变明确焦点 | 否 | 否 |
| 任意 | 用户查看/打开结果集 | 记录查看事件并保持为焦点候选；查看不等于选择 | 否 | 否 |
| 无焦点/有旧焦点 | 用户明确选择结果集版本，如“用第二批结果继续” | 唯一解析后创建焦点新版本，绑定所选结果集 ID/版本；前一焦点版本保留 | 是 | 是 |
| 无焦点/有旧焦点 | 用户明确指代结果集，如“V1 里的第二个”“最新结果里的第二个” | 先按显式限定唯一解析结果集，再绑定该快照序位/候选并创建焦点新版本 | 是 | 是 |
| 有明确焦点 | 用户使用省略结果集限定的“第一个/第二个/刚才第二个” | 始终使用当前明确焦点的结果集版本；焦点不变，只生成新的指代绑定 | 否 | 是，当前表达即明确动作 |
| 有明确焦点/候选 | 用户说“就看刚才这批结果” | “这批”只在当前分支最近已送达的结果集版本唯一时解析并切换；同时送达多批或跨分支不唯一则进入歧义焦点并澄清 | 唯一时是；歧义时否 | 是 |
| 任意 | 用户纠正普通事实/特征/范围 | 不改变明确焦点；按纠正依赖传播更新结果集当前有效性 | 否 | 是，但不是焦点动作 |
| 有绑定 | 用户明确纠正指代或结果集，如“不是 V1，是 V2 的第三个” | 创建纠正后的指代绑定和 V2 焦点新版本；旧绑定/焦点保留历史 | 是 | 是 |
| 有 V1 焦点 | V2 是 V1 的重排/再检索新版本 | V2 成为焦点候选；V1 继续是明确焦点。V1 序位和 V2 序位分别绑定各自快照 | 否 | 否 |
| 有明确焦点 | 来源失效、版本失效、权限收紧或 DataScope 缩小 | 创建同一焦点对象的可用性变更版本并标当前不可用；不自动切换到其他候选 | 是，但对象不切换 | 否；继续使用其他结果集须用户明确动作 |
| 不可用明确焦点 | 资料重新可用或权限恢复 | 重验后创建同一焦点对象的可用性变更版本；不自动恢复旧证据/结论，也不切换对象 | 是，但对象不切换 | 否；后续消费仍按当前动作重验 |
| 当前任务/分支 | 用户明确切换任务或分支 | 切换到目标任务/分支后，恢复该分支最后一个明确焦点及当前可用性；从未有焦点则为无焦点 | 是，记录上下文切换后的当前焦点；不改写分支历史焦点 | 是 |
| 当前任务/分支 | 系统自动创建任务分支 | 新分支为无焦点；不得继承父分支当前焦点为明确焦点，可将仍相关结果集列为候选 | 否 | 否 |
| 已保存任务 | 任务恢复/系统重启 | 从逻辑记录恢复当前任务、分支和该分支最后明确焦点，再重验可用性；不按页面或最近生成结果集重算焦点 | 否；可用性变化时按对应事件创建版本 | 恢复本身不需要；使用不可用焦点或切换时需要 |

显式限定的解析顺序固定为：用户给出的任务/分支 → 结果集稳定 ID 或版本 → 该分支内已记录的批次/送达限定（如“第一批”“最新结果”）→ 该结果集快照内序位。任一层出现多个合理对象时进入歧义焦点并澄清；不得退化为页面当前位置、全局最近结果、模型最高置信或候选稳定身份的猜测。

关键表达的唯一含义：

- “刚才第二个”没有结果集限定，始终绑定当前明确焦点版本中的第二个；如果无明确焦点则澄清，如果焦点当前不可用则保留历史绑定但阻止继续消费并要求用户明确选择可用结果集。
- “V1 里的第二个”显式绑定 V1 的第二个，并将 V1 建为当前明确焦点；即使 V2 更新也不改变该绑定。
- “最新结果里的第二个”在当前任务/分支内绑定最近已送达且唯一的结果集版本，并将其建为当前明确焦点；尚未送达的后台结果不能成为“最新结果”。
- V1 的第二个和 V2 的第二个分别绑定各自快照中的候选稳定身份；序位从不跨版本继承。

固定反向重放：`V1 → 用户绑定 V1 第二个 → 系统重启 → V2 产生 → V2 送达/展示 → 用户说“刚才第二个”`。重启恢复 V1 明确焦点；V2 仅为焦点候选，产生/送达/展示均不切换焦点；最终唯一绑定 **V1 的第二个候选**。若用户说“V1 里的第二个”，仍唯一绑定 V1；若用户说“最新结果里的第二个”，则按最近已送达的唯一结果集解析为 V2，创建 V2 焦点新版本并绑定 V2 的第二个。

## 9. 专利技术对照回流

对照不是独立工作台终点，而是 CON-12 任务中的子目标执行：

```text
CON-12 原任务快照
 -> 绑定 CON-04 结果集版本并选择候选
 -> 确认目标、用途和关键技术特征版本
 -> CON-06 逐项对照
 -> 逐项/整体证据充分性
 -> 对照产物和状态回流原任务
 -> 继续检索/补证/回答/部分完成/人工/结束
```

| 设计项 | 语义 |
|---|---|
| 输入 | 原任务/子目标身份与版本、目标专利/方案、候选稳定身份及文献版本、对照目的、确认特征版本、获准证据、请求人/DataScope |
| 输出 | 对照版本、逐项映射、相同/差异/无法判断、理由、证据定位、充分性、限制、失败项、人工建议、原任务回流引用 |
| 状态 | 对照执行状态独立保存；CON-12 根据所有子目标及证据汇总产品状态 |
| 失败 | 对象不明、版本冲突、特征未确认、无权限、来源失效、模型失败、工具失败、系统失败分别表达；已完成项不因局部失败丢失 |
| 证据不足 | 缺证据的特征标无法判断；允许深化、降级为初步参考、部分完成或人工，不强行判断 |
| 纠正 | 根据特征/候选/证据依赖图只重算受影响项，生成新对照版本，旧版保留 |
| 人工升级 | 正式法律/业务决定、高风险结论、重要冲突、关键证据缺失、超出 AI 能力/权限或用户要求人工 |
| 回流 | 原任务获得对照产物引用、每项状态、充分性、限制和未决项；后续回答必须引用该版本，不复制成无来源文本 |

## 10. 人工交接契约

触发条件沿用 END-04：正式法律/业务判断、高风险结论、无法消解的重要证据冲突、关键证据缺失、超出 AI 能力或权限边界、用户明确要求人工。

交接包至少包含：任务及子目标身份/版本、用户目标、已确认事实及版本、当前九状态、检索实际范围、结果集/候选、证据及来源版本、对照结果、冲突、失败步骤、权限/DataScope 引用、未决项、请求的人工动作、允许回流范围。敏感内容仅在当前权限和获批人工用途内传递。

人工语义分为“交接请求已形成、已发送、权威受理、处理中、已回执、拒绝/撤回/不可用”。只有真实权威回执可确认“已受理”。回执至少携带交接引用、处理身份/角色、时间、范围、结果类别、结论/附件引用、依据和可继续动作。人工结果形成新版本回流原任务，不覆盖机器输出或旧版本。

`OQ-HUMAN-01` 未关闭前，设计仅允许形成交接包和明确显示“人工服务暂不可用/尚未接通”；不得模拟工单号、受理状态或人工结论。

## 11. 逻辑 API 与事件语义

本节定义能力语义，不冻结传输协议、路径、DTO 或 Controller。

### 11.1 统一逻辑变更命令模型

所有改变任务、子任务或其产物的操作使用同一逻辑命令语义；这是业务并发契约，不是 DTO、Controller、锁或消息平台设计。

| 命令要素 | 统一规则 |
|---|---|
| command identity | 在任务边界内稳定标识一次业务意图；用于关联执行、事件和原始结果 |
| request idempotency key | 标识调用方对同一命令的重放；不得用它跳过版本和权限校验 |
| task expected version | 命令声明其读取并准备变更的任务版本；非当前版本时不写入 |
| referenced object version | 明确引用的事实、未决项、结果集、候选选择、证据、对照、交接或历史版本 |
| dependency versions | 命令结果所依赖的目标、范围、特征、来源、规则矩阵和配置版本集合 |
| authorization evidence | 保存受信身份和授权判定的引用作为审计；该快照不冻结权限，执行时仍重验当前权限 |
| payload fingerprint | 判断同一 command identity 的载荷是否相同；不规定具体摘要算法 |
| outcome | 已提交、重复返回原结果、版本过期、并发冲突、载荷冲突、无权限、依赖失效、取消后拒绝或执行失败 |

统一处理顺序为：识别命令与重放 → 校验任务/引用/依赖版本 → 重验当前身份、DataScope 和数据用途 → 校验任务状态与动作合法性 → 执行业务动作 → 以新任务版本原子提交结果和事件。外部只读调用前及受保护内容提交前再次重验相关权限；历史授权证据只用于审计，不能继续授权。

- 相同 command identity、相同幂等键且载荷相同：返回原命令结果，不重复创建事实、结果集、对照、交接或状态变化。
- 相同 command identity 或幂等键但载荷不同：返回载荷冲突，不选择任一载荷覆盖。
- 基于旧任务版本、旧引用版本或失效依赖提交：拒绝写入，返回当前版本和需重新读取/确认的冲突，不自动合并业务事实。
- 并发命令均基于同一版本时：先成功提交者产生新版本；后提交者成为版本冲突，不能最后写覆盖。
- 重试必须保留原命令、范围和权限边界；需要改变范围、来源、权限或业务含义时必须产生新命令并走确认/授权。
- 迟到确认、迟到选择、迟到工具结果和迟到人工回流均保留到达事实；只有依赖版本仍有效且命令可合法提交时才成为当前产物，否则进入冲突/历史记录。
- 技术锁、事务实现、超时、自动重试次数、容量和并发参数仍由 `OQ-NFR-01` 控制，本设计不设数值。

| 逻辑操作 | 核心输入/输出与语义 | 幂等、并发、重试、权限 |
|---|---|---|
| 创建任务 | 输入目标表达和用途；输出任务身份、版本、目标候选、未决项、状态 | 客户端请求键避免重复创建；服务端决定身份/DataScope |
| 读取任务快照 | 读取当前任务快照，或按明确版本读取合法历史；输出目标/事实/子任务状态、焦点、未决项、结果集/选择/证据/对照/人工引用、当前允许动作和限制 | 只读且每次重验权限；历史身份可见不等于内容可访问；当前快照不得由客户端拼装推定 |
| 继续任务 | 输入任务身份、期望版本和新表达；输出新任务版本与动作 | 乐观版本检查；并发冲突不静默覆盖，要求基于最新版本重放 |
| 用户补充 | 绑定未决项并提交补充事实/材料 | 同一补充幂等；材料权限/用途重验；产生事实候选或确认流程 |
| 用户确认 | 确认候选事实、范围、特征或动作 | 必须引用被确认版本；过期确认拒绝并返回当前版本 |
| 用户纠正 | 指明替代对象和新值；输出纠正版本、影响集合和后续动作 | 幂等键 + 期望版本；并发纠正须显式合并/重选，不最后写入覆盖 |
| 查询结果集 | 按任务、结果集身份和版本读取快照 | 每次读取重验当前权限；历史身份可见不代表内容仍可访问 |
| 选择候选 | 输入结果集版本、候选稳定身份或已解析指代 | 版本绑定；重复选择幂等；候选不可用/权限变化时拒绝 |
| 发起/继续检索 | 输入目标/事实/范围版本、策略意图；输出执行引用和结果集版本 | 相同有效输入可复用/关联执行；重试关联原执行；不得借重试扩大范围 |
| 发起技术对照 | 输入原任务、目标/候选/特征/证据版本 | 重复请求关联同一逻辑对照；输入变化产生新版本；权限重验 |
| 人工交接 | 输入交接包版本；输出请求状态或人工不可用 | 不能把发送成功当受理；重试不重复建单；角色/权限每次校验 |
| 人工回流 | 输入权威回执和交接关联；输出任务新版本 | 只接受受信来源；重复回执幂等；冲突回执并列保存并进入复核 |
| 取消 | 输入任务版本和取消意图；输出停止请求及取消状态 | 重复取消幂等；并发执行记录实际停止结果；保留按 OQ-RET-01 决定 |
| 恢复 | 输入可恢复任务/分支和期望版本 | 重验身份、权限、来源、数据用途、版本与保留有效性；不满足则明确拒绝 |

上表中的继续、补充、确认、纠正、选择、检索、对照、人工交接、人工回流、取消和恢复全部服从 11.1，不得各自发明不同的幂等或并发规则。所有变更操作产生可审计事件；事件至少表达业务动作、命令身份、前后任务版本、操作者/责任来源、依赖版本、关联产物、结果和时间。事件不是通用事件平台设计。异步与同步实现、技术重试次数、超时、锁策略和传输形式等待后续实现设计及 `OQ-NFR-01`，不得在本轮设默认值。

### 11.2 来源与权限变化事件

来源和权限变化由权威来源/权限系统的已验证通知，或任务读取/继续时的主动重验发现，转换为任务可消费的逻辑变化事件。事件至少指明权威事件身份、变化类型、受影响来源/版本或权限范围、权威发生时间、发现时间和可核验依据；不定义传输协议或消息基础设施。

| 事件 | 当前使用变化 | 历史与后续动作 |
|---|---|---|
| 来源撤回 | 该来源支持的当前证据立即不可继续使用或展示受控内容 | 保留来源身份、旧版本和历史引用；传播到陈述、充分性和对照并重评 |
| 来源版本失效 | 绑定失效版本的当前证据停止作为现行依据 | 保留旧版审计；有替代版本时先取得、核验并形成新证据版本，不能静默替换 |
| 权限收紧 | 超出当前权限的正文、证据、结果内容立即停止当前展示和继续消费 | 保留受控历史身份和授权审计；相关动作暂停并重新聚合任务状态 |
| DataScope 变化 | 不再属于当前范围的对象和内容变为当前不可用 | 保留历史范围和产物身份；不得以旧 DataScope 继续调用工具 |
| 资料重新可用 | 只恢复“可重新核验”资格，不自动恢复旧证据或旧充分性 | 重新获取/核验来源版本，形成新证据集合并触发重评 |
| 权限恢复 | 只允许在当前权限下重新读取或执行 | 不自动复活旧展示和结论；重验用途、版本及依赖后生成当前产物 |

传播按“变化事件 → 反向依赖定位 → 当前可用性更新 → 陈述/对照/充分性局部失效 → 主子任务重聚合 → 用户可见提示/下一动作”执行：

1. 通过来源、证据、结果集、陈述、对照和评估的依赖关系找出受影响任务与产物；不相关分支保持有效。
2. 当前无权访问或已失效的内容立即从当前可用视图移除或以不可用占位表达；不得泄露受控内容。
3. 历史身份、曾用版本、原判断、事件和影响记录保留，服从保留与访问政策。**历史可审计不等于当前可继续使用。**
4. 依赖失效证据的回答/实质陈述降级为当前不可支持或受限；不原地改写旧回答，生成当前有效性版本。
5. 依赖该证据的对照项和证据充分性评估局部失效并触发重评；不依赖项保持有效。
6. 活动任务立即产生用户可见提示；已结束任务在下次合法读取/继续时展示失效提示。是否存在外部主动通知渠道不在本设计中假设。
7. 若仍有获准替代证据/检索路径，任务可继续；否则依据 4.1 聚合为部分完成、证据不足或需要人工复核。正式判断、高风险冲突或用户要求时才进入人工。
8. 同一权威事件身份和相同变化版本只传播一次；重复到达返回原传播结果。相同身份但内容不同视为冲突；新变化版本只处理新增影响，避免重复失效和重复通知。

任务
 +-- 子任务
 +-- 目标版本
 +-- 已确认事实版本 / 模型候选事实 / 未决项
 +-- 任务分支 / 用户纠正版本 / 状态变更 / 恢复点
 +-- 当前交互焦点版本 / 焦点候选事件 / 自然语言指代绑定版本 / 候选选择版本
 +-- 结果集版本 -> 父结果集版本 / 产生原因 / 检索策略变化
 |    +-- 候选稳定身份 -> 专利文献/来源版本
 |    +-- 检索工具执行
 +-- 回答版本 -> 实质陈述版本 -> 陈述与证据依赖
 +-- 证据集合版本 -> 证据 -> 来源/版本/定位
 +-- 证据充分性评估版本 -> 目标/证据集合/规则矩阵版本

| 逻辑记录 | 保存原因 | 生命周期与依赖 |
|---|---|---|
| 任务/子任务 | 跨轮连续性、复合目标和状态汇总 | 从创建到合法删除/归档；期限待 OQ-RET-01 |
| 目标/事实/未决项版本 | 防止静默覆盖并支持纠正影响分析 | 版本不可覆盖；依赖确认、纠正和适用范围 |
| 当前交互焦点/焦点候选 | 证明某一任务分支在某轮明确聚焦或仅候选哪个结果集 | 明确记录焦点对象、焦点版本、形成事件、形成原因、前一/新焦点版本、用户明确动作、当前任务/分支、指代绑定、结果集 ID/版本及当前可用性；产生/送达/展示/查看只追加候选事件，只有 8.2 允许的用户动作切换明确焦点；失效后保留身份并标不可用 |
| 自然语言指代绑定 | 保存原表达、解析时任务版本、焦点版本、结果集 ID/版本、序位和候选稳定身份 | 绑定不可随重排漂移；纠正产生新绑定版本，旧绑定保留 |
| 候选选择 | 证明谁在何任务/结果集版本选择哪些候选、用于何目标 | 选择版本引用候选稳定身份及文献/来源版本；撤回、无权限或纠正只改变当前有效性 |
| 结果集/候选及谱系 | 稳定指代、重检差异和对照输入 | 结果集版本不可变；保存父结果集版本、产生原因、检索策略变化及差异；序位仅属于该快照，候选身份不等于序位 |
| 工具执行 | 审计连续调用、失败、重试和实际范围 | 关联输入/输出快照、授权/配置引用和派生结果集 |
| 回答/实质陈述 | 把用户看到的回答拆成可追溯陈述并支持局部降级/失效 | 回答和陈述均版本化；每条实质陈述关联目标、事实、分析和证据依赖，不原地改写历史 |
| 证据集合/证据 | 证明回答陈述和分析依据 | 集合及成员版本化；来源失效后保留历史身份，内容访问服从当前授权 |
| 证据充分性评估 | 作为 J08/J14/J15 和完成判断的稳定输入 | 按 6.1 保存独立评估版本；相关依赖变化时失效并重评，不覆盖旧评估 |
| 对照/对照项及输入依赖 | 支持局部重算和回流 | 显式依赖任务、目标、候选、特征、证据集合和规则版本；纠正只产生受影响项的新版本 |
| 依赖关系/纠正影响传播 | 证明直接依赖、传递依赖、失效、保留和重算链 | 记录纠正版本、影响分析所用任务版本、失效集合、仍有效集合和新产物，不物理删除旧关系 |
| 来源/权限变化影响 | 支持撤回、版本失效、权限收紧及恢复的局部传播 | 关联权威变化事件、受影响产物、当前可用性、通知和重评结果；重复事件幂等 |
| 纠正/分支 | 记录局部失效与上下文继承 | 关联父版本、失效集合、继承集合和重算动作 |
| 状态变更 | 证明任务状态不是由 HTTP/工具成功替代 | 记录前后状态、原因、规则和关联证据/执行 |
| 恢复点 | 防止技术失败后全量重跑或恢复到错误版本 | 保存失败前任务/步骤/依赖、已提交产物和未完成动作；恢复后产生新任务版本 |
| 逻辑变更命令/事件 | 支持幂等、并发冲突、迟到事件和审计 | 服从 11.1；保留命令结果及前后版本，不推导技术消息或锁实现 |
| 人工交接/回流 | 防止伪造受理并支持专业结果回流 | 请求与回执分离；期限、附件策略待外部证据 |

数据内容、保留、删除、模型发送、全文/权利要求使用和调试可见性分别受授权控制。这里的关系不是数据库表设计，不推导物理字段或跨域通用 Runtime 模型。

### 12.1 指代恢复与纠正传播可证明性

对于“刚才第二个和第一个比较”，系统在解析时保存任务/分支版本、当前交互焦点版本、结果集 ID/版本、该快照的序位到候选稳定身份映射、两项指代绑定、候选选择/比较对象对，以及随后技术对照引用的目标/候选/特征/证据版本。重启后先读取任务当前快照与这些不可变历史绑定，再重验当前访问权限：因此可以同时回答当时绑定的是谁、当前是否可访问、对照用了哪一版；结果集后来重排不改变旧绑定。若当前不可访问，只展示受控的不可用状态和允许公开的历史身份，不泄露内容。

纠正传播按可审计关系执行：`纠正事实版本 → 直接依赖边 → 传递依赖边 → 失效产物版本 → 仍有效产物版本 → 重算命令 → 新产物版本`。影响分析自身引用纠正前任务版本和依赖图版本；执行后保存实际失效/保留/重算集合。回答陈述、指代绑定、结果集、对照项和充分性评估均可作为传播节点，因此无需清空整个任务，也能重放为什么某项失效而另一项保留。

### 14.3 P1/P2 修正后的 Component/Contract 组合测试矩阵

以下是契约级必须验证的状态与版本关系，不替代 Real Integration 或 Business Acceptance，也不预设专业期望值。

| 场景 | 初始组合/事件 | 必须断言 | ACC 关联 |

| 全部终态 | 全部完成；全部证据不足 | 分别为已完成、证据不足；完成必须带充分性版本和限制 | ACC-01/06 |
| 取消竞态 | 工具完成与取消并发；取消后迟到结果 | 先提交版本决定先后；取消后不推进任务，迟到结果仅作历史 | ACC-05/09 |
| 失败恢复 | 技术失败后恢复 | 从记录的任务版本/活动点继续，只重做未提交或失效动作 | ACC-09 |
| 指代重启 | 保存“刚才第二个和第一个比较”后重启 | 同一任务/结果集版本/候选身份/对照输入可恢复，序位不漂移 | ACC-05 |
| V1 后产生 V2 | V1 是明确焦点，V2 在同一分支产生并送达 | V1 继续是明确焦点；V2 只成为焦点候选，不创建焦点切换版本 | ACC-05/07 |
| V2 展示/查看 | V1 是明确焦点，V2 已展示且用户打开查看 | 展示和查看均不切换焦点；省略结果集限定的“刚才第二个”仍绑定 V1 快照 | ACC-05/07 |
| 明确选择 V2 | V1 是明确焦点，用户说“用第二批结果继续” | 唯一解析 V2 后创建焦点新版本，保存前一焦点 V1 和用户明确动作 | ACC-05/07 |
| 明确引用 V1 | V2 是最近送达候选，用户说“V1 里的第二个” | 创建/确认 V1 焦点版本并绑定 V1 快照第二候选，不受 V2 送达顺序影响 | ACC-05 |
| “刚才第二个” | 已保存 V1 明确焦点，V2 仅产生/展示 | 唯一绑定 V1 快照第二候选；若无明确焦点或存在多个同等合理焦点则不猜测并澄清 | ACC-05 |
| 多分支焦点 | 分支 B1、B2 分别有结果集和历史焦点 | 当前任务/分支先确定；只恢复该分支最后明确焦点，跨分支表达不唯一时澄清 | ACC-03/05 |
| 焦点重启恢复 | 已保存任务、分支、焦点版本、形成事件和指代绑定后重启 | 恢复相同焦点和绑定；不按页面状态、最新生成时间或送达顺序重算 | ACC-05 |
| 结果集重排 | 新版本改变序位后使用旧指代 | 旧绑定仍指向旧快照候选；新焦点须显式形成 | ACC-05/07 |
| V1 焦点失效 | V1 是明确焦点，来源撤回或版本失效，V2 可用 | 保留 V1 历史焦点身份并标当前不可用；不得自动切换 V2，继续须用户明确选择 | ACC-05/09 |
| 焦点权限收紧 | V1 是明确焦点，当前 DataScope 不再允许访问 V1 | 保留审计绑定、停止展示和消费；权限变化不自动选择其他结果集 | ACC-05/09 |
| 歧义焦点 | 用户说“就看刚才这批”，当前分支有多个同等合理的已送达结果集 | 记录歧义候选并等待澄清；不创建明确焦点版本、不调用下游消费该结果集 | ACC-02/03/05 |
| 指代纠正 | 用户纠正错绑结果 | 只失效错误选择及下游；旧绑定、原因和新绑定可审计 | ACC-04 |
| 事实纠正传播 | 纠正关键特征 | 依赖图给出失效、保留、重检、重对照和新产物版本 | ACC-04 |
| 充分性失效 | 候选/特征/证据/规则版本变化 | 原评估失效且不能完成任务；新评估引用新版本 | ACC-04/07 |
| 来源撤回 | 当前答案证据来源被撤回 | 当前内容不可继续使用，历史身份保留，陈述/对照/评估局部失效并提示 | ACC-09 |
| 权限收紧/恢复 | DataScope 缩小后恢复 | 收紧时停止展示/消费；恢复后重新核验，不自动复活旧结论 | ACC-09 |
| 相同命令重放 | 同命令同载荷重复 | 返回原结果，不重复产生产物/事件 | ACC-05 |
| 幂等键冲突 | 同命令身份或幂等键不同载荷 | 明确冲突且不写入 | ACC-03/05 |
| 并发纠正 | 两个命令基于同一事实/任务版本纠正 | 首个提交成功；后者版本冲突并基于最新版本重新选择，不最后写覆盖 | ACC-03/04 |
| 迟到确认/选择 | 基于旧事实/结果集版本的命令迟到 | 拒绝写入并返回当前版本及冲突对象 | ACC-03/05 |
| 人工重复回流 | 相同回执重复或同身份异内容 | 同内容幂等；异内容并列冲突并继续人工复核 | ACC-08 |

Fixture/UI 只验证上述状态、冲突和提示可见；Component/Contract 验证规则与版本关系；Real Integration 才能证明真实来源/权限/模型/人工事件链；Business Acceptance 仍须由 `OQ-ACC-01` 提供的真实或批准脱敏案例和 `OQ-QLT-01` 的通过线证明产品行为。
