# 咨询智能体专利任务 D 门评审报告

任务：`GOV-CONSULTATION-PATENT-JOURNEY-D-GATE-REVIEW-01`  
日期：2026-09-22  
评审对象：`docs/35`～`docs/38`、相关正式咨询需求、`docs/08-总开发实现计划.md`  
评审方式：从真实用户任务反向验证行为、状态、证据、版本、记录和下一动作，不以章节存在、V0 技术验证或低层测试代替可实现性判断。

## 1. D 门结论

### A. 设计结构是否通过

**D 门不通过。**

`docs/38` 已覆盖全部要求的设计域，且七个当前产品契约的 65 条 MUST、50 条 MUST_NOT 均能找到文字对应；但反向执行时仍有 5 项 P1 设计缺口。主要问题不是缺少专业数值，而是同一输入可能被实现为不同的主任务状态、指代/选择无法在恢复后可靠重放、证据充分性无法形成稳定版本化判定、来源或权限失效缺少影响传播事件，以及部分变更操作的并发语义不统一。这些问题会迫使开发人员临场发明业务规则，属于设计结构缺陷，不得以“有条件通过”处理。

### B. 实现是否可以启动

**不可以启动。** 一方面 A 层尚未通过；另一方面 `OQ-DATA-01/02`、`OQ-AUTH-01`、`OQ-RET-01`、`OQ-EVD-01`、`OQ-QLT-01`、`OQ-HUMAN-01`、`OQ-MODEL-01`、`OQ-ACC-01`、`OQ-NFR-01` 均保持 OPEN，并继续按影响范围阻塞真实数据、权限、人工、专业效果、生产模型、验收与非功能分支。

本结论不恢复任何 stale 契约，不产生 READY，不否定 `docs/38` 已完成的安全设计部分。

### 5.2 发现

- 九种状态均可到达，没有纯粹不可达状态。
- `用户取消` 对新工具有明确禁止，正在运行的工具仅允许发出停止请求并记录实际结果，未发现取消后继续启动工具的路径。
- `等待确认` 面向用户对事实/范围/动作的确认，`需要人工复核` 面向授权专业人员或正式决定，两者概念可区分。
- **P1 缺口**：主任务聚合只规定“至少一个子目标完成且其余未满足则部分完成”，未定义“已完成 + 等待补充/等待确认/人工/技术失败/用户取消”等组合的展示主状态、行动优先级和原因码；无结果、无权限、来源失效也没有明确映射为“九状态 + 独立业务/执行原因”。
- **P1 缺口**：从技术失败恢复只写“恢复”，没有要求恢复到失败前活动状态/步骤及其版本；不同实现可能直接回到进行中、等待确认或重新执行。

因此状态集合本身正确，但状态转换和主子任务汇总尚不足以唯一实现。

## 9. 迭代检索检查

`docs/38` 支持以下完整循环：首次检索 → 结果不足分类 → 判断是否可能取得新信息 → 同范围改写/同义扩展/方法切换/重排/深化 → 再检索 → 新结果集版本 → 重新评估。

| 动作 | 自动边界 | 确认边界 | 结论 |
|---|---|---|---|
| 查询改写/同义扩展 | 同一确认范围、已获准能力内自动 | 改变用户语义时确认 | 通过 |
| 方法切换/重排 | 真实已具备且获准的方法内自动 | 改数据源/用途时确认 | 通过 |
| 全文/权利要求深化 | 当前目标必要且授权范围内自动 | 未授权用途不能执行，用户确认不能代替权威授权 | 通过，受 OQ-DATA-02 阻塞 |
| 再检索 | 仍可能有新信息且不越界时自动 | 扩时间、地域、数据源、权限或明确业务范围时确认 | 通过 |
| 停止 | 目标/证据满足、无合理新信息、需外部确认/人工、技术阻断或用户停止 | 不以固定轮数停止 | 通过，专业判据受 OQ-RET/QLT 阻塞 |

未发现隐含固定轮数、固定分数或固定候选数量。每次执行有输入快照和新结果集版本；但结果集父版本、策略变化理由和重排/重检谱系没有在逻辑记录表中明确列为必须保存，归入 DG-P1-02。

## 11. CON-06 对照回流检查

- 输入稳定绑定原任务、结果集/候选、目标、用途、确认特征及证据版本。
- 输出包含对照版本、逐项相同/差异/无法判断、理由、来源定位、充分性、限制、失败和人工建议。
- 回流对象是原 CON-12 任务，不是独立工作台终点。
- 特征/候选/证据纠正只重算受影响项，旧对照版本保留。
- 对照执行状态与产品任务状态分离，局部失败不清除已完成子目标。
- 重要冲突、关键证据缺失、高风险或正式决定进入人工。

结论：CON-06 的主路径和禁止项通过；稳定对照版本已经定义。阻断点来自共用的充分性判定产物及回答/选择记录不足，不是 CON-06 单独架构问题。

## 13. API / 事件语义检查

| 操作 | 幂等 | 版本/并发 | 重试/旧请求 | 权限/失效 | 结论 |
|---|---|---|---|---|---|
| 创建任务 | 有请求键 | 创建竞态可由请求键约束 | 重放不重复创建 | 服务端定身份/DataScope | 通过 |
| 继续任务 | 隐含变更事件 | 有期望版本 | 冲突要求基于最新版重放 | 应重验，但表中未逐项写明 | 基本通过 |
| 补充 | 明确幂等 | 未明确统一期望任务/未决项版本 | 重复补充可识别 | 材料用途重验 | P1 |
| 确认 | 引用确认版本 | 过期拒绝 | 返回当前版本 | 权限未统一声明 | 基本通过 |
| 纠正 | 幂等键 | 期望版本、禁止最后写覆盖 | 冲突合并/重选 | 需重验 | 通过 |
| 查询结果集 | 只读 | 指定结果集版本 | 旧版可读性由当前权限决定 | 每次重验，失效不继续展示 | 通过 |
| 选择候选 | 重复选择幂等 | 绑定结果集版本，未统一任务期望版本 | 候选失效拒绝 | 重验候选可用性 | P1 |
| 检索 | 可复用/关联执行 | 输入版本齐全 | 重试关联原执行 | 不得借重试扩范围 | 通过 |
| 技术对照 | 重复请求关联 | 输入变化成新版 | 失败恢复未统一命令结果 | 权限重验 | 基本通过 |
| 人工交接 | 防重复建单 | 交接包版本 | 发送不等于受理 | 角色/权限每次校验 | 通过，外部接口 OPEN |
| 人工回流 | 重复回执幂等 | 输出任务新版 | 冲突回执并列 | 受信来源校验 | 通过，外部接口 OPEN |
| 取消 | 重复取消幂等 | 有任务版本 | 记录实际停止结果 | 恢复时再重验 | 通过 |
| 恢复 | 需补统一命令幂等 | 有期望版本 | 旧版/过期拒绝语义存在 | 全量重验 | 基本通过 |

全局虽然要求“所有变更操作产生事件”，但没有对所有变更统一规定命令身份、期望任务版本、依赖版本、重复命令同载荷/异载荷、冲突结果和权限重验时点。`OQ-NFR-01` 可阻塞锁、超时和重试次数，却不应阻塞这些业务并发语义，故列为 P1。

此外，来源撤回、来源版本失效、权限收紧属于会主动改变已存在产物可用性的事件，当前操作清单没有其进入任务并触发影响分析的逻辑入口，列为 DG-P1-04。
