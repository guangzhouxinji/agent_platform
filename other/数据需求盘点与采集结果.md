## 二、数据分层模型

项目的数据需求分四层，来源与责任人完全不同：

| 层 | 内容 | 来源 | 我能否采集 |
|---|---|---|---|
| L1 来源层 | 官方网页/PDF 原文快照、原始检索响应 | CNIPA、SureChEMBL、EPO OPS、最高法 | **部分可以**（仅 CNIPA 可达） |
| L2 资料库层 | 专利库 / 商标库 / 案例库（结构化题录） | 由 L1 构建 | 可以（构建脚本） |
| L3 领域运行层 | 执法线索/材料/规则、裁决法规/争点、咨询任务 | 由 L2 映射 + 合成输入 | 可以（构建脚本） |
| L4 甲方输入层 | 真实检索 API、真实案卷、身份权限、环境 DM8 | **甲方必须提供** | **不可以** |

### 采集器的安全设计（值得肯定）

所有采集器统一强制：

- **同源白名单**：只接受 `www.cnipa.gov.cn`，跨域跳转直接抛错
- **路径白名单**：只允许 `/art/`、`/module/download/downfile.jsp`
- **类型与签名**：PDF 必须 `%PDF-` 签名，HTML 必须命中 `marker`
- **大小上限**：12MB / 25MB
- **漂移防护**：同一 catalogVersion 下 digest 变化即 `SOURCE_CONTENT_DRIFT` 报错，不静默覆盖

这符合 `docs/60` "不得绕过站点访问控制采集非公开数据"的约束。

## 六、我无法采集、必须由甲方提供的五类输入（核心缺口）

依据 `docs/42`，这五类必须由五类负责人提供，**不是技术问题而是授权与责任问题**：

| 包 | 材料 | 负责人 | 阻塞的任务 |
|---|---|---|---|
| **A. 中心 API / 授权索引** | 专利检索/详情/来源读取 OpenAPI；商标检索；案件目录与案卷材料元数据 | 中心系统、数据平台负责人 | `CON-04-PILOT-DESIGN`、真实检索适配 |
| **B. 数据与模型授权** | 数据处理矩阵（本地保存/索引/模型出域/保留期）、模型边界（DeepSeek 等出域许可） | 数据所有者、安全、法务 | 真实数据使用；模型出域审批 |
| **C. 身份 / 权限** | 组织树、试点用户、角色-动作-数据范围映射、SSO 元数据 | IAM/SSO、组织管理 | 真实权限校验与越权阻断验收 |
| **D. 样例 / 规则 / 验收** | 业务样例清单（专利20/商标20/案例10/执法10/裁决10）、业务规则来源、验收矩阵与责任人 | 法务、代理师、审查/执法业务代表 | 专业验收；D 门收口 |
| **E. 环境 / DM8** | 环境清单、DM8 参数（版本/字符集/时区/连接数）、网络矩阵、备份恢复与演练 | 运维、DBA、安全 | 生产部署；备份恢复演练 |
