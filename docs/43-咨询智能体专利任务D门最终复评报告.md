### 3.1 焦点转换守卫

| 事件 | `docs/38` 的唯一结果 | 复评 |
|---|---|---|
| 结果集产生 | 加入当前任务/分支的焦点候选；原明确焦点不变 | 通过 |
| 结果集送达 | 记录送达和顺序；原明确焦点不变 | 通过 |
| 结果集展示 | 记录展示；页面位置、滚动和排序不改变焦点 | 通过 |
| 用户查看 | 记录查看；查看不等于选择 | 通过 |
| 用户明确选择 | 唯一解析后创建绑定所选结果集版本的焦点新版本 | 通过 |
| 用户明确限定结果集/版本 | 按任务/分支、结果集身份/版本、批次限定、快照序位解析并切换焦点 | 通过 |

| 系统重启/任务恢复 | 从逻辑记录恢复当前任务、分支和该分支最后明确焦点，再重验可用性 | 通过 |

转换守卫现在只有一条：**系统结果事件不切换焦点；只有可审计、可唯一解析的用户明确选择或显式结果集限定才切换焦点。** 省略结果集限定的表达使用已持久化的当前明确焦点；没有焦点或不能唯一解析时澄清。

### 3.2 逻辑记录承载

`docs/38` 12 节已要求保存焦点对象、焦点版本、形成事件、形成原因、前一/新焦点版本、用户明确动作、当前任务、当前分支、指代绑定、结果集 ID/版本和当前可用性；产生、送达、展示、查看分别追加候选事件。该记录足以在跨请求和重启后重放焦点决定。

序位只属于特定结果集快照，候选以稳定身份保存。焦点和绑定均不依赖 UI 内存、页面顺序、全局最近结果、模型置信度或候选当前位置。

复评结论：原先允许 V1/V2 两种实现的缺口已经消除，`DG-RR-P1-01` 关闭。

## 6. 产品状态分离检查

焦点的“当前明确焦点 / 焦点候选 / 无焦点 / 歧义焦点”是交互语义和逻辑记录状态，不是产品任务状态。焦点“可用/不可用”也是对象可用性，不是第十种产品状态。

产品任务仍只能处于：

`进行中 / 等待用户补充 / 等待确认 / 部分完成 / 已完成 / 证据不足 / 需要人工复核 / 技术失败 / 用户取消`

焦点事件不能直接决定任务完成；结果集产生、展示、候选存在和引用存在均不能替代证据充分性或完成条件。
