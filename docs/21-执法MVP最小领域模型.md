# 执法 MVP 最小领域模型

版本：V0.1  
日期：2026-09-15  
关联任务：`ARC-05-ENF`  
设计输入：`docs/20-执法MVP-V0产品样例基线.md`、`docs/10-领域边界与上下文映射.md`、`ENF-04/05/07/11` 需求契约。  
设计性质：由合成 V0 样例倒推的领域设计，不是原始业务事实，不冻结 HTTP API、数据库表、技术状态机、Runtime、具体角色、专业规则或正式执法流程。

## 1. 设计边界

本模型只承载“已有线索及固定版本 → 解析与人工核实 → 证据关系整理 → 辅助分析版本 → 人工审核记录”的本地工作语义。中心系统继续拥有权威线索、案件、权利、证据原件、法规/规则、权限和正式业务状态。

模型遵循以下边界：

1. AI/Agent 是候选内容的产生或编排主体，不拥有领域数据，也不能写权限、人工决定或正式状态。
2. 当前授权是每次操作时的外部判定，不固化为未来读取的历史权限凭证；历史记录只保留最小审计引用。
3. 机器原始结果、人工修订、审核记录和权威来源分别版本化，任何重跑不得覆盖历史。
4. 证据的完整性信息不等于真实性、合法性、证明力或采信；证据关系只是待人工核实的执法域候选关系。
5. 辅助分析只允许“支持疑似成立、存在排除依据、材料不足无法判断”等候选分类，且不产生正式立案、违法/侵权认定、处罚或中心状态。

## 2. 最小对象总览

```text
中心线索/案件/权利/规则（权威引用，不归本域所有）
                    |
                    v
            EnforcementWorkItem
                    |
       +------------+-------------+
       |            |             |
       v            v             v
ClueAnalysisVersion EvidenceRef  EvidenceRelationSetVersion
       |            |             |
       +------------+-------------+
                    v
          AuxiliaryAnalysisVersion
                    |
                    v
              HumanReviewRecord
```

`SourceLocator` 和 `VersionReference` 是上述对象内部使用的值，不作为独立业务聚合。Task、Run、HTTP 请求和数据库事务是后续技术设计关注点，不在本模型中冒充业务对象。

## 3. 六个最小领域对象

### 3.1 EnforcementWorkItem（执法工作项）

职责：为一条权威线索的固定版本建立本地 V0 工作边界，关联本次解析、证据关系、辅助分析和审核历史；不复制或改写中心线索、案件或正式状态。

| 最小字段/关系 | 性质 | 必要性与来源 |
|---|---|---|
| `workItemId` | 技术标识 | 本地工作结果需要稳定关联；不得冒充中心线索/案件编号。 |
| `clueRef` | 权威来源引用 | 来源系统、线索标识、固定版本/摘要与定位；ENF-04-MUST-003、ENF-07-MUST-003。 |
| `caseOrRightRefs` | 可选权威引用集合 | 仅保存实际获得且获授权的案件/权利引用；缺失保持缺口；ENF-11-MUST-003/009。 |
| `organizationRef` | 可信上下文引用 | 支持资源隔离；具体组织模型和 DataScope 留给 P0-04/ARC-06。 |
| `createdAt` | 技术审计值 | 记录本地工作项创建时间，不等于线索发生或收集时间。 |
| `analysisVersions`、`relationSetVersions`、`reviewRecords` | 聚合关系 | 只关联本工作项的历史版本，不保存“当前正式案件状态”。 |

不包含：中心线索正文所有权、正式案件编号生成、立案状态、处罚状态、具体角色、权限规则、模型参数、Workflow 步骤。

### 3.2 ClueAnalysisVersion（线索解析版本）

职责：保存针对一个固定线索版本的机器原始解析、字段来源、缺失/冲突，以及人工核实形成的新版本关系。

| 最小字段/关系 | 性质 | 必要性与来源 |
|---|---|---|
| `analysisId`、`version` | 本地版本标识 | 重跑和修订形成新版本，不能覆盖；ENF-04-MUST-013。 |
| `inputClueRef` | 权威来源引用 | 固定实际解析的线索版本；ENF-04-MUST-003。 |
| `subjectCandidates[]` | 候选输出 | 每项含原文角色、名称、可选有来源代码和定位；ENF-04-MUST-005/006/007。 |
| `suspectedFacts[]` | 候选输出 | 只记录疑似事实及原文定位，不升级为已确认事实；ENF-04-MUST-001/NOT-001。 |
| `timeCandidates[]`、`placeCandidates[]` | 候选输出 | 同时保留原始表达、可选标准化值和定位；标准化失败不覆盖原值；ENF-04-MUST-008。 |
| `evidenceMentions[]` | 候选引用 | 只指向真实材料编号或明确待接入引用；ENF-04-MUST-009。 |
| `missingItems[]`、`conflicts[]` | 受约束输出 | 无法确定留空；冲突值分别保留来源，不由模型选择。 |
| `machineOutputRef` | 技术追溯 | 标识产生机器结果的模型/配置或确定性测试替身版本，不保存模型隐含推理。 |
| `previousVersionRef`、`revisionKind` | 版本关系 | 区分机器重跑和人工修订；旧机器结果与人工确认记录不可覆盖。 |
| `actorRef`、`createdAt`、`reason` | 审计信息 | 人工修订记录可信身份、时间、理由；机器版本记录技术执行主体。 |

不包含：违法主体、违法成立概率、自动信用代码、正式优先级决定、无来源补全值。

### 3.3 EvidenceReference（证据引用/版本）

职责：在执法工作项内引用中心证据或授权上传材料的确切版本，保存受控访问、完整性和原件/派生关系；不拥有法律采信结论。

| 最小字段/关系 | 性质 | 必要性与来源 |
|---|---|---|
| `evidenceRefId` | 本地引用标识 | 支持稳定关系和历史引用，不替代权威证据编号。 |
| `sourceRef`、`sourceVersion` | 权威来源引用 | 来源系统/上传渠道、源对象、固定版本和定位；不得由模型生成；ENF-05-MUST-004/005/006。 |
| `relatedClueOrCaseRefs` | 权威关联引用 | 至少关联线索或案件之一；ENF-05-MUST-007。 |
| `controlledResourceRef` | 受控资源引用 | 不暴露真实磁盘路径，访问时重新鉴权；ENF-05-MUST-009/016。 |
| `collectionInfo` | 可缺失来源事实 | 收集人、收集时间及缺失原因；不得以上传人替代；ENF-05-MUST-008。 |
| `integrityInfo` | 技术完整性 | 可含文件版本、摘要算法和值；只证明字节校验，不证明真实合法；ENF-05-MUST-014/NOT-008。 |
| `originalRef`、`derivedKind` | 版本关系 | OCR、转码、摘要等派生版本关联原件；不覆盖原件；ENF-05-MUST-013。 |
| `availability`、`unavailableReason` | 当前结果 | 区分可用、无权限、来源失效、不可解析和上游故障；不等于证据状态或采信状态。 |
| `recordedAt` | 技术审计值 | 记录本次引用形成时间，不替代收集时间。 |

V0 不冻结“待核验、已核验、已排除、已归档”的完整状态转换，因为真实角色和动作权限尚待 P0-04/09；样例只要求能够表达来源失效、人工候选排除和旧结果需复核，后续行为设计必须继续区分资源可用性、证据业务状态和人工采信决定。

### 3.4 EvidenceRelationSetVersion（事项—证据关系集版本）

职责：针对固定线索/案件快照、证据版本集合和规则版本，保存待证明事项、候选证据关系、时间线、缺口、冲突和未处理材料的一个不可变结果版本。

| 最小字段/关系 | 性质 | 必要性与来源 |
|---|---|---|
| `relationSetId`、`version` | 本地版本标识 | 证据或规则变化后生成新版本；ENF-07-MUST-011/012。 |
| `inputManifest` | 固定输入清单 | 引用线索/案件快照、每个证据版本和规则版本；ENF-07-MUST-003。 |
| `issuesToProve[]` | 执法域候选事项 | 只来自已发布规则或样例明确检查项；V0 不预置法律要件。 |
| `relations[]` | 候选关系 | 每项记录事项、证据固定版本、支持/反对/冲突/缺失关系、理由和具体定位；ENF-07-MUST-005/007/008。 |
| `timelineEntries[]` | 候选整理结果 | 区分事实发生、证据收集和上传时间，保留原始表达和标准化值；ENF-07-MUST-006。 |
| `gaps[]`、`conflicts[]`、`unprocessedItems[]` | 受约束输出 | 资料不足、冲突、不可解析和来源失败分别表达；ENF-07-MUST-008/009/017。 |
| `completeness` | 结果分类 | 只表达存在缺口、存在冲突、待人工核验等实际情况，不允许“完整有效证据链”自动结论。 |
| `previousVersionRef`、`needsReviewReasons[]` | 版本关系 | 输入变化不改写旧版本，新版本不能继续使用已排除/失效证据作为有效支持。 |
| `machineOutputRef`、`createdAt` | 技术追溯 | 标识产生方式和时间，不赋予机器采信权。 |

关系集属于执法域，不能用跨域通用 `Evidence` 对象替代其“待证明事项—证据关系”的具体语义。

### 3.5 AuxiliaryAnalysisVersion（辅助分析版本）

职责：在固定输入清单上形成逐检查项辅助分析，分开记录事实、陈述、推断、来源、排除依据、缺口和不确定性，作为人工审核的确切对象。

| 最小字段/关系 | 性质 | 必要性与来源 |
|---|---|---|
| `analysisResultId`、`version` | 本地版本标识 | 新材料、规则、权利状态或重跑生成新版本；ENF-11-MUST-012。 |
| `inputManifest` | 固定输入清单 | 线索解析、证据、关系集、规则、权利和来源的确切版本；ENF-11-MUST-001/003。 |
| `itemAnalyses[]` | 辅助分析 | 每项分开记录已确认事实、当事人陈述、机器推断、支持/排除关系、依据、缺口和不确定性；ENF-11-MUST-005/006。 |
| `auxiliaryOutcome` | 受限结果分类 | 仅为支持疑似成立、存在排除依据、材料不足无法判断；必须逐项解释且标记非正式决定；ENF-11-MUST-007/NOT-001。 |
| `severityAssessment` | 可缺失候选 | 只有已确认适用规则和充分数据时才可存在，否则记录无法评估及缺口；V0 默认不输出。 |
| `unprocessedItems[]`、`failureKinds[]` | 异常输出 | 资料不足、规则不适用、无权限、来源失败和部分失败分开；ENF-11-MUST-010。 |
| `previousVersionRef`、`needsReviewReasons[]` | 版本关系 | 旧报告、人工修订、审核和历史引用保持不变。 |
| `machineOutputRef`、`createdAt` | 技术追溯 | 标识合成测试替身/后续批准模型及时间，不保存隐含推理。 |

不包含：正式违法/侵权结论、立案决定、程序决定、处罚结论、正式案件状态或自动生成的权利事实。

### 3.6 HumanReviewRecord（人工审核记录）

职责：记录可信身份针对确切解析、关系集或辅助分析版本作出的本地修订、确认或退回动作及理由；不代表证据已依法采信或正式执法决定已经产生。

| 最小字段/关系 | 性质 | 必要性与来源 |
|---|---|---|
| `reviewRecordId` | 本地审计标识 | 审核动作不可覆盖并可追溯。 |
| `subjectType`、`subjectVersionRef` | 被审核对象引用 | 必须指向确切解析/关系集/辅助分析版本，不能只指向可变化的“最新结果”。 |
| `action` | 业务动作 | V0 只使用修订、提交审核、确认、退回；具体权限和完整状态机待 P0-04/09。 |
| `beforeRef`、`afterRef` | 版本关系 | 修订形成新版本并保留机器原始结果，不在记录内覆盖正文。 |
| `reason` | 业务说明 | 退回必须有理由；确认也保留必要说明。 |
| `actorRef`、`actedAt` | 可信审计值 | 来自服务端认证上下文；测试身份必须标记为测试，不冒充专业人员。 |
| `scopeLabel` | 限制标识 | V0 标明“合成流程验证/非专业认定”；后续真实身份语义需证据确认。 |

不包含：授权授予、证据法律采信结果、正式立案/认定/处罚/签发/送达/执行、中心状态回执。

## 4. 值对象和外部判定边界

### 4.1 SourceLocator

最小表示来源系统、源对象标识、源版本；无版本时表示获取时间和内容摘要；可选页码、字段路径、文本片段定位或音视频时间点。它只提供可核验定位，不统一咨询引用、执法证据或裁决依据的业务效力。

### 4.2 VersionReference

最小表示本地对象标识与确切版本。任何审核、引用和下游分析必须指向确切版本，不以“当前最新”替代历史输入。

### 4.3 AuthorizationDecision（外部判定结果，不是历史授权凭证）

应用层每次操作向授权端口取得当前允许/拒绝结果、最小原因码和追踪标识。领域对象不得仅凭历史允许记录继续泄露正文；拒绝时也不得保存或返回足以泄露受限资源的内容。具体角色、策略、DataScope 和缓存规则留给 P0-04、ARC-06、ENG-05。

## 5. 聚合与一致性边界候选

- `EnforcementWorkItem` 是 V0 本地工作边界候选，只维护版本引用关系，不把六个对象强制放进同一数据库事务。
- `ClueAnalysisVersion`、`EvidenceRelationSetVersion` 和 `AuxiliaryAnalysisVersion` 均为不可变结果版本；人工修订创建新版本。
- `EvidenceReference` 的来源版本和受控资源引用不可被关系集或分析结果改写；来源失效通过新可用性事实和“需复核”关系传播。
- `HumanReviewRecord` 追加写入并绑定确切对象版本；重跑、模型更新或新材料不得改写既有记录。
- 跨对象一致性由后续 Use Case 设计负责，例如“分析版本只能引用同一工作项内、当前可访问的固定输入版本”；本任务不冻结事务、锁、事件或状态机。

## 6. 三类样例覆盖验证

| 样例 | 必需对象 | 覆盖结论 |
|---|---|---|
| 正常 | 工作项、解析版本、两个证据引用、关系集版本、辅助分析版本、审核记录 | 能保留多主体角色、每项来源、固定输入、候选关系、辅助性质及确切审核对象；不需要正式案件状态。 |
| 资料不足/冲突 | 工作项、解析版本、三个证据引用、含冲突/未处理项的关系集、部分辅助分析、退回记录 | 不同时间和商品标识分别保留；缺失收集人、历史权利和不可解析材料均有归属；无需补造字段。 |
| 无权限/来源失效 | 工作项引用、证据引用可用性、旧关系集/分析版本的需复核原因 | 当前授权仍由外部端口判定；失效来源不进入新结果，旧版本不删除且不泄露正文。 |

没有样例要求建立完整案件、规则、证据文件、通知、处罚、文书、统一 Agent Runtime 或跨域公共证据模型。

## 7. 事实与结果所有权

| 信息 | 所有者/决定者 | 本模型允许的动作 |
|---|---|---|
| 原始线索、案件、权利、证据原件、法规/规则和正式状态 | 中心权威系统或授权来源 | 保存获授权引用和确切版本；不改写源记录。 |
| 当前访问权限 | 权威授权机制 | 每次操作消费判定；不由领域对象或模型授予。 |
| 线索解析机器结果 | 执法域本地工作结果；AI/测试替身是产生者 | 保存不可变机器版本、来源和不确定性。 |
| 人工修订与核实记录 | 可信人工身份产生，执法域保存 | 追加新版本和审计；V0 测试身份不得冒充专业确认。 |
| 事项—证据候选关系 | 执法域本地工作结果 | 保存关系、理由、来源、冲突和缺口；不自动采信。 |
| 辅助分析版本 | 执法域本地工作结果 | 保存受限结果分类、逐项来源和非正式标识。 |
| 证据采信、正式认定、程序和处罚决定 | 授权人工/权威系统 | 本模型不实现、不保存为本地产生的正式结果。 |

## 8. 明确排除的字段和对象

- 不加入 `isIllegal`、`isInfringement`、`officialDecision`、`penaltyAmount`、`officialCaseStatus` 等会伪装正式决定的字段。
- 不加入未经确认的法律要件、严重程度等级、优先级因素、程序选择、阈值、期限或金额公式。
- 不建立完整 `Case`、`AuthoritativeEvidence`、`Permission`、`Role`、`DataScope`、`RuleDefinition` 或中心数据副本对象。
- 不建立统一跨域 `Claim`、`Evidence`、`Review`、`Citation`、`Task`、`RunManifest` 或完整 Runtime 模型。
- 不冻结任务状态、审核状态、证据状态和正式业务状态为一个 `status`；它们必须继续分离。
- 不保存模型隐含推理、未采用材料全文、未经授权原文、长期模型上下文或真实磁盘路径。

## 9. 需求一致性复核

| 检查项 | 结果 |
|---|---|
| 涉及需求 | ENF-04、ENF-05、ENF-07、ENF-11 |
| 样例覆盖 | 六个对象及三个值/判定边界覆盖 `docs/20` 三类样例 |
| 无来源业务字段 | 0；本地标识、时间、版本关系和机器追踪均明确为技术字段 |
| MUST_NOT 违规 | 0；模型中不存在自动证据采信、正式认定、处罚或中心状态写入 |
| 待专业决定 | 法律要件、证据采信、优先级/严重程度/程序规则、真实人工职责和审核后衔接继续由 P0-08/09 阻塞 |
