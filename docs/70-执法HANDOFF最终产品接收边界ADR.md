# ADR-ENF-HANDOFF-01 最终产品内部接收与回流边界

- 日期：2026-09-28
- 状态：供`ARC-ENF-HANDOFF-03` D复核的项目技术决定
- 责任：项目技术设计（Codex）；现实岗位、正式流程及业务B由执法/身份责任方另行确认
- 依据：执法需求总览第5～6节、`docs/01`第7节、`docs/02`第27～28节、`docs/57`第4节、已完成的MATERIAL/EVIDENCE唯一产品合同

## 决定

唯一V2 HANDOFF产品以受控内部待办工作台作为可执行的接收通道。请求持久化只表示待领取；经产品Issuer认证、现时精确Grant和职责校验的具名人员成功领取并提交事务事件，才表示该包的该版本已被接收。页面展示、通知投递、模型输出和未经核证的外部字符串均不产生受理事实。内部领取是最终产品的一种输入/适配方式，不创建开发版Service/API/状态机；将来外部系统接入须适配同一可信接收事件合同，不能以通知回执替代领取。

包、请求、领取、意见和回流各有不可变版本及来源；新包不继承旧包受理或意见。意见只构成内部辅助工作记录，不自动改变线索处置、案件、处罚、签发或其他官方状态。Agent只能提出请求，不能领取、复核或作决定。现时授权/来源失败关闭，旧幂等键也不能恢复成功回执。真实岗位任命、外部接收协议、正式处置和业务签收属于现实业务启用/B，不是此产品合同D的前置事实。

HANDOFF自身初建包产生稳定`workId`，不假定Evidence已提供工作对象；上游EvidenceSet从确切组织版成员计算摘要，不凭空建立中心Set ID。机器候选、人工修订及审核版本按原义显示，不能由审核状态自动产生“事实已确认”的新结论。

## 取舍与边界

此技术选择落实`docs/02`第28节的内部领取决定以及需求总览“不假设外部推送通道”，不宣称原始需求指定了上述路由、表名或状态枚举。将来若真实组织要求另一接收流程，先作合同差异/Change Request；仅替换连接和输入不改变已冻结语义。当前切片只消费已核Evidence确切修订及MATERIAL引用，不扩展ENF-08～17的程序、行为、处罚或文书能力，不读写咨询和已冻结MATERIAL/EVIDENCE表。
