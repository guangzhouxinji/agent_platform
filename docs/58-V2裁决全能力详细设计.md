# V2 裁决全能力详细设计

版本D1，2026-09-24；交付任务ARC-V2-ALL-DESIGN-01，覆盖ADJ-01～12及既有咨询法规管理/条文解析/要点三份支撑来源。依据原文、当前契约和docs/02第23节，共用技术协议见[docs/55](55-V2业务数据服务与运行恢复详细设计.md)。正式流程、人员和法律规则不能由技术状态枚举代定；当前D准入只见docs/08。

## 1. 闭环与所有权

裁决人员建立有明确来源的案件工作任务→核双方材料和争点→确定专利/权项版本及相关时点→匹配并人工选择法律依据→分别核官方权利状态、技术风险与逐要素证据→形成可修订草稿→对指定版本逐项人工复核→真实签发/正式办理衔接。系统不能以完整草稿或审核通过宣称裁决已作出。

ARC-ADJ-MATERIAL-01覆盖案件、双方材料、法规/权利原文与版本；ARC-ADJ-ANALYSIS-02覆盖争点、时点、解析及辅助分析；ARC-ADJ-REPORT-03覆盖版本报告、引用原子绑定和人工回流。三段书面设计按逻辑依赖衔接，实施仍分别D、逐域真实验证。

`CaseWork`保存权威案件Ref或明确本地来源、资料版本和受控主体；`IssueRevision`保存争点及提出方/确认性质；`MaterialSet`固定双方各材料版本；`PatentInterpretation`保存所选权项/人修版本；`LegalSelection`是具名选择；`ReportRevision`拥有章节和引用绑定；`ReviewAttempt`及`OfficialEvent`相互独立。共享法规原文/文件不能共享采信、管辖、程序或裁决事实。

## 2. 公共操作与事务

候选API前缀`/v2/adjudication`；法规资料端点由公共资源模块唯一持有，裁决通过受控端口消费并保存本域适用性/采用记录。列表、完整详情、历史、分页排序按原文；查询不因只有当前页而冒全量，人员和机构以可信身份解释。全部修改带expectedVersion/幂等键/输入版本，长模型和渲染在事务外。

案件状态、流程事件、分析执行、报告完整性、审核、签发、归档、中心同步分别存值和来源；不把原文“建议状态”当已批准法定转换表。未取得中心流程策略只能维护获准工作数据/候选，不执行受理办结分支。工作任务可显示材料齐备性、当前活动、待人处理、辅助产物及失败原因，不宣称官方进度百分数。

事务重点：人工事实新修订+下游失效；报告版本+章节+引用绑定+输入manifest；复核决定+确切被审版本状态+审计；正式事件与权威回执映射。跨系统正式动作使用请求/outbox、回执/inbox与对账，不跨域分布式事务。故障/重启/取消epoch沿docs/55，不能因外部请求超时自动再签发。

## 3. 逐能力详细设计

<a id="ADJ-01"></a>
### ADJ-01 法规管理与原文版本

`LawVersion`保留稳定法规/源id、版本、正式名称、发布机关、发布/实施日期、类别、多业务领域、地域、全文、效力区间/来源状态、获取/编辑时间；`ArticleVersion`含稳定条文id、条号/款项层级和位置；`LawRevisionEvent`含修订日期、类型、说明、依据、旧全文Ref、新旧版本关系及具名录入信息。

`/v2/resources/laws`提供查询、历史、指定时点地域候选、完整详情和修订记录；源API记录只读；`/local-law-revisions`记录本地校核差异与理由，不冒中心数据。查询名称不能当唯一关联，效力无法核实时保持无法核实，日期不能单独推适用性。

`POST /law-imports/preview`输入受控文件/模板版本、重复策略、源关联，逐行给新增修订/跳过/来源冲突/关联失败及原因；`/commit`绑定预览摘要、目标expectedVersions和幂等键。按稳定来源对象/版本匹配，同版本同内容摘要幂等跳过；同来源版本不同原文为`SOURCE_VERSION_CONFLICT`，该条停止并待人核对；正式来源新版本生成法规及条文不可变版本。不能只按名称或条号认定相同。开发期未审核未引用的本地草稿“更新/覆盖”仅指新增待审核修订并在版本校验后切换当前待处理指针，保留旧机器输出、人工编辑和批次；错误草稿可具名说明原因后作废留痕，不默认物理删除。生产保留/删除及真实权限仍见docs/02第25、31节。

导入原子组为一个法规新版本及其条文/关联修订；失败组回滚，其他组可成功，报逐行及组结果。修订前全文必须与指定旧版本匹配，不能猜归属；提交时预览目标已变更返回冲突，重新预览，不带旧决定覆盖新数据。被引修订错误只能撤回留痕。

内部工作面保留批量导入、人工新增编辑、本地校核差异、修订弹窗和旧全文；不能只留API查询。D-ADJ-01：同名两法规关联歧义拒绝；正文更新旧引用仍原文；修订前文错配逐行失败；无效来源仍可按权限查历史但不能自动当现行。I法规版本覆盖及许可，B专业时点核验。

<a id="ADJ-02"></a>
### ADJ-02 条文解析与独立审核

`ArticleParseRevision`固定法规/条文/原文摘要、原文定位、通俗解析/核心含义、适用范围、要件/例外、场景/案例Refs、机器或人员主体、解析/导入时间和审核记录。原文只读，解释不回写原文。

`POST /article-parses/imports`保留一次性结构化导入；`/adapter-jobs`接已获准外部解析结果，通道未确认不宣称智能解析已接通。导入逐项检查确切法规/条文版本、原文摘要及案例存在；再按条文版本、派生对象ID、生成配置版本和解析业务载荷摘要判断重复。同来源同解析摘要跳过；原文未变但解析载荷变化须预览差异并追加待审核修订，不得用原文摘要跳过。源版本不匹配拒关联；已提交审核/已审核/被引用版本不得覆写。外部“已审核”仅作为外部声明，本地进入待审核。`/revisions`人改、`/submit`、`/review`通过/驳回/退回及重提独立，后两者必填原因，普通编辑不能填审核身份。

已审核且来源有效才作已校核知识；法规变化旧版待复核，新解析须新任务/导入，不自动重算。完整列表、独立审核页并列原文/解析/场景/案例/版本，不能只展示标题和摘要。D-ADJ-02：导入伪审核人不授权；原文摘要不一致拒关联；已审核编辑产生新待审核版；外部任务失败非空解析成功。

<a id="ADJ-03"></a>
### ADJ-03 条文要点

`LegalPointRevision`稳定id、法规/条文及解析版本、内容类别、程序场景、多案例版本、提取/导入主体与时间、原因、待核实/可用/停用/来源变更。处罚标准要点仅所属程序展示，不能关键词命中就进入裁决依据。

`/legal-points/imports`逐行校验所有关联、类别、场景、日期和原文支持；固定解析版本、要点稳定ID及生成配置版本后比较要点业务载荷摘要，摘要相同才跳过，解析原文未变但要点内容变化也须新增待审核修订。未审核未引用草稿变化按docs/02第31节切当前待处理指针，不破坏旧版及人工编辑；已提交审核、已审核、被引用或人工停用的版本不能被导入覆写或自动启用。维护改版并重校核。`/validate-availability`须已审核来源解析、原文支持及有权校核；外部生成不自动可用，`/disable`保持历史，源变化不自动再启用。

D-ADJ-03：解析未审则要点不可进已校核检索；改变源条文须新版本；处罚程序要点不能当裁决原文；模型不能补案例关联。内部列表支持原文完整字段及来源核查；I外部生成/分类审核，B要点正确与用途。

<a id="ADJ-04"></a>
### ADJ-04 案件工作与正式流程衔接

`CaseWorkRevision`记录本地稳定id、权威系统/源案件id/版本/正式号（可无）、名称、申请人/被申请人主体/代表及受控联系方式、类型/程序/管辖、涉案多权利Ref、事实/争点来源性质、资料版本；`CaseEvent`真实收件/受理/分配等事件，`WorkPlan`预计完成与法定期限依据分开，`ArchiveManifest`保存正式材料链与快照。

`POST /case-works`获准本地录入或`/syncs`来源同步；工作数据不等权威案件。`/facts/revisions`补正当前任务事实并失效依赖；`/assignments`可信人员与原因、新旧承办/expectedVersion；没有分配不得默认当前用户。`/official-requests`按已确认中心协议请求，响应未知存待对账，`/official-events`只收验证的回执或批准的具名登记事实。

受理、不予受理、办结、归档和重开由真实流程策略决定，缺角色/材料清单/正式接口时返回未配置/缺项，不造状态事件。办结核报告与签发/办理材料，归档核材料/未完成任务；已归档普通编辑拒绝，补正生成获准新版本保归档快照。法定期限无已确认规则不计算；工作计划可独立记录但标明性质。

D-ADJ-04：本地临时号不能作正式号；同步超时不改原确认状态；无材料不能归档；补料仍同caseWorkId且新资料版；普通用户不能编辑已归档。I权威系统/人员/回执，B真实案件工作流程与时间事实。

<a id="ADJ-05"></a>
### ADJ-05 法律匹配

`MatchingInput`案件资料/确认争点、事实性质、程序/地域/相关日期、确认关键词/问题；`ArticleCandidate`固定条文原文/版本、事实/要件对应、已满足/缺条件、风险、实体/程序用途、排序依据及实际覆盖。缺时点/程序/地域准备返回补充，不默认现行法。

`POST /law-matchings/prepare`给待补/可修正关键词，创建固定版本任务后按授权源、历史候选召回；已审核解析/可用要点可辅助，不能替原文。`/adjustments`具名新增/移除/确认具体条文及理由→新MatchingRevision；机器新版不覆盖人选。数值需固定标尺，无标尺稳定排序+标签。

D-ADJ-05：历史案不只查现行；无地域不猜；处罚条文关键词相似不能当裁决理由；源503不同未匹配；候选不直接进待签发稿。I法规/混合召回覆盖，BRecall@K、适用解释支持与误用案例。

<a id="ADJ-06"></a>
### ADJ-06 引用及报告采用

`CitationRevision`保存案件/资料、精确法规/条款/版本、逐字原文、节引、解释、格式化文本及样式版本、来源时点、事件依据/用途、选择者/理由、待确认/已确认/待复核/撤回；`ReportCitationBinding`保存reportId/version及稳定章节/段落锚点，页码只为渲染定位，不作唯一关联。

`POST /citations`既可由人工确认匹配进入，也可授权人直接选择原文，不强制ADJ-05。缺原文/版本/时点依据只存待核实稿，不能变可用或待签发。`/confirm`人工校核，`/withdraw`终止当前可用留历史。报告生成本域事务一次提交新报告与全部引用采用绑定；失败回滚，不先把引用“已采用”写下再生成正文。

报告修订新版本/新锚点/新绑定，旧位置保存；引用本身修改新版本重新审核。来源变化依赖报告待复核，不能自动换法条。D-ADJ-06：当前废止法规可为历史候选但核时点；原文与解释不能同字段；直接选条文可用；引用绑定失败无孤立采用；旧位置不随新稿漂移。I全文和事务，B逐字、时点及位置准确。

<a id="ADJ-07"></a>
### ADJ-07 专利解析

`PatentParseRevision`固定申请/公开/授权号、文献、主体/各日期/源状态、权项编号/类型/引用边、原文位置、特征/限定关系/必要上下文/说明书支持、OCR质量和未处理页、程序模型/执行时间；人工修订另版。准备可不绑案件，进入案件分析必须caseRef及资料版本。

`POST /patent-parses/prepare`核号码/版本与材料归属，`/patent-parses`执行，`/revisions`人工校正并`/confirm`确切版。从属链递归展开，发现环/缺节点直接列缺口，不能部分展开后称完整；说明书不能任意补成权项限定。外观采用视图/名称/简要说明独立结构，无能力保持未执行。

D-ADJ-07：摘要不能替权项；前项F1在从属链必须出现；缺权项不完整；人工版不被OCR重跑覆盖；文件路径输入拒绝任意服务器读取。I真实文献/解析质量，B专家核限定与特征完整性。

<a id="ADJ-08"></a>
### ADJ-08 官方状态与稳定性风险

`ValidityInput`案件、解析、选定权项、目的/时点/地域、状态/缴费/无效事件及对比文献来源；`OfficialStatusObservation`保存事件时点、查询时间、来源状态、缴费费种/期间、请求/受理/决定分层；`StabilityAnalysis`分新颖性、创造性及材料范围，不合成一个有效/无效标签。

`POST /validity-analyses`创建两个可独立失败/不足的执行分支。状态核验仅复述可证明的指定时点官方记录；API超时不当有效，缴费缺失不当终止，无效请求不当决定。对比文献逐项核公开日与相关日期，未知日期不得当已确认现有技术。

新颖性每单篇逐全部必要要素；创造性保存比较基础/区别特征/技术问题/组合启示及来源，无启示标不足。外观另行经确认流程，无规则不套文本模板。`/review`有权复核只锁辅助报告，不改官方状态。D-ADJ-08：当前状态不答历史；两篇分别覆盖不可称单篇全部公开；一栏成功另一失败为部分；无效请求保请求性质。I历史状态及非专利资料许可，B独立专业评价。

<a id="ADJ-09"></a>
### ADJ-09 双方证据与逐要素分析

`AdjudicationEvidenceVersion`拥有本域案件/资料、提供方、真实收集人时间方式、上传时间、原文件/实物位置、hash、权限、待证事实、双方主张/质证意见/采信记录；同文件共享存储不共享执法证据状态。`ElementEvidenceFinding`绑定所选权项/确认产品技术方案、全部必要特征、支持/反向/冲突定位及关系/缺证/无法判断。

`POST /case-materials`登记受控材料（同hash仍不同提交过程），`/evidence-analyses/prepare`确认集合、产品与权项/争议事实，创建分析任务；不可读文件仍在异常清单。文字对应与可能等同分栏，等同列事实/依据/专业待判，不用相似度阈值。销售记录只支持交易事实，照片只支持可见部位。

材料替换/新事实→新集合→依赖项待更新，不覆盖旧报告/采信意见。产品、方法、外观各自所需输入，缺确认规则的分支不执行完整结论。D-ADJ-09：单方材料不能抹双方争议；销售凭证不证内部构造；缺一必要要素显示缺证；跨案读取拒绝；同字节两提供方不合并。I双方材料/质证流程，B逐要素和采信责任。

<a id="ADJ-10"></a>
### ADJ-10 报告模板

`ReportTemplateRevision`保存id/名称、案件/专利类型、用途、稳定章节顺序、必填及确认条件表达、变量类型/来源schema/缺失策略、内容方式、字体字号/页眉页脚/页码、DOCX/PDF样例、受控版式文件、审核发布记录。内部分析模板不标法定模板。

`/report-templates`保存草稿，`/validate`核章节唯一/映射/依赖/条件无环/引用锚点；`/previews`固定脱敏样例和渲染器，`/submit-review`、`/review`、`/publish`分别具名权限动作。发布不可改，普通停用限新任务，紧急撤销在途停止并标草稿待复核，归档保历史，回滚重验依赖。

禁脚本/SQL/宏/外链，不默认Windows Office/外部SaaS/未授权字体。D-ADJ-10：必填条件循环拒发布；缺字体返回明确渲染失败；紧急撤销不继续生成；旧报告不随新模板变化。I国产环境DOCX/PDF，B实际批准版式及章节。

<a id="ADJ-11"></a>
### ADJ-11 报告修订和输出

`POST /reports/prepare`返回固定案件/模板、实际采用引用/解析/有效性/证据分析及确认状态、必填缺项/待复核/冲突/无权/不适用；模板不要求者不适用，要求但缺失不能标不适用。`POST /reports`生成结构化ReportRevision、章节/段落id、字段及句段来源、模型/规则、撰写责任人与执行主体、完整性与审核状态。

确定事实/主体/数字/法条原文直接填充，解释段落模型辅助且关联来源；未复核分析保辅助性质，不能写机关认定。必填缺失可存不完整草稿，`/submit-review`拒绝；引用正文与采用绑定按本篇第2节同事务提交。材料变更仅标影响并要求新版本，历史不改。

`/revisions`保存人改，`/regenerations`指定整篇或稳定章节生成候选差异，`/adoptions`具名确认采用且检查baseRevision；并发人改导致采用409，不合并覆盖。被审对象始终为已保存确切版本；实质变化重审。

### ADJ-12 人工复核及正式衔接

`ReviewAttempt`包含案件、对象type/id/version、原始内容及依赖manifest、提交者/时间、实际领取人/角色、逐项意见/争议/缺口、修改差异、决定及依据；`OfficialRequest/Event`另存锁定报告/正式文件/外部回执及对账，不与reviewStatus共用。

### 5.5 裁决独立开发切片的可执行候选合同（仍待窄D复判）

本节是对第5.4节未闭合项的技术推导，不是原需求的新增授权。拟设独立`adjudication-v2.development`显式开关，默认false，仅`dev-synthetic`/`test-synthetic`、非`prod`且本机隔离DM8的显式配置可启动；缺manifest绝对路径、会话时区、可信凭据或案范围配置时启动失败，而不是退回V0头或匿名访问。现有最高优先级`V2ConsultationBoundaryFilter`对所有`/v2/`执行默认404，且`V2ConsultationBoundaryConfiguration`对全V2路由做严格清单比对；将来需经统一V2注册清单审查后按域分发，未知方法、编码路径、反斜线、大小写变体及未启用域继续404。不得直接加Controller期待越过现有过滤器，也不得取消现有咨询路由清单保护。

可信HUMAN凭据可借鉴`DevelopmentSubjectPolicy`的服务端Bearer哈希、主体类别、到期和版本校验，但其`consultation-v2.development`配置与`decide()`的单owner判断没有案范围。裁决专属授权映射须由服务端配置固定`issuer=LOCAL_DEV`、稳定主体、`HUMAN`、`organizationRef=dev-adj-isolated`、允许动作和**精确**`caseId=DEV-ADJ-CASE-001`；默认不授CASE-002，不能从同机构或manifest的`testPrincipalRefs`推导跨案权。案工作保存创建者与源案ID，后续命令及每次读取同时核当前凭据、机构、精确案授权、当前源许可和工作到期。客户端传入的主体/机构/提供方字段一律不作为授权或来源事实。`dev-adj-reviewer`可保留为另一测试凭据，但本切片没有报告领取/复核动作，也不借它证明职责分离。单进程`revoke()`只证明当前进程；若I层涉及双实例/重启，授权版本及撤权必须来自共享可持久的可信授权源，或明确限制本切片单实例并实测重启后撤权仍有效。尚未选择/验证该源，不能宣称跨实例即时撤权。
