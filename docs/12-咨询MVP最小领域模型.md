# 咨询 MVP 最小领域模型

版本：V0.1  
日期：2026-09-15  
关联任务：ARC-05-CON  
历史 V0 样例：[咨询 MVP V0 产品样例基线](11-咨询MVP-V0产品样例基线.md)
当前产品行为依据：`docs/02` P0-20、`docs/35-咨询智能体产品行为待确认清单.md` 和更新后的咨询正式需求

本设计只覆盖“专利相似检索/技术参考”第一条闭环。它定义领域概念，不是数据库表、接口字段、Java 类或完整状态机。

> 2026-09-22 定位更新：下文五个对象只说明历史 V0 已验证的概念，不是完整目标产品模型。后续详细设计必须补充能够表达用户目标、确认事实及版本、稳定结果集快照、对象/目标分支、工具结果、证据充分性、迭代检索、技术对照、子任务状态和人工交接的业务概念；具体对象拆分、字段和存储仍须另行通过 D 门，本轮不冻结技术模型。

字段性质标记：

- `R`：原始咨询需求明确要求的业务信息。
- `V0`：经确认样例或 `docs/02` V0 临时产品决策引入，可回滚且不得解释为原始业务事实。
- `P`：仍需专业或中心责任方确认；当前不固化为字段取值规则。

## 1. 领域对象

### 1.1 咨询会话

职责：作为本闭环的聚合入口，保存用户实际提交的内容、内容来源以及尚未解决的缺失/冲突；关联检索请求和辅助回答。它不负责判断权限、执行检索、保存专利原文或作专业结论。

| 最小字段 | 含义与边界 | 性质 |
|---|---|---|
| `consultationId` | 咨询会话稳定标识，用于归属和关联，不以可重名用户名代替 | R |
| `requesterRef` | 当前请求者的不透明身份引用，仅用于交给授权能力校验；不包含角色或 DataScope 规则 | R；具体身份体系为 P |
| `userInputs` | 按提交顺序保存原始问题及后续补充；每项包含原文、提交时间和来源定位，不静默改写历史 | R |
| `intent` | 本 MVP 只允许“专利相似检索/技术参考”；无法识别或超出范围时保持未识别并请求澄清 | R + V0（首期只选此意图） |
| `informationIssues` | 当前缺失、歧义或冲突项；每项包含类型、说明及相关输入来源定位。解决后保留原记录并关联用户确认来源 | R |

边界约束：会话不重复保存已形成检索请求中的确认条件；用户确认后，由检索请求持有本次实际使用的不可变输入快照。是否必须专业复核不是会话属性，由具体辅助回答记录。

### 1.2 检索请求

职责：表示一次准备执行或已经执行的专利检索及其不可变输入快照，并记录授权门禁和实际执行结果。它不定义权限规则、不拥有专利数据，也不保存完整候选正文。

| 最小字段 | 含义与边界 | 性质 |
|---|---|---|
| `retrievalRequestId` | 本次检索请求稳定标识 | R |
| `consultationId` | 归属的咨询会话 | R |
| `confirmedInput` | 本次实际使用的用户确认技术方案/特征，并引用确认它的用户输入位置；不得包含模型猜测值 | R |
| `purpose` | 本阶段固定为“技术参考”；不支持时不得退化为其他法律分析目的 | R + V0 |
| `requestedScope` | 用户要求的专利类型、地域等范围；只保存明确提出或确认的条件 | R |
| `accessOutcome` | 本次访问门禁的最小结果：允许或拒绝；模型不能生成或修改此结果 | R；默认拒绝为 V0 |
| `accessDecisionRef` | 指向权威授权检查记录的引用，用于解释拒绝；不复制角色、组织和策略规则 | R；具体授权系统为 P |
| `executionOutcome` | 本次检索的结果类别：未执行、完成、部分完成或失败；它是一次执行结果，不是完整任务状态机 | R |
| `actualScope` | 数据源实际执行的范围、截断或能力限制；被拒绝或未执行时为空 | R |
| `failureCategory` | 仅在未执行、部分完成或失败时记录无权限、来源不可用、工具故障等可区分原因 | R |

边界约束：存在未解决的必要信息或冲突时不得创建可执行检索请求；可以形成待确认草稿，但本模型不把草稿设计成状态机。`accessOutcome=拒绝` 时不得产生含受限内容的检索候选。

### 1.3 检索候选

职责：表示某次检索返回的一项可追溯候选，以及该候选为何与用户确认特征相关。它不是专利权威记录，不保存完整专利，也不表示新颖性、侵权、有效性或授权概率。

| 最小字段 | 含义与边界 | 性质 |
|---|---|---|
| `candidateId` | 本次检索结果内的候选稳定标识 | R |
| `retrievalRequestId` | 产生该候选的检索请求 | R |
| `source` | 指向确切专利文献版本的来源定位 | R |
| `displaySummary` | 数据源允许展示的最小名称/号码/摘要信息；不是权威专利副本 | R |
| `matchBasis` | 用户确认特征与文献具体位置之间的匹配说明；不得无来源生成 | R |
| `orderingBasis` | 排序依据或相关程度标签；无稳定标尺时不得保存模型臆造的精确分数 | R |
| `sourceUseOutcome` | 回答生成前的最小复查结果：可使用或来源不可用；后者必须排除出回答依据 | R + V0（回答前复查） |
| `unavailableReason` | 来源不可用时记录撤回、版本失效、读取失败等事实类别；不得推断为专利权利失效 | R |

边界约束：实际检索范围只保存在检索请求中，候选不逐项复制。候选保存匹配关系和定位，不默认保存全文、未采用片段或向量。来源在检索后失效时保留候选追溯记录，但不得继续作为辅助回答依据。

### 1.4 辅助回答

职责：表达本轮能够向用户交付的辅助结果、限制和异常，并把回答中的关键内容关联到实际使用的候选及来源。它不是正式专业意见，也不记录人工复核决定。

| 最小字段 | 含义与边界 | 性质 |
|---|---|---|
| `answerId` | 回答稳定标识 | R |
| `consultationId` | 回答所属咨询会话 | R |
| `retrievalRequestRef` | 回答所依据的检索请求；仅补问时可为空 | R |
| `outcomeType` | 本轮交付类型：需要补充、无权限、来源失效/降级或带来源回答；用于区分三个样例，不构成完整状态机 | R + V0 |
| `content` | 面向用户的辅助回答或补问/拒绝说明；必须与 `outcomeType` 一致 | R |
| `candidateRefs` | 本回答实际采用的可使用候选引用；不得包含被拒绝或来源不可用候选 | R |
| `sourceLinks` | 回答关键内容到来源定位的对应关系；不是独立 Claim/Evidence 模型 | R |
| `limitations` | 缺失、冲突、实际检索范围、部分失败及“未查到不等于不存在”等必要限制说明 | R |
| `professionalReviewRequired` | 是否提示需要专业复核；V0 只支持布尔标记，不代表已转交或已完成复核 | R + V0 |
| `professionalReviewReason` | 触发提示的原因；当前只允许“拟正式采用”等通用说明，不固化专业判断规则 | V0；具体触发规则为 P |
| `answerVersion` | 标识用户实际看到的回答版本，后续更正产生新版本而不覆盖旧回答 | R |

边界约束：回答不复制检索条件、候选摘要或专利原文，只通过引用关联。无权限时 `retrievalRequestRef` 可指向被拒绝的检索请求，但 `candidateRefs` 和专利正文来源必须为空。来源失效时只能引用仍可使用候选，或生成不含失效文献事实的降级说明。

### 1.5 来源定位

职责：作为无独立生命周期的值对象，唯一定位用户输入、附件位置、专利文献版本或权威授权判定记录。它只回答“信息来自哪里”，不解释证据效力、权限规则或法律意义。

| 最小字段 | 含义与边界 | 性质 |
|---|---|---|
| `sourceKind` | 用户消息、受控附件、专利文献或授权判定记录 | R + V0（统一值对象） |
| `sourceSystem` | 来源系统或本地会话来源标识 | R |
| `sourceObjectId` | 来源对象稳定 ID | R |
| `versionRef` | 确切版本 ID；源没有版本时使用可核对摘要，不把获取时间冒充版本 | R；真实版本语义为 P |
| `location` | 消息顺序、附件页/字段、摘要段落或权利要求编号等可解析位置 | R |
| `retrievedAt` | 本次取得或校验该来源的时间，用于区分来源版本时间与获取时间 | R |

边界约束：来源定位不保存原文正文，也不保存“当前可用”这种会变化的判断；可用性由检索候选记录，授权结论由检索请求记录。相同定位值可以被多个对象引用，不复制来源事实。

### 1.6 不进入领域对象的技术字段

以下信息即使实施时需要保存，也属于技术执行或审计元数据，不应污染上述五个领域对象：请求关联 ID、日志 ID、调用耗时、重试次数、线程/节点信息、HTTP 状态、模型供应商、模型/提示词配置版本、Token 用量、温度参数、原始模型响应、向量、重排特征和缓存键。

其中“使用的模型/配置版本”和请求关联 ID 仍须按样例基线保存以支持最小技术追溯，但本阶段只声明保存义务，不设计 `RunRecord` 或其字段结构。模型隐含推理不保存、不展示。

当前不进入字段取值规则、继续等待专业或中心确认的内容包括：不同咨询目的的专业必填条件、候选相关性验收标准、正式采用的复核触发规则、真实授权范围与策略、中心专利版本语义及来源内容保留授权。这些缺口不改变五个对象的职责。

## 2. 对象关系

```text
咨询会话 1
  ├── 0..N 检索请求
  │          └── 0..N 检索候选
  └── 0..N 辅助回答
               ├── 0..1 依据的检索请求
               └── 0..N 实际采用的检索候选

来源定位（值对象）
  ├── 定位咨询会话中的用户输入、补充和冲突来源
  ├── 定位检索请求的授权判定依据
  ├── 定位检索候选的文献版本与匹配位置
  └── 定位辅助回答中关键内容的实际来源
```

唯一事实归属：原始输入和未决问题归咨询会话；确认后的本次检索条件、授权结果和实际范围归检索请求；匹配关系和来源可用性归检索候选；回答正文、限制及复核提示归辅助回答；源身份、版本和位置归来源定位。

## 3. 三个样例如何落到模型

| 样例 | 对象落点 |
|---|---|
| 正常检索 | 咨询会话保存完整问题且无未决项；检索请求保存确认特征、技术参考目的、允许的授权结果和实际范围；两个检索候选分别关联合成文献来源定位及匹配依据；辅助回答引用实际采用候选和来源，并标明限制及辅助性质。 |
| 信息不足/冲突 | 咨询会话保存原问题、附件 A/B 来源定位及“目的缺失、温度冲突”；在用户确认前不形成可执行检索请求和候选；辅助回答以“需要补充”输出针对性补问，候选引用为空。用户确认后才创建新的检索请求快照。 |
| 无权限 | 咨询会话关联一次检索尝试；检索请求保存“拒绝”和权威授权判定引用，执行结果为未执行；不创建含受限信息的检索候选；辅助回答输出拒绝说明且不引用受限正文。 |
| 来源失效 | 已有检索候选保留其来源定位，但 `sourceUseOutcome` 变为来源不可用并记录事实原因；辅助回答排除该候选，仅引用其他有效候选并降级，或只输出来源失效说明。 |

这四条映射能够覆盖三个样例要求的正常、冲突、无权限、来源失效、带来源回答和最小追溯；无需保存完整专利原文、未采用候选全文、模型中间数据或隐含推理。

## 4. 明确暂不建模的内容

- 完整会话、检索任务、候选和回答状态机及状态转换枚举。
- 通用 Agent、Runtime、Workflow、Task、Tool Registry、RunManifest 和 `RunRecord`。
- 具体角色、组织层级、SSO、权限策略、DataScope 和授权规则；只消费权威检查结果。
- 完整 `Claim / Evidence / Citation / Review` 模型以及正式人工复核流程和决定。
- 专利权威主数据、全文副本、知识库同步、索引、向量、缓存及来源保留策略。
- 新颖性、侵权、有效性、授权概率、专业相关性阈值和正式法律意见。
- 数据库表、主外键、索引、事务、ORM、API URL、请求响应结构和异步协议。
- 模型供应商、提示词结构、评分算法、部署、DM8 和文件存储实现。
- 商标、案例、法规咨询以及执法、裁决领域对象。

## 5. 下一步建议

下一步只设计 **咨询 MVP 最小领域行为与不变量**：围绕“何时允许形成检索请求、何时候选可以进入回答、回答何时必须降级或拒绝、引用何时算完整”形成可由三个 V0 样例验证的规则；仍不进入数据库、完整 API 或代码。
