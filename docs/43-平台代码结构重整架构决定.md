# 平台代码结构重整架构决定

状态：已采用  
日期：2026-09-17  
关联任务：`ENG-ARCH-STRUCTURE-REBASE-*`

## 1. 决定

平台采用一个 Git 仓库内的 Maven 多模块模块化单体。正式平台保持一个部署单元；开发期模拟中心成为独立 Spring Boot 服务，通过 HTTP 与正式平台交互。React 前端保持独立工程和独立质量门禁，生产打包时由显式发布步骤交付给平台应用，不再绑定每次 Maven 测试。

该决定只处理代码所有权、依赖和构建，不新增业务能力，不改变现有 API、状态、权限、数据语义或正式需求成熟度。

## 3. 模块责任

| 模块 | 拥有 | 禁止拥有 |
|---|---|---|
| `kernel` | 无业务语义的稳定技术值类型 | 三域状态、权限决定、中心数据模型 |
| 业务域模块 | domain、application、所需 port、域内 HTTP 合约 | DM8、厂商 SDK、模型/中心具体实现 |
| `persistence-dm8` | 各 port 的 DM8 实现与映射 | 业务决策、正式状态推进 |
| `model-deepseek` | 模型调用、错误归一和配置 | 权限、法律规则、最终决定 |
| `center-client` | 供应商无关中心 port 的 HTTP 实现和协议映射 | 领域服务、模拟中心目录 |
| `public-source` | 获准开发使用的公开源读取实现 | 将公开结果标记为中心权威数据 |
| `platform-api` | 正式平台启动、Bean 装配和运行配置 | 领域规则、具体仓储逻辑 |
| `mock-center-api` | 开发目录、独立存储、开发 API | 导入正式平台实现、伪装真实中心 |

## 4. 依赖规则

```text
domain <- application + ports <- adapters <- platform-api
```

- domain 只能依赖 JDK 和同域 domain。
- application 只能依赖同域 domain、port 及经批准的 kernel 类型。
- adapter 可以依赖其实现的 port，禁止反向被 domain/application 依赖。
- 跨域调用必须经显式 port/contract，禁止引用另一域 adapter、repository 或 Spring 配置。
- Spring 配置集中在两个应用装配根；业务模块不通过组件扫描隐式决定具体实现。

## 5. 模拟中心替换边界

平台不再在进程内构造或调用 `MockCenterPatentCatalog`。开发配置选择模拟中心 HTTP 地址；未来真实中心接入时选择真实地址、认证和协议映射。领域侧继续只看到供应商无关的检索命令、候选、来源版本、实际范围和错误分类。

模拟中心响应必须保留 `PUBLIC_PILOT`、`NON_CENTER_PUBLIC_SOURCE` 和限制说明。模拟中心成功只证明开发链路，不证明中心契约、数据授权、召回质量或专业结论。

## 6. 代码体量门禁

| 文件类型 | 软上限 | 硬上限 |
|---|---:|---:|
| Java 业务类 | 200 | 300 |
| Java Controller | 150 | 220 |
| Java 配置 | 120 | 180 |
| Java 方法 | 40 | 60 |
| TS/TSX | 180 | 300 |
| React 页面/组件 | 150 | 220 |
| Hook/API client | 120 | 180 |
| CSS | 200 | 300 |
| 测试文件 | 250 | 400 |

软上限用于提示下一轮拆分，硬上限阻止新增长期债务。例外仅限生成文件、数据库迁移和固定数据，并必须在结构校验配置中写明路径、理由和范围。拆分按责任、事务边界和可测试行为进行，不能用无意义转发类只为降低行数。

## 7. 迁移与验收

迁移按构建骨架、物理模块、模拟中心 HTTP 边界、超限拆分和全量验证五步推进。每步通过编译和受影响测试后再进入下一步。最终验收包括模块依赖、结构与体量、Java 全量测试、真实本地 DM8、前端单元/生产构建/浏览器、两个应用启动以及平台到模拟中心的 HTTP 端到端验证。

旧包路径、根级后端源码、Maven 测试隐式触发前端构建、平台进程内调用模拟中心目录，均不得作为最终兼容层保留。
