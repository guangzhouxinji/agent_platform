# 咨询智能体 R 门需求变化影响评审

评审日期：2026-09-22  
评审任务：`GOV-CONSULTATION-R-GATE-REVIEW-01`  
评审对象：负责人确认后的咨询产品基线、`CON-01` 至 `CON-12`、既有咨询设计/实现/测试  
评审结论：**产品行为基线在产品层面基本自洽；现有契约和详细设计不足以恢复 R/D 门，全部咨询契约继续保持 `stale/基线已变化`，不得产生 READY。**

## 1. 评审边界与依据

本次只做需求变化影响评审，不修改业务代码、测试代码、配置、数据库或基础设施实现，不设计通用 Agent Runtime、Workflow 平台或三域统一运行时。

主要依据：

- `docs/35-咨询智能体产品行为待确认清单.md`：负责人确认的产品行为和仍待外部证据事项。
- 已更新的 7 份咨询正式需求：总目录、专利库、专利相似度检索、专利相似度判断、咨询意图、咨询对话流、咨询智能体管理。
- `docs/06-三个MVP闭环与状态机.md`、`docs/11` 至 `docs/17`：现有 MVP/V0 和设计材料。
- `docs/30-智能体真实性验收报告.md`、`docs/31-咨询智能体调用链审计报告.md`、`docs/34-咨询智能体需求适配性审查.md`：真实性、调用链和需求适配证据。
- 当前磁盘实现和测试，仅用于判断影响，不反向定义产品规则。

判定词：

- `RETAIN`：原职责和核心契约继续有效，只需重新绑定新基线证据。
- `ADAPT`：核心职责保留，但输入、输出、状态或验收必须增补。
- `REDESIGN`：原职责仍存在，但现有契约结构不能表达新产品行为，必须重新设计。
- `REPLACE`：原契约职责应由新的职责整体替代。
- `SPLIT`：原契约混合了必须独立治理的职责，需要拆开契约边界。
- `MERGE`：多个契约应合并为一个职责。
- `DEFER`：完整产品目标保留，但不进入第一条开发主线。

### 2.2 自洽性结论

负责人确认后的产品行为在以下方面已经自洽：首批核心任务、最小必要追问、自主调用边界、检索迭代原则、证据边界、纠正传播、九种任务状态、人工责任边界和 V0 定位互不冲突；AI、规则、权威系统和授权人员的最终责任边界也一致。

但它还不是可直接开发的完整需求契约，原因不是产品目标矛盾，而是以下外部证据和可执行规则尚未补齐：

1. “结果不足”“仍可能获得新信息”“重要冲突”“高风险结论”的可评审判定依据尚未形成样例或规则表。
2. 回答类型到最低证据等级的矩阵尚未形成可验收附件。
3. 真实数据、全文、权利要求、模型出域、身份/DataScope 和保留期限仍无外部授权证据。
4. 人工接收角色、受理接口、回执、服务时限和回流责任尚无组织证据。
5. 专业评测集、标注规则、分歧裁决、K 值和通过线尚未提供。

因此，本次评审可以确认产品基线方向，但不能恢复任何 `CON-*` 的“需求就绪”，也不能进入新 API、物理数据或代码设计。

| CON-12 咨询对话流管理 | REDESIGN | 会话/消息、上下文、流程分支、工具结果、并发恢复、人工转接和权限 | 成为任务型多轮主契约：稳定结果集、连续工具、迭代检索、九状态、分支、人工交接回流 | 当前只传历史问题、一次请求一次工具、无持久任务上下文，直接违反 | 现有会话/来源/幂等基础可参考；`DailyConsultationRequest/Response` 和前端轮次模型需重新设计 | 必须重设计完整任务语义，但不预设通用 Workflow 平台 | 绝大多数现有“单轮成功”断言失效；须做跨轮、跨实例、纠正、指代和人工回流验收 |

本轮不采用 `REPLACE` 或 `MERGE`：没有证据表明任何正式业务能力应被删除或整体替代，也没有证据证明合并契约能保持各域事实所有权。`SPLIT` 仅用于澄清 CON-09 的契约职责，不等于批准新技术架构。

## 4. 领域模型语义影响

| 产品概念 | 产品语义必须存在 | 第一条主线要求 | 可暂不工程化的部分 |
|---|---|---|---|
| 用户目标 | 是 | 保存原目标、当前目标、目标类型和变化关系 | 通用目标 DSL、跨三域统一目标模型 |
| 已确认事实 | 是 | 区分用户明确、用户确认、来源事实和模型候选；保留版本 | 全行业统一槽位本体 |
| 任务上下文 | 是 | 关联目标、事实、子任务、结果集、未决项和当前状态 | 通用 Agent Runtime 上下文容器 |
| 结果集 | 是 | 稳定 ID、版本、范围、排序和候选快照，支持自然语言指代 | 跨域统一结果集仓库 |
| 候选对象 | 是 | 关联源对象、版本、匹配依据、证据和所在结果集 | 抽象成所有业务域共用超类型 |
| 工具执行记录 | 是 | 记录工具、输入快照、授权范围、输出/失败、时间、重试/后继关系 | 通用 RunManifest 或平台级执行引擎 |
| 证据 | 是 | 记录来源、版本、定位、片段、可用性和支持的陈述/特征 | 完整跨域 Claim/Evidence 图谱 |
| 证据充分性 | 是 | 按回答类型给出满足/不足/冲突及原因，驱动继续、降级或人工 | 自动化专业裁决器和统一数值评分 |
| 未决项 | 是 | 记录缺失、冲突、歧义、责任方、是否阻断及解决版本 | 通用工单系统 |
| 任务分支 | 是 | 表达复合子任务、对象切换和目标变化后的父子关系 | 通用 Workflow 分支引擎 |
| 任务状态 | 是 | 使用负责人确认的九种产品状态，并与工具执行状态分离 | 三域统一状态机 |
| 用户纠正版本 | 是 | 保存被纠正事实、替代值、影响范围、失效结果和重算结果 | 通用事件溯源平台 |

结论：领域模型语义必须修改。可以暂缓的是通用化和物理实现，不是上述业务概念本身。第一条主线的详细设计若不能表达这些概念，不得通过 D 门。

## 5. 现有实现的保留、重构与冻结边界

### 5.1 应优先复用

| 现有能力 | 可复用内容 | 复用限制 |
|---|---|---|
| 模型 Adapter 与模型链 | `OpenAiConsultationAnswerAdapter`、`ModelChainConsultationAnswerGenerator`、模型故障切换和受控输出解析 | 真实生产模型、数据出域和安全批准仍待证据；模型不得决定权限、完成状态或正式结论 |
| 检索 Adapter | 专利目录端口、公开/DM8/中心适配边界、实际范围和来源版本返回 | 固定字面匹配不能被称为语义或专业相似检索；是否继续检索由任务语义决定 |
| DM8 持久化基础 | 现有咨询、专利检索、专利对照仓储的连接、事务、版本和映射经验 | 现有表结构不能自动视为新任务模型；新记录和迁移须另过 D 门 |
| 来源/版本追踪 | `ConsultationSourceLink`、候选源 ID/版本/定位、打开来源时重新校验 | 当前来源详情深度不足；权限撤回和受控原文仍需设计/授权 |
| 引用白名单 | 模型引用必须落在当前候选集合、非法引用拒绝、候选证据隔离 | “引用合法”不等于“证据充分”，必须增加陈述级充分性判断 |
| 权限边界 | 后端持有凭据、来源读取时重查、模型/Agent 不授予权限的边界 | 开发字符串身份和默认关闭鉴权不能作为真实权限证据 |
| 数据映射 | 专利、候选、来源、版本和实际范围的已验证映射 | 仅在相同来源版本和授权范围内复用；开发数据不进入正式验收 |
| 专利对照结构 | 目标/候选引用、逐特征映射、相同/差异/未执行项的结构经验 | 当前 `contains` 规则和独立工作台链路不作为专业对照实现证据 |

### 5.2 需要重新设计的核心代码语义

本节是影响结论，不授权本轮修改代码。

1. `DailyConsultationService`：当前每次生成新 `consultationId`，按本轮解析结果直接遍历执行并汇总响应；需要改为加载同一任务、依据目标/事实/未决项/结果充分性规划下一动作，并持久化状态转换。
2. `DailyConsultationToolRunner`：当前由固定 `switch` 把意图映射为一次工具调用，且把 `PATENT_COMPARISON` 退化为专利检索和外链；需要由已批准的任务动作调用领域能力，并把工具执行、证据和失败回写原任务。
3. `ConsultationIntentParserService` 与模型候选合并：可保留候选抽取，但输出要从“本轮路由”扩展为目标/事实候选、纠正影响和需确认项；固定规则只能作为受控候选或回退。
4. `DailyConsultationRequest/Response`：当前仅传问题和历史用户问题文本；需要任务引用、结果集引用、确认/纠正输入、任务状态和结构化下一步语义。具体 API 形态须经 D 门，不能在本报告冻结。
5. `DailyConsultationChat`：当前前端只累积问题文本，“第二个结果”没有稳定快照语义，继续对照会离开主任务；需要围绕同一任务展示状态、未决项、结果集版本、证据和分支。
6. `ConsultationApplicationService` 与现有检索任务：可保留提交、幂等、候选和来源处理，但一次检索/回答的 `ANSWER_READY` 不能直接映射任务完成。
7. 专利对照服务：必须接收已确认特征和足够证据，输出回到原任务；当前完整字符串包含判断只能保留为明确标注的开发期逐字核对能力。

### 5.3 本轮及第一条主线暂不动

- 商标资料、检索和多维对照实现。
- 案例库、案例检索和案例研究实现。

- 通用 Agent Runtime、Workflow 平台和三域统一运行时。

“暂不动”表示不进入第一条开发主线，不表示从完整产品目标删除。

## 10. 十个重点问题的最终回答

1. **负责人确认后的产品基线是否已经自洽？** 产品行为层面基本自洽；外部授权、专业判定附件和验收数值尚未闭合，因此不是开发就绪契约。
2. **`docs/11`～`docs/17` 是否仍存在 V0 限制渗透？** 是。历史声明已经加上，但正文的对象、用例、API、持久化和 D 门仍是 V0，不能直接用于新设计。
3. **`CON-01`～`CON-12` 如何处理？** CON-01/03/05/07/08 为 DEFER，CON-02 为 ADAPT，CON-04/06/11/12 为 REDESIGN，CON-09 为 SPLIT，CON-10 为 RETAIN；全部继续 stale，等待重新抽取和独立评审。
4. **哪些现有代码可以保留？** 模型 Adapter/模型链、检索 Adapter、DM8 仓储基础、来源与版本追踪、引用白名单、后端权限边界和已验证数据映射可以作为组件复用候选。
5. **哪些核心代码需要重新设计？** `DailyConsultationService`、`DailyConsultationToolRunner`、固定路由/汇总状态、请求响应语义、前端轮次上下文、任务完成判断、检索迭代和专利对照回流。
6. **是否需要修改领域模型语义？** 需要。十二个列出的产品概念都必须存在；可延后的是通用化和物理实现。
7. **哪些测试必须重写？** 把候选存在当完成、只传历史问题当多轮、固定 switch/一次工具调用、伪 API 流程、独立对照跳转和 V0 合成样例当业务验收的测试必须重写或降级为历史/组件测试。
8. **哪些需求仍缺外部证据？** 数据/全文/权利要求/模型授权、真实身份与 DataScope、保留期限、证据等级矩阵、专业评测集及阈值、人工组织接口、生产模型安全和真实验收案例。
9. **重新产生 READY 前还缺什么？** 新契约逐条 R 门及独立评审，以及任务语义、证据/检索决策、API/逻辑数据、复用边界和四层测试映射的 D 门证据。
10. **第一条新的开发主线应该是什么？** 在契约 R 门和详细设计 D 门通过后，实施“专利资料查询 → 可迭代专利检索 → 证据充分性判断 → 专利技术对照 → 带证据回答 → 纠正/追问后继续同一任务”的持久任务闭环。它不是新 V0，也不先建设通用 Runtime/Workflow。
