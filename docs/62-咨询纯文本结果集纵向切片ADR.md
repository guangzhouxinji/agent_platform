# 咨询纯文本结果集纵向切片 ADR

决定编号：ADR-CON-TEXT-RESULT-01。日期：2026-09-24。性质：开发期技术实施顺序，不修改`requirements/`或甲方正式数据/备份规则。

## 背景与决定

`RUN-CON-FIRST-VERTICAL-01`需要尽快证明同一咨询任务能从用户目标进入检索结果、固定结果集并跨轮引用。当前`VER-CON-DB-CORE-01`已验证合成文本任务的DM8持久化；`DEV-CON-SYN-01`已逐用途签入P1/P2虚构权项，且本切片不接收附件、文件、真实专利或模型。文件根及备份回灌尚无运行配置，因此`ARC-CON-PERSIST-PHYSICAL-D-01`不能放行其对应文件代码。

决定将**纯文本合成结果集**另立窄D和实现任务，独立于文件/备份D。它以现有任务ID及可信开发主体为边界，保存固定来源版本/摘要、结果成员和明确焦点；每次查询、保存、展示和焦点引用均按当前用途/撤回核验。排序仅为固定开发顺序，不叫专业相关度；不调用真实检索、模型、文件、索引或外部系统。业务数据服务拥有结果集真相，Agent后续可编排已批准命令，但本切片的H入口只证明服务命令和用户选择，不冒充独立Agent已完成。

文件/备份D仍是半年全链路与产品验收前置条件。现阶段只允许`test-synthetic`/`dev-synthetic`显式开关和项目自造文本；生产、公开来源试点、甲方资料一律不激活。该顺序减少文件环境阻塞对无文件任务语义的影响，不降低任何真实数据/权限/专业或Business Acceptance门槛。

## 取舍与退出

不复用旧Fixture内存结果集为任务真相；可借鉴它的虚构输入，但新关系和事务须在隔离DM8上验证。若用途撤回、主体撤权或数据源异常，旧结果集不可泄正文或默认为无结果。新结果集不重排旧集合；“第二个”必须绑定具体已展示集合、序位及来源版本。

实施前由`ARC-CON-TEXT-RESULT-D-01`在[公共边界设计](61-咨询首任务开发期公共边界与独立验收设计.md)冻结表/路由/失败码与负例并单独判D。开发I只证明合成DM8结果和重启，正式检索覆盖、图像/语义、专家排序质量、文件/备份及完整咨询任务另验。
