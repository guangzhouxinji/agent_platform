# V2 产品蓝图与候选 ADR

本稿是从 [原始方案](../../知识产权智能体方案.docx) 三域目标及 47 份细化需求倒推的逻辑设计，不继承现有 Service/API/表/页面。以下 ADR 是**技术/产品选择提案**，不伪装成原始要求或已批准决定。每条统一给出依据、旧问题、方案、理由、三类收益、复杂度、风险、依赖和验收。

2026-09-24 边界更新：三智能体与数据服务的技术选择已由 [ADR-AGENT-DATA-01](../54-三智能体与数据服务边界ADR.md) 定案，采用三个独立 Agent 加一个内部按领域分模块的独立业务数据与能力服务，全部持久业务数据外置。本稿中相关候选架构表述以该 ADR 为准；其余提案不因此获批。Task/Run/Source/Version/Review 等机制复用不意味着统一三域状态、证据语义或建设通用 Runtime。具体任务 D 门、生产环境及外部许可仍按总计划分别控制。

## 信息架构和责任

```text
任务入口/任务箱 ── Task Workspace ── 人工待办/复核 ── 产物与来源
                          │
                  Task/Goal + 领域工作流
                          │
        Agent 编排 ── 发布的 Skill ── 受控 Tool
                          │
       咨询域       执法域       裁决域       法规/知识资源
                          │
        版本/证据引用/权限策略/规则运行/文件/模型适配
                          │
                 获授权源系统及正式系统
```

- 任务/子任务属于对应领域；共享运行层保存状态、检查点与版本依赖，不能拥有案件事实或裁量规则。知识资源有来源责任者，咨询/执法/裁决各自定义证据语义和完成标准。
- 用户第一层看 Goal、当前成果、下一关键缺口、需本人处理的动作；第二层展开来源和差异；管理者在 Studio/Release 看发布依赖、评测与运行安全。外部交付 UI 范围另定。
- 交互边界：同步创建/读取任务、人工动作、产物查询；耗时工具与模型走异步执行/事件投影；权威系统写回单独受控适配与真实回执，不能由 Agent Tool 直接执行。

## 重大设计决定（统一格式）

### ADR-V2-01 以 Task/Goal 组织产品

原需求依据：原始 DOCX 三域全流程目标；CON-12 与咨询总目录 8、ADJ-04。原方案问题：按功能/对话流拆分使“产生回复”早于“完成工作”。新方案：领域 Task 持有 Goal、范围、成果清单、完成标准和子任务。理由：一个成果可跨多个检索/补问/审核步骤。用户收益：中断后仍知道进度与缺口。Agent 收益：可按目标评估下一步。工程收益：功能替换不改变业务完成语义。复杂度：中。风险：过度统一三域状态。依赖：领域负责人定义实际任务和完成标准。验收指标：专家标注的目标完成/部分完成一致率、漏报关键缺口率；目标值[待确认]。

### ADR-V2-02 持续 Agent 与有限 Runtime

原需求依据：CON-04/12 的同范围继续检索与恢复、三域异步任务约定。原方案问题：固定一次路由或一问一答不能根据中间证据调整，通用大平台又过重。新方案：Observe/Plan/Act/Observe/Evaluate/Re-plan，最小 Runtime 管幂等、检查点、预算和停止。理由：决策循环与执行可靠性是不同责任。用户收益：减少机械手选模块和断线重做。Agent 收益：可以比较“再查是否有新增信息”。工程收益：可重放可取消，域逻辑不进编排器。复杂度：高。风险：无限搜索、重复动作和恢复误发布。依赖：Task/Tool 契约、预算政策。验收指标：无进展停止、断线恢复、取消迟到隔离场景全过；真实节省工时[待确认]。

### ADR-V2-03 Evidence 成为可追溯对象

原需求依据：CON-02/06、ENF-05/07、ADJ-06/09 的来源版本和定位。原方案问题：一串引用不能证明支持哪项主张，源变更后草稿仍可能显得可靠。新方案：Claim→支持/反驳 Evidence→Source/Version/Locator/Provenance，关键主张绑定最小证据集合和缺口。理由：专业复核需要核查关系而非引用数。用户收益：点击能核验支持/冲突。Agent 收益：据缺口决定重查或停止。工程收益：局部失效与追溯。复杂度：高。风险：关系泛化/成本失控。依赖：获准原文、域内证据标准。验收指标：关键陈述支持率、错误引用率、定位可打开率；阈值[待确认]。

### ADR-V2-04 AI/Rule/Human/Authority 分权

原需求依据：三域总览、ENF-15/16、ADJ-08/12。原方案问题：原 DOCX“判断/结论/正式文件”用语易让模型结果越权。新方案：AI 仅候选/草稿；发布的确定性规则算日期/金额/前置条件；授权人员认定/采信/复核；正式系统提供权威状态/回执。理由：证据、计算、裁量和法律决定的责任不同。用户收益：减少误用。Agent 收益：动作白名单和明确升级路径。工程收益：可测禁止写入边界。复杂度：中。风险：人工责任分配不明。依赖：有权规则、身份/流程。验收指标：越权正式状态写入为 0；规则边界样例全过；身份及规则待确认。

### ADR-V2-05 产物优先于回复

原需求依据：CON-04/06、ENF-07/14、ADJ-11。原方案问题：聊天文本无法稳定比较版本、重用证据或提交复核。新方案：结果集、事实集、对照表、证据包、报告草稿、复核包均有 ID/版本/状态/来源，回复只是产物视图。理由：工作成果要可移交和再计算。用户收益：可编辑、核对、继续。Agent 收益：可从已保存成果恢复。工程收益：契约清晰。复杂度：中。风险：产物过多拖慢使用。依赖：目标任务的最小产物定义。验收指标：离线重开任务仍能定位成果、局部再生成不覆盖人工版；用户采用率[待确认]。

### ADR-V2-06 分层检索而非 RAG 中心论

原需求依据：CON-04/05/08、ADJ-05/08、ENF-17。原方案问题：关键词/语义检索或摘要相关不等于穷尽、原文技术对照或法律适用。新方案：受限元数据/精确查询→可验证召回与排序→按问题取原文/权利要求/历史法条→逐项证据验证；RAG 是候选与上下文手段。理由：证据类型必须匹配主张。用户收益：知道搜索范围和盲区。Agent 收益：不再把更多文本当成更多确定性。工程收益：可按源能力降级。复杂度：中高。风险：召回不足、成本增加。依赖：授权索引/原文能力与专家标注。验收指标：Recall@K、关键文献漏检、来源支持率，K/阈值[待确认]。

### ADR-V2-07 纠错与来源失效传播

原需求依据：咨询总目录 8、CON-11/12、ADJ 总览 5、ENF-07。原方案问题：重跑覆盖人工结果或旧证据失效后仍可用于当前结论。新方案：事实/来源/规则/模板版本依赖边，事件触发受影响成果待复核或失效，无关成果保留。理由：局部重算才可解释。用户收益：纠错不从头来。Agent 收益：从失效节点继续。工程收益：可定位变更影响。复杂度：高。风险：漏边导致陈旧结论。依赖：来源稳定 ID、变更/撤回信号或读时核验。验收指标：注入源撤回/事实纠错的受影响传播覆盖率与误失效率；阈值[待确认]。

### ADR-V2-08 四类 Human Collaboration

原需求依据：CON-12、ENF-04/07/11、ADJ-12。原方案问题：“人工审核/转接”混合信息补充、范围授权、专业判定和接管。新方案：ASK 补事实，CONFIRM 确认范围/高影响选择，REVIEW 专业复核产物版本，TAKE_OVER 人接管执行与决策。理由：输入者、决策者和责任不同。用户收益：只被问必要问题。Agent 收益：可等待并回流。工程收益：权限与超时分流。复杂度：中。风险：审核队列不可用。依赖：人员/受理系统、SLA[待确认]。验收指标：错误自动代办 0、待办回流完整率、无人工时不伪受理。

### ADR-V2-09 规则和法条独立版本化

原需求依据：ENF-08/15/17、ADJ-01/05/06。原方案问题：法条检索相关度被当适用，模型算期限金额。新方案：原文/效力版本与领域已发布规则分开；规则携适用地域、时点、程序、例外、批准者和边界测试，冲突阻断发布。理由：原文权威不自动决定其对事实的适用。用户收益：算式与版本可核对。Agent 收益：明确何时无法判断。工程收益：规则回归。复杂度：高。风险：缺历史法、日历或裁量批准。依赖：法律/业务责任方。验收指标：固定边界样例一致性、误用历史版本率；未知时阻断。

### ADR-V2-10 最小共享内核、领域拥有语义

原需求依据：原 DOCX 三域不同流程；三域总览的版本、任务、证据与复核。原方案问题：41 套重复或一套万能状态都损失业务语义。新方案：共享 Task/Run/Source/Version/Review 基础协议，执法待证明事项和裁决采信等领域独有。理由：复用机制，不复用法律结论。用户收益：跨域体验一致而不混淆业务。Agent 收益：复合能力能调用专用 Skill。工程收益：独立测试。复杂度：中。风险：过早平台化。依赖：第二个真实消费者或明确公共不变量。验收指标：三域禁止跨用处罚/裁决状态和数据；共享变更的跨域回归通过。

### ADR-V2-11 任务级评测与安全门禁

原需求依据：各需求的专家标注集、异常、权限和 DM8 验收。原方案问题：单点“准确率”无法证明完成、可核验、安全或省时。新方案：离线固定任务集+真实影子/受控试点，分层报告质量、风险、工时、成本及失败，发布阻断严重违规。理由：效果是整个工作链的结果。用户收益：真实可用性可证伪。Agent 收益：识别错误的中间策略。工程收益：版本回归门。复杂度：中高。风险：样本偏差/指标投机。依赖：专家、许可、预注册指标。验收指标：任务完成/部分完成、关键漏检、无依据陈述、总工时、安全事件分别计；阈值[待确认]。

### ADR-V2-12 Studio/Release 与工作面分离

原需求依据：CON-09/10/11、ENF 规则配置、ADJ-10 模板。原方案问题：业务用户不应看到 Prompt/Intent/工具拓扑，管理员也不能草稿保存即上线。新方案：工作面完成任务；Studio 组合经批准的 Goal/Skill/Tool/Prompt/模型/规则依赖，Release 做试运行、评测、审批、灰度/回滚/紧急撤销。理由：运行与治理职责不同。用户收益：工作界面安静。Agent 收益：固定可信能力集合。工程收益：发布快照可追踪。复杂度：中高。风险：配置矩阵膨胀。依赖：有权发布者与回滚策略。验收指标：非法依赖无法发布、试运行不计正式量、紧急撤销阻断后续调用。

### ADR-V2-13 动态模型选择受数据政策约束

原需求依据：CON-09、三域模型使用/权限条款。原方案问题：一款模型全包和故障时无条件切外部模型都不可靠。新方案：先按任务所需能力及数据许可筛可用模型，再根据评测/成本/时延选择；任何未批准数据通道禁用。理由：能力与合法使用同时成立才可路由。用户收益：稳定且不泄漏。Agent 收益：工具失败可受控降级。工程收益：版本与成本可观测。复杂度：中。风险：模型切换造成语义漂移。依赖：数据分类、模型批准及实测画像。验收指标：不合规路由 0、同任务跨版本变化可追踪；成本/质量阈值[待确认]。

### ADR-V2-14 首条黄金任务及三域路线

原需求依据：CON-02/04/06/12 与咨询总目录 8；ENF/ADJ 各自完整业务链。原方案问题：全量平铺无法先验证用户价值，但仅做专利会隐性取消另两域。新方案：先验证内部专利技术参考的受限闭环，同时准备执法/裁决受限任务，随后按证据释放完整 41 项。理由：先验证高频可观察成果，再扩大高风险流程。用户收益：早见可核查成果。Agent 收益：先在低风险只读域打磨策略。工程收益：垂直切片降低不确定性。复杂度：高（全项目）。风险：真实数据/专家/合同交付时序不一致。依赖：责任方确定范围与数据。验收指标：首条真实任务的专家可用率/总工时、安全门通过；三域正式验收仍逐项独立。
