# 人工复核需求文档

模块标识：ADJ-12；对应原需求：一.1.1.1.1.3.3。  
版本：V0.1 技术评审稿；日期：2026-09-12。  
建设条件：中心主要通过 API 提供数据；国产化部署，业务关系型数据库固定为达梦 DM8。  
交付边界：对外交付服务及接口、部署和验收资料；自研前端仅供内部验证，不交付对外页面。

本文与[需求总览与通用约定](00-需求总览与通用约定.md)共同构成开发要求。字段中文名为业务契约，接口路径和英文名由详细设计统一。涉及事实的字段缺失时返回缺口，不以模型推测满足必填。当前未完成中心 API、模型或 DM8 实测。

## 1. 功能概述

由中心授权专业人员审核和修正法律条文匹配、引用、专利分析、证据意见及裁决报告，保留完整修改与决策依据。复核通过形成可进入正式办理流程的锁定版本；正式文件还需中心指定签发、签章或现有系统确认，不由模型自动完成。

本模块提供共用审核对象与报告汇总复核，可供 02 等模块复用技术能力，但知识解析审核与案件最终复核的状态、权限和责任分别管理。

## 2. 字段与状态

| 字段 | 说明 |
|---|---|
| 复核任务 ID、案件编号 | 稳定关联 |
| 复核对象类型、对象 ID/版本 | 报告、条文匹配/引用、专利或证据分析 |
| 复核内容、原始结果快照 | 固定被审版本和证据 |
| 提交人/时间、复核人/角色 | 按真实身份，不能模型填入 |
| 复核意见、修正内容、修正原因 | 逐项或全文，保留前后差异 |
| 复核时间、复核结果 | 实际操作时间 |
| 缺项/争议清单、处理状态 | 每项明确关闭或保留说明 |
| 依赖对象版本清单 | 判断审核是否仍有效 |
| 签发/正式文件状态及外部回执 | 与复核状态分开 |

建议状态：待复核、复核中、退回修改、通过、不通过、撤回、已失效。复核任务状态不等于案件已办结。

## 3. 审核流程与规则

1. 提交对象版本并执行完整性、权限和依赖检查，缺少必填或关键证据的报告阻止提交。
2. 按角色分配复核人员，领取与转派有记录，避免多人同时覆盖同一结论。
3. 核对事实、证据、技术对照、时点法规、引用格式及模板必填项；冲突与未决项必须逐项处理。
4. 专业人员填写意见，选择通过、不通过或退回；后两者须理由。通过也记录审核结论及采用的版本清单。
5. 复核中修正内容生成新修订，保留原始模型/人工版本；提交最终通过时必须针对已保存的修订版本，不能先审旧版后静默换文。
6. 退回后由承办人修改并重提，形成新的审核尝试，历史意见不删除。
7. 已通过版本被实质修改或依赖证据/法规/事实变更时标为待复核或已失效，禁止继续以旧审核结果签发。
8. 报告通过后锁定内容，按中心规则进入签发/正式文件形成环节，获得授权确认或真实回执后更新正式状态。

最终报告复核默认提交人与最终复核人分离，代审/多级审核按中心制度配置，不能允许服务账号或模型代替专业人员确认。中间技术标注的人员安排可单独配置，不套用为最终签发权限。

存在未核实的重要事实或引用时不能仅勾选“已阅读”绕过校验。专业人员可认定某事项不适用或资料已补齐，但须填写依据并保留证据关联。

## 4. 正式文件与归档衔接

- 未接通签发/签章系统时，提供已复核材料及待签发状态，不生成虚构签章、文号或“已送达”事件。
- 如采用线下签发，授权人员需登记实际签发信息和正式文件来源，经规则校验后确认，不使用一个普通“审核通过”按钮兼任签发。
- 外部签发响应不确定时进入待核实/待对账，不默认成功；请求幂等，回执关联正确报告版本。
- 正式文件一经确认锁定，后续更正采用新文件/补正流程，保留原文件；案件归档引用正式文件及审核链。
- 首版不自动发送通知、送达当事人或执行裁决。

## 5. 内部验证页面

复核待办列表按案件、对象类型、状态、人员和提交时间筛选。详情显示原始/修订结果、来源证据、引用、待处理项、版本差异及历史意见。

操作包括领取/转派、逐项核对、保存修正、通过、不通过、退回、撤回未完成申请、查看依赖变化及签发衔接状态。确认前显示正在审核的确切版本及变更摘要。

正式状态确认页面与复核动作分开，仅授权人员可操作；无外部接入时明确本地记录性质。

## 6. 服务契约

| 服务 | 输入 | 输出 |
|---|---|---|
| 提交/分配 | 对象版本、案件、人员、幂等键 | 复核任务或校验缺口 |
| 领取/转派 | 任务及并发版本、人员、理由 | 新任务状态或冲突 |
| 保存修正 | 被审版本、修改及依据 | 修订版本 |
| 提交决定 | 最终被审版本、动作、意见、依赖版本 | 决定事件或版本失效错误 |
| 查询审核链 | 案件/对象版本 | 尝试、意见、差异及依赖清单 |
| 正式状态登记/回执 | 锁定版本、授权动作、签发事实/源回执 | 正式状态或待对账 |

后端校验角色分离、案件权限、版本一致及依赖未变更。审核决定与对象状态更新原子一致，重复请求不重复通过。不得接受前端直接传入任意审核人冒用身份。

## 7. 国产化与 DM8 要求

DM8 保存任务、版本清单、意见、差异、决定及签发回执引用。验证多人竞争、审核事务回滚、依赖失效、幂等及审计不可覆盖；归档恢复后能追溯到原报告和文件。账号权限与数据库运维权限分别管理。

## 8. 验收要求

| 编号 | 场景与预期 |
|---|---|
| REV-01 | 对象及案件绑定正确，缺关键材料阻止提交 |
| REV-02 | 领取/转派防并发覆盖，最终审核角色分离由后端执行 |
| REV-03 | 修正保留前后版本，通过针对最终保存版本 |
| REV-04 | 退回/不通过理由必填，重提不删除旧意见 |
| REV-05 | 依赖变化使审核待复核，不能用旧批准签发新内容 |
| REV-06 | 通过与签发/送达分开，无真实回执不显示完成 |
| REV-07 | 正式文件锁定，补正与归档保留完整审核链 |
| REV-08 | 真实 DM8 和独立 API 验证原子决定、幂等、冲突及权限 |

## 9. 依赖与交付

依赖案件权限、各分析/报告版本、中心审核制度及可选签发系统。交付复核、修订、审计和正式状态衔接服务及验收记录。确认人员职责、多级审批、线下签发证明要求和外部回执协议；不默认具备签章或送达能力。
