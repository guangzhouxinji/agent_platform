版本：V0.2（技术评审初稿，补充国产化与达梦 DM8 约束）

## 1. 项目定位与交付口径

裁决中心通过 API 提供商标、专利、案例等数据；项目建设可独立调用的知识管理、检索比对、咨询及配置管理服务。同时开发内部前端页面，用于功能验证、联调、测试和演示。

- 对外交付：后端服务、接口说明、配置与部署说明、业务规则和验收记录。源码、镜像及其他载体按项目整体合同约定。
- 内部产物：各模块验证页面、测试及调试入口，不属于对外页面交付。
- 页面调用本项目后端，后端调用中心 API；中心凭据不进入浏览器。
- 后端不能依赖验证页面完成身份校验、业务校验、任务调度或数据维护。
- 每个小模块单独评审、估工、开发和验收，模块间按接口契约集成。
- 国产化部署为项目约束，当前业务关系型数据库明确采用达梦 DM8；各模块开发和数据库验收以实际 DM8 环境为依据。

本套文档沿用项目根目录“一功能一文档”的组织方式。原有法律法规管理、条文解析管理和条文要点管理文档不属于本次 12 项清单，继续作为已有资源需求；本次不改写其既有导入与编辑规则。

## 3. 共用业务规则

### 3.1 API 数据与本地内容

中心源记录保持只读；本地允许管理服务配置、派生索引、标注、任务、会话及报告。派生信息不能回写或覆盖中心原文。

数据接入默认按需查询。缓存、持久化、批量同步和索引建立必须确认授权、保留与刷新策略。中心查询接口不具备目标检索能力时，形成补建或范围调整决定，不能仅靠页面模拟或模型生成替代。

中心负责明确来源授权、数据覆盖及更新条件；项目负责接口适配、异常处理、范围展示、源引用和服务运行。双方共同确认字段缺口与专业评价标准。

### 3.2 来源、版本和权限

- 分开记录源更新时间、本次获取时间、任务时间和配置时间。
- 源记录、文献、配置、模型及规则使用可追溯标识；缺少源版本时可使用本次内容摘要值记录快照。
- 服务端在检索召回前过滤权限，读取原文、报告和消息时再次检查当前权限。
- 权限收紧或源内容撤回后，禁止向已失去权限者继续展示缓存、报告正文、引用片段及附件；保留受控审计记录不等于允许继续访问。
- 内部案件、用户技术方案和上传图片是否可发送至外部模型须在部署配置中明确；仅调用批准的数据处理通道。
- 不在日志中记录凭据，普通页面不显示系统模板、隐含推理或内部敏感堆栈。

### 3.3 异步任务契约

适用于检索、比对及其他耗时任务，具体模块可使用其子集：

| 状态 | 语义 |
|---|---|
| 排队 | 已接受，尚未执行 |
| 处理中 | 正在执行 |
| 成功 | 约定必需步骤全部完成 |
| 部分成功 | 有可用结果，但明确列出的数据源、对象或步骤未完成 |
| 失败 | 未形成可用结果，返回原因 |
| 取消 | 用户或系统终止，停止后续执行与结果发布 |

创建任务返回任务 ID，关闭页面不影响执行。幂等键按用户/调用方与操作作用域绑定；同键同内容返回原任务，同键不同内容返回冲突。重试创建关联的执行尝试，不覆盖已经完成的结果；取消后迟到结果不能将状态改回成功。

资料不足导致未执行核心分析时应返回需补充或不完整结果，不能用“成功”掩盖核心步骤缺失。超时、限流与部分成功必须可区别查询。

### 3.4 配置引用与发布

模板、意图、流程和智能体使用“稳定编号＋不可变版本”的引用方式。草稿编辑检查并发版本，发布前校验依赖。模板和意图先发布可用版本，流程引用后发布，智能体最后绑定完整版本组合，避免循环发布依赖。

普通停用限制新绑定，现有固定版本可继续使用；紧急撤销即时阻止运行，并使依赖该版本的智能体或流程进入可识别的不可用/回退状态。智能体整体暂停则即时阻止后续工具调用。

更新通过新版本发布；历史版本归档不破坏审计。只有明确执行的发布/回滚才能改变生效配置，不允许草稿保存自动影响正式服务。

### 3.5 评分及专业意见

检索相关度、技术对照评分、用户反馈和人工评测准确率是四种不同指标，不得互相替代。未标定的模型自评分不能直接作为可信百分数。

比对报告保留证据、缺失信息及复核状态。正式采用的意见由中心专业人员审核；人工复核意见单独记录，不覆盖系统原始输出。没有来源依据时不编造法律条款、案例和数据事实。

### 3.6 默认值与未决条件

文档中的分页、返回上限、文件大小及建议流程是可供技术估工的初版产品默认值，不代表已核实的中心 API 参数。具体接口 URL、认证、字段名、性能阈值和数据授权尚未提供，统一在联调中确认。

目标能力因上游限制不能完成时，验收标记为“未满足/待补齐”或“已书面调整范围”，不能仅靠隐藏按钮或显示不可用认定能力验收通过。图形检索和外观设计辅助比对尤其需要单独核验。

### 3.7 国产化部署与达梦 DM8 数据库

#### 3.7.1 已确认范围与环境基线

业务关系型数据库固定使用达梦 DM8，不再作为待选型项。具体 DM8 小版本、部署拓扑、字符集、大小写及兼容模式等实例参数尚需中心提供，不能自行修改生产实例参数来迁就应用。

国产操作系统、CPU 架构、JDK、应用服务器/运行方式、模型及推理硬件、文件存储和其他中间件的具体产品与版本尚未提供。技术需形成环境兼容清单，按中心实际环境验证；数据库适配通过不等于整个国产化环境已验收。

中心数据继续通过 API 接入，本要求不意味着直连或修改中心源库。未经授权的源数据仍不得落库，DM8 的采用不改变数据授权范围。

#### 3.7.2 存储及查询边界

- 本项目需要持久化的配置、权限关联、派生标注、任务、报告、会话、引用及业务审计记录使用 DM8。
- 获授权的源数据映射、快照或缓存若采用关系表持久化，同样使用 DM8；不要求为了使用 DM8 而复制全部源库。
- 图片、PDF 等二进制文件可使用中心批准的文件存储；DM8 保存文件标识、受控引用、版本和权限关联。文件存储的恢复须与数据库引用一致。
- 全文、向量与图像检索不视为 DM8 的默认已具备能力。优先调用中心 API；必须自建时核实实际版本能力或选择符合中心国产化要求的检索组件。
- 不将 MySQL、PostgreSQL、pgvector、Elasticsearch、Milvus、Redis 等产品预设为必需依赖。新增检索、缓存或消息组件须列明国产化符合性、目标环境兼容性、授权和运维要求，并经技术选型确认。
- 如存在派生索引，DM8 中的业务标识、版本及权限与索引须一致；索引失败或落后时能识别、补偿和重建。不得因索引陈旧继续返回已撤回或已失去权限的数据。

#### 3.7.3 数据库适配要求

| 项目 | 需求 |
|---|---|
| 驱动及连接 | 使用与 DM8 小版本、JDK 和部署架构匹配的驱动；验证连接池、事务、超时及重连；配置从后端注入，不硬编码凭据 |
| SQL 与持久层 | 对 ORM 方言、分页、排序、日期运算、聚合、批处理及手写 SQL 实测；不得原样照搬 MySQL 等专有语法 |
| 标识与唯一性 | 选定并验证主键生成方式；业务编号按字符串保留；用数据库约束或等效事务机制保障幂等及唯一性 |
| 字符与比较 | 验证中文、外文、特殊字符、名称包含查询、大小写及排序规则；空字符串与 NULL 的业务含义显式处理 |
| 长文本与结构化内容 | 模板、全文、报告、会话及嵌套特征不得截断；按目标实例选用经验证的长文本存储及序列化方式，不预设原生 JSON 类型/函数可用 |
| 时间与精度 | 日期和时间分别处理，明确应用时区、数据库存储及查询转换；分数精度按规则保存，不能因类型变化影响排序或判断 |
| 事务与并发 | 发布、审核、版本切换、消息幂等及任务状态变更须保持一致；验证回滚、锁等待、并发冲突和重试边界 |
| 建表及升级 | 提供 DM8 专用或经 DM8 验证的版本化脚本；区分空库初始化和已有库升级；升级失败提供经验证的恢复步骤，不假定所有 DDL 都可事务回滚 |
| 运行与维护 | 应用账号与建表/升级权限按中心规范分离；提供连接故障、空间增长、慢查询定位及保留清理说明 |

已有 MySQL 或其他数据库的脚本、配置与测试结果不能直接作为 DM8 兼容证据。技术实施时应先盘点现有持久层和迁移工具支持情况，再改造；本次更新仅约定需求，不代表代码适配已完成。

## 5. 建议开发与集成顺序

1. 核验 API 文档及真实样本，形成字段、筛选、全文、图片、授权和性能能力表。
2. 确认国产化环境清单与 DM8 实例参数，验证连接、持久层及初始化/升级方案；建立共用接口、权限、任务及来源规范，完成三类知识库。
3. 完成专利、商标及案例检索，再接入两类辅助比对；可独立的模块由技术团队按资源安排开发。
4. 发布首批提示词和意图，完善流程及智能体配置，串联多轮咨询。
5. 进行完整服务联调、专业样本评测、权限和异常测试，再归档验收材料。

所有 12 个模块均在本套需求范围内，开发顺序不代表将后续模块排除交付。图像等复杂能力须先验证可行性并单独安排资源。

## 6. 验收资料与共同口径

每个模块至少提交：

- 对照需求编号的实现清单及未满足项。
- API 调用样例、字段/错误码、状态和版本说明。
- 内部页面操作记录及脱离页面的服务调用结果。
- 真实数据样例及源结果对照，模拟测试单独标记。
- 本模块验收用例执行结果及异常、权限测试证据。
- DM8 初始化/升级脚本、版本及实例参数记录、配置说明、真实数据库测试和恢复演练证据，以及国产化依赖兼容清单。

功能验收按模块文档逐条检查。效果验收使用中心参与标注的固定样本集，记录样本版本、数据范围、配置/模型/排序版本，试测后约定阈值。统计必须包含分母、失败与资料不足数量，不得只报告成功样本。

性能验收须约定数据量、并发、中心接口限制、超时、首响应/最终完成耗时及可用性窗口；未试测前不承诺未经依据的统一准确率或秒级完成指标。

跨模块至少验证以下闭环：

1. 商标输入 → 相似检索 → 选定候选 → 辅助比对 → 对话引用报告。
2. 技术方案 → 专利检索 → 文献版本选择 → 技术特征对照 → 专业复核。
3. 咨询问题 → 补问 → 案例检索 → 查看原文 → 带引用回答。
