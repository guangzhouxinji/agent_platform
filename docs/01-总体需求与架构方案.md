# 三类知识产权智能助手总体需求与架构方案

版本：V0.4（保留纠偏基线，补V2服务边界）  
日期：2026-09-24

当前V2服务边界以[ADR-AGENT-DATA-01](54-三智能体与数据服务边界ADR.md)为准：三独立领域Agent＋一个按领域分模块的独立业务数据服务，全部业务持久化及恢复依据外置。下文V0阶段的“模块化单体待选”及ARC-03准入描述保留其历史适用范围，不覆盖本次技术定案；业务数据服务内部仍模块化起步。当前Task D、生产部署参数、许可和验收各自取证。

当前41项能力的逻辑详细设计入口为[docs/55](55-V2业务数据服务与运行恢复详细设计.md)及其关联的三域设计与验证迁移方案。具体命令、版本/事务、人工和失败恢复按该包审阅；文稿交付不改变docs/08中尚未通过的当前Task D，不将下文历史最小架构等同完整产品边界。

2026-10-05增量重构严格保持 **统一Agent Platform + Consultation / Enforcement / Adjudication三个独立Agent**，不是一个Agent加三个模块。当前共享机械内核及各域接线的技术边界见[Runtime ADR](adr/agent-runtime-kernel-20261005.md)，执行状态唯一见docs/08。各Agent独立Definition、Skill、Tool、Prompt/Policy/Evaluation版本及生命周期；共享内核不拥有领域数据、当前权限或正式决定，不允许跨Agent内部实现依赖。单进程开发运行不作为独立部署已验证证据。

## 1. 文档定位与信息性质

本文件是对三类助手 41 项原需求的总体技术归并，不替代 `requirements/`，也不确认中心尚未提供的业务事实。

- 原始业务需求：只以 `requirements/` 为准。
- 已确认业务决定：只以 `docs/02-待确认事项清单.md` 中附完整证据的结论为准。
- 技术设计：本文件中的分层、边界、端口和首期部署方向。
- 技术假设：模块化单体、异步任务、共享可信链等候选实现，须由真实约束和 Spike 验证。
- 待确认事项：中心 API、数据权限、角色、状态、规则、样例、模型和环境等，统一登记在 `docs/02`。

## 2. 技术总体判断

项目宜建设为“一套共享技术底座、三个业务域、多个可编排能力”，不按 41 项需求建立 41 套代码，也不把 Agent 当作业务域。

三个业务目标以原需求和 MVP 评审为准：

- 咨询域：围绕问题、检索、证据/来源、辅助分析和带引用回答形成闭环。
- 执法域：围绕线索、证据、证据链、辅助分析、人工确认和处理结果形成闭环。
- 裁决域：围绕案件、材料、法规/专利知识、辅助分析、报告和人工复核形成闭环。

机器结果均为候选、辅助意见或草稿。正式事实确认、证据采信、处罚、裁决、签发、送达、办结及归档由授权人员或权威系统负责，具体责任仍须结合原需求和 P0-09 确认。

## 3. 建设边界

原始需求已经明确两项环境方向：国产化部署、业务关系型数据库采用达梦 DM8。它们不是待选型建议；但 DM8 小版本、兼容模式、拓扑、驱动/JDK，以及国产 OS、CPU、中间件和实际环境仍需中心提供并完成验证。原始需求同时声明中心 API 能力、授权范围、业务规则和专业效果尚未实测或确认。

### 3.1 当前方案覆盖

- 对接中心允许使用的知识、案件、线索、证据和流程能力。
- 在授权范围内保存本地工作数据、派生结果、版本、引用、复核和审计证据。
- 提供检索、确定性规则执行、AI 辅助分析及草稿生成能力。
- 提供供中心系统调用的服务能力和内部验证入口。
- 在确认的国产环境和真实 DM8 上完成相应验证。

### 3.2 当前不得默认承诺

- 自建权威商标、专利、案例、法规或执法数据源。
- 未经授权缓存、索引、落库或向模型发送中心数据。
- 自动形成正式法律、处罚或裁决结论。
- 自动签发、签章、送达、归档或改变中心正式状态。
- 在接口、数据规模和部署条件未确认前冻结完整 API、物理模型、Runtime 或微服务方案。

## 4. 最小逻辑架构

```text
中心系统 / 内部验证入口
          |
Agent / Workflow（只编排）
          |
咨询域 / 执法域 / 裁决域（拥有业务语义和工作数据）
          |
知识 / 证据引用 / Task / Review / Version（按 MVP 复用）
          |
Identity / Rule / Search / Model / File / Center API 端口
          |
DM8 / 文件存储 / 检索 / 批准模型 / 中心适配器
```

依赖原则：业务域定义所需端口，适配器实现端口；Agent 不直接访问数据库、厂商 SDK 或中心写接口；共享能力不接管三个领域的业务决定权。

V2首期采用三Agent独立部署、业务数据服务内部模块化的边界，详见docs/54；未来按物理隔离、容量、故障恢复或团队所有权的真实约束拆域服务。原文业务端口与适配器依赖方向保持有效。

## 5. Agent 与最小运行记录

Agent 是能力编排者：选择经批准的 Workflow，组织授权工具调用，并把结果交回领域用例。权限、状态机、法律规则和正式决定不属于 Agent。

当前阶段只要求每次关键运行能够追溯：调用主体与组织、业务域/任务、输入与来源版本、实际使用的流程/规则/模型/工具版本、输出引用、时间和追踪号。具体对象名、字段、冻结时点和存储方式在 MVP 详细设计中确定。

运行记录不能作为历史权限凭证；读取历史内容时仍依据当前授权。这里是技术设计约束，不表示中心身份和 DataScope 模型已经确认。

## 6. 证据、引用与版本

三个业务域都需要“结果可说明来自哪里”，因此可以复用最小关系：

```text
Claim -> Evidence -> Source/Version -> Citation
```

- `Claim` 只是回答观点、分析项或报告草稿中的主张，不表示正式确认。
- `Evidence` 可支持、反驳或补充上下文；执法采信和裁决事实认定由领域模型扩展。
- `Source/Version` 标识实际使用的来源和版本或获授权快照。
- `Citation` 标识条款、页码、段落或其他可核验位置；不能定位时必须说明。

具体字段、证据合法性标准、保留期限和跨域访问规则尚待确认，不在本阶段固化。

## 7. AI、规则与人工边界

| 主体 | 可以做 | 不可以做 |
|---|---|---|
| AI | 理解、抽取、分类、总结、候选判断、辅助分析、生成草稿 | 授权、确定法定条件、推进正式状态、替代人工决定 |
| Rule/领域代码 | 执行已确认的资格、状态、流程、公式、期限或阈值 | 编造规则、事实或未配置例外 |
| Search/RAG | 在授权范围内召回知识和材料 | 宣称检索穷尽或将相关度直接作为法律结论 |
| 人工/权威系统 | 事实确认、采信、复核、正式审核和状态回执 | 由模型身份冒充执行 |

涉及处罚建议、有效性风险和裁决分析时，最低链路是“规则/授权检查 + 真实来源与证据 + AI 辅助分析 + 人工复核”，不得实现为 `LLM -> 最终结论`。

## 8. 数据、权限、状态和外部接口的事实检查

以下内容目前均不得写成已确认业务事实：

- 具体角色名称、层级、职责分离和 DataScope 表达方式。
- 中心对象字段、稳定 ID、版本、分页、错误、回执和写回能力。
- 业务状态名称、法定转换、期限、金额、阈值和例外。
- 缓存、全文落库、索引、文件下载、模型使用、数据出域和保留期限。
- DM8 版本、兼容模式、技术栈、检索产品、模型、文件存储和部署拓扑。

在 P0 结论到位前，只能定义拒绝越权、不得伪造权威结果、保留来源和不覆盖历史等安全边界，以及不含业务语义的可逆接口适配骨架。

## 9. 三个 MVP

具体闭环、范围和验收入口见 `docs/06-三个MVP闭环与状态机.md`。V0/合成范围可从明确标识的 V0 样例倒推最小领域对象、Task、接口和数据；真实接入和专业效果验收再从固定真实样例倒推，不先建设通用 Runtime 平台。

## 10. 架构决策状态

| 决策 | 性质 | 当前状态 |
|---|---|---|
| 一套平台承载三个业务域 | 技术设计 | 待 ARC-03 评审 |
| Agent 只负责编排 | 架构护栏 | 保留 |
| 业务域通过端口访问外部能力 | 架构护栏 | 保留 |
| 业务、Task、Review、正式状态分离 | 架构护栏 | 保留，具体状态待确认 |
| Claim/Evidence/Source/Citation 最小关系 | 技术设计 | 按 MVP 验证 |
| 模块化单体起步 | 技术假设 | 待环境和技术栈验证 |
| 完整 Runtime、统一 API、完整物理模型 | 延后设计 | 不在 ARC-03 冻结 |

## 11. 进入后续工作的条件

当前可以进入 ARC-03 的边界评审，但不能宣告通过。通过后按当前 MVP 分层推进：明确的 V0 样例 -> 最小领域模型 -> 具体 Task -> 必要 API/数据设计 -> 合成或授权测试实现；真实样例、真实接入与专业效果验收在其对应阶段补齐。

权限、数据使用、业务/法律规则、正式状态或中心回执未确认时，只停止依赖这些事实的真实数据、正式流程和生产实现；不受影响的 V0 样例、端口边界、纯逻辑和可逆技术验证可以并行。
