# 执法 ENF-RULE-V1 开发规则基线 ADR

版本：D1，2026-09-27。性质：项目技术与开发期专业规则候选，不是原始需求、法规原文、正式执法规则或业务验收结论。任务状态仅见 docs/08。

## 1. 决定与来源

项目负责人于 2026-09-27 明确：执法 V2 不以真实数据源、真实身份权限或业务方逐条交付专业规则作为开发前提；项目参考成熟知识产权产品的规则管理做法及可核验的中国公开资料形成自有 `ENF-RULE-V1`，要求可解释、可追溯、可配置，并容许后续业务修订。决定证据和适用范围见 docs/02 第36节。本 ADR 是项目推导，不将产品惯例、历史案例或开发规则说成法定标准。

原需求范围：ENF-02/06/08/10/13/15 的规则配置和 ENF-03/07/09/11/14/16/17 的受控使用，见 `requirements/知识产权执法助手/` 对应编号原文；逻辑边界见 docs/57 第2～4节。公开材料的已采集候选、用途与审核状态见 docs/60 和各来源 manifest；例如国家知识产权局第81号令公告及所附《专利纠纷行政裁决和调解办法》目前仍是 `REVIEW_REQUIRED`，不得仅凭采集成功发布为可执行规则。成熟产品实践在本版仅落实为规则草稿/试跑/发布版本分离、逐项依据、解释轨迹、缺口和人工复核的设计选择；未完成具体竞品逐项核查，不声称竞品背书。

## 2. V1 规则合同

一条候选规则至少保存 `ruleId`、`family`、`revision`、`status`、`scope`（行为/案件类型、地区、机构、程序）、`validFrom/validTo`（未知可空但不能发布依赖时点的分支）、`basisRefs`（来源系统、稳定标识、版本、原文定位、摘要、效力时点核验结果）、输入字段与来源用途、类型化条件树、例外/冲突优先级、输出类别、缺项策略、试跑样例及期望、作者/复核者和变更理由。草稿可不完整，试跑固定输入与规则版本且无业务副作用；发布前检查来源许可和现时可用、依据效力/范围、字段类型、例外、冲突和边界样例。发布版不可原地修改，停用只阻新运行，历史运行固定规则/来源/输入摘要与逐条件轨迹。后续业务修订产生新版本、影响分析与回归，不覆盖旧输出。

解释轨迹按 `ruleId@revision -> scope/effectivity -> basis locator -> input source/version/locator -> condition result -> missing/conflict -> candidate output` 留存。字段缺失为 `UNKNOWN`，源不可用为执行失败，范围不匹配为 `NOT_APPLICABLE`，均不得转成“通过”或“无违法”。重叠适用规则没有确定优先依据时拒发布或返回冲突，不默认选更重、更轻或最新版本。AI 可抽取候选及解释，不写规则依据、审核或正式决定。

## 4. 开发与验收边界

开发阶段使用显式开发开关和服务端可信的具名开发身份，人工操作能力全开但仍保留动作/资源检查、审计、版本和必要的两人复核；Agent、模型、服务作业均不能借开发身份代签。项目原创合成数据可按需准备；公开/第三方资料逐包审查用途，甲方真实数据到位后经独立适配器及许可切换，不将开发 grant 迁入生产。

当前可做候选规则编辑、静态配置校验、合成样例试跑与解释轨迹设计；任一业务 API、迁移或可执行规则分支仍须按 docs/08 的独立窄 D 门登记并通过。规则内容、时点、权限、真实效果及正式岗位在实际来源/责任方到位时逐项复核；C 的合成结果不等于真实 I、专业 V 或业务 A。

最小反例：失效/漂移来源、未知范围、缺必需字段、互相冲突规则、同输入不同版本、旧结果重算、缺反证、日期无日历、金额无舍入、试跑意外创建线索、开发身份伪造、Agent 代审与历史被覆盖。每条均须观察解释轨迹和零禁止副作用；未覆盖时不能发布对应分支。

## 5. 离线草稿结构校验窄 D（2026-09-27）

仅为 `ARC-ENF-RULE-OFFLINE-D-01` 定义可逆的本地开发工具，不读取业务库/签入观察、不开 HTTP、不加载法律依据正文、不试跑条件、不产生规则发布或线索。输入是操作者显式提供的单个 UTF-8 JSON 文件；工具不递归扫描目录，不修改输入或其它文件，stdout 输出诊断，进程退出码 0/1 分别代表结构合格/不合格。可用于检查草稿是否把第2节所要求的可追溯字段明确写出，不能检查字段内容是否合法、来源是否获准或规则专业正确。

结构版本固定为 `schemaVersion: 1`；只接受顶层普通对象、已知键、`status: "DRAFT"`、第3节六个 `family` 值之一、非空 `ruleId` 和正整数 `revision`。`scope`、`basisRefs`、`inputs`、`condition`、`exceptions`、`output`、`missingPolicy`、`examples`、`author`、`reviewer`、`changeReason` 均必须显式存在；草稿允许这些字段为 `null`，但拒绝布尔值/数值/字符串的错误容器类型。`scope`/`condition`/`output`/`missingPolicy` 是对象或 null，`basisRefs`/`inputs`/`exceptions`/`examples` 是数组或 null，作者/复核者/理由为非空字符串或 null。`validFrom`/`validTo` 为 null 或严格 `YYYY-MM-DD` 且是有效公历日期，双端已知时必须前不晚于后；未知时点保留 null，不推定适用。对于数组内部及条件树仅确认 JSON 值可解析，不推断合法字段、阈值、优先级、依据效力或解释轨迹。这些都是后续发布 D 的独立阻断，工具返回 0 也不赋予规则可执行性。

文件大小上限 64 KiB，严格 UTF-8（含非法字节拒绝），重复 JSON 键拒绝以避免解析覆盖和审计歧义；未知顶层键拒绝，禁止 `PUBLISHED`、`ACTIVE` 等状态。诊断只报路径和字段/错误代码，不回显可能包含来源或业务文本的值。负例覆盖缺项、未知字段、重复键、非法 UTF-8、超限、无效日期、非法状态/类型；正例仅为项目自造空草稿，不含实质法条/阈值。工具不得改写 manifest 或 docs/08 状态；接入全局验证时也只跑静态工具自身的自测，不以空草稿证明业务需求实现。

本窄 D 的可测试边界与第2节可配置合同一致，但刻意不验证 legal semantics；共享身份、恢复、签入资料用途与材料 D 均不作为本地纯结构校验的运行依赖。一旦要保存、试跑、发布、与执法材料关联或提供 API，须另立带真实来源/权限/事务/规则正反例的 D，不能继承本节的通过结论。
