## 4. 场景一：复合任务状态聚合

输入：子任务 A 已完成，B 等待确认，C 技术失败。

| 检查项 | 唯一结果 |
|---|---|
| 主任务状态 | `部分完成`，命中聚合顺序 3 |
| 子任务状态 | A 已完成；B 等待确认；C 技术失败，均独立保留 |
| 独立原因 | B 保存待确认事实/范围/动作；C 保存模型/工具/系统故障及失败执行 |
| 用户下一步 | 可确认或拒绝 B；可请求/允许 C 按恢复点恢复；不得重复要求 A |
| 恢复目标 | C 的失败前任务版本、子任务、旅程步骤、依赖版本和未完成命令 |
| 可继续项 | B 的非依赖准备、C 的合法恢复和其他无依赖子任务；A 默认不重算 |

反向结论：行为唯一，没有第十状态。技术失败恢复只重做未提交或已失效动作；取消优先后不启动新工具。DG-P1-01 关闭。

## 5. 场景二：跨轮“第二个结果”

输入：第 1 轮产生结果集 V1，用户将“第二个”绑定到 V1/P-B；系统重启；第 2 轮产生结果集 V2；用户说“刚才第二个”。

已成立的记录链：

```text
task/branch/version
 -> focus version
 -> reference binding(V1, ordinal 2, P-B)
 -> candidate selection
 -> result-set lineage(V1 -> V2)
```

已通过部分：

- V1 的序位 2 永久绑定 P-B，不因 V2 重排而改写。
- 重启后可恢复 V1、绑定和候选身份。
- V2 有独立结果集版本、父版本和策略变化。
- 一旦焦点版本确定，`task → resultSet → version → candidate` 可唯一得到。

未通过部分：

- `docs/38` 3.1 只说明焦点来自最近用户明确选择或无歧义指代。
- 产生/展示 V2 本身是否形成新的当前焦点、仅展示是否足够、用户是否必须显式选择 V2，均未定义。
- `docs/40` 8.4 表述为“若焦点仍是 FP2则绑定旧版；若焦点已明确切换至 V3则形成新绑定”，没有决定本场景属于哪一分支。

因此同一输入可能被实现为继续引用 V1/P-B，也可能引用 V2 的第二候选。V2 不会改写 V1，但“刚才第二个”当前应指向哪一快照仍不唯一。DG-P1-02 未完全关闭。

## 6. 场景三：用户纠正

输入：特征 A → 检索结果集 V1 → 对照 V1 → 回答 V1；用户将 A 纠正为 A2。

| 传播阶段 | 设计结果 |
|---|---|
| 新事实 | 创建纠正版本，引用被替代事实 A、纠正前任务版本和依赖图版本 |
| 直接失效 | 依赖 A 的查询输入、检索执行当前有效性、充分性评估 |
| 传递失效 | 依赖受影响结果/特征的候选选择、对照项、实质陈述和回答当前版本 |
| 保留 | A 无关事实、资料、结果分支、证据、已完成子任务及全部历史身份 |
| 重检 | 核心特征变化形成新检索命令和结果集 V2；不重放无关检索 |
| 重算 | 只重算依赖 A 的对照项、充分性评估和回答陈述 |
| 新旧关联 | 纠正、失效集合、仍有效集合、重算命令和新产物均引用父版本 |

反向结论：可以审计并重放 `纠正 → 直接依赖 → 传递依赖 → 失效/保留 → 重算`，没有全量清空。该部分通过。

## 7. 场景四：来源突然失效

对来源撤回、来源版本失效和 DataScope 收紧分别重放：

1. 权威通知或读取/继续时的主动重验形成逻辑变化事件。
2. 按权威事件身份与变化版本去重；同身份异内容进入冲突。
3. 通过来源→证据→结果集/陈述/对照/评估的反向依赖定位受影响产物。
4. 受控或失效内容立即停止当前展示/消费，生成当前可用性变化；不相关分支继续有效。
5. 依赖证据的对照和充分性评估局部失效并重评，回答陈述降级，不原地改写旧回答。
6. 活动任务立即显示提示；结束任务在下次合法访问时提示。
7. 来源身份、旧版本、原判断和传播历史保留，服从当前权限与保留政策。
8. 有合法替代路径则继续，否则按九状态聚合；只有正式/高风险/用户要求等既有条件才进入人工。

资料重新可用或权限恢复只恢复重新核验资格，不自动复活旧证据、评估或回答。反向结论：DG-P1-04 关闭，且“历史可审计 ≠ 当前可继续使用”成立。

## 8. 场景五：并发与重复命令

输入：A 基于任务 T7 纠正特征，B 同时基于 T7 确认旧特征。

| 情况 | 唯一行为 |
|---|---|
| A 先提交 | 形成 T8 和新事实版本；B 的 expected version T7 过期 |
| B 后提交 | 拒绝写入，返回当前 T8、冲突对象及需重新读取/确认；不得覆盖 A |
| 同一命令同载荷重复 | 返回原结果，不重复产生产物或事件 |
| 同 command identity/幂等键不同载荷 | 载荷冲突，不选择任一载荷覆盖 |
| 旧任务/对象/依赖版本 | 拒绝写入并返回当前版本及冲突 |
| 合法重试 | 沿用原命令、范围、权限和依赖；扩大范围/权限必须新命令并确认/授权 |
| 迟到确认/选择/工具/人工结果 | 保留到达事实；依赖仍有效才可提交，否则只进冲突/历史 |
| 权限 | 命令接收、外部调用前及受保护结果提交前按当前权威重验 |

反向结论：行为唯一，不允许最后写覆盖。锁、超时、自动重试次数和容量仍由 OQ-NFR-01 控制。DG-P1-05 关闭。

## 9. 状态聚合复核

- 主任务一个版本只有一个九状态。
- 已完成 + 任一未完成主要子任务统一为部分完成，并逐项展示未完成原因/动作。
- 没有完成项时按人工、等待确认、等待补充、进行中、技术失败、证据不足的明示顺序聚合。
- 无结果、无权限、来源失效、证据不足和技术失败是分别保存的原因/执行语义，不新增产品状态。
- 技术失败保存精确恢复点；取消与工具完成按先提交任务版本排序。

未发现不可达/无法退出状态或部分完成错误升级为已完成。该修正通过。
