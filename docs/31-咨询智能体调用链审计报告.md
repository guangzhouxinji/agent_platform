# 咨询智能体调用链审计报告

审计日期：2026-09-22  
审计性质：第二阶段真实性审计，静态代码追踪 + 当前运行实例只读核验  
审计范围：咨询入口、专利检索、专利对照、模型答复、引用与来源  
审计限制：未提交新咨询、未新建任务、未改动业务代码、配置、数据库或总计划状态

## 1. 结论摘要

| 检查项 | 结论 | 真实性判定 |
|---|---|---|
| 专利检索是否真的查询数据 | 是。主咨询链调用持久化检索任务，当前实例针对 DM8 装载的 474 条 `PUBLIC_LOCAL` 专利记录执行检索；只读探测可见实际任务、命中数、候选和版本 | 真实执行，但数据是本地公开开发快照，不是中心权威全库 |
| 相似度计算是否真实执行 | 有实际计算，但不是语义相似度。当前算法是分词后在标题、摘要、权利要求中做字面包含匹配，再按固定权重累计分数并映射高/中/低 | 名称“相似度检索”强于实际能力；属于可运行的启发式文本匹配 |
| AI 模型是否真实调用 | 代码存在真实 HTTPS 调用；当前实例中 DeepSeek 凭据已配置，模型连接测试状态为 `SUCCEEDED`。总计划还记录过真实端到端调用 | 具备并验证过真实调用；本次审计未再次发起付费/外部模型请求 |
| 引用是否来自真实来源 | 引用 ID、版本和定位来自本次实际检索候选，并有候选白名单校验；候选来自公开数据快照。咨询来源抽屉只返回 ID、版本、定位，不返回原始网页/全文 | 来源标识真实且可追踪，但咨询界面的可核验深度不足，不能等同于完整原文引用 |
| 答案是否基于检索结果 | 是。模型提示包含候选的来源 ID、版本、定位、匹配依据及证据文本；模型引用必须落在候选集合内。模型不可用时保留候选并披露失败 | 当前模型答复链基于检索结果；固定回退文案不是模型分析 |
| 是否存在独立 Agent Runtime | 否。没有独立通用 Runtime 对象；实际编排由 `DailyConsultationService`、意图解析器和 `DailyConsultationToolRunner` 完成 | “智能体”是服务编排形态，不是独立运行时平台 |
| 当前总体可用性 | 日常咨询的专利检索和带证据答复可运行；专业检索效果未验证；专利对照页面在当前公开数据适配器下无法自动产生待确认特征，前端闭环受阻 | 开发期可用，不能评价为生产可用或专业可用 |

最关键的真实性边界是：系统不是“假返回”，但也不是专业检索引擎。它真实读取本地公开数据、真实执行字面匹配、真实持久化任务、可真实调用模型；其召回、排序、相似度和引用深度仍是开发期能力。

## 4. 功能逐项审计

### 4.1 日常咨询统一入口

1. 用户入口：`/app/consultation`，无 `flowId`。
2. 前端文件：`DailyConsultationChat.tsx`；提交问题和历史问题文本作为上下文。
3. 后端接口：`POST /api/v0/consultations/daily`。
4. Service 调用：`DailyConsultationService.submit` -> `ConsultationIntentParserService.parse` -> `ExternalModelIntentAdvisor.advise` -> `DailyConsultationToolRunner.run`。
5. 实际 Adapter：按意图分别进入专利、商标、案例服务；意图模型通过 `ManagedModelConfigurationService` 获取模型端点。
6. 数据来源：用户问题、前端仅传问题文本形成的上下文、开发期意图契约、各领域本地知识库。
7. 是否真实运行：是。当前实例已配置工具目录和模型链；HTTP 测试覆盖专利、商标、案例路由。
8. Mock/Fake/Hardcode：固定规则解析器始终先运行；模型失败静默回退 `FIXED_RULE_FALLBACK`。总结和限制语句是固定模板。不存在独立 Agent Runtime。
9. 当前可用性：可用于开发期统一入口；多轮上下文只传历史“用户问题”，不传历史答案，不能视为完整会话记忆。

### 4.2 专利相似检索（咨询内）

1. 用户入口：默认咨询页输入专利技术描述。
2. 前端文件：`DailyConsultationChat.tsx`。
3. 后端接口：`POST /api/v0/consultations/daily`，下游内部调用核心咨询服务；来源复核为 `GET /api/v0/consultations/{consultationId}/source-links/{sourceLinkId}`。
4. Service 调用：`DailyConsultationToolRunner.patentSearch` -> `ConsultationApplicationService.submit` -> `PatentSearchPort.search` -> `PatentSearchApplicationService.createForConsultation` -> `PatentCatalogPort.search`。
5. 实际 Adapter：当前配置 `consultation.search.provider=task`，使用 `TaskBackedConsultationPatentSearchAdapter`；目录由 `PublicLocalPatentCatalogAdapter` 提供；任务和咨询记录可配置 DM8 仓储。
6. 数据来源：`Dm8PatentLibraryAdapter` 从 DM8 本地知识库读取公开专利快照。当前实例任务报告 474 条记录。
7. 是否真实运行：是。会创建真实检索任务，执行目录搜索并把任务 ID、候选顺序、来源版本回传咨询结果。
8. Mock/Fake/Hardcode：检索不是 Mock，但算法是硬编码启发式：分隔符切词，标题命中加 30，摘要/权利要求命中加 15，总分上限 100；60/30 为高/中/低阈值。最多返回 100 条。`SyntheticPatentCatalogAdapter` 和 mock-center 适配器仍存在，但分别由测试 profile 或显式配置启用，不是当前观察到的数据模式。
9. 当前可用性：技术上可用，能够对本地公开快照真实检索；不能称为语义相似度、向量检索、全库检索或专业查新。

### 4.3 独立专利检索工作台

1. 用户入口：`/app/search/patents`。
2. 前端文件：`frontend/src/features/search/SearchWorkspaces.tsx`。
3. 后端接口：`POST /api/v0/patent-search-tasks/preparations`、`POST /api/v0/patent-search-tasks`、`GET /api/v0/patent-search-tasks`、任务读取/取消/重试接口。
4. Service 调用：`PatentSearchApplicationService.prepare/create/execute`。
5. 实际 Adapter：准备阶段使用 `PatentAnalysisPort`；默认是 `DeepSeekPatentAnalysisAdapter`。检索阶段使用 `PublicLocalPatentCatalogAdapter`；仓储可用 DM8。
6. 数据来源：用户输入经模型提取后由用户确认的特征 + 474 条本地公开专利记录。
7. 是否真实运行：是。准备阶段会真实调用模型，创建后异步执行真实目录匹配。
8. Mock/Fake/Hardcode：无密钥时准备接口直接失败，不会伪造特征。匹配评分仍是固定字面规则。测试 profile 可切换合成目录。
9. 当前可用性：开发期可用；依赖模型可用性，且检索质量受字面切词和固定权重限制。

### 4.4 专利对照/“相似度计算”

1. 用户入口：日常咨询识别 `PATENT_COMPARISON` 后只返回候选并引导到 `/app/compare/patents`；独立页面也可直接进入。
2. 前端文件：`frontend/src/features/comparison/ComparisonWorkspaces.tsx`。
3. 后端接口：`POST /api/v0/patent-comparisons/preparations`、`POST /api/v0/patent-comparisons/tasks`、任务读取和历史接口。
4. Service 调用：`PatentComparisonService.prepare/create/compare`。
5. 实际 Adapter：`PatentComparisonSourcePort` 由 `PublicLocalPatentCatalogAdapter` 实现；任务仓储可为内存或 DM8。
6. 数据来源：用户选择的目标/候选专利及目标的已确认技术特征；候选权利要求文本来自本地公开记录。
7. 是否真实运行：后端确实逐特征执行 `claimsText.contains(feature.text())`；不是模型推理，也不产生数值相似度。日常咨询的 `PATENT_COMPARISON` 分支本身不执行对照，只执行检索并返回 `ACTION_REQUIRED`。
8. Mock/Fake/Hardcode：对照规则为逐字包含；关系只有 `CORRESPONDS/NOT_FOUND`。类中保留 `SYNTHETIC_CLAIM_COMPARE_V1` 常量；实际任务写入的是来源适配器的规则版本。公开数据适配器把 `featureTags` 构造成空列表。
9. 当前可用性：后端规则可运行，但当前 DM8/公开数据链的 `prepare` 会得到空的建议特征；前端没有新增特征按钮，随后创建会因 `FEATURES_REQUIRED` 被拒绝。因此当前普通用户的专利对照闭环不可用。即使手工构造 API 请求，也只是逐字核对，不是专业相似度分析。

关键代码：

- 对照实现：`backend/patent/src/main/java/cn/xinji/agentplatform/consultation/patentcomparison/application/PatentComparisonService.java:22-31`
- 公开记录的空 `featureTags`：`backend/adapters/public-source/src/main/java/cn/xinji/agentplatform/consultation/patentsearch/adapter/out/publiclocal/PublicLocalPatentCatalogAdapter.java:98-107`

### 4.5 AI 意图识别

1. 用户入口：所有日常咨询问题。
2. 前端文件：`DailyConsultationChat.tsx`。
3. 后端接口：仍为 `POST /api/v0/consultations/daily`，无单独外部意图 API 调用。
4. Service 调用：固定规则 `ConsultationIntentParserService` 先解析，随后 `ExternalModelIntentAdvisor` 产生受控候选，最后由 `DailyConsultationService.preferModelCandidates` 按契约复核。
5. 实际 Adapter：`ExternalModelIntentAdvisor` 直接使用 Java `HttpClient` 调用托管模型端点。
6. 数据来源：当前问题、历史用户问题文本、后端意图契约。
7. 是否真实运行：具备真实运行条件；当前托管 DeepSeek 已配置。模型候选为空、调用失败或输出不合规时返回固定规则结果。
8. Mock/Fake/Hardcode：存在固定规则回退；异常被捕获后返回空建议，不对用户暴露具体模型故障。槽位值必须能在用户文本/上下文中找到，降低模型编造风险。
9. 当前可用性：可用，但“模型候选已采用”只说明通过契约校验，不证明意图专业正确。

### 4.6 AI 答案生成

1. 用户入口：日常咨询中的专利/商标检索、案例参考；核心咨询提交也使用相同 `ConsultationAnswerGenerator`。
2. 前端文件：`DailyConsultationChat.tsx`、带 `flowId` 时的 `ConsultationPage.tsx/CoreConsultation`。
3. 后端接口：`POST /api/v0/consultations/daily` 或 `POST /api/v0/consultations`。
4. Service 调用：`ConsultationApplicationService.search` -> `ConsultationAnswerGenerator.generate` -> `ModelChainConsultationAnswerGenerator`。
5. 实际 Adapter：`OpenAiConsultationAnswerAdapter`，当前模型链指向 DeepSeek OpenAI-compatible API。
6. 数据来源：用户问题 + 实际检索候选。每个候选传递来源 ID、版本、定位、匹配依据和最多 2500 字证据文本。
7. 是否真实运行：代码真实发出 HTTPS POST；当前模型配置和凭据状态正常，且已有真实调用验证记录。
8. Mock/Fake/Hardcode：未配置托管模型时会使用固定文案“已根据当前输入整理可参考的候选信息”；模型链失败时返回固定失败文案，不伪造模型答案。模型成功后由代码追加引用和免责声明。
9. 当前可用性：当前实例具备可用条件；模型可用性仍受网络、额度、供应商和输出格式影响。模型答复是辅助文本，不是法律结论。

### 4.7 引用与来源复核

1. 用户入口：回答中的“查看来源”按钮。
2. 前端文件：`DailyConsultationChat.tsx:26-34,75`；核心咨询为 `ConsultationPage.tsx` 的来源抽屉。
3. 后端接口：`GET /api/v0/consultations/{consultationId}/source-links/{sourceLinkId}`。
4. Service 调用：`ConsultationApplicationService.readSourceLink`。
5. 实际 Adapter：`PatentSearchPort.isSourceAvailable` -> 当前任务目录 -> `PublicLocalPatentCatalogAdapter.isSourceAvailable`。
6. 数据来源：回答保存的 `sourceId/version/location` 与当前目录记录进行再核对。
7. 是否真实运行：是；不存在的、版本失效的或无权限的来源返回不可用。
8. Mock/Fake/Hardcode：模型引用必须属于本次候选集合，重复或越界引用被拒绝。来源链接对象本身由后端针对候选生成 UUID；它不是原始文献链接。
9. 当前可用性：具备来源身份和版本复核能力，但接口响应只含来源编号、版本、定位。前端没有展示原始 `sourceUrl`、摘要/权利要求原文或哈希，因此只能证明“引用了哪条本地记录”，不能让用户在咨询页直接核验原文内容。

## 8. 最终审计判断

咨询智能体的核心专利问答链不是 Mock 演示：它已经贯通 React 页面、HTTP Controller、应用服务、任务编排、端口、DM8 本地公开数据、检索结果、模型适配器、引用校验和返回展示。当前实例也能读到 474 条专利上的真实任务结果与已配置的 DeepSeek 模型。

但以下表述不成立：

- “已经实现专业专利相似度计算”：不成立，当前是字面匹配和固定权重。
- “已经接入权威专利全库”：不成立，当前是本地公开开发快照；pilot 动态源也不是中心权威数据。
- “引用已完整回链原始证据”：不成立，咨询页只展示本地来源 ID、版本和定位。
- “专利对照页面当前可正常完成”：不成立，当前真实数据适配器下存在空特征导致的前端阻断。
- “存在成熟的独立 Agent Runtime”：不成立，当前是应用服务级编排。
- “模型可用即代表答案正确”：不成立，模型调用真实性与专业正确性、召回率、法律有效性是不同问题。

综合评级：**开发期真实可运行，专业与生产可用性未成立**。
