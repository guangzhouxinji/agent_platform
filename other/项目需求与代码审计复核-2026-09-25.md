## 结论与证据边界

项目的 41 项原需求已有可追溯契约（R 门 41/41），但近期 13 项完整范围 D 门 0/13，API/数据和代码的整项双向追踪、偏移检查、业务验收均 0/41。当前主任务是 `RUN-CON-FIRST-VERTICAL-01`：V2 咨询的开发期身份/用途边界、DM8 任务核心、固定合成文本结果/焦点、只读证据准备及固定三候选的人工确认已有窄切片验证；完整检索、专业技术对照、纠正、人工处理、分层成果和工作面没有形成同一路径的可用任务。执法、裁决 V2 纵向闭环也未交付。此结论来自 [总计划第0、4节](../docs/08-总开发实现计划.md)，不是由“代码文件数量”反推完成率。

本次运行 `node scripts/verify-all.mjs` 通过：47 份基线文件和 41 行台账一致，结构检查通过但报告 53 项文件长度软限制警告；计划健康度 64/100、18 项警告。`npm test -- --run` 为 4 个前端测试文件/4 项通过；`mvn -f backend/pom.xml -pl apps/platform-api -am test '-Dtest=DevTaskCoreHttpContractTest' '-Dsurefire.failIfNoSpecifiedTests=false' -q` 通过，测试启动日志明确使用 `test-synthetic` 与 H2。没有在本轮运行完整 Java、Playwright、真实 DM8、恢复/性能或专业评测。治理脚本证明结构和摘要一致，不证明法律、业务语义或生产安全。

## 按严重度排列的发现

### P0：V0 裁决入口不能作为可信人工复核入口

[`AdjudicationController`](../backend/adjudication/src/main/java/cn/xinji/agentplatform/adjudication/adapter/in/web/AdjudicationController.java) 第 12、21-31、95-105 行注册 `/api/v0/adjudication/work-items` 等路由，直接读取调用方提供的 `X-V0-Actor`；默认 [`V0AdjudicationAuthorizationAdapter`](../backend/adjudication/src/main/java/cn/xinji/agentplatform/adjudication/adapter/out/synthetic/V0AdjudicationAuthorizationAdapter.java) 第 6-8 行以该字符串等于 `v0-adjudication-reviewer` 判定“可信人工”。[`ApiScopePolicy`](../backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/security/apikey/ApiScopePolicy.java) 第 14-24 行的保护前缀不含裁决路由，且 API Key 过滤器仅在 [`ApiAccessConfiguration`](../backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/security/apikey/ApiAccessConfiguration.java) 中 `api-access.enabled=true` 才创建；默认配置为 false。故即便打开该过滤器，它也不保护此裁决前缀。原需求 [`人工复核`](../requirements/知识产权裁决助手/12-人工复核需求文档.md) 第 23、43、74 行要求真实身份、职责分离和不得由前端任意指定复核人。**这是 V0 接口的真实信任边界缺口，不等于已发生生产越权**；上线暴露范围尚未核实。处置：隔离/禁用 V0 裁决写入口，直到有服务端可信身份绑定及路由级负向测试；V2 裁决另过其独立 D 门，不把旧头直接复用。

### P1：默认 V0 内存持久化与重启恢复目标不相容

[`AdjudicationStorageConfiguration`](../backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/config/AdjudicationStorageConfiguration.java) 第 15-18 行在未设置 `adjudication.storage` 时选择内存，咨询、执法和多个检索/对照配置也有相同 `matchIfMissing=true` 模式。若将 V0 路由当成持久业务服务运行且漏配 DM8，会在重启后丢失该内存工作数据。应对拟部署入口增加显式存储类型和启动期拒绝/告警，并做重启验收；不建议现在一刀切删除供合成测试使用的内存实现。**此项不适用于 V2 咨询 DB 核心**：[`V2ConsultationBoundaryConfiguration`](../backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/security/v2/V2ConsultationBoundaryConfiguration.java) 第 68-74 行直接装配 DM8 Store 且要求时区配置；旧报告将两者混同。

### P1：合成来源可由非测试 profile 显式选中，运行边界未全域统一

[`AdjudicationApplicationConfiguration`](../backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/config/AdjudicationApplicationConfiguration.java) 第 40-45 行在 `!test-synthetic` 下仍允许 `adjudication.source=synthetic`；其默认数据库来源在缺少 DataSource 时返回不可用适配器（第 47-53 行），不能概括成“默认使用合成来源”。V2 咨询则有 [`V2ConsultationBoundaryConfiguration`](../backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/security/v2/V2ConsultationBoundaryConfiguration.java) 第 37-42 行的 `prod` 拒绝及合成 profile 要求，默认开关也为 false。风险是 V0 显式误配或旧路由混入部署，而非 V2 默认泄露。建议建立部署配置断言：非隔离环境不得激活 V0 synthetic/mock/fixture，并在响应和审计中保留来源模式；验证所有旧路由的实际可达性后再退役。

### P1：首条咨询任务的“已确认特征”仍不等于专业对照

原需求 [`专利检索`](../requirements/知识产权咨询助手/专利相似度检索需求文档.md) 第 103-110 行要求获准范围、可核验来源及召回/排序/证据评测；[`专利判断`](../requirements/知识产权咨询助手/专利相似度判断需求文档.md) 第 103-109 行要求确认目标特征、逐项候选证据及无法判断原因，权利要求级判断必须有权利要求文本。当前 V2 [`路由注册表`](../backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/security/v2/V2ConsultationBoundaryConfiguration.java) 第 130-161 行只列任务、固定文本结果、焦点、只读证据准备和特征确认；[`DevTaskCoreController`](../backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/security/v2/DevTaskCoreController.java) 第 38-82 行是任务/租约/清理命令。V0 的 [`PatentFixtureFlowController`](../backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/consultation/fixture/PatentFixtureFlowController.java) 第 18-23 行是 `test-synthetic` 下的本地样例接口，不能作为 V2 专业对照证据。专业对应方法、直接技术证据和效果阈值待业务/专业责任方确认；先完成来源/证据缺口与拒绝降级的窄 D，再在获准数据和专家标注集上验证，不以字符串匹配或合成候选评分宣称准确率。

### P1：数据、身份、文件与专业验收存在跨方依赖，不能以“功能先做”消除

[`待确认事项`](../docs/02-待确认事项清单.md) 第 21-267、449-476 行将中心 API、对象版本、用途许可、真实身份、文件保存、模型出域、角色与专业样例分别列为外部证据；计划第 0 节明确文件/备份物理 D、真实 I/B 仍未完成。原需求要求真实 DM8、受控文件引用、重启与权限反例（如 [`专利判断`](../requirements/知识产权咨询助手/专利相似度判断需求文档.md) 第 10-15 行）。因此“甲方先不给数据但要求完整功能/验收”作为**交付顺序是不充分的**：可做合成开发和拒绝路径，不能承诺真实召回、合法数据处理、当前权限或专业效果。应由数据/身份/文件/业务责任方逐项给来源、版本、责任人、日期、用途及预期样例；只释放对应窄 Task，不推高整项 D/V/A。

### P2：前端可操作样例与 V2 产品工作面易被混淆

[`AppRoutes`](../frontend/src/app/AppRoutes.tsx) 第 32 行挂载 `/consultation/patent-fixture`；[`navigation`](../frontend/src/app/navigation.tsx) 第 50 行只在开发环境展示菜单，后端控制器又限定 `test-synthetic`。这有清楚的开发用途，但路由存在不等于 V2 工作面完成，直接访问时仍需按后端模式处理不可用。计划第 0 节已明确 V2 工作面、人工与成果缺失。建议产品演示和测试报告始终注明 V0 fixture/合成模式；V2 首任务工作面应消费同一受控任务/来源/版本 API，并检验加载、失权、撤回、冲突、重启及部分成果，不从 fixture 页面推算产品进度。

### P2：工程负债与证据盲区

`verify-all` 的 53 项长度软警告集中在 DM8 Store、Controller、服务和测试文件，说明修改热点复杂，但**长度本身不是缺陷**；只在继续改动的事务/授权热点拆分并补跨实例、失败回滚测试。`git ls-files` 确认追踪了 `frontend/*.tsbuildinfo`、`frontend/vite.config.js/.d.ts` 和 `tmp/pdfs/dm8-sql-reference.pdf`，未确认“所有 target/、日志都被提交”；清理应单独评估生成物是否被流程引用，不能在本审计中删除。前端本轮只有 4 项单测通过，Playwright 未运行，不能以通过率推断业务交互充分覆盖。现有 Java 合成 HTTP 测试使用 H2，计划中的本机隔离 DM8 I 证据另有边界，两者不能互相替代。

## 需求合理性与取舍建议

原需求把 AI 限定为辅助、要求来源定位、人工复核、真实 DM8 与可追溯版本，方向合理；不能把“严格门禁”本身当需求缺陷。主要不合理处在**尚无外部输入时要求同时兑现三域完整工作、专业指标与正式验收**，以及未冻结身份/数据用途/专业样例却期待稳定生产承诺。比如检索需求第 110 行把 K 值和通过线交给真实标注证据决定，这是正确的开放参数，却使当前无法判定专业达标；裁决人工复核第 43、95 行依赖中心岗位和正式通道，开发期自报 actor 不可代替。需将合成 C、隔离 DM8 I、真实来源 I、专业 B、生产验收分成明确可交付层级，而不是降低要求或虚构阈值。

## 优先处理顺序

1. 在任何对外部署前，核实全部 V0 路由暴露面；首先隔离裁决自报人工入口及其未受 API Key 保护的路径，建立未授权/冒名负例。此项属于安全处置，不授权借审计报告直接实现新的业务权限语义。
2. 对拟保留的 V0 业务入口加入明确的持久化/合成模式部署检查；V2 咨询现有 fail-closed 和 DM8 约束保持，不做破坏性的跨域统一重构。
3. 沿总计划当前主任务，先完成技术对照证据及专业方法的 D 门，再串联纠正、人工、成果和工作面；每一窄片保留排除项和 C/I/B 分层证据。
4. 并行向责任方索取真实来源用途、身份撤权、文件/备份恢复和专家标注样例；无证据分支继续拒绝，不把结构校验或合成演示记作业务验收。

本报告未更改 `requirements/`、契约、任务状态或业务代码；所有建议须按总计划登记依赖、退出条件和状态后实施。
