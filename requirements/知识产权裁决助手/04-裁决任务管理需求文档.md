# 裁决任务管理需求文档

模块标识：ADJ-04；对应原需求：一.1.1.1.1.2.1。  
版本：V0.1 技术评审稿；日期：2026-09-12。  
建设条件：中心主要通过 API 提供数据；国产化部署，业务关系型数据库固定为达梦 DM8。  
交付边界：对外交付服务及接口、部署和验收资料；自研前端仅供内部验证，不交付对外页面。

本文与[需求总览与通用约定](00-需求总览与通用约定.md)共同构成开发要求。字段中文名为业务契约，接口路径和英文名由详细设计统一。涉及事实的字段缺失时返回缺口，不以模型推测满足必填。当前未完成中心 API、模型或 DM8 实测。

## 1. 功能概述与范围

管理知识产权行政裁决案件录入、受理记录、承办分配、进度及归档，为分析和报告提供统一案件标识及材料版本。案件业务状态、分析任务状态、报告审核状态分开维护。

案件主档优先由中心案件 API 提供，本地录入用于中心授权的服务内工作任务。接入外部办案系统时，以约定的权威系统记录为准；未接通写接口时只保存本地工作记录，不声称已完成正式受理、送达或归档同步。

## 2. 案件字段

| 字段 | 规则 |
|---|---|
| 案件 ID、案件编号、案件名称 | ID 稳定，编号按中心编码；本地临时号不得冒充正式编号 |
| 来源系统、源案件 ID、源版本 | 区分外部案件与本地录入 |
| 申请人、被申请人信息 | 主体标识、名称、联系方式、代表信息；按权限查看 |
| 案件类型、程序及管辖信息 | 按中心业务目录，案件是否属于行政裁决需人工确认 |
| 涉案专利/商标标识 | 支持多项，关联具体权利资料版本 |
| 核心事实、争议焦点 | 每项区分当事人主张、待核实事实与人工确认事实 |
| 收件、受理时间、承办人 | 实际事件与人员；不得推测生成 |
| 当前环节、处理进度 | 由确认的流程事件驱动，不以模型百分数表示 |
| 预计完成时间、期限依据及调整事件 | 工作计划与法定期限分开，后者须配置确认规则 |
| 案件资料版本、权限范围 | 分析输入冻结依据 |
| 归档状态、归档时间、材料清单 | 本地归档与中心归档同步状态分开 |

## 3. 生命周期与业务操作

建议本地状态：草稿 → 待受理确认 → 办理中 → 待报告复核 → 待签发/办结确认 → 已办结 → 已归档；不予受理、撤回、终止、中止等作为独立分支，按中心流程及授权启用。本状态模型是软件建议，不预设法定程序及期限。

- 录入或同步案件，校验双方主体、类型、材料及源标识；允许不完整草稿，但提交受理确认前校验中心规定必填项。
- 受理/不予受理由授权人员确认，记录时间、依据及原因；源权威系统模式必须获取真实回执后同步正式状态。
- 分配/转派承办人保留前后人员、原因和时间；未分配任务不能默认归属当前登录人。
- 案情补充或更正生成新资料版本，标识受影响的匹配、分析及报告待更新，旧结果不直接改写。
- 中止、恢复、延期等保存事件及依据；无已确认的期限规则时仅展示人工计划日期，不能计算“法定逾期”。
- 办结确认检查报告及中心要求的签发/办理材料；归档检查材料清单和未完成任务，缺项返回原因。
- 已归档案件只读，补正或重新开启须走授权动作并保留归档快照，不提供普通删除按钮。

## 4. 内部验证页面

案件列表按编号/名称、双方主体、类型、承办人、环节、受理日期和归档状态筛选。详情包含基本信息、当事人、事实/争议、权利资料、证据目录、流程时间线、分析结果、报告及归档材料。

操作包括本地录入、同步、提交受理确认、分配/转派、进度事件、补充材料、打开分析模块、办结确认、归档和授权补正。正式系统接口未接通时按钮和回执明确“仅本地记录”。

## 5. 服务契约与异常

| 服务 | 输入 | 输出 |
|---|---|---|
| 创建/同步案件 | 主档、来源、幂等键 | 案件 ID 及同步状态 |
| 查询/详情 | 条件、分页或案件 ID | 授权主档、环节与资料版本 |
| 修改资料 | 当前版本、变更项、理由 | 新版本、受影响结果 |
| 流程操作/分配 | 当前状态版本、动作、人员及依据 | 新状态或冲突、外部回执 |
| 归档/补正 | 案件版本、材料清单、动作原因 | 归档快照或缺项 |

记录归属、承办与操作权限由后端执行。外部状态同步采用幂等及对账，不在超时后默认成功；源失败不覆盖已确认信息。编号重复、非法状态跳转、缺材料、权限不足及冲突返回明确错误。

## 6. 国产化与 DM8 要求

DM8 保存本地案件、主体关联、资料版本、流程事件、分配及归档快照。验证多案件隔离、状态乐观并发控制、事件原子写入、编号唯一性及日期/联系方式完整性。外部同步回执可重试对账但不得重复推进流程。

## 7. 验收要求

| 编号 | 场景与预期 |
|---|---|
| CASE-01 | API 同步与本地录入正确区分，重复同步不重复建案 |
| CASE-02 | 不完整草稿可保存，受理确认校验必填与权限 |
| CASE-03 | 非法跳转被拒绝，转派/中止/恢复有事件依据 |
| CASE-04 | 计划日期不冒充法定期限，未配置规则不报法定逾期 |
| CASE-05 | 资料更正标识下游待更新，保留旧结果 |
| CASE-06 | 未接通外部写接口不声称已正式受理或归档 |
| CASE-07 | 归档缺项阻断，归档后普通编辑被拒绝 |
| CASE-08 | 独立 API 与真实 DM8 验证事务、状态竞争及案件隔离 |

## 8. 依赖与交付

依赖中心案件/人员/流程 API、业务流程及材料清单。交付案件与事件服务、主从系统规则、状态机和验收记录。确认权威系统、受理/期限/办结规则、写回范围和源回执；不默认自动通知当事人。
