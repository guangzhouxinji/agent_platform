# 咨询 MVP 领域行为与不变量

版本：V0.1  
日期：2026-09-15  
关联任务：ARC-05-CON-BEH  
历史范围：仅“专利相似检索/技术参考”咨询闭环；对象定义见 [12-咨询MVP最小领域模型](12-咨询MVP最小领域模型.md)，样例依据见 [11-咨询MVP-V0产品样例基线](11-咨询MVP-V0产品样例基线.md)。

本文件定义可由三个 V0 样例检查的领域行为，不是通用工作流、完整状态机、权限策略或工具实现方案。`R` 表示原始需求约束，`V0` 表示已确认的 V0 临时产品决策。

## 0. 负责人产品行为覆盖层（2026-09-22）

本节覆盖与历史 V0 限制冲突的产品行为；下文章节继续作为已有 V0 技术链的历史不变量。新的首段任务型闭环必须满足：

1. 用户通过自然语言目标进入专利资料查询、专利检索、技术对照或其复合任务，不要求选择内部模块。
2. 非关键字段缺失可先执行并披露限制；影响结果含义的关键缺失或冲突必须澄清。系统提取的关键技术特征在正式对照前由用户确认。
3. 授权范围内、只读、低风险、可恢复的能力可连续自动调用。同一范围内可改写查询、扩展同义词、切换获准检索方式、重排和深化证据。
4. 系统评价候选覆盖、证据充分性和冲突；有结果不等于完成。结果不足且仍可能获得新信息时继续检索，不设置固定业务轮数。
5. 摘要只支持初步线索；逐项技术对照和权利要求级回答必须有权利要求或等效直接证据。每项对照区分相同、差异和无法判断。
6. 用户纠正只使依赖该事实的下游结果失效；结果序号绑定稳定结果集快照；目标或对象变化按规则分支、重检或新建任务。
7. 任务状态使用 `进行中 / 等待用户补充 / 等待确认 / 部分完成 / 已完成 / 证据不足 / 需要人工复核 / 技术失败 / 用户取消`。完成同时要求主要目标、必要证据和限制披露。
8. 无结果、证据不足、无权限、来源失效、模型失败、工具失败和系统故障分别表达。正式法律/业务判断和重要未解冲突进入人工复核。

数据授权、真实身份/DataScope、保留期限、人工组织和专业指标数值仍待外部证据，不由本节推定。

## 1. 问题补充与澄清

触发：咨询会话接收到用户问题或补充。

| 规则 | 约束来源 | 可观察结果 |
|---|---|---|
| 保留原始输入及其来源；提取值必须标明来自哪个输入，模型推测不能成为确认条件 | R：CON-11 第 4、7 节；CON-12 第 3 节 | 会话中可回查用户原文与提取值来源 |
| 技术方案/核心特征或专利号码不足时，产生具体补问；已经确认的信息不得重复索要。仅缺少可选上下文且技术输入足以形成请求时，允许继续，固定在 V0 技术参考范围并披露限制 | R：CON-04 第 2、3 节；CON-11 第 3、4 节；CON-12 第 3、8 节；项目负责人 2026-09-19 V0 决策 | 必要缺失时产生“需要补充”的辅助回答，不创建检索请求；可选缺失时创建只含用户已给技术输入的有限检索请求 |
| 同一关键事实出现互相冲突的值时，保留每个值及其来源并请求确认；不得自动选择任一值 | R：CON-11 第 4、7 节；CON-12 第 3、5 节 | 冲突项和附件/消息定位可见，候选为空 |
| V0 只受理“专利相似检索/技术参考”；其他意图返回范围说明或澄清，不路由至未实现能力 | R：CON-11 第 1、3、7 节；V0 | 不调用商标、案例、相似度判断或其他工具 |

不变量：`检索请求.confirmedInput` 中的每个条件都必须能追溯到用户输入或用户明确确认；存在未解决的冲突或无法在不猜测条件下形成检索请求的必要缺失时，不能执行检索。可选上下文被跳过时，检索请求不得写入该上下文，结果必须标明范围受限。

## 2. 检索准入与授权门禁

触发：会话已具备可执行检索条件。

| 规则 | 约束来源 | 可观察结果 |
|---|---|---|
| 检索请求固定保存实际使用的确认输入、目的和用户请求范围；修改关键条件创建新的请求快照，不覆盖旧结果 | R：CON-04 第 2、3、6、7 节；CON-12 第 3、4 节 | 每次检索可回查其输入、范围和产生时间 |
| 在候选召回、文献读取和回答使用前，必须由授权能力做当前检查；意图识别和模型输出均不能扩大访问范围 | R：CON-04 第 3、6、7 节；CON-11 第 1、4、7 节；CON-12 第 1、3、4、7 节 | 拒绝时记录授权判定引用，不读取正文、不产生受限候选 |
| V0 对未知或无法判定的授权结果采取拒绝；真实角色、组织范围及 DataScope 不在当前模型中定义 | V0；P0-04 | 返回“无权限/无法访问”，不把技术故障伪装成无结果 |
| 执行结果必须区分无权限、来源不可用、工具故障、部分成功和真实无结果 | R：CON-04 第 6、7 节；CON-12 第 5、8 节 | 回答具有对应限制说明和追踪引用 |

不变量：`accessOutcome=拒绝` 时，检索候选集合为空，辅助回答不得包含受限来源正文、片段或由其推导的内容。

## 3. 候选形成与使用

触发：获授权检索返回候选，或候选在回答前再次校验。

| 规则 | 约束来源 | 可观察结果 |
|---|---|---|
| 候选必须关联专利标识、确切文献版本、匹配依据和来源定位；排序应说明依据和实际检索范围 | R：CON-02 第 2、4、6、7 节；CON-04 第 1 至 4、7 节 | 候选可回查文献版本和匹配位置，不伪造全文或评分 |
| 仅在有限候选内重排、上游截断或部分失败时，明确披露实际范围和未完成部分 | R：CON-04 第 3、6、7 节 | 不声称全库检索或穷尽现有技术 |
| 回答生成前重新检查候选来源是否仍可用；权限收紧或来源撤回后，不得从缓存继续使用或展示受限内容 | R：CON-02 第 2、4、6、7 节；CON-04 第 6、7 节；CON-12 第 4、5 节 | 候选标记不可使用并从回答依据排除 |
| 相关度只用于检索排序，不得写成侵权概率、新颖性、有效性或授权成功率结论 | R：CON-04 第 1、4 节；V0 | 回答保持“技术参考辅助信息”边界 |

不变量：辅助回答实际采用的每个候选必须属于其依据检索请求、当前可使用，且至少具备一个可解析的来源定位和匹配依据。

## 4. 辅助回答与专业边界

触发：检索完成、补问需要交付、授权被拒绝或来源在处理中失效。

| 规则 | 约束来源 | 可观察结果 |
|---|---|---|
| 回答只依据真实工具结果，分别标识检索发现、辅助说明、待核实事项和实际范围；关键内容附可解析来源定位 | R：CON-12 第 3、5、8 节；CON-04 第 3、4 节 | 带来源回答，或明确的补问/拒绝/降级说明 |
| 无结果不能表达为不存在相关技术；来源或工具失败不能表达为无结果 | R：CON-04 第 3、6、7 节；CON-12 第 5、8 节 | 输出“未查到/未完成/来源失效”等准确类别 |
| 回答不得编造专利号、原文、匹配片段、精确评分、法律条款或案例事实 | R：CON-02 第 2、6 节；CON-04 第 4 节；CON-12 第 3、5 节 | 所有关键事实均有来源；无来源时明确资料缺口 |
| 需正式采用的结果只能标记“需要专业复核”及原因；不得表示已转交、已受理、已审核或形成正式意见 | R：CON-12 第 5、8 节；V0；P0-09 | 回答保持辅助性质，未产生正式业务状态 |

不变量：带来源回答的 `sourceLinks` 必须覆盖每个采用候选的关键匹配说明；“无权限”回答不含候选引用；“来源失效”回答不含失效候选作为事实依据。

## 5. 三个样例验证

| 样例 | 应满足的不变量 | 不得发生 |
|---|---|---|
| 正常 | 条件来源完整；授权允许；候选版本、匹配依据和实际范围可回查；回答引用有效候选 | 法律结论、虚构评分、无来源匹配说明 |
| 资料不足/冲突 | 缺失目的和冲突温度均记录来源；产生补问；无可执行请求和候选 | 自动选定 80 或 120；把推测写为用户确认；伪造检索完成 |
| 无权限/来源失效 | 拒绝时无受限候选；失效候选从回答依据排除；回答准确区分类别 | 绕过授权、缓存泄露、把失败说成无结果或权利失效 |

## 6. 明确不处理的原需求范围

当前行为设计不覆盖：专利号码多候选选择、外观设计图像检索、数值评分标尺、相似度判断、完整会话并发/重连/取消、流程和智能体配置发布、人工转接、真实授权规则、保留期限、真实中心 API 及专业效果评测。这些原需求仍保留在对应 `CON-*` 契约和计划台账中，不能因 V0 闭环存在而标记完成。
