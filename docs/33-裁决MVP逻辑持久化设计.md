# 裁决 MVP 逻辑持久化设计

版本：V0.1  
日期：2026-09-16  
关联任务：`ARC-10-ADJ-LOGICAL`  
前置：`docs/29-裁决MVP-V0产品样例基线.md`、`docs/30-裁决MVP最小领域模型.md`、`docs/31-裁决MVP用例与服务设计.md`、`docs/32-裁决MVP最小API设计.md`。  
设计性质：合成 V0 的存储无关逻辑记录；不是 DM8 物理模型、SQL、迁移、中心数据映射、正式档案或数据保留策略。

## 1. 保存边界

只保存本地合成 V0 工作链路所需的不可变输入版本、派生版本、来源定位、测试操作记录和技术幂等绑定。权威案件、真实材料正文、正式法规库、真实模板文件、真实身份/授权事实、签发/裁决/送达/办结状态均不属于本设计。

所有根记录均带 `scopeLabel=SYNTHETIC_V0`；任何草稿、引用或测试复核记录均带 `notOfficialDecision=true`。读取历史记录仍须通过当前授权，历史所有者或旧链接不能构成永久访问凭据。

## 2. 逻辑记录与唯一归属

| 记录组 | 最小内容 | 版本/关系 | 明确不保存 |
|---|---|---|---|
| `adjudication_work` | 本地工作 ID、受控合成 `caseRef`、创建追踪、工作版本、范围限制 | 工作是全链根；输入清单和各派生资源都归属一个工作 | 中心案件状态、受理号、真实案件正文、正式文号。 |
| `work_input_snapshot` | 案件/材料的来源类型、稳定标识、实际版本、定位、读取时可用性 | 仅追加；创建工作后输入不原地改写 | 材料原文件、受限全文、中心凭据、客户端声称的事实。 |
| `material_inspection_version` | 检查 ID/版本、固定输入清单、当事人主张、待核实事项、缺项、冲突、未处理项、来源链接 | 归属工作；新检查追加版本，指向前序版本 | 已认定事实、证据采信、程序结论。 |
| `legal_candidate_set_version` | 候选集 ID/版本、检查版本、法规来源/确切版本/定位、时间/程序/地域疑点与限制 | 候选基于确切材料检查版本；不可覆盖历史候选 | 自动法律适用、有效性结论、模型推断冒充原文。 |
| `citation_version` | 引用 ID/版本、候选/条文确切版本、位置、人工理由、前序版本 | 归属工作并关联候选/来源；选择、修订、移除均追加版本 | 正式采纳状态、裁决依据结论、任意条文全文副本。 |
| `draft_version` | 草稿 ID/版本、固定输入清单、合成模板版本、稳定章节、章节内容、来源映射、缺项/冲突、差异摘要、前序版本 | 一份草稿只追加版本；每版固定材料检查/候选/引用/模板版本 | 正式裁决书、签名/签章、文号、送达/办结标志、真实模板文件。 |
| `test_review_record` | 记录 ID、确切被审草稿版本、`CONFIRM/RETURN`、理由、可信测试主体引用、时间、范围限制 | 只追加，永不改写；确认不改变正式业务状态 | 专业审核角色事实、签发动作、真实人员身份凭据。 |
| `source_link` | 本地链接 ID、来源类型/稳定标识/实际版本/定位、首次读取快照和当前可用性摘要 | 输入、检查、候选、引用和草稿以链接 ID 引用；失效只追加状态事实 | 永久下载 URL、磁盘路径、受限正文或访问令牌。 |
| `idempotency_binding` | 可信主体、端点语义、幂等键、规范化输入指纹、原结果引用、创建时间 | `(actor, endpoint, key)` 唯一；相同指纹回放原结果，不同指纹冲突 | 完整认证会话、客户端传入的权限结论。 |

`work_input_snapshot` 与 `source_link` 分开：前者表达创建工作时采用的输入版本，后者是可被多个历史版本引用的安全定位记录。任何 `source_link` 当前不可用时，不得改写旧版本内容；只影响之后的读取、草稿生成和测试确认。

## 3. 完整性与版本不变量

1. 所有对象 ID、版本、归属工作和 `scopeLabel` 必填；一条工作不能跨案件引用材料、候选、引用、草稿或测试复核。
2. `material_inspection_version` 固定其材料输入版本；资料缺失/冲突必须有结构化条目，不能用空字符串掩盖。
3. `legal_candidate_set_version` 只能引用同一工作内的确切检查版本和受控法规来源；候选永远不是已适用条文。
4. `citation_version` 必须指向一个确切条文版本、定位和创建理由；删除引用也追加一个可追溯版本，而不是物理删除历史。
5. `draft_version` 必须固定材料检查、候选、引用和合成模板的确切版本；每个关键章节内容必须能够指向输入、引用或明确缺项。
6. 草稿修订或采用候选重生成只能创建新版本，不能覆盖人工内容、历史差异或机器原始内容。
7. `test_review_record` 必须针对确切草稿版本。`CONFIRM` 前检查该草稿没有关键缺项、未解决冲突或失效来源；记录始终不是正式决定。
8. 每次可变聚合更新必须以 `expectedVersion` 比较更新；失败不写半条派生版本。并发赢家形成新版本，其他请求返回冲突。
9. 幂等绑定与对应业务写入原子保存。相同键同指纹返回原结果；相同键不同指纹不产生第二个结果。
10. 当前读取重新授权；无权不返回历史快照或来源正文。来源失效保留历史关系，并使依赖它的新草稿/确认受到阻断或待复核标记。

## 4. 原子保存与失败传播

| 业务操作 | 单个原子单元 | 失败后必须成立 |
|---|---|---|
| 创建工作 | 工作、输入快照、来源链接、幂等绑定 | 不存在半创建工作或孤立输入。 |
| 检查材料/匹配候选 | 新检查或候选版本、明细来源关系、幂等绑定 | 不存在无父工作、无输入或无来源定位的版本。 |
| 选择/修订/移除引用 | 新引用版本、前后关系、动作追踪、幂等绑定 | 当前引用不被静默覆盖；失败不产生孤立“已选择”条文。 |
| 创建/修订草稿 | 草稿版本、章节、来源映射、差异、幂等绑定 | 不存在没有固定输入清单或来源映射的成功草稿。 |
| 测试复核 | 复核记录、确切草稿版本关系、幂等绑定 | 不改变正式状态；检查失败不生成确认记录。 |
| 来源可用性刷新 | 新来源可用性事实、受影响对象待复核标记 | 不改写历史材料/引用/草稿正文；不得把失效降格为空数据。 |

完整草稿创建可能在资料不足时返回不完整版本及 `MATERIALS_INSUFFICIENT/PARTIAL_RESULT`，但它不能拥有 `CONFIRM` 测试复核记录。技术失败、并发冲突或幂等冲突均不留下孤立记录。

## 5. 三类样例记录回放

| 样例 | 必须存在 | 必须不存在/不得改变 |
|---|---|---|
| 正常 | 一工作、固定输入、检查、候选、引用版本、草稿至少一版、测试复核、可回链的来源链接与幂等绑定 | 中心案件写入、正式裁决/签发/办结状态。 |
| 资料不足/冲突 | 检查版本的缺项/冲突、候选限制、不完整草稿或可见阻断、退回测试记录 | 自动补造事实、把冲突消成唯一事实、`CONFIRM` 测试复核。 |
| 无权/来源失效 | 不泄露的拒绝/失效追踪；若已有历史，保留版本和受影响标记 | 受限正文、永久访问链接、用失效来源创建/确认新草稿。 |

## 6. 物理设计前的验证与排除项

后续 `MVP-ADJ-V0-01` 必须把下列验证映射到测试：无损历史回放、同键重放/冲突、乐观版本冲突、每项操作的事务回滚、资料不足阻止确认、来源失效传播、当前授权重查和重启恢复。测试数据必须为版本化 `SYNTHETIC`，不得使用真实案件、条文库、模板或人员身份。

本任务不定义 DM8 表、SQL、索引、保留期、备份恢复策略、真实文件存储、全文检索、中心来源缓存、模板渲染或迁移。物理实现只能在单独的、通过窄范围 D 门的任务中开始。

## 7. 需求一致性复核

| 检查项 | 结果 |
|---|---|
| 涉及需求 | ADJ-04、ADJ-05、ADJ-06、ADJ-10、ADJ-11、ADJ-12 |
| API/逻辑映射 | 9 组记录覆盖 `docs/32` 的工作、检查、候选、引用、草稿、测试复核、版本读取、来源访问和幂等操作。 |
| 来源与人工边界 | 来源仅用受控链接/定位；测试主体和复核记录不具备正式人员、签发或裁决语义。 |
| 无来源业务行为 / MUST_NOT 违规 | 0 / 0；未写入自动法律适用、正式裁决、签发、送达、办结、中心写回或权限事实。 |
| 验证范围 | 逻辑关系与三类合成样例反查；未执行 DM8、HTTP、中心接口、真实身份、渲染或业务验收。 |

结论：每一项合成 V0 输入、派生结果、引用、草稿与测试复核都有唯一逻辑归属，历史版本可回放而当前授权和来源状态不被历史快照冻结。完成本任务后可进入窄范围实现任务设计，仍不得直接实现 API、DM8 或业务代码。
