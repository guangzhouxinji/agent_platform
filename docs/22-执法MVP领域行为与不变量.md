# 执法 MVP 领域行为与不变量

版本：V0.1  
日期：2026-09-15  
关联任务：`ARC-05-ENF-BEH`

## 2. 行为一：开始执法工作项

**触发**：可信调用主体请求基于一条已有线索的确切版本开始本地辅助工作。

**前置条件**：

- 线索引用包含来源系统、稳定标识和版本；无源版本时包含获取时间与内容摘要。
- 授权端口确认调用主体当前可以读取该线索；关联案件/权利只在实际提供且有权访问时加入。
- 相同主体、操作、幂等键和完整输入不得创建重复工作项；同键不同输入必须冲突。

**结果**：创建 `EnforcementWorkItem`，只保存本地标识、权威引用、机构引用和创建时间；不复制未经授权正文，不创建中心案件或正式状态。

**失败结果**：无权限、来源不存在、来源失效、版本冲突和上游故障分别返回；拒绝结果不得泄露受限正文或通过存在性细节扩大信息。

**禁止副作用**：不得回写中心线索、授予权限、自动立案或触发线索发现。

依据：ENF-04-MUST-003；ENF-05-MUST-004/005/007；ENF-11-MUST-003；执法总览第 3 节。

## 3. 行为二：生成线索解析版本

**触发**：工作项引用的线索版本当前可访问，调用主体请求解析或重新解析。

**前置条件**：固定线索版本；确认实际可用的解析器/模型或合成测试替身版本；当前权限通过。

**结果**：追加不可变 `ClueAnalysisVersion`：

- 多个主体候选分别保存原文角色、名称和定位，不合并为“违法主体”。
- 统一社会信用代码只接收原文或获授权主体核验来源的值；没有来源则为空。
- 疑似事实、时间、地点和证据提及逐项保存原文定位；时间/地点标准化值不能覆盖原始表达。
- 无法确定的字段为空并加入缺失项；冲突值同时保留并指向各自来源。
- 优先级只有在已确认规则和必要因素齐备时才可产生；V0 合成闭环默认输出待评估，不使用模型分值表示违法概率。

**失败结果**：部分字段失败时保留有来源结果与未处理项；源接口失败不能伪装为空字段，解析失败不能伪装无事实。

**版本不变量**：重新解析追加机器版本；人工修订或确认过的版本、前后值和引用保持不变。

依据：ENF-04-MUST-001/003/005/006/007/008/009/010/013、MUST_NOT-001/003/004/005/006/007/008。

## 4. 行为三：人工核实线索解析

**触发**：可信测试或后续授权人工身份对某一确切 `ClueAnalysisVersion` 执行修订、确认或退回。

**前置条件**：当前权限通过；提交的预期版本与被操作版本一致；动作理由满足当前 V0 要求，退回必须有理由。

**结果**：

- 修订创建新的解析版本并保存 `previousVersionRef`、前后值、人员、时间和理由。
- 确认或退回追加 `HumanReviewRecord`，指向确切解析版本。
- V0 测试身份记录 `scopeLabel=合成流程验证/非专业认定`。

**失败结果**：无权限、版本冲突、对象不存在和动作不适用分别拒绝；拒绝不改变原版本。

**禁止副作用**：不得覆盖机器原始结果，不得把解析确认写成违法主体或违法事实的正式认定。

依据：ENF-04-MUST-012/013、MUST_NOT-001/007；P0-04/09 V0。

## 5. 行为四：登记或刷新证据引用

**触发**：工作项需要引用来自中心 API 或授权上传渠道的一个确切证据版本，或重新检查既有引用的当前可用性。

**前置条件**：证据至少关联该线索或案件之一；当前访问权限通过；来源、源版本和关联事实由权威来源/上传上下文提供。

**结果**：

- 创建或追加 `EvidenceReference`，保存受控资源引用、来源/版本、关联对象、收集信息或缺失原因、原件/派生关系和当前可用性。
- 实际取得文件字节时可以保存摘要算法和值，只用于完整性校验；相同摘要只提示可能重复。
- OCR、转码、摘要或重新上传创建关联派生版本，不覆盖原件和既有引用。
- 每次列表、详情、预览、下载、历史和下游读取均重新执行当前权限检查。

**失败结果**：无权限、关联不存在、来源失效、不可解析和上游故障分别记录；不可解析材料进入未处理项。

**禁止副作用**：不得暴露磁盘路径；不得以上传人替代未知收集人；不得把摘要/OCR/上传成功当作真实合法或证明力；被引用证据不得物理删除。

依据：ENF-05-MUST-001/002/004/005/006/007/008/009/013/014/015/016/017/018、相应 MUST_NOT。

## 6. 行为五：形成事项—证据关系集版本

**触发**：已有一个人工核实或明确标记待核实的解析版本、固定证据版本集合和固定合成/已发布规则版本。

**前置条件**：所有输入属于同一工作项并当前可访问；规则来源与版本明确；不可用、无权限或被排除的证据不能作为新结果的有效支持。

**结果**：追加不可变 `EvidenceRelationSetVersion`：

- 每个待证明事项分别记录支持、反对、冲突或缺失的证据关系及理由。
- 每条关系指向具体证据版本和页码、片段、字段路径或音视频时间点。
- 时间线分开保存事实发生、证据收集和上传时间，未知值不补造。
- 冲突材料同时保留并标记待人工核验；无支持材料保留未证实状态。
- 资料不足仍返回有依据的部分关系、具体缺口和未处理材料；完整性只能表达实际缺口/冲突/待核验。

**失败结果**：规则不适用、材料不可解析、来源故障、无权限和版本冲突分开；失败不转写成“无证据”或“事项不成立”。

**版本不变量**：证据、规则或关系发生变化时创建新关系集；旧结果标记需复核但不改写。被排除/失效证据不进入新版本的有效支持关系。

**禁止副作用**：不得宣称形成完整有效证据链、事实已获证明或证据已被采信。

依据：ENF-07-MUST-001/003/005/006/007/008/009/010/011/012/017、相应 MUST_NOT。

## 7. 行为六：形成辅助分析版本

**触发**：调用主体请求基于固定解析、证据、关系集、规则、权利和来源版本形成辅助分析。

**前置条件**：

- 全部输入稳定编号、关联、版本和当前权限通过。
- 规则明确适用范围且版本固定；没有已确认专业规则时，V0 仅运行明确标识的合成检查清单。
- 权利状态含来源、版本、状态时间和查询时间；历史状态缺失不能用当前状态替代。

**结果**：追加不可变 `AuxiliaryAnalysisVersion`：

- 逐检查项分开记录已确认事实、当事人陈述、机器推断、支持/排除关系、规则/来源、缺口和不确定性。
- 结果分类只允许“支持疑似成立、存在排除依据、材料不足无法判断”，且逐项说明形成原因并标记非正式决定。
- 材料不足时保留有依据的部分分析、补证事项和未处理项。
- 严重程度、适用程序或其他专业结果只有中心确认规则和充分输入同时存在时才可产生；合成 V0 默认不输出。

**失败结果**：无权限、规则不适用、历史状态缺失、资料不足、来源/模型失败和部分失败分别表达。

**版本不变量**：新材料、规则、权利状态、模型或重跑创建新版本；旧分析、人工修订、审核记录和引用不变，受影响旧结果标记需复核。

**禁止副作用**：不得自动立案、正式认定、选择正式程序、产生处罚、写中心状态或把资料不足/失败改写成“不成立”。

依据：ENF-11-MUST-001/003/005/006/007/008/009/010/011/012、相应 MUST_NOT。

## 8. 行为七：人工审核辅助结果

**触发**：可信测试或后续授权人工身份对确切辅助分析版本执行修订、提交审核、确认或退回。

**前置条件**：当前权限通过；被审核版本仍存在；提交预期版本一致；退回有理由；测试身份明确标识。

**结果**：

- 修订创建新辅助分析版本，保留机器原始结果和版本关系。
- 提交、确认或退回追加 `HumanReviewRecord`，保存对象版本、动作、理由、人员和时间。
- 新输入或来源失效后旧审核记录仍保留，但相关结果通过独立原因标记需复核。

**失败结果**：无权限、版本冲突、审核对象变化或动作不适用时拒绝且不覆盖。

**禁止副作用**：V0 确认不等于专业采信、正式认定、立案、处罚、签发、送达、执行或中心回执；Agent/模型适配器不能调用人工动作的内部决定路径。

依据：ENF-11-MUST-011/012、MUST_NOT-001/008；执法总览第 5 节；P0-09 V0。

## 9. 行为八：传播输入变化与来源失效影响

**触发**：权威来源版本变化、权限撤回、证据排除/失效、规则更新、权利状态更新或模型/配置更新。

**结果**：

1. 不修改旧解析、关系集、分析或审核记录。
2. 计算并保存受影响对象的“需复核原因”关系；只记录必要标识，不借机读取已失权正文。
3. 新关系集/分析不得继续把失效或已排除版本作为有效支持。
4. 再次读取历史正文或来源定位时仍按当前授权检查；无权则拒绝正文但保留最小审计可追踪性。
5. 重新执行必须显式创建新版本并固定新输入清单。

**禁止副作用**：不得以删除历史掩盖来源失效，不得沿用缓存泄露失权内容，不得把技术失效解释为证据无效或业务不成立。

依据：ENF-05-MUST-016/017；ENF-07-MUST-011/012；ENF-11-MUST-012/MUST_NOT-008；P0-02/03 V0。

## 10. 状态和责任分离

| 状态种类 | V0 使用范围 | 明确不得混用 |
|---|---|---|
| 技术执行结果 | 成功、部分失败、失败等仅用于说明一次调用/执行结果；具体 Task 状态留给后续设计 | 不等于解析、证据、审核或正式业务状态 |
| 来源可用性 | 可用、无权限、来源失效、不可解析、上游故障 | 不等于证据被采信/排除或权利有效性 |
| 解析/关系/分析版本 | 通过不可变版本和需复核原因表达历史关系 | 不使用一个可变 `status` 覆盖历史内容 |
| 人工审核动作 | V0 只记录修订、提交、确认、退回及确切对象版本 | 测试确认不等于专业认定或中心正式状态 |
| 正式业务状态 | 不在 V0 领域模型中定义或写入 | 不由 AI、Agent、测试身份或本地审核动作推导 |

## 11. 三类样例验证矩阵

| 行为/不变量 | 正常 | 资料不足/冲突 | 无权限/来源失效 |
|---|---|---|---|
| 开始工作项与当前授权 | 固定 `CLUE-001@v1` 并创建本地引用 | 固定 `CLUE-002@v1` | `CLUE-003` 或关联证据无权时拒绝且不泄露 |
| 解析与人工核实 | 多主体角色和定位完整；测试身份确认确切版本 | 时间/商品标识冲突并存，缺失值为空；可退回 | 源失效或无权不伪装空数据 |
| 证据引用 | 两份证据固定版本、关联与完整性可回查 | 未知收集人有原因；音视频列为未处理 | 每次读取重新鉴权，失效版本不进入新结果 |
| 证据关系集 | 支持/反对关系、时间线、缺口均可定位 | 冲突和缺口同时保留，不宣称完整证据链 | 旧关系标记需复核，新关系不使用失效证据 |
| 辅助分析 | 逐项区分事实/陈述/推断并标记非正式 | 返回部分分析和材料不足，严重程度不输出 | 无权限/来源失效与真实空结果区分 |
| 审核与版本 | 审核记录绑定确切版本 | 退回理由和补证事项保留；补充后新版本 | 旧审核不删除，历史正文仍按当前权限读取 |
| 禁止正式决定 | 未立案、未认定、未处罚、未写中心状态 | 同左 | 同左 |

## 12. 后续 Use Case 设计输入

下一任务 `ARC-05-ENF-UC` 只能从上述行为倒推出最小应用用例与端口，至少需要覆盖：开始工作、生成/核实解析、登记证据引用、生成关系集、生成辅助分析、审核确切版本、读取历史与来源定位。用例层负责当前授权、幂等和跨对象编排；领域对象不直接调用 DM8、模型 SDK、文件系统或中心 API。

本任务不决定这些用例是同步还是异步，不定义 URL/DTO、数据库表、事务边界、角色枚举、模型供应商、规则 DSL 或正式流程。

## 13. 需求一致性复核

| 检查项 | 结果 |
|---|---|
| 涉及需求 | ENF-04、ENF-05、ENF-07、ENF-11 |
| 行为覆盖 | 8 项行为覆盖三类 V0 样例的输入、解析、核实、证据、关系、分析、审核和失效传播 |
| 无来源业务行为 | 0；合成检查清单、测试身份和结果分类均沿用 `docs/20` 的 V0 限制 |
| MUST_NOT 违规 | 0；所有行为均显式禁止越权、补造、覆盖历史、自动采信和正式决定 |
| 未进入范围 | 专业规则、真实证据采信、正式角色/状态、处罚、文书、中心写回、API、数据库和代码 |
| 验证范围 | 文档语义和三类合成样例矩阵；未执行真实数据、真实权限、模型效果或业务验收 |

结论：8 项行为和全局不变量能够约束三类 V0 样例，并保持来源、授权、版本、人工控制点和正式决定边界。该结论只完成 `ARC-05-ENF-BEH` 的设计范围；下一步可以进入 Use Case / Service 边界设计，仍不得直接进入 API、数据库或代码。
