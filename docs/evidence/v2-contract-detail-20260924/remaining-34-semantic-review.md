## 复核方法和结论边界

以47份已固定摘要的需求为业务来源，检查本轮34项主来源各节、咨询/执法/裁决总目录、裁决复用的三份既有法规需求、现有条款和反例、输入输出、权限状态、开放问题；对照 `docs/02` 第20、22、23节已确认决定及V2逐项建议。旧契约的原文第二遍复核记录可复用其原文提取，但旧 `ready` 本身不是V2复核证据。发现缺口时按源义补足；V2建议未获批准的部分只作为待决取舍，不倒填为原需求。以下各项均检查数据/权限/来源、任务与业务及正式状态分离、人工决定、异常及真实验收；共同约束仅在能力被智能体任务调用时适用，不把配置服务改造成任务运行时。

本轮复核是同一Codex的源优先再检查，非第二名人员独立签字。契约R只说明当前原文和已确认共同产品范围忠实、未知项明确，允许开始相应边界评审；不批准所有V2建议、专业标准、角色、生产数据许可、三Agent部署、详细设计、实现、真实联调或业务验收。需求中的DM8、服务脱离内部页面、源/派生隔离、模块字段表、错误和交付项继续有效，不因阶段延期或V2重组而删除。

## 执法：17项

下列每项原文第1～8节与执法总览第1～9节共同适用。既有机器条款已覆盖多数原文细则；本轮的增量判断是将它们用于三智能体任务时，不能从一次工具、规则或文件成功直接推出用户任务完成，且人工作业必须有实际受理/决定记录。专业/法定条件仍按各项开放问题后置，不产生默认规则。

| ID | 原文与契约重点 | 本轮语义结论及反例 |
|---|---|---|
| ENF-01 | 来源、连接、同步游标与撤回；原文第3～5节和总览数据授权 | 同步成功不是线索核实；失败游标不越未处理项，公开开发数据不能代替正式授权 |
| ENF-02 | 规则字段、试运行、发布和不可变版本 | 发布归授权人员，试运行不建正式线索；旧运行绑原版，规则分数不等违法概率 |
| ENF-03 | 批次发现、跨源重复、通知和处置分态 | 疑似不等违法或立案；通知投递不是人员受理回执；模型失败不记未命中，重复执行不双推送 |
| ENF-04 | 主体角色、逐字段原文定位、优先级和确认 | 多主体不合成违法主体；无统一代码不推算；重跑保留人工确认版本和来源 |
| ENF-05 | 原件、派生、哈希、实物与采信分层 | 字节相同不等收集过程或真实性相同；撤权后受控下载不能从旧链接绕过 |
| ENF-06 | 待证明事项和整理规则的中心确认及发布 | 缺必要事项或规则版本不放行；配置规则不拥有采信权，历史链不被新版覆盖 |
| ENF-07 | 支持、反证、缺口、冲突材料的整理 | 证据链只形成待复核工作包；撤回一份证据使依赖解释待复核，反证不被覆盖 |
| ENF-08 | 程序期限/例外/日历规则版本 | 未确认起算与延期事件不得发布或断言逾期，模板化规则不生成程序事实 |
| ENF-09 | 固定程序事件逐项校验与失败 | 事件缺失为无法判断，来源故障不是全通过；人工处理不由Agent更改正式流程状态 |
| ENF-10 | 假冒专利、专利侵权等类别要件与排除规则 | 类别相似不等程序相同，规则冲突或未知例外留给专业责任方 |
| ENF-11 | 固定事实/权利时点的逐要件辅助分析 | 当前权利状态不代替行为时点；材料不足返回可用部分及补证，不声称侵权成立 |
| ENF-12 | 中心模板、DOCX、机构/程序适用和发布 | 未批准版式不叫正式模板，预览成功不是签章/签发；旧文书保留模板版 |
| ENF-13 | 字段来源、确定性金额日期、叙述辅助及缺失策略 | 没有真实问答不生成笔录；必填缺失只形成不完整草稿，不能提交审核 |
| ENF-14 | 可编辑文书初稿、修订审核和DOCX导出 | 导出/审核不等正式文号或送达；未确认处罚结论不得写成已决定 |
| ENF-15 | 职权程序、法定幅度、裁量公式、边界试算 | 无金额口径或冲突优先关系不发布；不能选“更重/更新”的规则充专业决定 |
| ENF-16 | 经确认事实、确定性计算、人工调整 | 不适用行政处罚不生罚款；缺额不按零；人工越界调整不得确认有效 |
| ENF-17 | 历史法条版本、逐字原文、业务锚点和审核 | 无可靠匹配不编条号；候选/解释不自动成为已确认依据，现行法不替历史法 |

## 裁决：12项及三份既有法规需求

每项主文各节及裁决总览第1～9节共同适用。`ADJ-01～03`还反查 `requirements/知识产权咨询助手/法律法规管理需求文档.md`、`条文解析管理需求文档.md`、`条文要点管理需求文档.md`：原文允许更新/覆盖/删除，但新细化需求要求已引用、已审核或源原文不被破坏性覆盖，错误历史记录以撤回留痕处理。应保留导入、维护、完整列表、弹窗和独立审核能力；是否调整既有未引用草稿的具体覆盖策略要在设计中明示，不能删掉整个入口。

| ID | 原文与复用重点 | 本轮语义结论及反例 |
|---|---|---|
| ADJ-01 | 法规导入、人工维护、修订前原文与版本、效力 | 名称/条号不作跨版唯一键；被引用旧正文不被覆盖，错误历史可撤回留痕；历史适用仍需人员判断 |
| ADJ-02 | 外部一次性解析导入、完整列表和独立审核 | 导入完成不是智能解析效果；外部审核标记不能冒用本地审核人，已审核解析修改新版本重审 |
| ADJ-03 | 外部要点导入、关联校验和完整内容维护 | 要点不是原文；处罚要点不因共库进入裁决依据，来源解析失效标待核实 |
| ADJ-04 | 案件/本地任务、受理、转派、办结和归档 | 本地任务状态与权威案件状态分开；没有真实人员受理或权威回执，不称正式受理/签发/归档 |
| ADJ-05 | 法条候选、历史时点、要件缺口与人工确认 | 时间/地域/程序缺失不套现行法，候选分数不是适用概率；旧确认不自动继承新事实 |
| ADJ-06 | 引用位置、具体原文版和绑定/解绑 | 原文与解释分开，报告修订需重核锚点；失败不留下孤立“已采用”引用 |
| ADJ-07 | 权利要求及从属关系、全文图样和人工修订 | 缺权项不能用摘要冒充，外观不用发明要素矩阵；来源与解析版本分开 |
| ADJ-08 | 官方状态与新颖性/创造性风险分栏 | 无效请求不等决定；缺历史状态为无法核实，多篇拼接不冒单篇公开 |
| ADJ-09 | 双方材料、逐特征对应、反证及人工采信 | 销售资料不证明内部结构，哈希不等合法真实性；模型不作采信或侵权成立结论 |
| ADJ-10 | 模板版本/适用用途/预览与撤销 | 内部分析模板不是法定文书；预览不构成正式报告，已用版不可删除 |
| ADJ-11 | 有源草稿、章节修订、同版DOCX/PDF和复核 | 缺必填不提交；重生成先候选差异；复核通过仍不等签发，导出失败不丢草稿 |
| ADJ-12 | 人员复核、具名决定、正式文件/回执 | 审旧版不签新版；服务账号不代审；受理/复核/签发/送达/归档分别凭真实动作/回执 |

## 共同行为如何进入契约

已确认四项约束见 `docs/02` 第23节：完成分层、跨轮结果稳定引用、纠正后同任务继续、人工交接需真实接收/受理记录。它们对数据/规则/模板管理本身仅在被智能体任务调用时生效；配置服务仍保持自己的草稿/发布/撤销状态。对线索、分析、报告、案件与复核则须分别定义任务、业务、审核和正式状态，真实人工交接不能凭“已生成通知/待办”宣称已受理。完整证据与专业完成条件归各领域，不能统一为HTTP或模型成功。各项契约的V2审阅元数据只引用本次证据，不能取代已有条款或总计划状态。

所有未确认项保留在契约 `openQuestions` 及 `docs/02`：中心源与用途许可、身份/DataScope、规则/期限/金额/专业标准、模型通道、受理岗位和真实回执、DM8目标环境、样本/阈值与验收人。对需要外部决定的具体行为，详细设计和真实接入按依赖阻断；不从相邻领域或旧Mock推断答案。

版本绑定和机器结构检查见 [all-reviewed-check.json](all-reviewed-check.json)：41份当前契约及主/辅来源SHA-256、条款与场景双向引用、复核证据可读性，另比对714份本轮前已存在的业务/前端/需求文件，未发现差异。五份咨询失效契约的变更前内容与29份旧ready契约的变更前内容见 `remaining-34-before.json`；处理脚本 `apply-remaining-review.mjs` 留作可复核的机械变更说明，不是状态台账。机器检查证明文件及引用结构，不能证明法律适用、专业结果或测试执行。既有浏览器失败、Fixture范围及三域真实数据许可未因R复核消失。
