# ADR-CON-MODEL-FENCE-01：咨询模型外呼前持久预留

日期：2026-10-06；技术决定责任：Codex（开发团队）。归属 IMP-AGENT-CONSULTATION-01 的限定切片 FIX-CON-MODEL-INVOCATION-FENCE-01；状态仅见主计划。依据：CON-12已过R、docs/71§3～5、ADR-AGENT-BINDING-02未知提交不得盲重发合同及用户本轮继续实施指令。此为技术恢复D，不新增业务/法律批准。

## 当前限定D与不变量

- 保留PROPOSAL/EXPLANATION已有输入、输出、权限、来源MODEL用途、Task版本、人工边界及有效回合合同。没有新路由、身份、正式状态、供应商回执或假模型回合。
- V097新增con3_model_invocation：不可变预留元数据，唯一(task_id,actor_subject,request_id)，invocation_id等于拟留存turn_id；只保存请求SHA、Task/结果绑定及既有保留引用/版本/SHA/有效期，不保存消息、令牌或原始模型输出。保留有效期与既有回合合同相同且不超过Task期限；纳入同批原生DB备份和保留原件核查。
- 预留用独立短事务锁Task，重新检查现时授权、版本、结果和来源；锁内查询既有回合/预留。相同键已有合法回合则读原回合；已有预留但无回合则409 MODEL_INVOCATION_UNRESOLVED，不重复外呼、不宣称成功、不猜测供应商是否收到。不同输入同键409。并发同键最多一名预留拥有者可以发起一次外呼；不承诺供应商恰好一次。
- 预留必须提交后才外呼，模型调用前再次检查现时Task/来源。外呼不持事务。结果保存沿用原短事务与末端授权检查，模型不可用、调用中撤权或结果落库失败均不得删除预留、盲目自动重发或伪造原封套；明确的新请求仍沿既有接口与批准输入合同，不自动换键。
- 历史V089回合保持只读，优先读取旧回合，无须补造预留。模型启用启动检查要求V097，不自动在旧业务库迁移；迁移仅在自有隔离库验证，U097有预留时拒绝破坏性退役。
- 原生完整恢复含预留，当前恢复核查追加Task/期限/保留证据、请求绑定以及与已存在回合的精确一致性校验；孤立未完成预留保留为未知外呼，不升级为失败或成功。缺V097只允许历史只读核查，不允许当前模型调用降级。

## 验证出口

真实SQL/事务组件反例先红后绿：外呼后异常、保存失败、并发、服务重建、同键不同输入、预留事务回滚、Task/Source撤销、无长事务及原回合重放。恢复与保留正反例；迁移在自有DM8随机schema验证。外部模型/权限端口替身只证明工程合同，不是业务Golden或供应商验收；咨询完整HTTP/真实模型/浏览器闭环仍归父任务。

## 成功回合规范返回切片的限定D

FIX-CON-DIALOGUE-PERSISTED-VIEW-01（2026-10-06，Codex）：复用docs/71同键重放原回合、现时授权及不可变结果合同。已复现纳秒Clock的首次内存Turn时间与SQL TIMESTAMP精度不同，导致同一持久回合的Observation SHA不同。成功回合事务提交后调用既有read返回实际留存回合，不调整保留期限、不重算模型、不放宽输出或权限；失败回合仍按原502审计拒用。读取仍重新检查当前Task/Source权限，提交后失权不可返回成功内容。退出：精度反例先红后绿、原始输出/调用次数不变、H2和自有DM8重放、Checkpoint提交失败恢复及未筛选回归。此为当前技术恢复D，不新增业务批准。
