# 咨询首任务开发期公共边界与独立验收设计

版本：D8，2026-09-24。文稿任务：`ARC-CON-PUBLIC-BOUNDARY-DESIGN-01`；各切片D准入只以总计划当前Task判定。本设计只覆盖首条专利技术参考任务所需的公共机制，承接[数据服务设计](55-V2业务数据服务与运行恢复详细设计.md)、[咨询设计](56-V2咨询全能力详细设计.md)及docs/02第23、26～30节；不重新定义专利检索/对照的专业方法。第7～12节的“拟实施/未执行”保留当时设计和窄D时点，当前DB实测与文件/备份缺口见第13节及总计划；第14节仅批准合成文本结果窄D，第15节对照D未通过；内部路径不等于甲方接口。

## 1. 独立验收的边界

用户以自然语言提出一条专利技术参考目标，在同一任务补充事实、执行获准范围内的检索、固定结果集/选择、查看确切来源、确认关键特征、形成有证据或明确缺口的辅助成果、纠正并继续、请求系统内人工接收，断线/重启后恢复或取消。服务保存任务真相，Agent只编排；不能用一次HTTP成功、聊天记录或Fixture演示代表整个任务完成。

开发期可使用**显式标识的合成专利资料**，或另有逐数据集、字段和用途批准的资料；受限来源只用于其批准用途。这个范围可验命令、持久化、权限边界及错误语义，不能验真实召回、法律/专业正确性或甲方数据接口。无已批准模型数据通路时，模型调用分支关闭；通过确定性输入/受控替身验编排故障，不能宣称模型能力已接通。真实专利全文、图片、跨域分享、外部人工/官方动作均需各自的来源许可和切片D/I证据。

共用模块只提供可信身份绑定、当前访问裁定入口、受控源/文件及租约、回执、事件、存储的技术机制；咨询域拥有任务、Goal、Fact、ResultSet、Focus、Evidence、Outcome、HumanRequest及相关执行/人工事件的语义、状态和事务决定。公共模块不能独立决定任务完成、取消或审核；不得把九种咨询用户状态强加执法/裁决。部署采用docs/54的三Agent加领域化业务数据服务；本设计不新增通用Workflow平台。

## 2. 信任边界和入口清单

| 入口/操作 | 发起者与服务端主体 | 每次授权与结果 |
|---|---|---|
| `POST /v2/consultation/tasks`、`/{id}/messages`、`/{id}/continue` | 开发期具名测试人；服务端认证产生`SubjectRef`、开发域和用途 | 新建/追加前检查开发期开关、目标归属、可保存用途；命令带幂等键和除新建外的expectedVersion |
| `GET /{id}`、`/{id}/events`、`/{id}/source-links/{ref}`、`/{id}/files/{ref}` | 当前获准主体；共享任务另须显式授权 | 每次读取、流式分片和下载重验当前身份、来源许可与任务/对象版本；失权不泄露存在性或正文 |
| `POST /{id}/searches`、`/{id}/selections`、`/{id}/comparisons` | 具名用户命令或受控Agent建议；Agent使用服务身份加用户委托交集 | Search/ReadSource/Compare分动作判定，结果绑定实际范围、方法、来源和版本；无全文不能出深入对照 |
| `POST /{id}/corrections`、`/{id}/cancel` | 具名用户控制命令 | 独立于普通消息忙碌槽；校验expectedVersion，旧epoch迟到成果不能发布 |
| `POST /{id}/human-requests`、`/human-requests/{ref}/claim`、`/opinions`、`/return` | 创建可由用户/Agent建议但服务裁定；领取、意见、退回只允许当前具名测试人 | 事件绑定请求包和成果版本；创建不算受理，成功领取才算；旧包意见不能批准新版，不改变官方状态 |
| `POST /internal/consultation/attempts/{ref}/lease`、`/renew`、`/checkpoint`、`/complete`（同一attempt前缀） | 仅咨询Agent服务身份，附原用户委托和具体task/attempt | 服务端校验授权交集、fencingToken、任务/输入/取消版本；不接受人审、权限、源记录写入 |
| `POST /internal/consultation/retention/reconcile` | 仅开发环境受控作业身份 | 仅清理项目自有到期任务及关联数据，记录批次结果；不得由Agent或页面调用 |

开发期仅显式配置和本机/隔离网络可启用上述入口。API Key登记表为每一具名测试主体绑定稳定principalRef和允许的开发组织；至少两个不同主体供裁决职责分离的后续复用。Agent有独立服务凭据，不持有人用凭据。客户端的actor、organization、`X-V0-Requester`、`X-V0-Actor`、scope字符串和任务owner字段不能生成或扩大身份/范围。若暂借现有`TrustedClientRequest`覆盖旧头，必须先确保每个入口都在过滤范围并证明头覆盖生效；首任务更宜由新`/v2/consultation`入口直接读取可信服务端上下文，禁止将旧头作为授权来源。`ApiScopePolicy`目前仅列部分`/api/v0`路径，不能因存在过滤器就声称新入口受到保护；过滤未启用或无法绑定主体时新入口不得注册为可访问。Fixture控制器仍只用于`test-synthetic`本机演示，`/resume`不能作为取消任务恢复的V2语义。

权限检查次序为认证→主体/目标归属→动作和用途→来源有效性→业务版本；写入提交及结果发布/文件传送前重验撤销版本。401表示未认证，403/不泄露存在性的404按可见性确定，授权服务不可用返回受控失败而非开放；Agent只有服务凭据或只有用户委托均不可代替两者交集。测试主体“全操作”仅针对已定义的人类开发动作与获准数据，不能操作正式决定或扩大源许可。

## 3. 来源、模型与文件合同

开发数据登记`datasetId,sourceKind,approvalRef,approvalVersion,allowedSubjects,allowedActions,allowedPurposes,fields,contentKinds,validFrom,validUntil,withdrawalRef,retentionUntil`；合成资料仍有`SYNTHETIC`标识及稳定recordId、documentVersion、内容摘要、原文定位和实际检索范围。查询、落库、索引、全文/附件展示、下载、入模、跨域分享是不同用途，不从“可查看”推导其他用途。许可缺项或状态`REVIEW_REQUIRED`则该用途默认拒绝，不能用一个总开关泛授权。用户提供的材料亦按对象归属和保存许可检查。

检索返回每个结果的来源版本、许可状态、实际覆盖范围和能力限制；无命中、仅摘要、无权项、来源503、无权、撤回分别返回不同availability/limitation。索引只提高召回速度，不替代源原文；搜索入口先过滤许可，每个结果展示/打开再验。内容变更生成新观察版本，同源同版内容漂移隔离；源撤回立即阻止新的读取、入模、下载和旧回答的受限正文展示，异步失效传播不得成为继续泄露的窗口。禁止将本轮四项`REVIEW_REQUIRED`的CNIPA采集资料直接作为已批准专业规则/模板或首任务全文。

`ModelPort`仅接收获准的内容片段、其SourceRef、用途和固定模型/提示词版本；无通路/超时/非法输出则标模型失败，保留已提交的检索与事实，不发布伪成果。文件先受控暂存，验证摘要和来源/用途后由业务事务登记fileManifest；事务失败的孤儿文件不可下载/检索，清理与重试按manifest状态互斥。下载令牌短期绑定主体、文件版本及用途，每次取字节重验，不生成永久公开链接。

## 4. 事务、恢复与保留

最小持久对象沿docs/55第5节：任务/目标/事实/消息、执行尝试/检查点/租约、结果集/成员/焦点、证据/对照/成果、人工请求/事件、命令回执/outbox、来源版本/文件manifest。每个保存的成果有inputRefs和确切版本；DM8保存业务真相及文件受控引用，Agent进程/React内存不是唯一仓库。实现切片须在真实开发DM8提交物理表/索引/事务映射和受控文件目录，不能用内存仓库加重启重放测试冒持久化。

命令流程：当前授权→按主体/域/目标/操作/幂等键查回执→相同载荷在当前读取许可下返回原回执，不同载荷409→只对新命令比较expectedVersion/来源及依赖→单事务写新版本、失效标记、检查点、回执、审计和outbox。模型与外部调用在事务外；提交后丢响应查询原回执。新尝试用新键及retryOf；未知外部副作用先对账。任务级活动槽阻两个会话并发运行；旧租约token、旧输入版本和旧cancelEpoch均不能提交。

重启扫描非终止且租约到期的执行，取新fencingToken，重验当前身份/委托/来源、任务版本与最后已提交检查点；已提交的结果不重算，未提交且可幂等步骤新建关联尝试，来源撤回则保持受限/待补，不无限重试。取消先提交提升epoch并阻后续成果；成果先提交可保留历史，取消停止剩余步骤。开发期取消任务不可直接resume，继续须建关联新任务且重新核权核来源；单纯断线不取消任务。

开发期到期算法是技术设计决定：每次已提交业务变更写`lastBusinessChangeAt`；终止事务写`terminatedAt`，后者优先作锚点。使用服务端UTC时间戳保存，按`Asia/Shanghai`日历时间加六个自然月，月末日期不足时取目标月末同一当地时刻；到达该瞬间即视为到期。读、租约续期、扫描、未提交失败不改变锚点；较短来源许可即时限制对应内容。到期首先以查询/命令守卫拒绝旧任务使用，再由幂等清理作业按taskId和关联版本删除正文、文件、索引与回执并记录结果，失败保留拒绝可见状态重试；清理结果只留不含正文的最小技术审计且期限需批准，未获准时不得无限保留。开发期备份策略须明确最长轮换时间不超过任务期限并在每次恢复后先隔离、运行到期/许可筛查及清理，再开放流量；未完成筛查不提供读写，不能把备份快照当免清理区。物理备份期限、加密和恢复试测由实际环境切片取证，生产期限仍待甲方。

### 11.2 六个月、重启恢复与取消的提交顺序

仅**已提交的业务变更**写服务端UTC `last_business_change_at`；完成、失败终止或取消的事务写`terminated_at`并改用它作期限锚点。锚点转`Asia/Shanghai`当地时间，加六个自然月，目标月缺该日时取月末同一当地时刻，再转UTC写`expires_at`。查询、失败重试、心跳、租约续期、扫描及回执重放不续期。所有读、命令、租约、流和文件分片在`now < expires_at`且状态非PURGING时才可继续；到达边界立即拒绝，作业延迟不是宽限期。

新命令依次验证当前身份/归属/用途/来源与期限，按作用域查询已提交回执；仅对新命令比较expectedVersion；锁任务及租约并在提交前复核撤权版本、来源、期限和epoch，同事务写不可变版本、失效标记、检查点或事件、回执及outbox。外部搜索/模型/文件暂存不在DB事务内；提交后响应丢失凭回执确定结果。授权或来源服务不可用不得复用旧ALLOW。重启只扫描未终止、未到期及租约失效的任务；新worker用递增token接管，从最后**已提交**检查点及精确依赖版本继续。未知外部副作用先对账，无法核实时保留待处理/待人工，不盲目重试；旧worker不得发布。

取消独立CAS提交提升cancelEpoch、写终止时间/事件并使旧租约失效。成果先提交则只留历史；取消先提交则旧token成果拒绝。取消旧ID的continue/resume及新命令拒绝；仅在当前许可下看获准历史。继续目标只能新建带`predecessor_task_ref`的任务，重新授权/核来源，旧到期时间、租约和幂等作用域都不继承；重放旧回执不得泄露失权正文。

### 11.3 清理、文件对账及备份回灌

只有独立JOB凭据可触发受控到期扫描，不提供任意用户指定ID删除接口。读写守卫先拒绝到期任务；作业按`expires_at,task_id`分页锁定，CAS标PURGING并保存无正文的批次/阶段。先同步禁读任务索引、文件令牌和缓存，再按任务拥有关系清除索引、文件字节、暂存/导出/预览及关联子表（人工事件、成果/依赖、检索成员、检查点、消息/事实/修订、outbox、回执），最后删除任务；共享来源只解除任务引用。文件先删而DB失败可重试；DB已删而文件未确认须由不含正文的清理清单继续对账。失败仍不可访问，记录阶段和失败码供幂等重试；不能只凭“已扫描”标清理完成。最小无正文技术审计的期限仍待运维批准，不能默认为无限期。

DM8与文件备份应记录一致性水位、快照时间、加密/隔离位置、轮换上限、到期清除与恢复负责人；期限不得绕过六个月或更短来源许可。回灌先隔离外部流量及worker，在受控区恢复DB/文件，加载当前撤权/许可与清理水位，重算期限并核对manifest摘要；缺文件标UNAVAILABLE，清空或重建索引/缓存，完成到期/撤回清理，核验旧租约失效后才开放服务。无备份轮换上限和隔离恢复演练配置时物理适配D不通过；恢复演练本身属于开发I，不能由文稿代替。

### 14.1 命令和数据

`POST /v2/consultation/tasks/{id}/text-searches`由H提交幂等键、`expectedTaskRevision`及`expectedResultSequence`，不接受客户端源ID/排序分/目标正文。服务只读取同任务最后一条已提交消息的输入版本，按签入清单生成S1成员P1、P2，下一次新命令可生成S2成员P2、P1以验证顺序稳定，但必须明确返回`SYNTHETIC_FIXED_ORDER`、执行范围2、实际返回2、没有全库数量/数值相关度。具体执行顺序由服务端固定版本`DEV-TEXT-V1`及本次结果序号决定。先在task行锁内检查当前任务修订与结果序号，再核逐用途许可；新集合、独立结果序号、事件和回执同事务提交，回执重放先重验当前主体及该集合来源用途，不能泄已撤回正文。失败不写半个集合、事件或回执。

`GET /v2/consultation/tasks/{id}/text-searches/{setId}`只返回当前H可见成员的稳定顺序、来源版本、摘要/定位和可用性；展示权项正文须再次通过DISPLAY且摘要与签入原文字节一致，撤回、过期或来源不可用时只返回不可用标记，不返回旧正文或旧缓存。`POST /v2/consultation/tasks/{id}/focus`由H携`setId,ordinal,expectedTaskRevision,expectedFocusSequence,Idempotency-Key`选择已展示集合的确切成员；0或越界、他人集合、不可用来源拒绝。焦点保存`setId,ordinal,recordId,sourceVersion,contentDigest,inputRevision,focusSequence`，不从后来的S2或当前列表重解释S1第二项。新搜索不会自动覆盖已选择焦点；重选以新版本/事件追加，取消或到期拒写。旧集合仍可读取获准历史，不随新排序变化。

最小新增关系为`con2_result_state(task_id PK,result_seq,focus_seq)`、`con2_result_set(set_id PK,task_id,seq,input_revision,method_version,actual_scope,receipt_id,created_at)`、`con2_result_member(set_id,ordinal PK,record_id,source_version,content_sha,locator)`和`con2_focus(task_id,seq PK,set_id,ordinal,input_revision,receipt_id,created_at)`；同任务FK约束、`UNIQUE(task_id,seq)`和成员序位唯一。`input_revision`取最后一条消息的修订，不用当前集合序号冒充输入版本。现有`con2_task.revision`继续仅随接收消息/取消变更，当前attempt和`message:<revision>`检查点语义不被搜索/选中打断；结果序号和焦点序号各自CAS，task行锁与取消互斥。搜索/选中是已提交业务变更，更新`last_business_change_at/expires_at`，但不改消息修订；读取或回执重放不续期。`con2_receipt`沿现有作用域绑定SEARCH/FOCUS及载荷指纹，结果集/焦点以`receipt_id`回取原响应，不复制正文；`con2_event`记集合/焦点引用。到期清理先删除焦点/成员/集合/状态再删现有任务子表，取消保留已提交历史至期限。文本原文只从签入manifest在当前DISPLAY许可下读，DB成员不复制全文。V024/U024只作用新表及清理适配，V023不可原地改名或覆盖。

### 14.3 第二遍语义复核与编码边界

任务`revision`代表消息和Agent attempt，不因搜索/焦点递增。没有补充时输入修订取创建消息的1，有补充时取最后已提交消息修订；旧集合保留当时的输入修订。独立`result_seq`、`focus_seq`分别CAS，写命令与取消共用任务行锁；有效RUNNING租约期间拒写`TASK_BUSY`。结果集有`UNIQUE(task_id,seq)`及`UNIQUE(task_id,set_id)`，成员以`(set_id,ordinal)`唯一；焦点以同任务集合及确切成员的复合外键绑定，不能引用他人集合。回执先于引用它的集合/焦点在同一事务写入，任一失败整笔回滚。回执重放先核当前主体、任务、来源许可和摘要，同键同载荷返回原集合/焦点，不受后来序号影响；异载荷409，读取/重放不续期。到期清理先删焦点、成员、集合、序号状态，再删V023子表及任务，U024只回滚新增表。

来源端口仅暴露签入P1/P2的权项、版本、摘要及定位。建集合要求当前QUERY和SAVE；展示正文要求DISPLAY及字节摘要一致；选焦点要求SAVE和DISPLAY。写入开始与提交前再核来源用途，撤回、服务不可用或摘要漂移时零新集合/焦点/回执，既存集合只给无正文的不可用标记。Controller仅在开发profile和单独默认关闭的`text-result-enabled`开关下注册，并同步扩充方法+规范路径白名单。C覆盖第14.2节所有拒绝分支；开发I必须在临时DM8 schema重启和双连接验证，不能以H2冒充。
