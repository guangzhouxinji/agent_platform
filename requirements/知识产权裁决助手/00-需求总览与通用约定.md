# 知识产权裁决助手需求总览与通用约定

版本：V0.1 技术评审稿  
日期：2026-09-12  
范围：3 个业务模块、12 个小功能，每个小功能一份需求文档。

## 1. 建设与交付范围

中心主要通过 API 提供案件、法规、专利商标、案例和证据数据，并提供业务制度、报告样例和专业审核；服务方建设数据接入、法律与技术分析、引用、报告及复核服务。

国产化部署、达梦 DM8 是已确认要求。自研前端只用于内部验证，不属于对外交付页面；所有业务、权限、状态及生成规则由后端实现，脱离页面仍可调用。按模块拆需求和验收，不要求 12 个独立智能体或微服务。

本套原需求编号与咨询/执法助手重复，使用“裁决助手 ADJ-01—ADJ-12＋原编号”联合定位。全部新文档放在本目录，避免覆盖其他助手。

## 3. 与已有法规需求的衔接

本套保留以下已有业务能力，并在对应单篇中补充版本和裁决场景要求：

- [已有法律法规管理](../../../法律法规管理需求文档.md)：批量导入、人工新增/编辑、修订弹窗和修订前原文。
- [已有条文解析管理](../../../条文解析管理需求文档.md)：外部一次性解析后导入、完整内容列表、人工编辑及独立审核页面，不因原文变化自动重算。
- [已有条文要点管理](../../../条文要点管理需求文档.md)：外部生成导入、关联校验、完整内容和编辑维护。

已有文件保持原样。技术复用已有实现时，以本目录对“裁决助手适用的版本、权限与审核规则”补充设计，不取消原有导入和维护能力。

中心 API 原文只读；本地人工维护版本、派生内容与源原文分开保存。已有“覆盖/更新”导入策略不得破坏被引用或已审核版本，只能更新未审核草稿或生成新版本。对错误历史记录的删除采用撤回及留痕，保留引用链。

外部解析/要点程序是明确依赖：支持结果导入，也可经适配器发起外部任务。端到端智能解析效果须以实际程序结果验证，不能只完成 CRUD 就声称智能解析完成。具体外部接口尚未提供，需联调落实。

## 4. 行政裁决业务边界

- 案件是否属于本机关可办理的行政裁决范围，由中心规则和授权人员确认，不因“知识产权案件”标签自动受理。
- 行政裁决、行政处罚、无效宣告及司法程序分别表达。法规库可含处罚规定，但不能自动把处罚建议写成裁决结论。
- 当事人主张、材料反映、机器提取、人工确认事实分别保存；模型不能自行填入实际未发生的调查、质证或签发过程。
- 专利法律状态与新颖性/创造性风险分开。无效请求不等于无效决定，模型分析不能修改官方权利状态。
- 侵权分析按选定权利要求和证据逐项说明；图像、销售资料、哈希与相似度分数均不能单独替代完整法律判断。
- 报告生成仅形成初稿。复核通过、签发、签章、送达、办结及归档是不同状态，分别依据真实操作或回执推进。
- 首版不自动对外通知、送达、执行裁决或发起其他法定程序。可提供相应待处理状态和接口衔接要求，实际对接另行确定。

## 5. 数据、版本与变更规则

### 5.1 身份和来源

使用稳定记录 ID＋源系统 ID＋具体版本，名称和条号不作为跨法规唯一键。源无版本时保存本次授权快照及内容摘要值。原文定位保留文献版本、页码/段落/条款，无法定位时明确说明，不能伪造定位。

源更新时间、业务事件时间、获取/导入时间、分析时间和审核时间分开。人员身份从真实登录/服务身份获得；机器执行主体不伪装为审核人。

缓存、原文保存、索引和模型处理遵循授权范围。当前权限在召回、模型上下文、详情、历史报告及文件下载各环节执行；权限撤回后不能继续从缓存泄露内容。

### 5.2 资料变化影响

| 发生变化 | 应处理的下游内容 |
|---|---|
| 法规原文/效力版本 | 解析、要点、匹配、引用及相关未签发报告标识待复核 |
| 条文解析/要点 | 依赖其内容的候选解释和分析标识来源变化，不自动改写法规原文 |
| 案件事实/程序/相关日期 | 匹配、有效性、证据分析和报告检查输入过期 |
| 专利/权利要求版本 | 解析及全部相关技术对照、有效性和报告标识待更新 |
| 证据新增、替换或人工采信变化 | 对应证据分析、引用该分析的报告及审核重新校验 |
| 模板新版本 | 只影响新选择任务，历史报告保留原模板 |
| 审核中或审核后内容修订 | 生成新结果版本，旧批准不自动适用于新内容 |
| 已正式确认文件需更正 | 走补正/新文件流程，保留旧文件和归档引用 |

每个结果记录输入版本清单。来源变化可通过同步事件或读取时比较检测；进入复核、签发确认等关键操作必须重新核对依赖。无法核实关键来源是否仍有效时返回待核实，不默认为通过。

历史快照保留用于审计，不等于允许失权用户访问，也不意味着自动撤销已签发文件；正式文件的后续法律处理由中心执行。

## 6. 通用服务与内部页面

### 6.1 服务契约

- 详细设计提供 OpenAPI 或等效可执行说明，包括类型、必填规则、长度/大小限制、枚举、错误码、状态、权限及示例；中文业务字段在单篇定义。
- 列表默认 20 条，可选 10/20/50，单次最多 50；这是产品初版默认值，可在评审调整。同字段多选为“或”，不同字段为“且”，日期范围含端点。
- 默认排序按单篇规定，再加稳定 ID；上游仅有游标时不伪造总数，不对当前页过滤或排序后宣称全库完成。
- 原文不存在、源能力未提供、无权限、源超时、解析失败和无检索结果分别返回；响应含请求追踪号，不暴露凭据及内部堆栈。
- 写操作检查对象版本；幂等键按调用方、操作及内容绑定。同键同内容返回原结果，同键不同内容返回冲突。
- 案件流程、分析任务、审核和文件渲染状态分别保存，不共用一个含义混乱的状态字段。

### 6.2 耗时任务

异步任务状态为排队、处理中、成功、部分成功、失败、取消。部分成功必须列出对象/步骤缺口，核心分析未执行不能标完整成功。

关闭页面不终止任务。重试产生可追溯尝试，不覆盖人工结果；取消后阻止后续步骤和迟到成功发布。服务重启识别中断任务，按幂等规则恢复或明确失败，不盲目重复外部写入。

### 6.3 页面验证

各模块页面均调用交付服务，支持加载、空数据、失败、无权限、重试及真实/模拟标识。任务进度刷新后可恢复，过时请求不能覆盖最新结果。

长法规、条文解释、要点和报告应可完整展开查看。引用打开具体版本，证据预览使用受控链接。管理按钮隐藏不能替代后端鉴权。

## 7. 国产化与达梦 DM8

### 7.1 实施约束

- 业务关系型数据使用达梦 DM8，不再重新选择数据库产品。小版本、兼容模式、字符集、大小写、拓扑及驱动/JDK 参数由中心环境清单确定，不擅自修改生产参数迁就代码。
- DM8 保存授权主档/快照、版本、任务、配置、引用、报告、审核及业务审计；图片、PDF 等可存批准的文件存储，数据库保留元数据与受控引用。
- 适配连接池、ORM/手写 SQL、分页、聚合、主键、批量导入、日期/数值精度、长文本和事务；不得假定其他数据库的 JSON/数组/函数或 DDL 回滚行为可直接使用。
- 初始化和已有库升级分开提供脚本，明确失败恢复；已有其他数据库配置通过不代表 DM8 验证完成。本次不自动启动生产迁移。
- 全文/向量/图像检索单独核验能力，优先中心 API，自建组件需符合中心国产化环境及授权，不预设额外数据库或国外组件为必需依赖。
- 模型、OCR、PDF、DOCX/PDF 转换、字体、CPU/操作系统/JDK及可选中间件均列入兼容清单；不默认依赖 Windows Office 或外部云转换。
- 数据库备份恢复、文件一致性、索引重建和权限恢复一并验证；交付运维配置与真实测试记录。

### 7.2 共用专项验收

| 编号 | 场景与预期 |
|---|---|
| ADM-01 | 记录真实 DM8 小版本/参数，完成驱动连接、空库初始化与服务启动 |
| ADM-02 | 有数据升级与失败恢复经过验证，不用清库重建替代 |
| ADM-03 | 中文/外文/特殊字符、长法规/报告、日期及分数完整准确 |
| ADM-04 | 版本发布、人工审核、状态推进、幂等及并发冲突符合事务规则 |
| ADM-05 | 数据库连接中断与服务重启恢复明确，不重复受理/审核/签发请求 |
| ADM-06 | 备份恢复后报告、引用、证据文件和审核链一致 |
| ADM-07 | 目标国产环境完成 OCR、模型和 DOCX/PDF 渲染样例验证 |
| ADM-08 | 约定规模及并发下测试性能，记录资源、耗时和外部接口限制 |

单篇列出本模块重点，真实 DM8 必须参与验证。模拟 API、内存数据库测试可辅助，不替代生产目标环境兼容证据。

| 依赖 | 需要中心提供/确认 | 缺失处理 |

| 法规与案例 | 全文、历史版本、效力、地域、条款结构及案例原文 | 返回版本/依据缺口，不自动确认适用 |

| 专利资料 | 文献、权利要求、附图、状态、缴费、无效及历史时点 | 缺项显示无法核实，不反推事实 |

## 9. 开发与验收组织

建议先落实中心 API 与 DM8 环境，复用 01—03 的已有能力并完成 04 案件基础；随后实施 05—09，10 模板可按已确认字段准备；最后串联 06 引用、11 报告和 12 复核。12 共用审核基础可提前实现供解析及模板使用，最终报告审核依赖实际报告版本。

共用 API 适配、文件、任务、版本、权限、DM8、模型和渲染框架只计一次工作量；各模块规则、页面和验收分别估工。排序依赖不表示排除任何原需求，复杂图像与技术分析需单列样例验证资源。

每个模块交付：实现对照、服务契约、部署/DM8脚本、直接调用样例、内部页面验证记录、真实数据来源对照、权限/异常/版本测试及未满足项。效果评测固定样本与数据/模型版本，中心专家分别评估事实准确性、引用支持度、特征完整性和意见合理性；不能只取成功样本计算准确率。

跨模块至少验证：

1. 案件录入/同步 → 分配 → 事实确认 → 法条匹配 → 人工调整 → 版本化引用。
2. 涉案专利 → 权利要求解析确认 → 指定时点状态/稳定性分析 → 证据逐项对照。
3. 案件与分析版本 → 指定模板初稿 → 人工修订 → 复核 → 待签发；有真实签发凭据时再形成正式文件。
4. 证据/法规/案情更新 → 下游过期识别 → 重分析/重审，历史报告仍可追溯。
5. 接口超时、取消、权限撤回、服务重启及 DM8 故障 → 明确状态，无虚构结果、重复决定或孤立引用。
6. DOCX/PDF 导出 → 同一锁定内容核对 → 签发材料登记 → 归档清单和审核链核验。
