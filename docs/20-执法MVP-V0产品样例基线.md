# 执法 MVP V0 产品样例基线

版本：V0.1  
日期：2026-09-15  
关联任务：`ARC-04-ENF-V0-SAMPLE`  
基线性质：依据原需求和已生效的 V0 临时产品决策形成的合成产品样例，只用于确认产品行为、异常边界和倒推后续最小设计范围；不替代真实线索、中心规则、证据采信、法律判断、模型效果评测或业务验收。

## 1. 样例共用约束

三个样例均使用 `V0-SYN-*` 合成数据，不是真实案件、线索、证据、主体、权利或法规。`V0-SYN-ENF-RULE-001` 只是验证软件路径的合成检查清单，不是法律规则、中心裁量规则或专业确认结论；据此形成的结果只能标为“辅助分析/待人工审核”。

样例从“已有且获授权的线索”开始，经过线索解析、人工核实关键解析结果、证据整理、证据链候选、辅助分析和人工审核记录结束。不实现线索自动发现、证据自动采信、正式立案、违法或侵权认定、处罚建议、文书签发、送达、执行或中心正式状态变更。

所有来源、版本、权限结果和人工动作必须来自相应系统或测试夹具，AI/Agent 不得生成或修改这些事实。当前测试身份的“确认/退回”仅验证动作、版本和审计留痕，不称为专业认定。

## 2. 三个产品样例

### 2.1 正常场景：来源完整、固定版本、人工审核对象明确

| 项目 | V0 产品样例 |
|---|---|
| 输入 | 获授权线索 `V0-SYN-CLUE-001@v1`：合成投诉材料中分别出现“投诉人甲”“经营者乙”和“权利人丙”，描述 2026-08-18 在某测试门店展示合成商品 X；关联合成证据 `V0-SYN-EVD-001@v1`（页面截图及字段定位）、`V0-SYN-EVD-002@v1`（商品照片及拍摄信息）；关联测试权利状态快照、测试来源定位和合成检查清单 `V0-SYN-ENF-RULE-001@v1`。所有数据均标记为合成且当前授权允许读取。 |
| 处理步骤 | 1. 校验线索、证据、权利快照和规则的标识、关联、固定版本与当前权限；2. 从线索原文提取多个主体候选、原文角色、疑似事实、时间、地点和证据引用，每项保留原文定位；3. 测试身份核实解析字段，修订时保留前后值；4. 按固定合成清单整理待证明事项、支持/反对关系、时间线和缺口；5. 形成逐检查项的辅助分析，将确认事实、当事人陈述和机器推断分开；6. 生成待人工审核的确切分析版本；7. 测试审核身份对该版本执行确认或退回并记录理由、人员和时间。 |
| 来源与版本 | 每个解析字段指向 `V0-SYN-CLUE-001@v1` 的字段路径或片段；每条证据关系指向证据编号、固定版本及页码/字段路径；时间线分别保存事实发生、证据收集和上传时间；权利状态保存状态时间、查询时间、来源和版本；任务固定全部输入版本。 |

| 人工控制点 | 关键解析字段由测试身份核实；证据关系只作为候选，由测试身份修订；证据采信和专业结论不在 V0 测试中完成；确认/退回只作用于本地辅助分析版本，不产生正式业务状态。 |
| 禁止行为 | 不得把提及主体直接认定为违法主体；不得推算统一社会信用代码；不得将摘要/OCR/上传成功解释为证据真实合法；不得省略反对或冲突材料；不得把合成检查清单称为中心规则；不得自动立案、认定、处罚、签发或回写中心状态。 |
| 需求来源 | `ENF-04-MUST-001/003/005/006/008/009/012`、`ENF-04-MUST_NOT-001/004/005`；`ENF-05-MUST-001/002/004/005/006/007/008/013/016`、`ENF-05-MUST_NOT-001/004/005`；`ENF-07-MUST-001/003/005/006/007/010`、`ENF-07-MUST_NOT-001`；`ENF-11-MUST-001/003/005/006/007/009/011`、`ENF-11-MUST_NOT-001/004`；执法总览第 3 至 5、7、9 节。 |

### 2.2 资料不足 / 信息冲突：保留部分结果和待核实状态

| 项目 | V0 产品样例 |
|---|---|
| 输入 | 获授权线索 `V0-SYN-CLUE-002@v1` 的正文写“8 月上旬”，附件 A `V0-SYN-EVD-003@v1` 写 2026-08-03，附件 B `V0-SYN-EVD-004@v1` 写 2026-08-12；两份材料对同一合成商品标识不一致；收集人和历史权利状态均未提供；另有一个音视频材料格式在当前测试环境不可解析。 |
| 处理步骤 | 1. 固定可访问输入版本；2. 分别保留线索原始时间表达、附件 A/B 的时间和来源，不选取其中一个覆盖其他值；3. 线索解析字段无法确定时留空并列出缺失项；4. 证据记录对未知收集人记录原因，不以上传人替代；5. 证据链同时展示支持、反对/冲突关系、具体冲突位置及待人工核验状态；6. 不可解析音视频列入未处理材料；7. 辅助分析只返回有依据的部分、具体补证事项和“材料不足无法判断”；8. 测试审核身份可退回并说明需要补充的材料。 |
| 来源与版本 | 时间、商品标识和陈述分别定位至线索、附件 A、附件 B 的固定版本；音视频只记录受控资源标识、格式和失败原因，不臆测内容；历史权利状态缺失被记录为缺口，当前状态不得替代行为时点状态。 |
| 期望输出 | 明确区分“资料不足”“内容冲突”“不可解析材料”和“待核实权利状态”；保留已有依据的部分解析和证据关系；逐项列出缺口、冲突、未处理材料及建议由人工补充/核实的事项；结果状态为“材料不足无法判断/部分结果/待人工审核”，不得伪装完整成功或“不构成”。 |
| 人工控制点 | 人工决定采用哪份材料、如何处理冲突、是否补证及是否退回；机器只呈现关系和缺口。后续新增材料会生成新的解析/证据链/分析版本，旧版本和审核记录保留。 |
| 禁止行为 | 不得自动选择 2026-08-03 或 2026-08-12；不得把上传时间当作收集或发生时间；不得补造收集人、统一社会信用代码、权利历史状态或音视频内容；不得静默排除冲突证据；不得将资料不足、规则不适用或源故障混同。 |
| 需求来源 | `ENF-04-MUST-005/007/008/009/013`、`ENF-04-MUST_NOT-003/005/006/007/008`；`ENF-05-MUST-008/013/015/018`、`ENF-05-MUST_NOT-005/007/008/009`；`ENF-07-MUST-005/006/007/008/009/011/017`、`ENF-07-MUST_NOT-003/004/005/006/007`；`ENF-11-MUST-005/006/007/008/009/010/012`、`ENF-11-MUST_NOT-003/004/005/006/007/008`。 |
| 专业确认边界 | “不得猜测、冲突必须保留、缺失与失败必须区分”已有原需求依据；何种材料足以支持专业要件、历史权利如何核实、补证优先级和允许差异仍待真实规则、样例和业务负责人确认。 |

### 2.3 无权限 / 来源失效：默认拒绝且不泄露正文

| 项目 | V0 产品样例 |
|---|---|
| 输入 | 测试调用者提交线索 `V0-SYN-CLUE-003@v1`，授权适配器返回无权读取关联证据 `V0-SYN-EVD-005@v1`；另一次运行中，`V0-SYN-EVD-006@v1` 在证据链形成后、辅助分析读取前变为来源不可用或权限被撤回。 |
| 处理步骤 | 1. 在线索解析、证据详情/预览/下载、证据链和辅助分析每个读取点执行当前授权检查；2. 无权访问输入时拒绝创建分析且不返回受限正文、片段或存在性细节；3. 来源处理中失效时停止使用该版本，保留最小审计记录，将相关关系和旧结果标记需复核；4. 只基于仍获授权且可用的来源返回明确标注的部分结果；5. 区分无权限、来源失效、上游故障和真实空数据。 |
| 来源与版本 | 拒绝结果仅引用授权判定标识、追踪标识和不泄露内容的资源引用；失效来源不再作为新分析依据。已形成的历史记录保留来源标识和失效/需复核状态，但每次读取正文仍重新鉴权。 |
| 期望输出 | 无权限时返回稳定拒绝结果和 `request_id`，不泄露材料；来源失效时列出受影响关系、未处理项和部分失败原因，说明旧版本需要复核。不能将失败说成“没有证据”“不构成”或成功无缺口。 |
| 人工控制点 | 权限恢复只能由权威授权机制或责任方处理；证据排除、是否重新收集及后续审核由授权人员决定。AI、Agent、前端隐藏按钮或测试身份不能授予权限。 |
| 禁止行为 | 不得从旧缓存、历史结果、下载链接或模型上下文泄露失权内容；不得由模型判断权限；不得让失效证据继续支持新结果；不得物理删除被引用证据来掩盖失效；不得把技术故障改写成业务结论。 |
| 需求来源 | `ENF-04-MUST-003`、`ENF-04-MUST_NOT-003/008`；`ENF-05-MUST-005/007/009/016/017`、`ENF-05-MUST_NOT-003/004/009`；`ENF-07-MUST-003/011/012`、`ENF-07-MUST_NOT-003/006`；`ENF-11-MUST-003/010/012`、`ENF-11-MUST_NOT-003/007/008`；执法总览第 3、5、7 节。 |
| 专业确认边界 | 默认拒绝、读取时重新鉴权、失效来源不再用于新结果已由原需求和 P0-03/04 V0 决策约束；真实授权范围、撤权传播时间、资源存在性披露和恢复流程仍待中心身份/安全责任方确认。 |

## 3. 最小业务流程

```text
获授权的已有线索及固定版本
  ↓
线索解析（字段均带原文定位）
  ↓
人工核实关键解析结果
  ↓
证据接入/引用与完整性记录
  ↓
证据关系、时间线、缺口和冲突整理
  ↓
逐检查项辅助分析（事实/陈述/推断分离）
  ↓
针对确切版本的人工审核记录
  ↓
结束：不进入正式立案、认定、处罚或中心状态
```

| 步骤 | 责任主体 | V0 最小边界 |
|---|---|---|
| 输入固定与授权检查 | 权威来源/授权系统提供事实，应用服务执行检查 | 固定线索、证据、权利、规则版本；每次读取执行当前权限；无权即拒绝。 |
| 线索解析 | 执法域，AI 可做候选抽取 | 提取多个主体角色、疑似事实、时间地点和证据引用；保留原文定位、缺失和冲突；不认定违法主体。 |
| 关键字段核实 | 授权人工 | 修订、确认或退回解析版本并留痕；测试身份只验证机制。 |
| 证据记录 | 执法域，文件/中心能力经端口接入 | 保存受控引用、来源、版本、完整性和原件/派生关系；真实性、合法性和采信由人工决定。 |
| 证据关系整理 | 执法域，AI 可生成候选关系 | 按固定规则形成支持、反对、冲突、时间线和缺口；不得宣称完整有效证据链。 |
| 辅助分析 | 执法域；Rule 执行已确认条件，AI 生成候选分析 | 分离事实、陈述和推断；披露来源、缺口和不确定性；V0 合成清单不冒充法律规则。 |
| 人工审核记录 | 授权人工 | 对确切辅助分析版本确认或退回，保留机器原始结果、修订和理由；不改变正式业务状态。 |

## 4. 由样例倒推的最小概念对象

以下只用于约束下一任务 `ARC-05-ENF` 的设计输入，不在本任务冻结字段、状态枚举、API、数据库表或公共模型。

| 概念对象 | 最小责任 |
|---|---|
| 线索工作项 | 引用权威线索及固定版本，聚合本次解析、证据整理和辅助分析的工作关系；不拥有中心线索。 |
| 线索解析版本 | 保存机器原始抽取、字段原文定位、缺失/冲突、人工修订及核实记录；重跑不覆盖历史。 |
| 证据引用/版本 | 标识来源、证据固定版本、受控资源、完整性信息、原件/派生关系和当前可用性；不表达自动采信。 |
| 待证明事项与证据关系 | 表达某一事项与具体证据版本间的支持、反对、冲突或缺失候选及定位；业务含义归执法域。 |
| 辅助分析版本 | 固定输入清单、检查项、事实/陈述/推断、来源、缺口、不确定性、结果分类和机器版本；不表示正式结论。 |
| 人工审核记录 | 指向确切解析/证据关系/分析版本，记录测试或真实授权身份的修订、确认/退回、理由和时间；V0 测试记录不等同专业认定。 |

是否合并或进一步拆分上述概念，必须在 `ARC-05-ENF` 中依据不变量和样例决定。不得直接复制咨询域的对象，也不得提前建立跨域统一 `Evidence`、`Review` 或完整 Runtime。

## 5. 第一阶段候选范围

1. 仅受理一条已存在、固定版本且当前获授权的合成线索，不实现自动线索发现。
2. 输出可定位原文的多个主体角色、疑似事实、时间、地点和证据引用候选，支持测试身份修订与版本留痕。
3. 接入或引用与线索关联的合成证据，记录来源、版本、完整性、派生关系、不可用和权限结果；不确认真实性、合法性或证明力。
4. 按固定合成清单形成证据关系、时间线、缺口与冲突候选，保留未处理材料和反对依据。
5. 形成逐检查项辅助分析，区分事实、陈述和推断，明确实际输入范围、缺口、不确定性与非正式性质。
6. 对确切版本执行测试身份的修订、确认或退回并保存历史；不实现正式业务角色、专业采信或中心状态衔接。
7. 覆盖正常、资料不足/冲突、无权限、来源失效/部分失败分支，并验证重跑不覆盖人工记录。
8. 后续详细设计必须先明确对象所有权、行为不变量和端口责任，再决定 API、逻辑数据、DM8 物理结构和代码。

项目负责人对第一阶段只能验收：产品流程是否符合三个样例、来源与版本是否可回查、权限与异常是否如实处理、人工动作是否针对确切版本、禁止行为是否没有发生。任何专业正确性、证据采信、法律结论、模型效果或真实中心联调仍保持未验收。

## 6. 当前明确不做

- 不实现 ENF-01/02/03 的全量数据源管理、规则管理和自动线索发现。
- 不实现真实证据文件上传、OCR、音视频解析、完整文件存储或下载系统；只设计可替换端口及错误边界。
- 不预置法律要件、优先级、严重程度、裁量、程序或处罚规则，不把合成检查清单提升为业务规则。
- 不输出正式违法/侵权认定、处罚建议、执法文书或法律签发结果，不写中心正式状态。
- 不实现完整案件管理、流程合规校验、处罚建议、文书模板/生成和送达执行。
- 不冻结具体角色、DataScope、SSO、中心 API 字段、文件策略、模型、检索产品、DM8 表或部署拓扑。
- 不把 `Claim / Evidence / Citation / Review / Task / RunRecord` 预设为跨域公共领域模型。
- 不以合成数据、模型自评分、静态页面或测试身份操作宣称真实业务、法律、模型效果或国产环境验收。
