# ADR：裁决正式报告人工修订安全编辑（2026-10-03）

技术决定责任：Codex；授权来源：负责人在最终产品首案闭环后要求“继续”。范围仅IMP-ADJ-V2-TASK-02，沿REQ-ADJ-R-CORE-14 / ADJ-11人工修订与ADJ-12确切版本复核的已过R，以及首案D2现有HTTP、权限和状态机。不是新增法律规则、业务审批级次或专业验收。主计划唯一控制状态。

## 当前缺口与限定D

当前Reports修订textarea为空，章节切换不能载入原正文，离开报告可能丢失输入；工作台命令吞并错误后无法向编辑器表达成功/失败，选择旧报告修订后可能继续展示旧版本。直接检查Reports.tsx、AdjudicationWorkspace.tsx、Forms.Command和现有真实浏览器脚本可复核。

合同：
1. 修订绑定报告revision/contentSha256及所选章节。显示原章节并默认载入完整正文，人工改写形成新版本，原报告/来源/审核历史不覆盖。每章节独立保留正文和原因，切换章节不丢；原正文无客户端格式化/删改。
2. 未保存内容仅内存，不写localStorage/sessionStorage/自动HTTP。显式放弃、切换报告/当前工作区面板/案件/历史及刷新前确认；整页关闭或刷新用beforeunload浏览器保护。保护范围是本裁决工作区，不宣称平台外部SPA路由或浏览器SPA前进/后退已全部接入拦截。锁定和401/403/来源撤回安全清正文优先于草稿，不允许草稿阻断失权清理。
3. 直接用现有POST /reports/{revision}/revisions，expectedVersion和reportSha256仍后端核。命令提供UI成功信号：只有HTTP回执和后续读取都成功才true；拒绝/网络未知false，保留输入，不自动换键/变更版本/重试。既有结果不确定同键对账继续生效。
4. 成功后查看服务端新稿并清理内存草稿；如果其他章节也有未保存内容，必须先确认只保存当前章、成功后放弃其他章；取消确认不发请求。拒绝时仍显示原后端错误和输入。旧稿/非法状态按钮不以本编辑器偷偷放宽或替代后端规则。前端离开确认是防输入丢失，不是新业务状态。
5. 不改领域/API/DB/共享安全/CON/ENF；仅裁决前端与测试。Command允许boolean成功信号，既有忽略返回值的裁决表单兼容，undefined不能被当保存成功。新建案件callback适配保持Promise<void>契约。

## 正反核对与准入

正向：原章节精确预填、两章节切换保留、保存绑定原revision/SHA/字段，HTTP成功新版本可见。反向：后端拒绝/未知结果不能清输入；取消离开保留、明确放弃可切换；历史只读不能写；失权不得保留敏感稿；源/权限/规则/版本继续后端裁定。没有新增身份、许可、专业阈值或恢复语义疑问；现有API和安全清理合同足够，本限定D通过，可实现。

## 退出

组件正反例、真实Chromium/PKCE/双DM8单案闭环含新增编辑操作、生产构建、CON106/ENF100领域回归与统一verify-all实际通过，归档错误轮和边界证据后才标完成。01A～D原完成记录不重做，不声称全部ADJ或专业验收完成。
