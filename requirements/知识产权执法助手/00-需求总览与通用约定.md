# 知识产权执法助手需求总览

版本：V0.1 需求评审稿  
日期：2026-09-12  
范围：6 个业务模块、17 个小功能，每个小功能一份需求文档。

## 1. 建设与交付口径

中心提供数据 API、授权范围、业务标准、法定模板和专业审核；服务方负责接口适配、规则执行、智能分析、结果管理与服务运维。本文是供技术评审和拆任务的需求稿，接口能力尚未实测，不能作为已完成联调或已确认法律口径的说明。

对外交付服务接口、接口说明、部署配置说明、联调样例及验证结果。自研前端是内部联调和验证工具，不纳入对外页面交付；页面操作必须调用同一套服务接口，不能把规则、金额计算或权限判断仅写在前端。前端隐藏按钮不能替代后端授权。

本轮仅整理执法助手，不修改咨询助手或已有法规需求。无需将每个小功能实现为独立智能体或独立微服务；按业务边界提供可单独测试的能力即可。

## 1.1 已确认的国产化与数据库要求

- 部署适配中心国产化环境；数据库确定使用达梦 DM8，数据库选型不再列为待确认事项。
- 业务结构化数据持久化、建表及升级脚本、数据库驱动与访问组件、分页查询、事务、索引和备份恢复方案均须适配 DM8。文件存储方式按中心环境确定，不要求将全部证据文件存入数据库。
- 内部验证环境使用 DM8，验证字段类型、中文及长文本、时间与金额精度、分页排序、事务回滚和版本并发控制；其他数据库上的运行结果不能代替 DM8 兼容验证。
- CPU 架构、操作系统、中间件、大模型以及 OCR、文档转换、音视频处理等依赖，统一按中心国产化环境适配，不预设具体厂商或产品。
- 中心提供环境清单、产品版本、部署与网络条件；技术核验 DM8 具体版本、兼容模式、字符集、驱动及权限配置，以及各依赖的可部署性。上述内容为实施对接参数，不再重复确认国产化方向。
- 对外交付相应部署配置说明、DM8 建表及升级脚本、依赖兼容清单和实际验证记录。需求确认不代表国产化或 DM8 兼容测试已经通过。

## 3. 通用接口约定

以下为服务行为要求，具体 URL、字段英文名和认证协议在详细接口设计时统一。技术交付须提供可运行的 OpenAPI 契约、请求响应样例及错误样例。

- 身份来自可信认证上下文，记录机构、人员或服务身份；不得直接信任调用方传入的人员名称作为权限凭据。
- 编号使用字符串；列表类接口支持关键词、文档规定的筛选、页码、每页条数与排序字段，返回 items、total、page、page_size；默认每页 20 条，上限 100 条。
- 时间戳使用带时区的 ISO 8601，内部验证页面按 Asia/Shanghai 展示；仅日期使用 YYYY-MM-DD。金额使用定点十进制字符串，注明币种、金额口径与舍入规则。
- 新增任务支持幂等键，同一主体、操作和幂等键配相同输入返回同一任务；配不同输入返回冲突。
- 分析、同步和文书生成采用任务提交及状态查询方式。提交返回 task_id、status、request_id；状态包括 queued、running、succeeded、partial_failed、failed、cancelled。输出业务 result_id 和版本；部分失败需明确未处理项目，不能伪装完整结果。
- 参数错误、未认证、无权限、资源不存在、状态冲突、限流、上游不可用及内部异常分别返回稳定错误码、可读说明、request_id、是否可重试；参数错误附字段路径。凭证和敏感材料不写入错误详情。
- 接口超时与“成功但无结果”分开表达。重试不重复产生业务记录和提醒；恢复及最大重试次数通过服务配置管理。
- 对规则发布、结果审核和状态变更做后端权限及状态机校验。编辑带预期版本，版本冲突须返回冲突，不能覆盖其他人员更新。
- 案件、线索、证据、分析报告和文件按中心授权范围隔离；受控文件预览/下载执行同一权限检查，访问链接有有效期。
- 保存输入资源编号及快照版本、规则/模板/模型版本、来源定位、操作者及时间。上游变化不能重写历史报告，受影响结果标记需复核。
- 内部模拟数据明确标识并与真实环境隔离；真实联调和模拟测试的验证结果分别记录。

## 4. 信息字段说明

单篇表格中的“是”表示该业务操作必须提供；“条件”表示满足说明条件时必填；“生成”由服务生成；“输出”为分析结果字段，可以为空但必须返回缺失原因。字段表包含原需求信息项以及必要的来源、版本与状态字段。

分析字段不得为了满足必填而编造事实。规则状态与任务状态、业务处置状态、审核状态分别存储，不能共用一个 status。审核人和收集人、上传人和撰写人按真实含义分别记录。

## 5. 审核与版本通用要求

- 配置：草稿可编辑；发布后形成不可变版本；修改发布版本创建新草稿。停用影响后续任务，不删除历史依据。
- 结果：保存草稿、提交审核、确认或退回；退回需理由，重新提交产生新版本。审核动作由中心授权角色执行，后台接口验证权限。
- 文书缺少必填项处于不完整草稿；补齐后才允许提交审核。正式签发、签章、送达、处罚执行均不由本服务自动完成。
- 人工修订保留原模型结果、修订内容和审核记录。重新运行不能覆盖已经人工修订的结果。
- 资料不足、规则不适用、API 故障分别表达；疑似线索、辅助分析和正式执法结论不能混用状态。
- 上传材料和外部 API 文本仅作为业务数据，不得作为改变系统指令、调用权限或执行任意操作的指令。

## 6. 内部前端通用要求

内部工作台按六个业务模块组织菜单，可复用表格、详情抽屉、编辑表单、任务进度和版本对照组件。单篇规定具体字段和操作，不要求 17 个独立前端项目。

每个页面至少覆盖加载、空数据、成功、失败、无权限状态；异步任务可刷新后继续查看。提交期间防重复点击，错误展示业务原因和 request_id。原文及证据链接必须可核验，无法访问时明确提示。

页面测试与直接 API 测试均须执行；禁止通过静态演示数据证明真实服务已通过验收。

## 7. API 与业务材料依赖清单

| 依赖 | 最低需要的内容 | 不满足时的处理 |
|---|---|---|
| 线索 API | 唯一键、原文、来源、更新标识、分页或推送机制 | 只实现已接入范围，不宣称全网实时发现 |
| 案件流程 API | 案件标识、程序、环节事件、时间、材料及延期中止事件 | 缺失项返回无法判断，不能宣称全流程已校验 |
| 证据 API | 文件或可读资源、来源、关联关系、版本及收集信息 | 不可读材料列为未处理，不补造内容 |
| 权利信息 API | 权利标识、文本/图片、相关时点状态 | 无法核实的权利基础标记待核实 |
| 法规 API | 条文原文、层级、版本、适用地区、效力和历史信息 | 不可靠依据不自动确认 |
| 规则和裁量基准 | 专家确认的适用条件、例外、公式及边界样例 | 可建设配置服务，不能自行预置法定标准 |
| 文书模板 | 首批模板、字段说明、版式样例 | 不承诺覆盖所有文书格式 |
| 通知接收端 | 接口、授权接收范围、确认和去重机制 | 提供待办查询接口，不假设已有外部推送通道 |

缓存、原文存储、索引与模型调用出域范围须以中心授权为准。权限、日志和备份保留期按中心要求配置。具体 API 名称、地址、同步频率、文件大小限额、数据规模、并发、响应时间和模型效果目标在技术评审和样例试测后形成双方确认的验收配置，不在此虚设数值。

## 8. 建议实施顺序

1. 核验中心接口，统一认证、案件/资源标识、任务及审计能力；接入 01、05、17。
2. 建设配置能力 02、06、08、10、12、13、15，准备中心确认样例。
3. 跑通 03 → 04、05 → 07、08 → 09 的独立闭环。
4. 跑通 11 → 16 → 14，并按具体文书需求连接其他结果。
5. 使用内部前端和直接 API 执行回归，输出接口交付包与测试记录。

这只是依赖顺序，不代表必须先完成所有配置才能验证第一个闭环。

## 9. 验收组织

单篇验收场景是基础功能验收。规则匹配、金额、日期计算用预先确认的输入与期望值逐例检查；模型抽取、线索发现及分析用中心专家标注的独立样本集评估，分别记录准确率/召回率、来源正确性、缺失处理与专家复核结果，不能拿模型置信度充当准确率。

每个小功能至少记录：需求编号、接口请求、输入版本、预期、实际输出、页面结果、通过/失败及问题编号。API 能力未确认的项标为联调依赖，不计为已验收。性能阈值和样本量在试测后确认，再执行性能和效果验收。
