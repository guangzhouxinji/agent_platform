# 可观测性与运行追溯

依据三域需求中任务 ID、版本、来源、错误、审核和效果统计；`ADR-V2-02/03/11`。区分服务健康、Agent 行为、业务成果、专业质量与正式系统结果，不把一次工具成功当作任务完成。

## 事件与最小追踪

每个 Task/Attempt/Tool/Artifact/Human Request 关联 `traceId`、`taskId`、`goalVersion`、`attemptId`、`causationId`；记录步骤目的、开始/结束、数据源及具体版本、实际范围/截断、工具/Skill/Prompt/模型/规则/模板版本、预算消耗、结构化结果类别、证据/产物 ID、重试/停止原因。业务时间、源更新时间、获取时间、执行时间和人工决定时间分开。敏感原文用受控引用，日志不含凭据或全文。

## 指标分层

| 层 | 指标及分母 | 不作何种推论 |
|---|---|---|
| 运行可靠性 | 任务启动/完成/部分/失败数；各失败原因、恢复成功、取消迟到、重试率、首个成果与最终时长 | 工具成功率不等于用户完成率 |
| 检索/证据 | 实际源覆盖、截断、关键来源可核验、Claim 支持/反证/缺项、撤回传播时延 | 引用总数/分数不等于证据充分 |
| 人工协作 | ASK 次数及必要性、CONFIRM 拒绝、REVIEW 排队/退回/修订、TAKE_OVER 受理与未接通 | “请求已发”不等于人工受理 |
| 用户价值 | 分域目标完成/部分完成/未完成、成果采用、总工时（含审核）、用户纠错/重做 | 消息数和点赞不叫专业准确率 |
| 安全/成本 | 越权拦截与确认的泄漏事件、规则版本错用、无依据结论、每任务模型/工具费用及预算停止 | 零监控告警不代表零风险 |

对无结果、证据不足、无权限、源故障、模型失败、人工不可用分别计数；公布质量率必须同时给样本版本、有效分母、失败/拒答/未评估数、时间窗、领域/风险层与误差。研发模拟和真实生产数据分别标记，不合并成总体准确率。跨任务或跨组织报表遵守数据权限及最小化。

## 故障处置和回放

Run trace 应能回答：任务为何补问/重检/停止、用哪版来源和规则、哪项人工决定使其继续、哪个事件使产物失效。支持受控重放合成/获准数据与相同依赖版本，重放不得执行外部写回或冒充真实人员；源撤回后只可保留最小审计，不复制已失权内容。监控发现来源延迟、索引落后、异常循环、预算耗尽、审核积压、越权尝试或发布后质量退化时暂停相关 Tool/Release 并转人工处理。告警阈值和留存 **[待确认]**。
