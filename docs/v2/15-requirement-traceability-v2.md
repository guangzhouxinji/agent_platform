## 取舍和冲突

| 原要求或重复/冲突 | 诊断 | 建议取舍与必须保留的义务 |
|---|---|---|
| 原 DOCX 的“相似度量化/判断侵权/有效性结论/处罚建议/最终形成正式文件”与细化文档的辅助/人工/权威边界 | `[CONFLICT]` 自动化措辞易越权 | 重定义为分数仅排序、逐项证据与规则/人工决定；正式决定由有权主体，不删辅助分析需求 |
| CON-10/11/12 把 Prompt、Intent、Chat 列为独立中心功能 | `[IMPLEMENTATION]` 机制主导用户体验 | 合并到 Goal 理解、引导与 Task 工作面；各原功能仍有可测试版本、配置、评测/多轮追踪 |
| 咨询/裁决法规及要点资源、执法/裁决引用、三域模板/任务/审核 | `[PRODUCT]` 重复基础协议但语义不同 | 合并基础来源/版本/引用/发布/运行能力；保留各领域用途、权限、专业语义及验收 |
| 既有法规/解析/要点文件的“覆盖/删除”与后来裁决版本引用保护 | `[CONFLICT]` 可能破坏历史证据 | 不覆盖被引用/审核版；新版本或撤回。覆盖未审核草稿是否可用需责任方决定 |
| 需求总览的中心 API 主路径与 `docs/02` 后续本地 DM8 主路径决定 | `[CONFLICT][UNCERTAIN]` 数据权威、授权、合同/交付可能不同 | 产品只承诺获准来源与正确血缘，不预设旧实现路径；责任方确认正式源/本地数据许可及验收范围 |
| 咨询原始方案含公众/企业，而后补行为以内部业务人员为主；内部页面原文不属对外交付 | `[CONFLICT][UNCERTAIN]` 用户和 UI 承诺不同 | 首条内部专利任务已有P0-20依据；公众入口/交付工作面仍须合同与负责人确认 |

## 首条咨询范围的契约分层与冲突消解

首条关联 CON-02/04/06/09/10/11/12，共7项；配置/提示词的最小版本控制是该任务运行依赖，不扩成通用配置平台。五个直接用户能力与两个支撑能力共同验收，不能只做主页面。

1. CON-04/06 的旧“成功/失败”表示单次检索/对照执行；CON-12九状态表示完整产品任务；CON-09发布与服务状态另列。不得把全部枚举合并或把执行成功自动映射任务完成。
2. CON-04“新检索任务不覆盖旧任务”和CON-06“修改后新建分析任务”保留为不可变执行版本；P0-20及第23节决定要求同一用户目标的纠正继续原任务链。是否建新Attempt/子任务由D决定，不静默清空当前目标。
3. CON-12“首版固定流程/循环上限”不能限制已确认的结果驱动连续行动；保留配置校验和技术防失控，不预设固定业务轮数。规则/预算必须有来源；不靠无限循环实现智能。
4. 会话结束/过期关闭该会话输入与任务持久恢复分开；新会话只继承显式获准资料，任务恢复重新授权。不得把关闭网页等同取消任务，也不得以“继续任务”绕过会话失效。
5. 首期主线是专利技术参考；原需求中的新颖性辅助准备、外观等后续能力仍保留各自门禁，不借“首期”删义务。普通辅助报告与正式法律结论严格区分。
6. 7份机器契约保留旧有效条款，增加原文产品补充及已确认决定的执行反例；重抽取与第二遍语义复核是两步。仅更新内容不自动将stale改ready；C4已对这7项另做第二遍语义复核并逐项恢复R，记录见总计划第7.13节。后续仍可逐项R复核，不被全41项批准锁住。
