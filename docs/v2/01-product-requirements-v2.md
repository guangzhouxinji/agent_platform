# V2 产品需求

修订：2026-09-24，契约优化稿 C2。依据：[整体评估第6/10节](../V2-项目整体评估报告.md)、[P0-20既有负责人决定](../02-待确认事项清单.md#20-p0-20-咨询智能体产品行为负责人基线)。本轮路线确认见 docs/02 第22节；任务状态仅见总计划 REQ-V2-CONTRACT-OPT-09 / REQ-3AGENT-REVIEW-03。

确认范围：完成分层、稳定跨轮引用、纠正后同任务继续、人工交接真实回执已由用户明确确认为三域共同约束，证据见 [docs/02第23节](../02-待确认事项清单.md)。各域分别定义证据标准和完成条件；其余新增建议、范围与外部条件仍按相应责任评审，不将整份V2称为已批准。原始业务事实、产品行为补充和新提案分开：`[原文]` 可定位原始 DOCX/requirements，`[新增]` 为 V2 建议，`[假设]` 可逆前提，`[待确认]` 阻断正式承诺。需求编号 `V2-*` **不是**现行 41 项状态台账。

## 定位、角色与成果

- 目标用户：内部检索/分析人员、执法承办及复核人员、行政裁决承办及专业复核人员；管理员维护经批准资源/规则/版本。原始 DOCX 同时提及企业和公众咨询，但细化咨询文档 2026-09-22 第 9 节以内部人员为主要对象。公众/企业入口、匿名能力、交付 UI 与服务责任 **[待确认]**，不能由内部工作台推定。
- 首要工作：咨询获得可核查的技术/商标/案例参考；执法将线索整理成有缺口/冲突的证据与程序辅助包；裁决将案件材料形成有时点法规、逐项分析和复核的报告草稿。结果服务于人，不替代机构正式程序。
- 用户价值假说 **[假设]**：相比现有人工工作流，总工时（含复核）、查证成本及漏项下降，来源错误和无依据判断不增加。必须真实任务对照验证，不能用回答“像专家”替代。

## 用户旅程与完成定义

| 任务 | 用户动作和系统响应 | 最小正式工作成果 | 完成/停止条件 |
|---|---|---|---|
| 专利技术参考 | 自然语言技术方案；确认核心特征与检索目的；自动受限检索、人工选文献，逐项对照；纠错后局部重做 | 候选集、实际范围、权利要求/原文定位、技术对照、未知项、来源版本 | 能回答技术参考目标且关键陈述有直接依据；缺全文则线索级/证据不足，不出侵权或有效性结论 |
| 商标近似参考 | 名称/图样、商品服务、类别；独立文字/读音/含义/图形召回与多维对照 | 各维度证据与未分析项、分类/标准版本及整体辅助意见 | 图形未接通不伪图像分析；不同类别不等于不类似；无法分析则部分成果 |
| 案例参考/复合咨询 | 给事实和法律问题，补关键争点；检索原文和审核派生要点；比较异同；多个子目标分别跟踪 | 案例原文版本、参考点、重大差异、历史法条时间及带引用答复 | 他案结果不推定本案；每子目标有成果或明确缺口 |
| 执法线索工作 | 接受授权线索，抽事实/主体候选，检查证据、反证、规则/流程，形成草稿 | 事实-证据链、要件缺口/矛盾、合规项、辅助分析/文书草稿 | 授权人核对前仅待复核；资料不足不得进入处罚确定金额 |
| 裁决案件工作 | 选择案件/争点与权利要求；核实法规时点、权利状态和双方证据；生成初稿并复核 | 案件事实集、条文引用、分栏有效性/技术证据意见、报告版本与复核包 | 复核通过止于待签发；正式状态仅真实操作/回执 |

## 非功能和范围

- 业务关系型存储为 DM8、目标国产环境需真实验证 **[原文]**；但领域设计不绑定其物理结构。全文/图像/OCR、模型、文件和中心 API 能力需核实，不能从产品结构反推供应商或性能。
- [假设] P0 先服务内部专利任务，支持服务 API 与内测工作面；面向公众的 UI、中心 API 与本地数据主路径之间的交付选择要合同/业务确认。路线图并行准备执法与裁决的受限切片，不擅自缩减 41 项。
- 服务响应、召回阈值、证据充分标准、可自动运行时长、保留期限、数据许可、人员角色和正式办理流程均 **[待确认]**；本稿只规定其须被参数化、评测和门禁，不填写虚构数值。

## 首条咨询完整任务的可检查合同

首条任务沿用 P0-20 的专利资料查询、检索、技术对照及复合场景，不把“首条”变成删去商标、案例或另外两域。当前细化的是用户可观察行为，尚不冻结API、数据库或D门。

| 输入/触发 | 必须得到的行为或产物 | 失败反例（据此设计测试） |
|---|---|---|
| 正常目标：查找与某技术方案相关文献并对照选定文献 | 确认必要特征，受限检索，明确选择，按原文逐项对照，交付来源/范围/未知项 | 只返回搜索链接、跳转独立页面后丢失目标却宣布完成 |
| 关键特征缺失；或只是精确专利号码查询 | 只补影响目标的必要信息；精确查询不强制技术特征 | 反复索取已知信息，或模型自行补足事实 |
| 输入互相冲突 | 显示冲突及影响，暂停依赖判断；无关授权分支可以继续 | 擅选一方事实、不记录分歧 |
| 用户纠正特征 | 新事实版本，定位受影响结果/对照，保留旧版并提供继续 | 全部清空、覆盖历史或旧结果继续装作有效 |
| 多轮追问“继续” | 延续同一目标、范围、结果和已完成进度 | 只拼接聊天文本、重新启动孤立查询 |
| 当前结果不足 | 报实际范围/覆盖/不足；允许范围内继续寻找，必要时要求材料 | 固定前几条当全部命中，声称不存在相关专利 |
| 用户要求继续检索 | 获准方法内深化；新结果集有独立快照，原引用仍可定位 | 每次排序后重编号并改变“原第二条”含义 |
| 只有摘要，无可读权利要求 | 返回线索与全文缺口；暂停权利要求级对照 | 填满对照表、把字面未命中判技术不存在 |
| 权限失效，读取旧结果 | 服务端按当前权限拒绝内容，不通过历史缓存绕过 | 历史运行曾授权所以继续展示全文/导出 |
| 数据源失败或被撤回 | 区分超时/撤回和零命中，保留受控进度、列恢复条件 | 将不可达记录成无结果；撤回材料继续支撑当前结论 |
| 模型失败 | 已核查原文和机器输出区别保留；显示技术失败/部分成果，符合策略才重试 | 把预设字符串当模型分析，或伪造专业完成 |
| 人工升级 | 交明确版本的证据/问题包；无真实受理回执就显示未受理 | 本地按钮点击当人工已接管 |
| 进程重启后恢复 | 读取持久版本/检查点，重新授权，核对当前目标/来源后继续 | 内存会话丢失、重复发布或旧输出盖过人工修订 |
| 用户取消 | 停后续调用与发布，未能中断的迟到结果隔离；保留受控历史 | 取消后继续生成“已完成”成果 |
| 跨轮引用“原第二个/刚选中的” | 绑定已明确的结果集版本及对象；新展示不改明确焦点；无法唯一绑定则补问 | 自动用最近排序中的第二条替换用户对象 |

这些场景是产品反例，不是已执行测试或专家金标；跨进程恢复、真实权限/来源/模型/人工接入必须有 Real Integration 证据，技术对照质量与是否减少复核总工时必须另做 Business Acceptance。

## 确认范围与尚需决定的最小增量

- 已有依据直接继承：原41项义务、三域AI/规则/人工边界、咨询P0-20十条行为、DM8与国产化要求。不能因为V2重写就要求重批这些行为，也不能因本稿整理完成自动刷新机器R。
- 本轮已确认：六步实施顺序与先优化产品契约；真实验证按域条件及时进行。这不等于已批准生产数据、专业通过线或物理部署方案。
- 本轮新增已确认：四层完成语义、稳定跨轮引用、纠正后同任务继续与真实人工回执作为三域共同可观察约束；完成和证据标准分别归领域，不强制共享状态枚举。确认记录见docs/02第23节，不再重复请求本项批准；四动作的具体触发、权限和办理责任仍在目标任务中以证据确定。
- 架构仍为候选：三独立Agent＋所有持久业务真相外置到按域分模块服务；仅共享公共数据也是保留备选。负责人选择部署方向后，还需当前Task的D门证实故障隔离、权限和恢复，不能以本稿准入通用Runtime。
- 范围仍待合同责任方：公众/企业入口、正式UI/API交付、任何41项删除或实质重定义。本稿不删除义务，首条内部咨询沿用已有P0-20范围。
- 外部证据仍缺：获准样本、逐用途数据许可、可信身份与人工接收职责、领域专业标准/模板、评测通过线和保留政策；分域依赖受阻，不笼统冻结无关文档工作。
