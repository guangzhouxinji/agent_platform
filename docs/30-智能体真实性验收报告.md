# 智能体真实性验收报告

验收日期：2026-09-22  
验收对象：当前工作区磁盘状态下的 `agent_platform`  
验收结论：**不通过**

## 1. 结论摘要

当前平台已经存在较多页面、控制器、领域服务、DM8 适配器和自动化测试，但尚不能据此认定业务可用。默认配置下后端不能启动；真实 DM8、真实身份、真实业务来源和真实模型并未形成可复现的一键闭环；完整质量门禁有 5 个浏览器用例失败；大量浏览器验收直接拦截并伪造 API 响应，75 个 Java 测试被跳过。三个 MVP 均没有正式业务验收证据。

本次共记录 18 个问题：P0 6 个、P1 10 个、P2 2 个。这里的“不可用”包括无法启动、只能依赖开发/合成输入、按钮不能抵达对应流程、自动化只验证伪响应、以及能力明确为空或固定算法但界面仍可能让人理解为智能能力。

本报告只审计真实性，不新增功能，不修改需求文件，不升级任何需求的 D/V/A 状态。结构校验通过只说明台账和基线结构一致，不证明法律、专业或业务正确。

## 2. 验收范围与方法

- 静态检查：生产代码、配置、当前前端路由、按钮事件、适配器、TODO/FIXME、合成/开发数据、空实现和固定输出。
- 启动检查：构建可执行 JAR，并分别检查无数据源和当前 DM8 配置下的启动结果。
- 自动化检查：运行统一质量入口 `npm test`，另行运行 `mvn -q test` 统计后端测试及跳过项。
- 追踪检查：对照 `docs/08-总开发实现计划.md` 的正式 D/V/A 状态和三个 MVP 的既有验收声明。
- 限制：工作区存在大量未提交文件、旧 `src/` 删除和新 `backend/`、`frontend/` 未跟踪内容；本结论只对应当前磁盘快照，不能由 Git 提交重放。

## 3. 问题清单

### RA-01 默认配置后端无法启动

- **功能**：平台 API 基础运行与知识库/专利检索装配
- **文件位置**：`backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/AgentPlatformApplication.java:14`；`backend/apps/platform-api/src/main/resources/application.yml:77-83`；`backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/config/PatentSearchConfiguration.java:71-80`；`backend/adapters/persistence-dm8/src/main/java/cn/xinji/agentplatform/knowledgebase/adapter/out/dm8/Dm8KnowledgeBaseJsonReader.java`
- **当前实现**：应用在未设置 JDBC URL 时排除数据源自动配置，但默认 `knowledge-base.provider=dm8`，DM8 知识库读取器/专利库适配器仍要求 `DataSource`。可执行 JAR 构建成功后，无数据源启动报 `No qualifying bean of type javax.sql.DataSource`；使用当前不可用凭证启动报“用户名或密码错误”。从 `platform-api` 子模块直接执行 `spring-boot:run` 还出现 `NoClassDefFoundError: AdjudicationLocalSourceImporter`。
- **为什么不可用**：默认配置无法得到可服务的 API 进程，前端所有真实调用链因此没有基础运行条件；“无数据库时排除自动配置”与“默认强制装配 DM8 能力”相互矛盾。
- **修复建议**：定义并验证唯一受支持的启动配置；所有 DM8 Bean 与数据源条件一致；启动前校验配置并给出单一明确错误；提供从干净检出可复现的全反应堆启动验收。
- **优先级**：P0

### RA-02 完整质量门禁和当前 MVP 浏览器验收失败

- **功能**：统一回归与 MVP 验收案例
- **文件位置**：`frontend/e2e/development-acceptance.spec.mjs:46`；`frontend/e2e/remaining-workspaces.spec.mjs:20,224,236`；`frontend/e2e/workflow-full-flow.spec.mjs:28`
- **当前实现**：`npm test` 中治理校验、Vitest 4/4、前端构建通过；Playwright 43 个通过、5 个失败、2 个未运行，流水线在 Java 测试前退出。失败包括咨询没有出现答复、执法页面仍断言旧标题/“创建工作项”按钮、移动端旧标题断言，以及执法全流程等待已不可达按钮超时。
- **为什么不可用**：项目自己的总验收入口为失败状态，当前 UI 与验收案例已经漂移，不能声称 MVP 案例能通过。
- **修复建议**：先确定当前获批 MVP 路由和验收案例，再让用例调用真实后端、真实存储和允许的数据源；删除或改写针对已退役入口的断言，直到统一入口全绿并保留运行证据。
- **优先级**：P0

### RA-03 自动化验收大量伪造 API，真实 DM8 测试被跳过

- **功能**：API 闭环、按钮闭环及数据库持久化证明
- **文件位置**：`frontend/e2e/development-acceptance.spec.mjs:27-69`；`frontend/e2e/workflow-full-flow.spec.mjs:16-55`；`frontend/e2e/remaining-workspaces.spec.mjs:27-209`；`backend/apps/platform-api/src/test/java/cn/xinji/agentplatform/infrastructure/`
- **当前实现**：多数组合流程通过 `page.route(... route.fulfill(...))` 返回预制 JSON；“development acceptance”对执法/裁决只检查按钮启用，没有提交。独立 `mvn -q test` 为 394 个测试、0 失败、0 错误、75 跳过；42 份 DM8 报告中 13 份明确使用 `test-synthetic`，本机未满足条件的咨询、执法、裁决、模型配置、检索、对照、证据和知识库 DM8 测试被跳过。
- **为什么不可用**：浏览器看到的成功结果不是后端产生的，Java 通过也没有覆盖当前真实数据库环境；这些结果不能证明 API、存储和 UI 的端到端闭环。
- **修复建议**：把“组件契约测试”和“真实性验收”分层；真实性套件禁止路由伪响应，强制启动真实 API、检查数据库副作用/重启恢复，并将关键环境缺失视为失败而不是跳过。
- **优先级**：P0

### RA-04 身份与权限是硬编码开发字符串

- **功能**：咨询、执法、裁决访问控制和人工复核授权
- **文件位置**：`frontend/src/shared/ui/Workbench.tsx:5-8`；`frontend/src/features/workflows/AdjudicationWorkspace.tsx:9`；`frontend/src/features/workflows/EnforcementWorkspace.tsx:9`；`backend/consultation/src/main/java/cn/xinji/agentplatform/consultation/adapter/out/synthetic/V0AuthorizationAdapter.java:8`；`backend/enforcement/src/main/java/cn/xinji/agentplatform/enforcement/adapter/out/synthetic/V0EnforcementAuthorizationAdapter.java:15-22`；`backend/adjudication/src/main/java/cn/xinji/agentplatform/adjudication/adapter/out/synthetic/V0AdjudicationAuthorizationAdapter.java:6-7`
- **当前实现**：前端固定发送 `v0-authorized-user`、`v0-enforcement-reviewer`、`v0-adjudication-reviewer`、`org-v0`；后端以字符串相等判断访问者和可信复核人。`application.yml:18-29` 默认关闭 API Key 验证。
- **为什么不可用**：任何能构造请求头的调用方都可以冒充开发用户或复核人，无法证明当前授权、组织隔离和人工决定主体，不能承载真实案件或正式复核。
- **修复建议**：接入可信身份认证和角色/组织映射；由服务端身份上下文生成 actor，不接受前端自报身份；为越权、跨组织和复核权限建立真实集成验收。
- **优先级**：P0

### RA-05 咨询智能体默认不调用模型，返回固定兜底答案

- **功能**：咨询智能体的模型推理与答复生成
- **文件位置**：`backend/apps/platform-api/src/main/resources/application.yml:36-49`；`backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/config/ConsultationAgentModelConfiguration.java:35-63`；`backend/consultation/src/main/java/cn/xinji/agentplatform/consultation/application/ConsultationAnswerGenerator.java:11-15`；`backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/consultation/unified/DailyConsultationService.java:72,81`
- **当前实现**：模型运行默认关闭、API Key 默认空；没有可运行托管模型时走 deterministic generator，固定答复“已根据当前输入整理可参考的候选信息。”，意图链标记 `FIXED_RULE_FALLBACK`。真实 OpenAI 兼容模型适配器虽存在，但不是默认可用闭环。
- **为什么不可用**：用户看到的是固定模板和规则结果，不是模型基于问题与证据生成的智能答复；“智能体真的调用模型”在默认验收环境中不成立。
- **修复建议**：将模型调用设为受控验收前置条件；启动时验证可用模型、凭证和出域策略；响应中保留实际模型/规则路径，真实验收检查供应商请求、证据引用和失败语义，禁止静默伪装成模型答复。
- **优先级**：P0

### RA-06 执法和裁决没有真实业务输入闭环

- **功能**：执法线索处理、裁决案件处理和公开资料消费
- **文件位置**：`backend/enforcement/src/main/java/cn/xinji/agentplatform/enforcement/adapter/out/synthetic/SyntheticEnforcementSourceAdapter.java`；`backend/adjudication/src/main/java/cn/xinji/agentplatform/adjudication/adapter/out/synthetic/SyntheticAdjudicationSourceAdapter.java`；`backend/adapters/persistence-dm8/src/main/java/cn/xinji/agentplatform/enforcement/adapter/out/dm8/EnforcementLocalSourceImporter.java`；`backend/adapters/persistence-dm8/src/main/java/cn/xinji/agentplatform/adjudication/adapter/out/dm8/AdjudicationLocalSourceImporter.java`；`docs/08-总开发实现计划.md:705`
- **当前实现**：领域流程和 DM8 适配器存在，但既有本地工作输入仍来自 `SYNTHETIC_LOCAL`/`SYNTHETIC_V0` 基线；真实中心补充未实现。公开 CNIPA 资料只完成隔离转换，当前主计划明确 DM8 导入、权限 API 和前端消费仍未完成，且资料禁止进入案件、证据、规则、草稿或模型。
- **为什么不可用**：执法/裁决可以演示技术动作，却不能用真实授权线索、证据、案件和材料完成业务流程；公开参考资料也依法规边界不能替代业务输入。
- **修复建议**：在来源授权、记录级审核和 D 门证据齐备后接入真实只读业务来源；保留来源版本、撤回和权限；以真实匿名化案例分别完成执法、裁决端到端验收，不将公开参考投影越界写入业务工作流。
- **优先级**：P0

### RA-07 默认存储为内存，重启后工作结果丢失

- **功能**：咨询、检索、对照、标注、执法和裁决任务持久化
- **文件位置**：`backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/config/ConsultationStorageConfiguration.java:14-16`；`EnforcementStorageConfiguration.java:14-17`；`AdjudicationStorageConfiguration.java:14-17`；`PatentSearchConfiguration.java:108-126`；`PatentComparisonStorageConfiguration.java:14-17`；`TrademarkComparisonStorageConfiguration.java:14-17`；`CaseAnnotationStorageConfiguration.java:15-17`
- **当前实现**：多个存储属性未配置时使用 `InMemory*` 仓储；只有显式指定 `dm8` 才持久化。
- **为什么不可用**：默认运行中的任务、版本、人工修订和审计记录随进程重启消失，不能满足可追溯、恢复和审计要求。
- **修复建议**：为非测试环境强制持久化配置；内存仓储仅在测试 Profile 可见；验收必须包含重启后精确版本读取和数据库副作用核对。
- **优先级**：P1

### RA-08 当前执法主路由与旧完整工作台脱节

- **功能**：执法创建、处理、修订、复核全流程
- **文件位置**：`frontend/src/app/AppRoutes.tsx:20`；`frontend/src/features/workflows/BusinessWorkspaces.tsx:1`；`frontend/src/features/workflows/EnforcementJourneyPage.tsx:17-57,91-106`；`frontend/src/features/workflows/EnforcementWorkspace.tsx:1-100`

- **为什么不可用**：代码中的完整操作控件不是用户当前可达能力，旧全流程测试也因此找不到“创建工作项”；代码存在不能等价为业务可用。
- **修复建议**：以获批主线为准删除陈旧验收假设；要么为仍获批的工作项流程提供明确入口和权限，要么把旧组件判定为退役代码，避免继续作为实现证据。
- **优先级**：P1

### RA-09 执法数据源“连接检查”和“同步”只操作固定开发数据

- **功能**：执法数据源配置、连接检查与同步
- **文件位置**：`frontend/src/features/workflows/EnforcementSourceManagementPage.tsx:30-35,59,66`；`backend/enforcement/src/main/java/cn/xinji/agentplatform/enforcement/adapter/out/synthetic/DevelopmentEnforcementSourceAdapter.java:15-39`
- **当前实现**：页面保存时强制 `DEVELOPMENT_FIXED_API` 和 `local://enforcement/development-feed`；连接检查只比较该固定字符串即判定通过；同步返回代码内三条固定记录，不连接任何外部系统。
- **为什么不可用**：“检查连接”“立即同步”的成功不代表网络、凭证、上游协议或增量游标可用，无法接入真实执法来源。
- **修复建议**：继续明确标记为开发夹具；真实适配器必须验证网络、认证、契约、分页/游标、失败恢复和来源版本，并由端到端测试证明实际外部交互。
- **优先级**：P1

### RA-10 开发来源接口默认开启且部分接口缺少主体参数

- **功能**：内部执法/裁决开发目录访问
- **文件位置**：`backend/apps/platform-api/src/main/resources/application.yml:4-5`；`backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/web/DevelopmentOperationalSourceController.java:21-23,79-86`
- **当前实现**：`internal-workbench.development-sources-enabled` 默认 `true`；开发来源控制器随默认配置开放，裁决开发目录端点未接收 requester/actor 请求头。
- **为什么不可用**：开发夹具和目录可能在普通运行环境暴露，且裁决来源读取不能证明调用主体及权限；这不是可上线的业务来源访问链。
- **修复建议**：默认关闭并限定专用开发 Profile；所有读取经过服务端身份与组织授权；部署验收验证开发端点在非开发环境为 404/拒绝。
- **优先级**：P1

### RA-11 知识库/检索配置存在但默认闭环不可复现

- **功能**：专利检索、咨询检索和本地知识库调用
- **文件位置**：`backend/apps/platform-api/src/main/resources/application.yml:32-35,71-83`；`backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/config/PatentSearchConfiguration.java:47-99`；`backend/adapters/persistence-dm8/src/main/java/cn/xinji/agentplatform/consultation/adapter/out/dm8/Dm8ConsultationPatentSearchAdapter.java`
- **当前实现**：专利检索默认 `public-local`，咨询检索默认 `task`，知识库默认 `dm8`；另有 `synthetic`、`mock-center`、`database` 多种分支。模拟中心默认地址为本机 18082，但不会随平台进程自动成为真实中心；知识库导入默认关闭。
- **为什么不可用**：配置名称相近但数据路径不同，默认启动又被 DM8 依赖阻断；没有一份从干净环境证明“问题→实际检索→知识库记录→来源→答复”的当前验收证据。
- **修复建议**：定义单一真实性验收 Profile，明确每一步实际 provider、数据版本和进程依赖；用调用日志、数据库记录和来源定位器证明真实检索，不允许 synthetic/mock-center 结果冒充真实知识库。
- **优先级**：P1

### RA-12 智能体配置草稿是内存占位且永远不能发布

- **功能**：咨询智能体配置保存、校验和发布准备
- **文件位置**：`backend/consultation/src/main/java/cn/xinji/agentplatform/consultation/agentconfig/application/ConsultationAgentDraftService.java:30-41,82-84`
- **当前实现**：草稿存放在 `AtomicReference`，重启丢失；`validate()` 无条件加入 `FORMAL_DEPENDENCIES_PENDING` 并返回 `publishReady=false`。前端仍提供保存、应用模型和校验操作。
- **为什么不可用**：用户只能编辑临时开发草稿，无法形成可发布、可审计、可恢复的智能体配置版本；“校验”不可能通过。
- **修复建议**：在正式依赖、权限和版本契约通过 D 门后实现持久化版本与发布审批；在此之前页面应明确为不可发布草稿，不能作为智能体配置闭环证据。
- **优先级**：P1

### RA-13 模型配置管理依赖当前不可用的 DM8 和主密钥

- **功能**：模型凭证配置、连接验证和运行链管理
- **文件位置**：`backend/apps/platform-api/src/main/java/cn/xinji/agentplatform/modelconfig/ManagedModelConfigurationService.java:51-52,243-250`；`backend/apps/platform-api/src/main/resources/application.yml:53-55`
- **当前实现**：没有数据库时返回 503，没有 `MODEL_CONFIG_MASTER_KEY` 时也返回 503；管理员身份仍通过固定 requester 字符串比较。当前默认配置主密钥为空。
- **为什么不可用**：默认环境无法从 UI 建立可运行模型链，且管理员真实性无法证明，导致“存在模型管理页面”不等于模型可配置可调用。
- **修复建议**：把数据库、密钥托管、管理员认证和连接测试设为部署前置条件；验收使用非明文凭证完成配置、连接、调用、切换和审计全链路。
- **优先级**：P1

### RA-14 专利/商标对照是固定启发式，不是专业智能分析

- **功能**：专利权利要求对照、商标多维对照和案例相似性
- **文件位置**：`backend/patent/src/main/java/cn/xinji/agentplatform/consultation/patentcomparison/application/PatentComparisonService.java:18,28`；`backend/trademark/src/main/java/cn/xinji/agentplatform/consultation/trademarkcomparison/application/TrademarkComparisonService.java:18,76-91`；`backend/case-reference/src/main/java/cn/xinji/agentplatform/consultation/casesearch/application/CaseSearchApplicationService.java:27-31,101-124`
- **当前实现**：专利以 `claimsText.contains(feature.text())` 判定对应；商标语义、图像和商品服务关系直接返回未分析，文字维度采用字符位置/共有字符启发式；案例相似度使用固定 35/20/10 权重。规则版本也明确含 `SYNTHETIC`。
- **为什么不可用**：这些算法只能作为开发期候选排序或逐字核对，不能证明专业相似性、侵权判断或法律结论；若仅以页面结果验收，会把硬编码规则误当智能分析。
- **修复建议**：在专业样本和验收指标获批后建立可解释的专业模型/规则版本；页面持续展示未分析维度与算法边界；用专家标注集验证准确率，而不是只验证有返回值。
- **优先级**：P1

### RA-15 商标图形与组合检索是显式空能力

- **功能**：商标图形检索和图文组合检索
- **文件位置**：`backend/trademark/src/main/java/cn/xinji/agentplatform/consultation/trademarksearch/domain/TrademarkSearchCommand.java:25-36`
- **当前实现**：命令只接受 `TEXT`；`IMAGE`、`COMBINED` 输入及 `IMAGE` 维度直接抛出 `UnsupportedOperationException`。
- **为什么不可用**：领域枚举和页面分类可能让用户认为商标检索覆盖图形/组合输入，但后端没有实现该能力，真实请求必然失败。
- **修复建议**：在真实图像来源、模型、授权和验收指标通过 D 门前，前端只展示文字检索的明确范围并禁用不可用入口；后续能力单独设计和验收。
- **优先级**：P1

### RA-16 执法规则试运行只接受合成样本

- **功能**：执法发现规则试运行与发布
- **文件位置**：`backend/enforcement/src/main/java/cn/xinji/agentplatform/enforcement/discovery/application/EnforcementDiscoveryRuleService.java:82,89`；`frontend/src/features/workflows/EnforcementDiscoveryRulesPage.tsx:52,77-78`
- **当前实现**：服务要求 `sampleOrigin=SYNTHETIC_LOCAL`；前端固定该来源并预填 `synthetic-sample-001`，发布按钮文案为“开发期发布”。
- **为什么不可用**：规则只能对人工输入的合成 payload 演示命中，不能在真实授权样本上证明字段映射、误报率或业务适用性。
- **修复建议**：维持开发期标签，不作为真实规则发布证据；取得授权样本和专业验收标准后，增加隔离回放、版本锁定、误报/漏报评审及人工批准。
- **优先级**：P1

### RA-17 运行环境 Java 版本不一致

- **功能**：后端可执行包启动
- **文件位置**：`pom.xml`（Java 21 配置）；本机 `PATH` 与 `JAVA_HOME`
- **当前实现**：项目编译目标为 Java 21，`JAVA_HOME` 指向 JDK 21，但当前 `java` 命令解析为 Java 17；直接 `java -jar` 会发生 class version 不兼容，项目脚本只有在主动解析 `JAVA_HOME` 时才能避开。
- **为什么不可用**：按常规命令运行会失败，部署和验收结果依赖调用方式，不能稳定复现。
- **修复建议**：统一工具链检查，在启动脚本和 CI 中对实际 `java -version` 快速失败；文档只保留已验证的唯一启动命令。
- **优先级**：P2

### RA-18 数据采集存在占位字段，但没有生产 TODO 标记

- **功能**：公开专利数据采集完整性与未完成项识别
- **文件位置**：`scripts/collect-epo-cn-patent-pilot.mjs:140`
- **当前实现**：EPO LOD 缺少标题时使用 label 作为 placeholder。对生产目录执行 TODO/FIXME 扫描，未发现其他可直接代表未完成功能的有效 TODO/FIXME；大量明确的 `UNAVAILABLE`、`UnsupportedOperationException` 和开发边界已在本报告其他项列出。
- **为什么不可用**：占位标题若未经字段级溯源和人工复核，会降低展示与检索语义可信度；同时不能以“没有 TODO”推断功能完整。
- **修复建议**：保留缺失状态和原始字段，禁止把 label 当权威标题；在导入/展示处显式标注并纳入人工复核。持续以行为测试和能力边界审计替代仅扫描 TODO。
- **优先级**：P2
