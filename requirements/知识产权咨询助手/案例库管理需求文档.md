# 案例库管理需求文档

对应需求：一.1.1.1.1.1.3  
文档状态：技术评审初稿，中心 API 能力、授权范围及性能参数尚需联调确认。  
交付边界：后端服务及接口说明对外交付；前端页面用于内部开发、联调和验收，不属于对外交付内容。


## 国产化与达梦 DM8 适配要求

- 本模块面向国产化环境交付，业务关系型数据库固定使用达梦 DM8；开发联调及数据库兼容验收均须覆盖真实 DM8，不能以 MySQL、H2 等环境通过替代。
- 本模块需要持久化的业务内容包括：授权保存的案例映射、原文版本、派生标注、审核记录和任务信息。数据库采用 DM8；文件二进制可使用项目已批准的文件存储，DM8 保存受控引用及元数据，不要求把所有图片和附件存入数据库。
- 驱动、连接池、ORM/持久层、分页、建表及升级脚本按实际 DM8 小版本和实例参数适配；不得直接依赖其他数据库专有语法、JSON 类型或函数。长文本、结构化内容、编号、时间及分数应选用经目标实例验证的数据类型和访问方式。
- 本模块 DM8 专项验收覆盖：案例与文书关系、长文本、标注发布事务、并发修改冲突和版本追溯。验证事务失败回滚、连接故障恢复和权限控制；接口故障不伪装成空结果。需要恢复的任务应识别中断状态，按幂等规则恢复或显式失败，不盲目重放。
- 全文、向量和图像检索能力不得因采用 DM8 就视为已经具备；优先调用中心 API，自建时按总目录的国产化与检索约束选型并验证。
- 交付本模块适用的 DM8 初始化/升级脚本、数据库配置说明和真实 DM8 验证记录；确无本地业务表时注明原因，仍须验证与共用 DM8 服务的集成。其他国产操作系统、CPU、JDK、模型及中间件的具体型号以中心环境清单为准，不预设已完成适配。

详细共用要求见[需求总目录](知识产权咨询助手需求文档总目录.md)“3.7 国产化部署与达梦 DM8 数据库”。

## 1. 功能概述与范围

通过中心 API 接入商标、专利及行政裁决等知识产权案例，提供分类查询、原文查看、结构化信息提取、标注校核和版本管理，供相似案例检索及咨询引用使用。

中心原文保持只读。系统生成的争议焦点、裁判要点及关联法条作为本地派生信息维护，不回写中心。相似案例排序和咨询答复由独立模块实现。

## 2. 数据来源与治理

- 后端调用中心 API 获取案例元数据、全文和附件，保留源记录 ID、版本或内容摘要值、来源更新时间及获取时间。
- 案例编号、案号、标题分开处理；同一纠纷的不同程序或不同文书作为不同记录，通过关联关系连接，不因案号或标题相近直接合并。
- 原文解析保留页码、段落及文书结构；扫描件记录 OCR 状态和质量异常，解析失败不生成“已完成”结果。
- 模型提取内容须带原文证据定位。无法定位的内容标记为待核实，不能以确定事实发布。
- 源内容更新时创建新的关联版本，旧标注保留可追溯性，受影响的已发布标注标为待复核，不继续作为当前有效标注输出。
- 原文和附件的访问范围继承中心授权。内部案件材料不能因提取或索引而变为公开内容。

## 3. 字段设计

| 字段 | 说明 |
|---|---|
| 数据源、源记录 ID、原文版本 | 稳定引用与版本追溯 |
| 案例编号、案号、案例名称 | 分别保存；无案号不得编造 |
| 案件类型、知识产权类型 | 源分类及本地标准映射 |
| 审理/处理机构、程序或审级 | 不把不同处理机构统一称为法院 |
| 审理时间、裁判/决定日期 | 有明确来源时分别记录 |
| 裁判结果 | 原文摘录及可选结构化标签 |
| 案件事实、核心争议焦点、裁判要点 | 派生内容与证据定位 |
| 关联法律法规 | 法规标识、版本、条号、原文引用；未解析成功保留原引用文字 |
| 关联案件/文书 | 源提供或人工校核后的关联关系 |
| 全文、附件 | 来源引用和解析状态 |
| 可访问范围 | 继承源权限并可进一步收紧 |
| 标注版本、状态、提取/审核人员及时间 | 用于发布与追溯 |
| 来源更新时间、本次获取时间 | 分别展示 |

## 4. 功能与业务规则

### 4.1 查询及详情

支持案例编号/案号精确查询，名称包含查询，案件类型、机构、程序、裁判日期范围、标注状态筛选。不同字段为“且”，同字段多选为“或”；日期含端点。分页默认 20、可选 10/20/50，默认裁判日期倒序及稳定 ID 排序，缺失日期置后。

详情展示基本信息、完整原文、附件、派生标注和关联法条。引用点击后定位到原文页码或段落；无定位能力时明确说明并提供文献引用，不伪造定位。

上游不支持筛选或排序时，须在获授权的索引中实现或调整范围，不能仅过滤当前页。

### 4.2 提取、编辑与审核

1. 操作人员选择一条案例的原文版本，发起要点提取，生成后台任务。
2. 提取结果进入“待审核”，展示生成内容与对应原文。
3. 标注人员可修改案件类型、争议焦点、要点和法条关联，并记录修改人、时间及原因。
4. 审核人员检查证据后发布或退回；退回须填写原因。首版允许同人标注与审核，但两步操作及权限分别留痕。
5. 发布内容供后续模块使用；草稿、退回和待复核内容仅供有权限的内部人员查看。
6. 已发布标注的修改形成新版本，不直接覆盖；可撤回已发布派生标注，后续检索停止使用该版本。

提取任务状态为排队、处理中、成功、失败、取消。重复提交同一原文版本及提取配置时，应提示已有任务并允许查看；失败可重试，成功结果不会被失败重试清空。

### 4.3 原文与派生内容的关系

原文查询可独立于标注发布使用；只有审核发布的派生信息可作为已校核要点输出。法条关联无法确定历史适用版本时标记“版本待核实”，不自动关联为现行版本。源记录被撤回或权限收紧后，相应内容不得继续被无权限用户检索。

## 5. 内部验证页面

- 列表：案例编号、名称、类型、机构、裁判日期、标注状态、来源更新时间。
- 操作：查询、重置、详情、提取要点、查看任务、审核、撤回派生标注。
- 详情：原文和标注并列展示，支持证据定位、字段编辑、保存草稿、提交审核。
- 版本区：原文版本、标注版本、审核记录、退回原因。
- 未授权按钮隐藏或禁用，后端仍检查权限；原文无编辑/删除入口。
- 部分附件失败、原文未提供、提取失败分别提示。模拟数据明确标识。

## 6. 服务契约

| 服务 | 输入 | 输出 |
|---|---|---|
| 案例查询/详情 | 条件、分页或案例标识 | 案例、原文引用、权限及版本 |
| 发起提取/查询任务 | 案例版本、提取配置或任务 ID | 任务状态、结果或错误 |
| 保存标注 | 案例版本、标注内容、当前标注版本 | 新草稿版本或版本冲突 |
| 提交/审核/撤回 | 标注版本、动作及意见 | 新状态和操作记录 |
| 发布信息查询 | 案例标识、调用方权限 | 可用的已发布标注及证据 |

写操作执行版本冲突检查，防止多人覆盖。任务异步返回 ID，不要求浏览器持续开启。错误区分权限、版本冲突、原文缺失、解析失败、源故障及生成失败，并返回追踪号。

## 7. 验收要求

| 编号 | 场景与预期 |
|---|---|
| CL-01 | 多程序文书正确区分并关联，不误去重 |
| CL-02 | 查询、分页和日期边界符合约定 |
| CL-03 | 原文、附件、提取内容及引用可核验对应 |
| CL-04 | 无依据的提取内容进入待核实，不自动发布 |
| CL-05 | 草稿、审核、退回、发布、撤回流程完整留痕 |
| CL-06 | 原文更新使受影响标注待复核，历史版本仍可追溯 |
| CL-07 | 并发编辑返回冲突；任务失败重试不破坏已有结果 |
| CL-08 | 内部材料在列表、详情、索引及直接调用中均按权限隔离 |
| CL-09 | 不启动验证页面仍可完成服务查询及标注流程 |

## 8. 依赖、交付与确认项

依赖中心案例 API、原文解析、模型服务、法规资源和项目权限。服务、标注流程、字段映射、接口说明及验收记录对外交付，页面仅内部使用。

确认案例覆盖、原文与附件格式、程序关系、授权范围、历史法条版本资源、专家审核人员、允许的持久化/索引策略及性能指标。审核发布派生标注是本初稿推荐业务流程，技术评审时应与中心确认人员安排。
