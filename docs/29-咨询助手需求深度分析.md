# 知识产权咨询助手需求深度分析

版本：V0.1（原文分析稿）  
日期：2026-09-16  
状态：仅供范围评审、计划拆分和后续详细设计输入；不构成业务确认、D 门设计、实现或验收结论。

## 1. 阅读结论

咨询助手不是一个“问答机器人页面”，而是一组可以被独立调用的知识资源、异步检索、辅助比对、配置发布和多轮对话服务。其核心价值链是：

```text
授权来源数据 / 已发布配置
  -> 可追溯查询或检索任务
  -> 候选、原文与版本
  -> 辅助对照或案例参考
  -> 带引用的咨询答复
  -> 专业复核或权威系统的后续处理
```

最重要的边界是：检索相关度不是法律近似、注册成功率、侵权结论或裁判结果；AI 的输出只能是候选、解释、辅助意见或草稿。权限、数据范围、确定性规则、专业审核和正式状态由服务端规则、授权人员或权威系统承担。

| 类别 | 包含内容 | 信息性质 |
|---|---|---|
| 咨询主范围 | CON-01 至 CON-12：三类知识资源、三类检索、两类辅助比对、四类咨询配置/编排 | 原始业务需求，均已通过 R 门；未整体通过 D/V/A |
| 既有知识资源 | 法律法规管理、条文解析管理、条文要点管理 | 同目录内已有资源需求；咨询模块可引用，不应重写其导入/编辑规则 |

## 3. 产品结构

### 3.1 十二个模块的职责分层

| 层 | 模块 | 解决的问题 | 不负责什么 |
|---|---|---|---|
| 知识资源 | CON-01 商标库、CON-02 专利库、CON-03 案例库 | 从中心读取记录、原文、版本、历史及可发布的派生标注 | 近似结论、相似度排序、中心源数据写回 |
| 候选发现 | CON-04 专利检索、CON-05 商标检索、CON-08 案例检索 | 将确认输入和范围变为可追溯任务，返回候选、依据、覆盖和截断信息 | 直接输出法律结论或用有限候选冒充全库检索 |
| 辅助比对 | CON-06 专利判断、CON-07 商标判断 | 对已选对象逐项分析，给出证据、差异、缺口和待复核报告 | 自动决定新颖性、侵权、商标近似或注册可行性 |
| 配置与编排 | CON-09 智能体、CON-10 提示词、CON-11 意图、CON-12 对话流 | 管理版本化配置、多轮上下文、工具调用和引用答复 | 掌握业务数据、权限、正式状态或替代人工审核 |

### 3.2 三条面向用户的业务链路

**商标咨询**：目标商标文字/图样与商品服务确认 -> CON-05 分维度检索 -> 选择候选及固定快照 -> CON-07 多维度辅助比对 -> CON-12 带引用答复或复核提示。

**专利咨询**：技术方案、核心特征或专利号码确认 -> CON-04 候选检索 -> 选择文献版本 -> CON-06 技术特征/权利要求逐项对照 -> CON-12 带引用答复或复核提示。

**案例参考**：咨询问题和关键事实补充 -> CON-08 相关案例检索 -> 查看案例原文与版本 -> 选择可参考点/关键差异 -> CON-12 引用答复。案例结果只能作为参考，不能把他案结果当作当前事项处理结果。

三条链路都可由 CON-11 识别意图并由 CON-09/10/12 的版本化配置编排，但下游服务必须再次校验参数和当前权限，不能因为“意图识别成功”就直接放行。

## 4. 跨模块强制约束

### 4.1 来源、版本与权限

- 中心商标、专利、案例和文件是只读权威来源；本地可管理任务、会话、配置、派生标注、报告和受控引用，但不得覆盖中心原文。
- 每次使用应区分源更新时间、本次获取时间、任务时间和配置时间。源记录至少以“来源系统 + 源 ID + 版本”定位；源没有版本时使用获取时间和内容摘要作为快照依据。
- 检索召回前实施权限过滤；读取原文、图样、报告、引用、附件和历史会话时按当前权限再次检查。权限收紧或源撤回后，缓存和历史结果不能继续泄露内容。
- 页面仅调用本项目后端，中心凭据不进入浏览器；后端服务必须脱离页面独立完成鉴权、校验、任务调度和数据维护。

### 4.2 异步任务和幂等

适用于检索、比对、提取等耗时操作的统一任务状态为：排队、处理中、成功、部分成功、失败、取消。资料不足导致核心步骤没有执行时，只能返回补充要求或不完整结果，不能标为成功。

幂等键与调用方、操作范围和请求内容绑定：同键同内容返回原任务，同键不同内容返回冲突。浏览器关闭不取消服务端任务；取消后迟到结果不可把任务改回成功；重试形成新的执行尝试并关联历史，而不破坏已完成结果。

### 4.3 版本、发布和撤销

模板、意图、流程和智能体采用“稳定编号 + 不可变版本”。推荐发布顺序是：先发布模板和意图，再发布引用它们的流程，最后由智能体绑定完整版本组合。

- 草稿保存不会自动影响运行中的服务。
- 发布或回滚前必须校验依赖和并发版本。
- 普通停用只阻止新绑定；紧急撤销立即阻止运行，并使依赖配置进入可识别的不可用或回退状态。
- 会话创建时固定配置版本，但权限撤回和整体服务暂停仍需实时生效。

### 4.4 评分、专业意见与人工边界

四类指标不可混用：检索相关度、技术对照评分、用户反馈、人工评测准确率。未标定的模型自评分不能作为 0-100 的可信分数；没有稳定映射时应返回排序或标签。

比对报告必须保存证据、资料缺口、版本和复核状态。正式采用的专业意见由中心指定人员审核；人工意见以独立版本/记录保存，不覆盖原始系统输出。没有可定位依据时不得生成法条、案例、数据事实或办理要求。

## 5. 模块深度分析

| 编号 | 模块与原文目标 | 关键输入/输出 | 关键规则和边界 | 主要依赖与验收焦点 |
|---|---|---|---|---|
| CON-01 | 商标库管理：接入商标基本信息、商品服务、状态、变更、异议和无效信息 | 条件、分页、稳定记录 ID -> 列表、详情、历史子项状态、来源时间 | 注册号按字符串保留；名称不是唯一 ID；“无记录”“未提供能力”“受限”“失败”必须区分；不新增/编辑/删除中心源数据 | 中心商标 API、图样访问、权限；验证全局筛选/排序、多类别、历史事项与刷新失败保留旧数据 |
| CON-02 | 专利库管理：查询三类专利、全文、版本、法律状态和事件 | 号码/条件/版本 -> 文献、全文定位、事件、来源 | 申请号、公开/公告号、授权号不能混为一个号码；同申请不同版本不能合并；全文解析失败不伪造全文；源不可用不等于权利失效 | 中心专利 API、全文/图片授权、版本关系；验证号码定位、权利要求/段落定位、事件语义与局部失败 |
| CON-03 | 案例库管理：原文、结构化提取、标注审核和版本 | 案例/原文版本/提取配置 -> 提取任务、标注草稿、审核记录、已发布标注 | 原文只读；不同程序/文书保持独立；无证据提取内容是待核实，不能发布；源更新令受影响标注待复核 | 中心案例 API、原文解析、法规资源、审核人；验证版本冲突、撤回、权限隔离及原文/标注追溯 |
| CON-04 | 专利相似度检索：对技术方案、特征或号码召回专利候选 | 原始/确认特征、范围、目的 -> 任务、候选、片段、排序版本、固定输入快照 | 号码多候选需人工选择；范围、日期、类型和权限在召回前生效；相关度不等于新颖性/侵权结论；有限候选、失败和截断必须披露 | CON-02、中心检索或授权索引；验证三种输入、稳定排序、取消/重试、传递比对与 Recall@K |
| CON-05 | 商标相似度检索：从文字、图形或组合召回商标候选 | 原始文字/图样、类别项目、维度、范围 -> 候选、各维度依据/状态、排序快照 | 文字、读音、含义、图形和组合是独立能力；OCR 不可冒充图形检索；类别相同不等于商品服务类似；未分析维度不是零分 | CON-01、分类字典、文件和图像/文字检索；验证上传、跨类范围、状态过滤、维度不可用和分维度 Recall@K |
| CON-06 | 专利相似度判断：对目标与选中文献作技术特征对照 | 目标/候选版本、目的、日期、特征 -> 逐项关系、证据、缺口、辅助报告、复核记录 | 检索与比对分离；不得用摘要替代缺失权利要求；多篇文献不能拼接成单篇公开；技术文本相似不等于落入保护范围 | CON-02/04、法规、分析能力、复核；验证从属权利要求、逐项证据、外观设计视图完整性和报告版本 |
| CON-07 | 商标相似度判断：对目标与候选作多维度辅助比对 | 目标/候选、商品服务、目的、维度 -> 维度意见、依据、综合辅助意见、复核版本 | 图样缺失不能输出图形/整体视觉意见；类别相同或不同均不直接等于商品服务关系；不能把相关度变成注册结论 | CON-01/05、分类标准、图像能力、复核；验证各维度事实支持、资料不足和依据版本 |
| CON-08 | 相似案例检索：按问题和事实找可参考案例 | 问题、补充事实、范围 -> 任务、案例版本、参考点、差异、原文引用 | 宽泛问题先补问；不同程序可聚合展示但不合并结果；未审核派生要点不冒充已校核结论；历史案例不默认适用于当前事实 | CON-03、案例检索、法规版本；验证范围/权限、程序差异、引用依据、截断与专家 Recall@K |
| CON-09 | 咨询智能体管理：场景、工具、版本、运行与评测 | 草稿配置、依赖版本、试运行 -> 发布版本、服务状态、指标、优化记录 | 智能体是编排者，不拥有数据/权限；草稿试运行与正式统计分开；停用阻止新请求和在途后续工具调用 | 提示词、意图、流程、工具、认证；验证依赖发布、暂停、回滚、并发编辑及指标分母 |
| CON-10 | 提示词管理：用户引导与内部执行模板的版本化管理 | 场景、模板、变量、版本 -> 可展示引导或受控内部渲染、统计 | 用户引导和执行模板权限不同；变量校验、不可变发布和紧急撤销是关键；用户文本不能篡改工具权限 | 场景、意图、智能体、模型试运行；验证变量缺失、版本绑定、撤销和事件去重 |
| CON-11 | 意图管理：识别诉求、槽位和路由建议 | 问题、允许上下文、固定配置版本 -> 主/候选/多意图、槽位来源、缺口、路由建议 | 支持未知和澄清，不能强制分类；模型推测不是已确认事实；解析成功不等于获得工具或数据权限 | 工具目录、提示词、流程、智能体、样本；验证多意图、歧义、槽位更正、未知样本和分项评测 |
| CON-12 | 对话流管理：多轮会话、上下文、工具、引用和结束 | 身份、智能体版本、消息、附件引用 -> 事件、最终回复、来源、会话状态 | 同会话首版只允许一条用户消息处理中；指代必须绑定实际结果集；取消、重连和上下文摘要不可重复执行或串会话 | CON-09/10/11、工具服务、任务、权限、人工受理；验证补问、对象切换、可定位引用、撤销、重连和独立客户端调用 |

### 5.1 三个既有法规资源的作用

| 资源 | 已有能力 | 对咨询的价值 | 需注意的边界 |
|---|---|---|---|
| 法律法规管理 | 外部导入法规全文与修订记录，支持维护、筛选、历史原文快照 | 为法规查询、案例法条关联、对话引用提供来源和版本 | 不能用当前正文覆盖历史修订原文；法规状态和版本必须可追溯 |
| 条文解析管理 | 外部一次性导入条文解析，支持审核、驳回和退回修改 | 为办理/法规咨询和辅助理解提供经审核的解析材料 | 新导入默认待审核，只有已审核结果才能作为正式生效解析；法规正文变化不会自动重写解析 |
| 条文要点管理 | 由已解析条文导入结构化要点及场景/案例关联 | 用于快速定位可引用的关键要点 | 要点关联需校验法规和条文；不应在咨询中把要点脱离来源版本使用 |

## 6. 数据对象与关系

以下是原文已经共同要求的最小关系，不是数据库表或最终 API 设计：

```text
中心源记录 / 文献版本 / 案例原文
  -> 受控来源引用与可访问范围
  -> 检索或提取任务（输入快照、范围、状态、追踪号）
  -> 候选或派生内容（依据、排序/维度、缺口）
  -> 辅助报告或咨询回复（引用、配置版本、复核状态）
  -> 人工复核记录 / 权威系统后续处理
```

必须分离的概念包括：源记录与本地工作对象、原始输入与模型/规则建议、检索相关度与比对评分、系统辅助结果与人工复核意见、配置版本与运行服务状态、历史访问证据与当前授权。

## 7. 状态模型与异常表达

| 对象 | 原文明确的状态或要求 | 不允许的表达 |
|---|---|---|
| 检索/比对/提取任务 | 排队、处理中、成功、部分成功、失败、取消 | 把资料不足、源故障、限流或截断伪装成“无结果”或“成功” |
| 案例派生标注 | 草稿、待审核、退回、已发布、待复核、撤回等版本化流转 | 未审核内容作为已校核要点；新版本覆盖历史版本 |
| 模板/意图/流程/智能体 | 草稿、校验、已发布、停用/撤销、归档；运行状态另行表达 | 草稿自动生效；停用和紧急撤销等同；历史引用被破坏 |
| 对话/消息 | 会话进行中、结束、过期；消息接收、处理、完成、失败、取消 | 断线重复计轮或重复调用；取消后把迟到工具结果发布为完成答复 |
| 数据子项 | 加载中、有记录、无记录、未提供能力、受限、失败 | 将“未提供/受限/失败”显示为“无数据” |

## 8. 验收结构

需求把验收分成四类，缺一类都不能用页面演示替代：

1. **服务可独立调用**：每个模块均要求后端接口在不启动内部页面时可运行。
2. **来源和版本可核验**：候选、原文、文献、条文、报告和配置使用实际版本或快照，不能凭标题、名称或当前内容猜测。
3. **异常和权限可区分**：无权限、源能力缺失、超时、限流、失败、无记录、资料不足、取消/重试要有不同结果与追踪号。
4. **真实效果与环境证据**：检索需专家固定标注集评测 Recall@K/排序；DM8、国产化、真实 API、数据授权、备份恢复和性能须在真实条件下验证。

总目录给出了五个跨模块闭环：商标检索到比对再到对话、专利检索到特征对照再到复核、问题补问到案例引用、配置发布与撤销、中心 API 故障后的恢复。这些是后续端到端验收的骨架，不能仅用单接口成功代替。

## 9. 关键待确认项和风险

| 优先级 | 待确认事实 | 影响模块 | 未确认时可继续 / 必须停止 |
|---|---|---|---|
| 高 | 中心 API 的字段、稳定 ID、版本、查询、全文/图样、分页、排序、限流和错误语义 | CON-01 至 CON-08 | 可做端口和合成契约；停止真实联调、字段冻结和真实覆盖承诺 |
| 高 | 数据查询、缓存、落库、索引、文件和模型处理授权 | 全部，尤其 CON-01 至 CON-08/12 | 可使用合成、公开或获准脱敏数据；停止真实数据持久化、索引和出域 |
| 高 | 身份、角色、组织范围与 DataScope | 全部读取和管理操作 | 可使用默认拒绝的测试身份；停止生产鉴权和真实权限验收 |
| 高 | 专业规则、复核人、正式受理/审核衔接 | CON-03、06、07、09、12 | 可停在辅助结果/待复核；停止正式结论、受理、审核和状态写回 |
| 高 | 专家标注样本、Recall@K、评分与性能阈值 | CON-04、05、06、07、08、09、11 | 可验证流程和版本；停止声称真实效果、准确率或业务验收 |
| 中 | 图像检索、外观设计视图、OCR 和分类/类似群规则 | CON-05、06、07 | 可明确标记不可用；不得用 OCR/文字/伪分数替代图形或外观能力 |
| 中 | 真实 DM8、小版本、文件存储和国产环境 | 全部模块 | 可做本地开发验证；停止声称目标环境兼容、恢复或交付验收 |

## 10. 建议的后续使用方式

1. 以本分析作为需求评审材料：合成 V0 可先使用现有临时决策推进；进入真实接入、专业效果验证或业务验收前，再确认相应模块的真实数据来源、权限范围、专业人和验收样本。
2. 每个目标模块仍应从其原需求和 `governance/contracts/CON-*.json` 单独提取可执行 Task；不能因为本分析出现了模块关系，就跨过 D 门直接编码。
3. 先冻结三个最短闭环的 V0 输入、排除条款和异常边界；真实输入、指标和验收方式在对应真实接入与效果验证阶段冻结，再逐步扩展资源库、图像、外观设计、案例语义和复杂配置能力。
4. 对每个已确认缺口形成“补建能力、书面缩减范围或保持待补齐”之一，避免靠隐藏页面入口或模型回答掩盖能力缺失。
