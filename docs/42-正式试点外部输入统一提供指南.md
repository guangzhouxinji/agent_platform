# 正式试点外部输入统一提供指南

版本：V0.1  
日期：2026-09-17  
适用范围：知识产权咨询、专利/商标检索与比对、执法辅助、裁决辅助的正式试点准备

## 1. 这份文档解决什么问题

本指南把正式试点所需的五类外部输入统一成可导出、可检查的交付包：

1. 中心专利、商标、案件 API 或合法授权索引；
2. 数据处理、存储、模型出域和保留授权；
3. 身份、角色、组织与数据范围规则；
4. 真实业务样例、业务规则、验收指标和验收责任人；
5. 国产化目标环境、DM8 运维与备份要求。

目标是尽量复用现有系统导出物，减少人工访谈和重复填表。提供方不需要理解本项目代码，只需导出已有材料、补充少量负责人和授权结论。

本指南不是新的状态台账。待确认项及其确认状态仍以 `docs/02-待确认事项清单.md` 和 `docs/08-总开发实现计划.md` 为准。模板或样例被填写，不等于授权已经生效；正式结论仍需记录来源、版本、责任人、日期、适用范围和结论。

## 2. 项目负责人实际要做什么

把本指南分别转发给五类负责人，并要求每类只提供对应导出物：

| 输入包 | 主要负责人 | 最省人工的首选交付物 | 没有首选交付物时 |
|---|---|---|---|
| A. API/索引 | 中心系统、数据平台负责人 | OpenAPI/Swagger 文件或地址 | 接口清单 Excel + 3 组脱敏请求响应样例 |
| B. 数据与模型授权 | 数据所有者、安全、法务、模型负责人 | 已有数据分类分级和模型使用制度 | 填一张数据处理矩阵 |
| C. 身份权限 | IAM/SSO、组织管理、业务负责人 | IAM 角色、组织、用户导出 | 填三张最小 CSV/Excel 表 |
| D. 样例与验收 | 法务、代理师、审查/执法业务代表 | 原系统样例 ID 清单 + 专家已有结论 | 填样例清单和验收矩阵 |
| E. 环境与 DM8 | 运维、DBA、安全 | CMDB、部署平台、DM8 配置和备份制度导出 | 填环境与数据库参数表 |

账号、口令、Token、私钥、未脱敏案卷原文不得写入本指南或普通 Excel。凭据通过中心现有密钥管理、账号申请或安全传输渠道提供。

## 4. A 包：中心 API 或合法授权索引

### 4.1 首选提供方式

按优先级从上到下选择一种，不需要重复提供：

1. OpenAPI/Swagger 地址或 `openapi.json`、`openapi.yaml`；
2. Postman Collection + 环境变量模板，模板中不得包含真实密钥；
3. 网关导出的接口目录 + 数据字典；
4. 接口清单 Excel + 每个接口 3 组脱敏请求/响应样例；
5. 暂无 API 时，提供获授权的数据库视图、搜索索引或批量交换文件规范。

项目侧应优先从 OpenAPI 自动生成客户端、数据类型和契约测试。只有 OpenAPI 未描述的业务含义、权限和版本语义才由负责人补充。

### 4.2 所有 API 都必须说明的通用字段

| 项目 | 必须提供的内容 |
|---|---|
| 基础地址 | 测试、预生产、生产的 Base URL；生产可暂不提供 |
| 协议 | HTTPS、REST/JSON 或实际协议 |
| 认证 | OAuth2、JWT、SSO 代理、mTLS、API Key 等 |
| 调用身份 | 用户委托身份、服务身份或两者 |
| 权限传递 | 用户 ID、机构 ID、角色、DataScope 如何传递 |
| 分页 | `page/pageSize`、`offset/limit` 或游标字段 |
| 排序 | 可用排序字段、默认顺序和稳定性 |
| 时间 | 时区、日期格式、更新时间字段含义 |
| 限流 | 单用户/单服务每分钟或每天限制 |
| 超时 | 网关和源系统建议超时 |
| 错误 | HTTP 状态码、业务错误码、可重试与不可重试错误 |
| 幂等 | 写接口幂等键或重复请求处理方式；只读接口注明不适用 |
| 版本 | 对象版本、接口版本、删除/撤回语义 |
| 审计 | 请求 ID、调用日志、谁可以查询日志 |
| 数据限制 | 哪些字段不可缓存、不可下载、不可发模型 |

通用响应建议至少包含：

```json
{
  "requestId": "中心请求标识",
  "data": {},
  "page": 1,
  "pageSize": 20,
  "total": 100,
  "errorCode": null,
  "errorMessage": null
}
```

实际中心格式不必改成这个样子，项目会在适配器中映射；但必须能找到对应信息。

### 4.3 专利检索 API

最低需要：检索、详情、来源读取三个能力。全文和附件可以后置。

### 检索请求字段

| 字段语义 | 最低要求 | 推荐字段名 | 说明 |
|---|---:|---|---|
| 检索文本 | 是 | `query` | 标题、摘要、技术方案或特征 |
| 检索范围 | 是 | `searchFields` | 标题/摘要/权利要求/全文；不支持时给固定值 |
| 页码/游标 | 是 | `page` / `cursor` | 二选一 |
| 页容量 | 是 | `pageSize` | 给最大值 |
| 国家/地区 | 否 | `countryCodes` | 如 CN、US、EP |
| IPC/CPC | 否 | `classificationCodes` | 支持前缀还是精确匹配需说明 |
| 申请人 | 否 | `applicant` | 精确/模糊匹配需说明 |
| 发明人 | 否 | `inventor` | 可后置 |
| 申请日期范围 | 否 | `applicationDateFrom/To` | 日期边界是否包含 |
| 公开日期范围 | 推荐 | `publicationDateFrom/To` | 正式试点范围需要 |
| 法律状态 | 否 | `legalStatus` | 状态字典需同时提供 |
| 排序 | 是 | `sort` | 相关性/日期；相关性算法版本需说明 |
| 语言 | 否 | `language` | 原文或翻译语言 |

### 检索结果最小字段

| 字段语义 | 最低要求 | 推荐字段名 | 缺少时影响 |
|---|---:|---|---|
| 稳定记录 ID | 是 | `id` | 无法建立来源引用和详情读取 |
| 公开号 | 是 | `publicationNumber` | 无法准确识别文献 |
| 申请号 | 推荐 | `applicationNumber` | 家族和申请过程追踪受限 |
| 中文标题 | 是；无中文可原文 | `title` | 主结果不可读 |
| 摘要 | 推荐 | `abstract` | 只能做标题级检索 |
| 申请人 | 推荐 | `applicants` | 无法按主体判断 |
| 发明人 | 可选 | `inventors` | 不阻塞第一版 |
| IPC/CPC | 推荐 | `classificationCodes` | 分类过滤和解释受限 |
| 申请日 | 推荐 | `applicationDate` | 时间判断受限 |
| 公开日 | 是 | `publicationDate` | 正式检索范围不完整 |
| 优先权 | 可选 | `priorities` | 可后置 |
| 法律状态 | 可选 | `legalStatus` | 不得在缺失时推断有效性 |
| 数据来源 | 是 | `sourceSystem` | 无法追溯 |
| 来源定位 | 是 | `sourceUrl` 或可读定位参数 | 无法复核原文 |
| 源对象版本 | 是 | `sourceVersion` 或 `updatedAt` | 无法固定历史证据 |
| 匹配片段 | 推荐 | `highlights` | 无法解释为何命中 |
| 可用能力 | 推荐 | `capabilities` | 说明摘要、权利要求、全文是否可读 |

### 详情与来源读取建议字段

```text
title
abstract
claims
description
classificationCodes
applicants
inventors
priorities
familyMembers
citations
legalEvents
documents
sourceSystem
sourceVersion
updatedAt
```

其中 `claims`、`description`、`familyMembers`、`citations`、`legalEvents`、`documents` 可以标记不支持。系统必须显示能力缺失，不能自行补造。

### 4.6 没有 API 时的授权索引方案

按优先级推荐：

1. 中心提供只读搜索 API；
2. 中心提供只读数据库视图；
3. 中心周期性导出增量文件到受控交换区；
4. 获书面授权后建立本地只读检索索引；
5. 无授权时继续使用 `PUBLIC_PILOT`，不得称为中心数据。

批量文件或索引最少需要以下控制字段：

```text
sourceSystem
sourceId
sourceVersion
operation         UPSERT / DELETE / WITHDRAW
effectiveAt
updatedAt
checksum
accessScope
recordPayload
```

必须说明全量/增量频率、删除和撤回如何传播、重放方式、重复记录处理、失败补传和历史版本保留方式。

### 5.3 推荐默认方案

在正式授权未形成前采用以下安全默认值：

| 数据 | 本地保存 | 建索引 | 外部模型 |
|---|---|---|---|
| 明确可公开的专利/商标题录 | 允许试点保存 | 允许 | 仅授权字段 |
| 中心专利/商标非公开字段 | 默认否 | 默认否 | 否 |

| 案卷附件、证据、当事人信息 | 默认否 | 否 | 否 |

| AI 输出和草稿 | 保存版本与来源 | 否 | 不再次外发 |

任何未知项按“不允许”处理；负责人确认后再按数据类别放开，不采用全局开关一次性放行。

## 6. C 包：身份、角色、组织与数据范围

### 6.1 优先自动导出

优先从 IAM、SSO、LDAP 或组织系统导出，不要求业务人员重新录入。提供以下四类信息：

1. SSO/OIDC/SAML 元数据或对接说明；
2. 组织树；
3. 试点用户或试点用户组；
4. 角色与权限映射。

### 6.2 组织表字段

`organisations.xlsx`：

| 字段 | 必填 | 说明 |
|---|---:|---|
| `organizationId` | 是 | 稳定机构 ID |
| `organizationName` | 是 | 机构名称 |
| `parentOrganizationId` | 是 | 根机构可为空 |
| `organizationType` | 是 | 企业、代理机构、审查、执法、平台等 |
| `status` | 是 | 启用/停用 |
| `dataScopeCode` | 推荐 | 现有数据范围代码 |
| `validFrom/validTo` | 推荐 | 有效期 |

`role-permissions.xlsx` 一行代表一个“角色 + 动作 + 资源范围”：

| 字段 | 必填 | 示例 |
|---|---:|---|

| `approvalRequired` | 是 | 是/否 |
| `approverRole` | 条件必填 | 导出或高风险动作审批角色 |
| `effectiveFrom/To` | 推荐 | 权限有效期 |
| `ownerName` | 是 | 业务授权负责人 |

试点至少要覆盖这些动作：

```text

查看详情和来源
查看案件
查看/下载案卷材料
上传材料

提交复核
确认/退回复核
导出
配置模型/规则
查看审计日志
```

### 6.5 推荐的最小权限模型

第一版采用“机构 + 角色 + 案件成员”三层判断：

```text
当前用户
  -> 是否属于有效机构
  -> 角色是否允许执行动作
  -> 数据是否属于本机构/授权客户/管辖范围
  -> 案件材料是否要求案件成员资格
  -> 高风险动作是否要求审批或复核角色
```

推荐原则：

- 服务端执行权限判断，前端隐藏按钮不能代替授权；
- 管理员默认不拥有案件内容读取权限；
- 模型配置、批量导出、确认复核单独授权；
- 角色名称可以沿用中心现状，项目只映射职责，不要求中心改名；
- 无法匹配的数据范围默认拒绝。

### 7.2 建议样例数量

数量不是正式效果阈值，仅用于启动试测：

| 能力 | 建议首批 | 组成建议 |
|---|---:|---|
| 专利咨询/检索 | 20 | 正常 10、资料不足 4、冲突/边界 3、无权限/来源失效 3 |

### 7.4 验收矩阵

`acceptance-matrix.xlsx`：

| 字段 | 必填 | 说明 |
|---|---:|---|
| `acceptanceId` | 是 | 稳定编号 |

| `metric` | 是 | 覆盖率、错误率、时长、可追溯率等 |

| `baseline` | 推荐 | 首轮试测值 |

## 9. 如何进一步减少人工

| 工作 | 推荐自动方式 | 人工只确认什么 |
|---|---|---|
| 接口清单 | 从 Swagger/OpenAPI 或网关导出 | 业务含义、权限、版本和限制 |
| 字段字典 | 从数据库元数据或数据治理平台导出 | 哪个字段是权威字段 |
| 组织用户角色 | 从 IAM/LDAP/SSO 导出试点范围 | 哪些角色能执行高风险动作 |
| 真实样例 | 只选原系统 ID，由适配器读取 | 关键证据、禁止错误、验收人 |
| 数据授权 | 复用现有分类分级、出域审批 | 本试点是否在批准范围内 |
| 环境参数 | 从 CMDB/K8s/虚拟化平台导出 | 哪套环境用于试点 |
| DM8 参数 | DBA 导出非敏感参数和版本 | 账号流程、备份与恢复责任 |
| 测试证据 | 自动化测试输出请求 ID、版本、日志位置 | 专业效果和业务结论 |

项目侧接收后可以自动完成：

1. 校验文件和必填字段是否齐全；
2. 从 OpenAPI 生成接口客户端和契约测试骨架；
3. 生成字段映射差异报告；
4. 生成待确认项清单，但不自动把未知项判定为通过；
5. 用样例 ID 建立固定试测集；
6. 生成权限矩阵测试和数据出域阻断测试；
7. 生成环境兼容性与 DM8 迁移检查项。

不能自动完成的只有四类责任结论：数据能否使用、谁能访问、专业结果是否正确、谁批准上线。这四类必须由对应负责人确认。

## 10. 推荐落地顺序

### 第一批：可以开始正式检索适配设计

只需先提供：

1. 专利检索 OpenAPI 或索引字段清单；
2. 一张专利数据处理矩阵；
3. 测试调用身份及其机构/数据范围；
4. 3 至 5 个脱敏专利检索样例 ID；
5. 测试环境网络入口。

这些信息足以完成 `CON-04-PILOT-DESIGN`，不需要等待完整生产环境和最终验收指标。

### 第二批：可以实施并联调

补充测试账号安全发放、错误码/限流、稳定 ID 和版本、完整试点角色、20 个左右固定样例、DM8 测试环境和日志监控。

### 第三批：可以进行专业验收和上线准备

补充正式指标、验收责任人、生产环境、全量数据授权、模型批准、备份恢复演练和交付审批。

## 11. 接收验收标准

项目收到输入包后，只按以下标准判断“材料可用”，不判断业务已经正式批准：

- 每个交付物有来源、版本、负责人、日期和适用范围；
- API 或索引能定位稳定 ID、源版本和来源；
- 未支持字段和能力明确标记，不用空白掩盖；
- 数据矩阵明确本地保存、索引、模型使用和保留期限；
- 用户、组织、角色和 DataScope 可以关联；
- 样例包含必须行为、禁止行为和专业验收人；
- 规则具有来源位置和决定责任人；
- 环境和 DM8 具有精确版本、账号流程、网络和恢复责任；
- 凭据、真实密钥和未授权敏感原文未进入普通文档；
- 任何“待确认”都有责任人和退出条件。

## 12. 推荐结论

当前项目最适合先收第一批五项最小输入，优先解除正式专利检索设计阻塞。API 采用 OpenAPI 自动导入，样例采用原系统 ID，身份权限从 IAM 导出，环境从 CMDB/DBA 工具导出；人工只做授权、专业判断和批准。这是在不降低安全和业务责任要求的前提下，人工投入最低的方案。
