# 执法 MVP DM8 物理持久化设计

版本：V0.4  
日期：2026-09-15  
关联任务：`ARC-10-ENF-PHYSICAL`  
前置：`docs/25-执法MVP逻辑持久化设计.md`、`SPK-01-CON-JDBC`、`MVP-ENF-V0-02`。  
设计性质：只将执法合成 V0 逻辑记录映射到本机隔离 Docker DM8；不表示中心 DM8、真实数据存储授权、真实文件、备份恢复、性能或业务验收通过。

## 1. 物理对象与唯一事实归属

| DM8 表 | 逻辑记录/用途 | 关键约束 | 明确不保存 |
|---|---|---|---|
| `enf_work_item` | 本地执法工作项 | 固定线索来源、机构、可信上下文所有者、`SYNTHETIC_V0` 和技术版本 | 中心线索正文、请求体身份、案件/正式状态 |
| `enf_source_locator` | 权威/合成来源定位 | 来源系统、对象、版本、位置组合唯一 | 凭据、永久授权、文件本体 |
| `enf_clue_analysis` | 线索解析版本头 | 每工作项版本唯一；前一版本自关联；机器/人工修订分离 | 违法主体、违法概率、正式优先级 |
| `enf_clue_field` | 解析字段候选 | 字段种类与顺序约束；每项引用来源 | 无来源补全值、正式事实认定 |
| `enf_clue_issue` | 解析缺失/冲突 | 缺失和冲突分类独立 | 自动选定冲突答案 |
| `enf_clue_conflict_candidate` | 冲突候选明细 | 按冲突问题保存候选顺序、原值、标准化值、时间语义和来源 | 逗号拼接候选、自动选择冲突答案 |
| `enf_evidence_ref` | 证据来源版本与可用性 | 关联工作项、来源和线索/案件；收集人或缺失原因至少一项；可用性枚举 | 真实性、合法性、证明力、采信、磁盘路径 |
| `enf_relation_set` | 事项—证据关系集版本头 | 每工作项版本唯一；固定解析/规则；禁止“完整有效证据链”状态 | 正式证据链结论 |
| `enf_relation_input` | 关系集固定证据版本 | 关系集与证据复合唯一及双外键 | 可变化的“最新证据”引用 |
| `enf_evidence_relation` | 候选支持/反对/冲突/缺失关系 | 固定事项、证据版本、来源、理由和待人工标识 | 自动采信/事实已证明 |
| `enf_timeline_entry` | 关系集时间线 | 发生/收集/上传三种语义分离 | 猜测时间或互相替代 |
| `enf_relation_issue` | 关系集缺口、冲突、未处理项 | 分类检查约束并可引用来源 | 将失败伪装为空数据 |
| `enf_aux_analysis` | 辅助分析版本头 | 固定解析、关系集、规则/权利来源；结果分类受限；`not_official_decision='Y'` | 正式认定、程序、处罚、正式状态 |
| `enf_analysis_input` | 分析固定证据版本 | 分析与证据复合唯一及双外键 | 模糊“当前证据”引用 |
| `enf_analysis_item` | 分析逐项内容 | 事实/陈述/推断类型分离；来源和不确定性必填 | 模型隐含推理、无来源推断 |
| `enf_analysis_issue` | 分析缺口/失败 | 资料不足、规则不适用、历史状态缺失、来源/分析失败及未处理分开 | “不构成”等业务结论替代错误 |
| `enf_review_record` | 绑定确切版本的人工动作 | 对象类型、动作、退回理由、测试范围和非正式标识约束 | 权限授予、专业采信、正式决定 |
| `enf_review_impact` | 来源/输入变化影响 | 指向受影响对象版本，只追加原因 | 覆盖或删除旧结果 |
| `enf_idempotency_record` | 写用例幂等绑定 | 主体、操作、幂等键复合主键；回指工作项和确切结果；保存该次结果的不可变合成快照用于后续精确回放 | 请求正文、凭据、授权快照 |

共 19 张最小表。拆表依据是版本不可变、来源定位、冲突候选无损回读、证据关系和人工记录需要数据库级引用完整性；它不表示未来生产必须保持相同表数。除 `enf_idempotency_record.snapshot_payload` 保存写操作当时的不可变合成结果以保证跨版本精确回放外，业务读取均从规范化表重建；未使用触发器、序列或 ORM。

## 2. 物理约束边界

数据库约束可以保证：

- 本地主键、工作项归属、来源/版本引用、前后版本引用、输入集合和幂等键不孤立。
- 所有领域有序集合均使用父记录内的显式顺序列恢复；不得依赖 UUID、插入顺序或数据库默认返回顺序。
- 领域时间在写入前收敛到毫秒精度，避免 DM8 时间精度舍入造成重启前后快照漂移。
- 每工作项解析/关系集/辅助分析版本唯一。
- 工作项所有者来自服务端可信上下文并可供仓储重启后恢复；冲突候选按顺序和来源独立保存。
- 解析种类、证据可用性、关系类型、时间语义、辅助结果、审核动作和问题分类只能取 V0 允许值。
- 辅助分析与 V0 审核记录的 `not_official_decision` 只能为 `Y`。
- 退回审核必须存在理由；收集人未知时必须存在缺失原因。

数据库约束不能证明：

- 当前身份真正有权读取线索、证据、文件或历史结果。
- 来源内容真实、证据合法或应被采信，候选关系/分析专业正确。
- 模型/合成适配器没有编造内容，规则真正适用，历史权利状态完整。
- 失效来源已经从所有缓存和外部系统传播，或测试身份是正式业务审核人。

这些不变量继续由应用端口、领域服务、集成测试和真实业务验收负责。

## 3. 初始化、回滚和验证

- 初始化脚本：`db/dm8/V002__enforcement_mvp_v0.sql`。
- 回滚脚本：`db/dm8/U002__enforcement_mvp_v0.sql`，按外键依赖逆序删除，仅删除 `enf_*` 表。
- 自动验证：`EnforcementDm8SchemaTest`。
- 验证环境：本机隔离容器 `agent-platform-dm8`，映射 `127.0.0.1:5237`，Java 21 与仓库内 DM8 JDBC 驱动。密码只从容器运行环境传入测试进程，未记录在仓库或测试输出。
- 实际执行：清理旧 `enf_*` → 初始化 → 写入正常和冲突/来源不可用记录 → 检查计数与所有者/冲突候选精确值 → 验证幂等唯一、外键和 `not_official_decision` 约束 → 回滚 → 再初始化 → 再回滚，全部通过。

本次未执行生产升级、历史数据迁移、连接中断恢复、并发写入、备份恢复或容量性能验证。

## 4. 三类样例映射

| 样例 | 最小记录 | 关键验证 |
|---|---|---|
| 正常 | 来源、带可信所有者的工作项、解析字段、证据引用、关系集/输入/关系/时间线、辅助分析/输入/逐项内容、审核、幂等 | 每层固定来源与版本；所有者可恢复；分析和审核强制非正式；幂等重复被拒绝 |
| 资料不足/冲突 | 线索冲突问题及候选明细、未知收集原因、冲突关系集、未处理问题、材料不足分析和历史状态缺失 | 冲突候选的值、顺序和来源无损保存；未知、不可处理和历史状态缺失均有独立记录 |
| 无权限 | 无权内容不写业务表；只允许上层保存不泄露的最小拒绝追踪 | 本次 schema 不保存权限表或受限正文；实际拒绝由应用端口测试 |
| 来源失效 | 新证据可用性版本/关系问题、影响记录；旧分析与审核仍在 | 影响记录追加，旧历史不删除；新结果是否排除失效证据由领域测试证明 |

## 5. 索引与查询意图

- 工作项下解析、证据、关系集、辅助分析按 `(work_item_id, version)` 查询。
- 关系项按 `(relation_set_id, relation_type)` 查询，支持查看支持、反对和冲突候选。
- 审核和影响记录按工作项与时间查询。
- 幂等使用主键直接定位，不建立包含请求正文的索引。

当前未建立全文、向量、文件内容、来源对象反向检索、分区或归档索引。真实查询规模和 DM8 执行计划确认后再增加，避免无依据索引。

## 6. 安全与保留边界

- 表中只允许合成 V0 数据；真实正文、文件、OCR 和模型输入必须等待 P0-03/07/10 授权。
- `controlled_resource_ref` 只能保存受控逻辑标识，应用必须拒绝盘符/物理路径。
- `source_refs` 在 V0 只保存本地来源标识列表，不保存未经授权片段。
- 不保存中心凭据、权限策略、永久放行决定、模型隐含推理或正式业务状态。
- 删除、保留、加密、脱敏、归档和权限撤回传播尚待 ARC-11/P0，不能从本地测试结果推定。

## 7. 与咨询物理模型的关系

执法使用独立 `enf_*` 表，没有复用 `con_*` 业务表。两域都出现来源定位、版本和幂等技术需求，但当前只保持字段设计相似，没有提前抽取共享表或跨域外键。待第二个 MVP 的仓储实现验证实际重复和生命周期后，再由 P4 任务评估共享技术结构。

## 8. 需求一致性复核

| 检查项 | 结果 |
|---|---|
| 逻辑记录映射 | `docs/25` 的工作项、来源、解析、冲突候选、证据、关系、分析、审核、影响和幂等均有唯一表归属 |
| 三样例 | 正常、资料不足/冲突、无权限边界和来源失效记录均有验证方式 |
| 数据库约束 | 主外键、版本唯一、幂等唯一、受限枚举、退回理由、收集缺失原因和非正式决定均覆盖 |
| 无来源字段 | 0；技术主键、版本、时间和索引均标为物理设计决定 |
| MUST_NOT 违规 | 0；没有正式状态、自动采信/认定/处罚字段，辅助分析和审核强制非正式 |
| 验证范围 | 本地 Docker DM8 初始化/回滚和合成记录；不代表中心环境、真实数据、备份恢复、性能或业务验收 |

结论：19 张最小 `enf_*` 表、约束、索引和可逆脚本已在本地 DM8 执行通过，能够无损承载合成 V0 的工作项所有者、冲突候选、追溯与禁止边界。V0.2 修正来自 `MVP-ENF-V0-03-DESIGN` 的映射审查，不升级任何原需求状态；下一步仍须完成该 D 门，方可实现仓储或 HTTP。
