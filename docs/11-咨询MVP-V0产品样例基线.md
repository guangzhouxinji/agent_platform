# 咨询 MVP V0 产品样例基线

版本：V0.2
日期：2026-09-19
关联任务：P0-08（咨询 MVP）  
基线性质：依据原需求形成的 V0 产品样例，仅用于冻结产品行为和倒推最小实现范围；不替代真实专业样例、法律正确性评测或业务验收。

> 2026-09-22 定位更新：本文件保留为历史 V0 技术样例，不再作为咨询产品目标或首段任务型闭环的唯一产品依据。负责人确认的产品行为见 `docs/02` P0-20 和 `docs/35`；新的首段路线包含专利资料查询、可迭代检索、证据充分性判断、技术对照、多轮纠正/追问和任务级结束状态。本文合成样例仍可用于回归已有技术链，但不能替代新的真实业务验收案例。

## 1. 三个样例

三个样例均使用合成数据。`V0-SYN-PAT-*` 是测试文献标识，不是真实专利号；样例中的技术内容、检索范围和预期措辞是可回滚的 V0 测试设定，不新增业务规则。

### 1.1 正常场景：完整问题与有效来源

| 项目 | V0 产品样例 |
|---|---|
| 用户输入 | “我准备研发一种锂电池极片涂布方法，包含水性粘结剂、双区烘干、在线测厚并反馈调整涂布间隙。请检索中国发明专利供技术参考。” |
| 系统需要执行的步骤 | 识别为“专利相似检索/技术参考”；提取并向用户呈现检索特征；校验访问授权；检索获授权的合成专利集；记录实际范围；筛选候选及匹配片段；生成带来源定位的辅助回答。输入已经满足本场景必要条件，不强制追加无关问题。 |
| 允许使用的数据/来源 | 用户本轮输入；获授权的合成专利文献 `V0-SYN-PAT-001`（水性粘结剂、双区烘干）与 `V0-SYN-PAT-002`（在线测厚反馈）；每份文献明确版本、摘要/权利要求片段及位置。不得接入未经授权的真实业务数据。 |
| 期望输出 | 返回可追溯候选，分别列出匹配特征、未匹配或无法判断部分、实际检索范围和来源定位；明确“相关度只表示检索相关程度，本回答为技术参考辅助信息”。候选次序和非关键表述可以变化，但候选来源、匹配依据、限制说明和辅助性质不能缺失。 |
| 必须引用什么来源 | 每个关键匹配点必须引用对应合成文献的源标识、文献版本和摘要/权利要求具体位置；检索范围及获取时间随结果保留。 |
| 禁止行为 | 不得编造专利号、原文、片段或精确评分；不得把检索相关度表述为新颖性、侵权、专利有效性或授权成功率结论；不得声称已检索全部现有技术。 |
| 必须人工复核 | 普通辅助回答只需标识其辅助性质；用户拟将结果作为正式专业意见、立项或法律判断依据时，必须提示由专业人员复核。本样例不实现完整复核流程。 |
| 需求来源 | `知识产权咨询意图管理需求文档.md` 第 3、4、7 节；`专利相似度检索需求文档.md` 第 1 至 4、6、7 节；`知识产权咨询对话流管理需求文档.md` 第 3、5、8 节；咨询总目录第 3.5 节。 |
| 当前是否需要专业确认 | 产品行为、安全边界和可追溯性不需要专业确认，可由项目负责人作 V0 验收；候选是否专业相关、分析是否法律正确及正式采用方式仍待后续知识产权专业责任方确认。 |

### 1.2 可选补充 / 信息冲突

| 项目 | V0 产品样例 |
|---|---|
| 用户输入 | 可选补充：用户描述了可检索的技术方案但未填写额外背景或检索目的；冲突： “我想查一下这个电池涂布方案有没有相似专利。附件 A 写烘干温度 80 摄氏度，附件 B 写 120 摄氏度。”附件中的同一关键参数冲突。 |
| 系统需要执行的步骤 | 对可选补充场景：服务端确认技术输入足以形成请求后，允许用户继续，不补造目的或技术条件；按 V0 固定技术参考范围检索，结果标为部分结果并说明未补充的上下文。对冲突场景：分别保留两个参数及其来源，提出针对性补问；用户确认前不得把任一温度写成已确认条件。 |
| 允许使用的数据/来源 | 用户原始消息、附件 A 和附件 B 的获授权内容及定位；不得引入模型猜测值、默认日期或未声明的技术条件。 |
| 期望输出 | 可选补充时返回实际范围、候选和“未补充上下文”的限制，不把固定 V0 范围说成用户确认的目的。冲突时清楚列出冲突项和各自来源，并询问应采用的温度；不允许遗漏冲突、替用户选择参数或伪装成已完成检索。 |
| 必须引用什么来源 | 冲突说明必须分别定位到附件 A 的“80 摄氏度”和附件 B 的“120 摄氏度”；可选继续的限制必须能说明它只使用当前用户已给出的技术输入。 |
| 禁止行为 | 不得默认选择 80 或 120 摄氏度；不得把模型推测当作用户确认；不得在冲突或必要检索条件未确认时生成确定候选、法律结论或虚构工具结果；不得把资料不足说成“没有相关专利”。 |
| 必须人工复核 | 用户必须确认关键检索条件。若冲突无法由用户澄清，只能保持待核实；任何拟正式采用的后续判断仍需专业复核。 |
| 需求来源 | `知识产权咨询意图管理需求文档.md` 第 3、4、7 节（IM-02 至 IM-04）；`知识产权咨询对话流管理需求文档.md` 第 3、5、8 节（DF-01、DF-04）；`专利相似度检索需求文档.md` 第 2、3、6 节。 |
| 当前是否需要专业确认 | 项目负责人已确认开发期 V0 可在不猜测的前提下跳过可选补充；哪些技术参数在不同专业目的下属于必填，仍待专业人员按真实样例确认。 |

### 1.3 无权限 / 来源失效

| 项目 | V0 产品样例 |
|---|---|
| 用户输入 | “请读取并分析检索结果中的 `V0-SYN-PAT-003`。”当前授权检查返回无权访问；另一次测试中，该文献在检索后、回答生成前被标记为来源不可用或版本已撤回。 |
| 系统需要执行的步骤 | 在召回和读取原文前校验当前授权；无权限时停止读取和分析并返回可识别拒绝结果。来源在处理中失效时重新校验，移除受影响内容，返回来源失效/部分失败说明；不得把故障解释为零结果。 |
| 允许使用的数据/来源 | 只可使用授权判定结果、来源可用状态和不泄露正文的源标识。无权限或已撤回的正文不得传给模型，也不得从旧缓存恢复给用户。 |
| 期望输出 | 无权限时明确说明当前不能访问该资料，并给出追踪标识；来源失效时说明受影响的候选和未完成范围，可基于其他仍获授权且有效的来源给出标明范围的部分回答。错误文案可以变化，但必须区分无权限、来源失效、真实无结果。 |
| 必须引用什么来源 | 拒绝结果引用授权检查/来源状态记录和追踪标识，不引用或泄露受限正文；失效来源不得作为回答事实依据。 |
| 禁止行为 | 不得绕过授权、让模型自行判断权限、泄露片段、沿用撤权缓存、将来源失效说成权利失效或“没有相关专利”，也不得生成看似完整的回答。 |
| 必须人工复核 | 权限恢复只能由权威授权机制或授权责任方处理，AI 和普通咨询流程不能授予权限；需要正式采用的剩余分析仍按专业复核边界处理。 |
| 需求来源 | `知识产权咨询对话流管理需求文档.md` 第 1、3 至 5、7、8 节；`知识产权咨询意图管理需求文档.md` 第 1、4、6、7 节（IM-05）；`专利相似度检索需求文档.md` 第 3、5 至 7 节（PS-03、PS-05）；`专利库管理需求文档.md` 第 1、2、4、6、7 节（PL-07、PL-08）。 |
| 当前是否需要专业确认 | 默认拒绝、权限不由 AI 扩大、失效来源不得继续使用已由原需求和 V0.7 明确；真实授权范围、责任方和恢复流程待中心/安全责任方确认。 |

未发现上述三个样例与原始咨询需求冲突。正常场景只覆盖原需求已列出的“专利相似检索/技术参考”，不代表咨询 MVP 已扩展到全部咨询意图，也不代表专业效果已经验收。

## 2. 咨询 MVP 最小业务流程

```text
用户问题
  ↓
问题理解
  ↓
可选补充或必要追问
  ↓
授权检查
  ↓
检索
  ↓
结果筛选/分析
  ↓
带来源的辅助回答
  ↓
必要时人工复核
```

| 步骤 | 性质 | V0 最小边界 |
|---|---|---|
| 用户问题、问题理解、可选补充或必要追问 | 咨询业务能力 | 保留原问题；识别“专利相似检索/技术参考”；提取值必须有来源；可形成请求的可选上下文允许跳过并披露限制；冲突、歧义或无法形成请求时追问，不猜测。 |
| 授权检查 | 共享安全能力 | 在检索召回、原文读取和回答使用前执行默认拒绝的授权判定；咨询域只消费判定，不定义角色或 DataScope。 |
| 检索 | 专利检索业务能力，由技术适配器接入数据源 | 使用用户确认的条件形成检索输入快照；返回实际范围、候选、版本和匹配片段；V0 先接合成数据适配器。 |
| 结果筛选/分析 | 咨询业务能力 | 只在授权且有效的候选中说明匹配点、差异和信息缺口；相关度不升级为法律结论。 |
| 带来源的辅助回答 | 咨询业务能力，引用定位为共享技术能力 | 关键事实能够回到所用文献版本和位置；明确辅助性质、实际范围、失败或未完成部分。 |
| 必要时人工复核 | 人工责任边界 | V0 只产生“需要专业复核及原因”的标记/提示，不建设复核工作流，不声称已经受理或完成复核。 |

最小 API 只冻结能力，不冻结 URL、字段和同步/异步形式：

1. 创建咨询会话；提交问题或补充确认信息；查询本轮处理结果及引用。
2. 执行当前访问授权检查。
3. 按确认条件发起专利检索并取得候选、实际范围和执行引用；读取获授权文献版本及定位片段。
4. 解析/打开回答中的来源定位。

如果检索实现必须异步，只增加最小执行引用和结果查询，不建设通用 Task/Workflow 平台。

## 3. 最小领域对象

以下是由三个样例反推的概念对象，不冻结字段、状态枚举、数据库表或跨领域公共模型：

| 对象 | 最小责任 |
|---|---|
| 咨询会话 | 聚合用户原始问题、补充/确认、缺失项、冲突项及本轮辅助回答；保留信息来源关系。 |
| 检索请求 | 表示用户已确认的检索目的、技术方案/特征、实际范围及输入快照；未确认值不能进入正式请求。 |
| 检索候选 | 表示一个获授权候选的来源引用、文献版本、匹配依据、有效性状态和本次实际检索范围。 |
| 辅助回答 | 表示回答正文、限制/缺口、异常或降级说明、采用的候选引用、版本，以及是否需要专业复核和原因。 |
| 来源定位（值对象） | 表示来源系统、源对象、版本/摘要、段落/页码/字段位置和获取时间，使回答可回查。 |

此阶段不把 `Claim / Evidence / Review / RunRecord` 冻结为咨询领域公共对象。三个样例只证明“回答内容与来源定位的关系”必需；统一证据链、完整复核和运行记录模型继续保持技术候选。

必须保存：用户原始问题及补充、已确认检索条件及其来源、检索输入快照和实际范围、回答采用候选的源标识/版本/匹配依据、回答版本及引用、缺失/冲突/异常、是否需专业复核及原因、最小请求追踪标识；使用 AI 时保存能够定位所用模型/配置版本的标识。

只临时使用：提示词拼装内容、未采用候选全文、中间向量或重排特征、流式片段。模型隐含推理不保存、不展示；未经授权的中心全文不得进入临时缓存或模型输入。

## 4. 第一阶段必须开发的功能

1. 单个咨询会话中的问题提交、补充和必要追问，仅覆盖“专利相似检索/技术参考”。
2. 从输入中提取技术特征和检索目的，显式呈现缺失、歧义与冲突，不把推测写成确认值。
3. 可替换的授权检查能力；V0 默认拒绝，使用职责类别而非虚构具体角色。
4. 合成专利数据检索适配器，返回候选、实际范围、文献版本、匹配依据和来源定位。
5. 对获授权有效候选进行最小筛选/分析，生成带来源、范围限制和辅助性质说明的回答。
6. 正常、资料不足/冲突、无权限、来源失效/部分失败的明确分支及测试。
7. 保存上节列出的最小追溯数据，并提供查询本轮结果和打开来源定位的能力。
8. 产生“需要专业复核及原因”的标记和提示，不实现正式复核决定。

第一阶段的项目负责人验收仅判断：流程是否符合三个样例、来源是否可回查、异常是否如实披露、禁止行为是否未发生。候选专业相关性、法律正确性、真实数据权限和正式意见仍不得标记为已验收。

## 5. 现在不要做

- 不搭建完整 Agent、Runtime、Workflow、Task、RunManifest 或统一工具平台。
- 不建设完整角色权限、DataScope、SSO 或人工复核系统；不冻结具体角色、权限规则和复核状态。
- 不同步完整专利知识库，不建设正式向量索引，不接入未经授权的中心真实数据或外部模型。
- 不实现完整意图/提示词/流程配置管理；不同时覆盖商标、案例、法规、执法和裁决。
- 不进入专利相似度正式判断，不输出新颖性、侵权、有效性、授权成功率或正式专业意见。
- 不做数据库表、API 字段、状态枚举、模型供应商、文件存储和部署方案的详细设计。
- 不提前统一 `Claim / Evidence / Citation / Review / RunRecord`；只实现本咨询闭环确实需要的来源定位与最小追踪。
- 不实现真实中心 API 写入、正式业务状态变更、自动转人工、通知、签发或归档。
