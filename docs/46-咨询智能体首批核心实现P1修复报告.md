## 3. 关键逻辑记录

- `TaskCommandReceipt` 是命令到达事实，不属于九种产品状态，也不要求产生任务版本。
- `TaskEvent` 保存成功业务变更的前后任务版本、授权上下文引用、对象/依赖版本、关联产物和结果；恢复事件另外区分保留的已提交产物与重新进入执行的未完成动作。
- `RecoveryPoint` 保存稳定引用，不复制完整业务对象；历史失败快照保持不可覆盖。
- `CancellationRecord` 保存取消前任务版本、活动子任务版本引用、逻辑停止请求和可选工具停止结果引用。当前未实现真实工具停止，因此结果引用保持未记录，不伪造成功。
- `TaskConflict` 是内部逻辑异常结构，不冻结 HTTP API。

本轮保留原 18 个测试意图并扩展为 28 个 patent task Contract Tests：Task Core 18、Auth Boundary 9、统一命令 1。

覆盖包括：

- stale、对象/依赖版本和并发冲突的结构化信息；
- 恢复依赖变化、来源不可用、权限变化、取消后恢复边界、已完成产物不重跑、未完成动作恢复；
- stale 命令留下到达记录、拒绝不产生任务版本、服务重建后逻辑审计仍可读取；
- 无身份、无策略、资源授权要求不可解析、scope 不匹配、越界动作、前端身份伪造和前端 scope 伪造；
- 服务端资源 scope 变化后下一次命令重新解析并重新授权。

这些测试仅证明 Component/Contract 行为，不证明真实权限、真实数据、真实恢复、Real Integration 或 Business Acceptance。

## 5. 反向场景

### 5.1 任务核心

`创建 → 子任务变化 → 等待确认 → 技术失败 → 按恢复点恢复 → 取消 → 经恢复边界再恢复`

结果：任务版本从 V1 原子推进到 V6；V3 历史快照保持技术失败及原恢复事实；恢复事件区分已提交产物和未完成动作；取消生成逻辑停止请求；取消后恢复不绕过显式恢复边界。迟到旧版本命令被拒绝、写入独立到达记录且不新增任务版本。

### 5.2 授权边界

`无身份 → 默认拒绝 → Fixture 身份 → 服务端资源 scope 解析 → 合法访问 → 资源 scope 变化 → 拒绝 → 当前 DataScope 变化 → 再次重验后允许`

结果：身份仅来自服务端 `CurrentAuthorizationContextProvider`；资源授权要求仅来自服务端 Resolver；前端伪造 identity/scope 均不能改变判断；每次访问重新解析和重验。
