# 三领域任务工作流

依据：[原始方案](../../知识产权智能体方案.docx) 三域“全流程辅助”，及 CON-01～12、ENF-01～17、ADJ-01～12。以下是目标体验与逻辑步骤，不假设旧 API/数据库/页面具备能力。正式程序、真实数据、规则与人工角色按域 **[待确认]**；每阶段产物都带输入版本、来源、权限和未完成项。

## 已确认的共同约束

依据 [docs/02第23节](../02-待确认事项清单.md)，三域均遵守完成分层、稳定跨轮引用、纠正后同任务继续及真实人工受理回执。纠正保留原目标任务链与历史版本；全新案件/目标替换不据此强行复用旧任务。各域完成、证据及正式状态独立定义。

- 咨询绑定结果集/选定文献/技术陈述版本。
- 执法绑定线索或案件工作、材料/证据关系/辅助文书版本；补正后回到原辅助工作链，保留原机器和人工关系。
- 裁决绑定案件工作、争点、双方材料、所选权利要求及报告修订；修正后继续同一案件辅助任务，受影响审核需重新核验。
- 人工请求只有取得可信人员受理记录或真实接收回执才能标已受理；不要求额外建设统一工单平台。

## Consultation Copilot

`问题 → Goal → 信息缺口 → 最少必要补问 → 受限 Retrieval → Candidate → Evidence → Analysis → Result → Human Review/继续`。

1. 接受自然语言、号码、文件或既有任务；目标可为专利查询、技术参考、商标检索/对照、案例参考、法规信息或组合。保留原文和模型提议的 Goal，关键目的、对象、日期、商品/服务、关键技术特征按需要确认。意图/槽位只帮助理解，不直接控制权限或结束任务。
2. 先精确查询/元数据，再按授权文本、语义、图像能力召回；记录实际库范围、算法版本、截断、源故障。专利发明/实用新型文本与外观图像分支分开，商标文字/读音/含义/图形分维度；案例按事实、争点、程序和历史法条比较。他案结果不推本案结论。
3. 候选集有稳定顺序、快照版本、对象/文献版本。“第二个结果”必须绑定可唯一确定的结果集版本与对象；已经明确的选择优先，新展示不覆盖它；没有明确焦点且有多个合理指代时 ASK，展示本身不自动确认采用；新结果自动产生不静默改变用户明确选择。用户可选候选、编辑检索范围、纠正事实，依赖分支局部失效。
4. 技术对照使用实际权利要求/说明书定位，展开从属关系、逐项给对应/部分/未找到/无法判断；摘要仅可支持主题线索。咨询首条只提供技术参考，不输出新颖性、有效性或侵权等正式法律结论；商标判断需商品服务关系及图样实际可读，不能把相关度变注册成功率；案例解释区分原文与未审核提取。
5. 输出候选、证据片段、对照表、参考报告、限制和下一步。普通辅助答复可直接看，拟正式采用的专业意见进入 REVIEW。无权、无结果、来源失效、证据不足、工具故障各自呈现；无权内容不得在旧消息或附件中泄漏。

完成层级按 [产品契约C2](01-product-requirements-v2.md)：辅助成果完成不等于专业接受或正式办理。

完成：目标问题逐项回答，关键结论有适配证据，实际范围与未覆盖信息披露；不完成时交付已做部分及明确缺口。首条黄金任务限定内部专利技术参考，真实业务效果仍待样本和授权。

## Enforcement Copilot

`线索 → 疑似事实/主体 → 证据 → 待证明事项与证据链 → 发布规则 → 逐项辅助分析 → 程序合规 → 文书/建议草稿 → 人工审核`。

1. 接受获准线索源/批次或人工输入，保留源记录版本；规则命中只成待核实线索，失败记录不作无命中，跨源疑似重复不自动并案。抽取主体/行为/时间/地点及出处；投诉人、经营者、权利人角色分开，优先级需批准因素。
2. 按案件或线索登记原件、收集/上传时间、文件与实物位置、哈希及派生 OCR，访问受当前权限控制。哈希只核字节；相同文件的不同收集过程不合并。人工核验真实性、合法性和采信；机器产物仅候选事实关系。
3. 已发布且匹配案件类型的证据规则列待证明事项、支持/反驳/矛盾、未取证、不可读材料和时间线。规则不存在时可显示材料清单与缺口，不称“完整有效证据链”。来源/规则/采信变化触发影响审阅。
4. 规则引擎核对职权/程序/时点、要件、期限和计算条件；缺事件/日历则无法判断。AI 解释候选事实与条文，不作侵权认定；专利侵权与假冒专利/商标行为分流程。处罚建议只在已确认事实、依据和裁量规则存在时列可解释范围，模型不算金额。
5. 采用批准模板/字段映射生成不完整或可提交草稿，缺项不模型补齐；不生成虚构笔录、签章、文号和处罚决定。授权人修正、审核并在正式系统办理；审核结果不自动立案、处罚、签发或送达。

完成：**辅助工作包**的事实/证据/冲突/规则结果/缺项和人工待办齐备；正式执法流程完成由权威系统及有权人员单独判定。任何本地“已复核”不等于正式案件状态。

## Adjudication Copilot

`案件 → 材料/双方主张 → 待确认事实与争点 → 专利/法规指定版本 → 条文候选与引用 → 双方证据逐项对照 → 法律状态/稳定性风险分栏 → 分析 → 报告初稿 → 人工复核`。

1. 案件来源、主档、受理/分配/归档权威和写回能力待确认。本地任务不冒充正式受理；申请人、被申请人和材料权限独立检查。当事人主张、机器抽取和人工确认事实分开。
2. 解析法规原文、历史修订和条文要点，只有审核可用的派生解释可称已校核；时点/地域/程序/过渡规则有缺口时列候选，不认定适用。专利文献明确申请/公开/授权版本、权利要求依赖与低质 OCR；无全文不得以摘要代替。
3. “有效性分析”拆为指定时点的官方状态核验与基于有限文献的稳定性风险。缴费记录缺失和无效请求不等于权利终止；新颖性单篇对照、创造性组合理由需来源；任何稳定性意见不修改官方状态。
4. 证据按待证事实及所选权利要求必要要素逐项对应，同时保留反证、质证和缺项；销售资料不推内部结构，照片/哈希不证明真实性。等同问题只列争议和事实基础，专业判断交有权者；外观设计独立流程。
5. 用经批准模板、具体条文版本和报告位置生成结构化草稿；缺必填可保存不完整草稿但不提交复核。人工编辑与重新生成保留差异，复核锁定最终版本及依赖，变化后重审。签发、签章、送达、办结、归档只能真实动作/回执推进。

完成：报告草稿及引用/证据/未决包达到可复核条件，或返回证据不足及具体补件；复核通过只意味着待签发工作成果，不是正式行政裁决。

## 负向业务样例（预注册，不是专家答案）

| 场景 | 必须表现 | 禁止表现 |
|---|---|---|
| 专利只有摘要、用户要权利要求对照 | 线索级结果与全文缺口 | 完整要素对照/侵权结论 |
| 商标缺图、跨类别商品关系不明 | 文字维度可做，图形/商品服务待核实 | 零分图形或“可注册” |
| 案例同纠纷不同审级、历史法规 | 分列文书版本与差异 | 合并裁判结果/套现行法 |
| 执法源限流、证据撤回、规则冲突 | 部分失败/证据待复核/规则阻断 | 无线索、完整证据链或自动罚款 |
| 裁决仅有无效请求、双方材料矛盾 | 状态未核实、反证并列、交人工 | “专利已无效”或正式裁决 |
| 报告已复核后事实/法条变更 | 新版本、原批准失效/待复核 | 旧批准用于新内容签发 |
