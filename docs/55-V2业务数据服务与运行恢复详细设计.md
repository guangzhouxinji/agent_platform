## 2. 服务及信任边界

三个Agent只使用所属域的受控业务命令和查询；领域服务包括咨询、执法、裁决及公共资源模块，领域代码仅依赖端口。人类审核与配置发布走独立可信入口；不能让Agent代持人工操作权限。现有platform-api未来可作为服务宿主候选，须完成代码隔离核查；本设计不决定直接搬迁旧Controller。

开发期人工接收通道按docs/02第28节选择各域内部工作台：请求、领取、退回/意见及回流由所属域保存具名不可变事件，公共模块仅提供可信主体、当前授权和受控文件/来源能力，不拥有业务审核决定。真实甲方接收系统若后续存在，作为对应领域的可替换适配器接入，不把开发期内部事件改标外部正式回执。裁决提交人与最终复核人仍须不同主体；两个测试主体即便都可执行全部操作也不能取消此不变量。

端口最小集合：IdentityPolicy（可信主体、资源、动作、用途决策）、SourceQuery/SourceContent（来源与具体版本）、Search（能力及范围）、Model（允许内容、固定模型与模板版本）、File（受控文件）、DomainRepository（事务）、HumanReceipt（实际接收）、OfficialReceipt（权威状态）。不用一个任意HTTP工具替代这些端口。域服务返回允许动作，Agent只能从允许集建议；最终命令仍在服务校验。

数据读取路径为：认证→域资源归属→当前用途许可→源范围过滤→适配器→输出字段/引用授权。模型上下文由授权片段及固定版本组成，模型没有数据库、权限写入或正式决定接口。源内指令、提示词变量和模型输出都是不可信内容，不能定义工具地址、角色或数据范围。

当前身份系统未确认，因此定义端口结果而不伪造机构字段来源：`SubjectRef(issuer, stableSubjectId, subjectKind)`、`DelegationRef`及可信组织/资源范围由适配器验证。Agent服务身份与被委托用户权限取交集，附动作及用途。缺委托、过期、策略不可用一律不执行受影响动作。真实角色到动作映射在docs/02第25节取得证据；字符串scope不是授权事实。

## 3. 共用值类型及缺失语义

| 类型 | 必需内容与不变量 |
|---|---|
| ObjectRef | domain、type、id、version；版本是服务分配的单调修订号，不能使用名称/列表序号代替id |
| SourceRef | sourceId、sourceRecordId、sourceVersion或获准内容摘要、fetchedAt；sourceUpdatedAt可缺，缺失原因必须保留 |
| EvidenceLocator | SourceRef + 定位类型（条号/页段/字段/图像区域/音视频时间点）+定位值；不能定位则明确不可定位，不伪造 |
| BusinessDate | 原值、精度、可解析值及已知时区；日期不能强制转UTC导致变日；业务发生、来源更新、系统获取时间分开 |
| ObservedField | value、availability、originRef、originKind；availability区分已提供、未提供、不适用、解析失败、访问受限、待核实；null不表达所有原因 |
| Money/Score | 十进制值、单位/币种、精度/舍入或标尺、规则版本；缺值≠0；无标尺不输出数值分；原号码均为字符串 |
| DependencyRef | 消费对象版本、输入对象版本、用途、定位、有效性及变化原因；记录字段级/章节级依赖，无法缩小影响时标“待核对”而非猜无影响 |
| CompletionEvidence | 被满足的目标版本、具体产物版本、证据检查结果、未完成项、限制及责任来源；不能单以HTTP或执行成功生成 |

正文可为大字段或受控文件引用。索引不能成为唯一事实仓库。消息/报告/提取既存原始机器输出又存人工修订；是否可保存模型原始输入输出按用途和保留批准，不保存隐含推理或凭据。无保存许可且任务必需持久上下文时拒绝该数据通路，不能为“可恢复”扩大许可。

## 4. 逻辑命令信封与返回

所有写入命令使用：`commandId`（幂等键）、`operation`、`targetRef`、`expectedVersion`、`inputRefs`、`payload`。身份来自认证通道；`traceId`由服务生成/验证，客户端传操作者、组织或审核人字段均不能改变身份。新建无目标版本，其余写入必须给预期版本；跨对象命令逐一给被修改对象的预期版本。

同步提交返回`receiptId,targetRef,newVersion,committedAt,changeRefs`；异步接受返回`attemptRef,acceptedVersion,pollRef`，明确只是已接受。业务结果查询返回`executionState,availability,completeness,domainState,reviewState,officialStateRef,limitations,allowedActions`中适用字段，不虚造不适用状态。无结果是成功读取后的业务结果，不是异常或系统故障的替代值。

候选接口命名采用`/v2/{domain}/...`；只有各篇列出的显式操作才能路由，不能开放任意`operation`反射执行器。本篇使用逻辑命令名，具体中心URL和供应商响应映射保持待证据。未来HTTP实现：新建201、异步202、正常读取/提交200，参数结构400、未登录401、禁止403、确证不存在404、版本/幂等/忙碌409、前置资料/规则不足422、上游限流429、依赖不可用503、超时504；不存在与越权的细分只给获准主体，匿名/越域请求不泄露存在性。

统一错误体`code, message, traceId, retryability, missingFields, currentVersion`：后两者只返回调用者有权知道的内容。细分码包括AUTH_UNAVAILABLE、SOURCE_CAPABILITY_MISSING、SOURCE_WITHDRAWN、SOURCE_PARSE_FAILED、MODEL_FAILED、INPUT_VERSION_CHANGED、DEPENDENCY_INVALID、REVIEW_REQUIRED、RECEIPT_UNKNOWN、CANCELLED。重试建议不自动批准扩大来源或外部副作用。

## 6. 原子性、幂等与授权竞态

一次命令先取得当前授权/依赖检查结果，再在短事务内执行：核可验证授权及撤销版本→锁定幂等作用域并查已有回执→同键同请求在重验读取权限后返回原回执→仅新命令锁定/比较目标版本与依赖→校验域不变量→追加业务版本与依赖→更新当前指针/检查点→写回执、审计和待发事件→提交。重放检查必须先于新写的预期版本比较，否则第一次提交后的合法重试会被错误判版本冲突。长模型调用、文件转换、外部HTTP均不在事务内。跨域不建立全局事务。

幂等规范化包含操作、目标、预期版本及完整业务载荷/输入引用，排除追踪号和短期令牌；同键同载荷返回原回执前仍重验读取权限，同键异载荷409。未提交事务失败后可原键重试；提交成功但响应丢失查回执，不重复产生目标/轮次。新的业务尝试用新键并关联retryOf，不能把未知外部结果作为失败重做。开发期幂等回执与所属任务同期限保存，期间不得先行清除而造成重复执行；生产期限依真实协议确定。

同一事务可原子提交：事实修订+影响失效标记；报告结构+本域引用绑定；审核决定+被审版本状态；文件登记引用+业务材料登记；命令结果+检查点+outbox。文件字节与DB不原子：先受控暂存和校验，业务事务将manifest标为已关联；未关联文件只进入对账清理，不成为证据。上传失败不得提交已关联状态。

权限的历史证据不替代当前决定。命令提交、片段入模、下载/流式每次传送前检查当前撤销版本；策略变化使旧执行停止，持久成果标受限。外部授权服务无法与本地DB原子提交时，适配器必须给有边界的有效性凭证/撤销机制，并在提交与发布前重验；没有可信协议不宣称消除了所有时序竞态，相应真实通路不启用。已实际送出的字节不能被“撤回”追回；停止后续发送并记录可核实影响，不承诺物理追回。

## 7. 执行租约、取消与恢复

咨询每会话同时最多一条普通用户消息处理中；纠正、取消是带版本控制命令，不作为第二条普通消息抢占。命令接受纠正后提升任务版本及执行epoch，旧消息尝试以输入已变化结束，保留用户消息不重复计轮。以用户消息表达的控制动作同事务登记一个用户消息ID及轮次，关联已有消息时不再计轮；纯按钮系统控制事件不冒充用户消息。跨会话恢复同任务时任务级活动槽同样串行，避免两个窗口各自认为拥有执行权。

Agent申请执行权返回`leaseId,fencingToken,expiresAt,checkpointRef`；时钟以服务端为准，租期和续约间隔是待运维实测的技术参数。提交必须同时匹配当前租约token、任务版本、输入版本和取消epoch。过期或被替代worker不可发布；不能仅比较客户端时间。服务重启后重取租约，不把running直接改成功。

恢复算法：扫描到期且非终止执行→收回旧权→重新授权和核查来源→读取最后提交检查点→若输入失效先登记新版本/重规划→若外部动作结果未知先对账→对可幂等未提交步骤创建关联尝试→新worker执行。提交前重新检查，已有效完成的步骤不重做。没有新的授权、材料或合理动作时保持相应等待/不足原因，不后台无限重试。

取消按本地提交先后裁决：取消先提交则提升epoch并拒绝以后成果发布；成果先提交则保留成果，取消停止剩余动作。完成任务的重复取消是无新副作用的结果；实际正在执行的外部动作可能无法撤销，显示“本地停止，外部待核实”，不能伪称外部取消完成。开发期已取消任务不可直接恢复，保留历史供当前获准主体查看；继续目标必须新建关联任务、重新核权及核来源，不继承旧租约或幂等作用域。生产取消后恢复策略仍待甲方证据。

开发期项目自有任务记录按docs/02第30节保留六个自然月：进行中从最后一次已提交业务变更起算，终止任务从终止时间起算，读取不续期。任务版本、检查点、回执、内部人工事件和派生成果共用任务到期界限；更早到期的来源许可立即限制其内容使用/恢复。到期拒绝恢复及旧ID命令，清理关联正文、文件和索引；备份轮换须防止恢复到期记录重新可用，并记录清理结果/重试。来源资料、真实甲方数据及生产审计/备份不得由此获得六个月保存许可，实际删除批次和备份策略在开发期限定D中给出可验证方案。

读模型提供`GET task?revision`及`GET events?afterSequence`；事件重放当前鉴权，失权内容不重播，可返回不含正文的受限占位。断线不取消。序号超出保留范围返回重新获取快照提示，不能静默丢事件或重计轮次。流式草稿明确未完成，最终完成消息有唯一约束；同一完成事件重复传送不生成第二份答复。

## 8. 来源、文件、索引与失效传播

来源新增/更新创建新版本；同源同版本内容变化为SOURCE_VERSION_CONFLICT，隔离核对而不覆盖。无源版本仅在获准情况下使用内容摘要的观察版本，不把它当中心版本。解析版本绑定原文、解析器/模型及质量结果，OCR与原件分开。

新版本、撤回、用途变化事件同事务写出；消费者按eventId去重，沿DependencyRef标记需复核/不可用，保留旧引用。索引用版本化条目，更新成功才切查询可见指针；索引失败返回降级实际范围，不能用旧索引冒最新。授权过滤须在召回入口执行；每个返回结果再次检查，不只在前端过滤。

报告无法安全按字段去除受限内容时整份停止展示/导出，返回可见元数据及获取授权指引。文件统一通过受控访问入口，不使用绕过当前授权的永久公开链接；下载令牌绑定主体、对象版本、用途及到期，并在取文件时再验。真实大小、格式及保留参数来自原文初值或批准配置，不由模型设置。
